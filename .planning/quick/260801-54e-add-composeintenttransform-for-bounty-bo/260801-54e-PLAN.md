<objective>
Add a natural-language intent-transform layer to the Skynet pretty-view ComposeBox
send pipeline. Ashley speaks "bounty bounty add a banana button" (voice-first
workflow, "/" is the last keyboard reach she wants to avoid), the STT layer
transcribes it (often with Whisper-inserted punctuation like "Bounty, bounty."),
and the ComposeBox rewrites the payload to "/bounty add a banana button" before
`onSend(payload)` fires. Registry-gated (bounty only for now), front-anchored,
punctuation-tolerant on both sides of the second word.

Purpose: Eliminate the last slash-keystroke friction in Ashley's voice-first flow
while keeping false-positive rate at zero (no natural English sentence starts
with a doubled registry word).

Output: `composeIntentTransform.ts` (implementation), `composeIntentTransform.test.ts`
(25 vitest cases), and 4 wrapped payload sites in `ComposeBox.tsx`.
</objective>

    Create `src/ui/features/pretty-view/composeIntentTransform.ts` per locked design:

    - Export `INTENT_REGISTRY: Record&lt;string, string&gt; = { bounty: "/bounty" }`. Do NOT add any other keys — YAGNI (per hard_constraints).
    - Define regex constant: `/^\s*([a-z]+)[\s.,;:!?\-]+\1[\s.,;:!?\-]+(\S.*)$/is`. Notes for the JSDoc: `s` flag lets `.` cross newlines (multi-line rest); `i` flag makes both `[a-z]+` and the `\1` backref case-insensitive; `[a-z]+` is letters-only (no digits, no underscores) for keyword precision; punctuation class `[\s.,;:!?\-]+` appears on BOTH sides of the second word (Whisper habitually inserts commas/periods there); requires `\S.*` after so bare "bounty bounty" is passthrough (probable accidental send).
    - Export `applyIntentTransform(text: string): { transformed: string; matched: boolean; command: string | null }`.
      - Run regex against `text`. If no match -> return `{ transformed: text, matched: false, command: null }`.
      - If match: `const key = match[1].toLowerCase(); const rest = match[2];`
      - If `key` is a key in `INTENT_REGISTRY`: `const command = INTENT_REGISTRY[key]; return { transformed: \`${command} ${rest}\`, matched: true, command };`
      - Otherwise (regex matched but key not in registry) -> return `{ transformed: text, matched: false, command: null }` (passthrough — this is the registry gate).
    - JSDoc header must explain: voice-first origin (Ashley avoids "/" keystroke), front-only anchoring (`^\s*`), registry gate (unknown doubled words pass through), requires-content contract (`\S.*`), punctuation-tolerance-both-sides, and "empty/no-match returns passthrough with matched:false, command:null".

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ComposeBox input -> `onSend(payload)` | User-typed / STT-transcribed text becomes a wire payload. Intent-transform rewrites the front of the string. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-54e-01 | Tampering | `applyIntentTransform` regex | mitigate | Front-anchored `^\s*` prevents mid-message injection; registry gate blocks unknown doubled words; requires-content `\S.*` blocks accidental bare doubling. |
| T-54e-02 | Elevation of Privilege | Rewriting to `/bounty` slash command | accept | The wire already accepts `/bounty` from the user typing it directly; intent-transform is a keystroke shortcut, not a new capability. No new privileges introduced. |
| T-54e-03 | Denial of Service | Regex catastrophic backtracking | mitigate | Regex uses simple `[a-z]+` + `\1` backref with bounded punctuation class `[\s.,;:!?\-]+`; no nested quantifiers; input is user-typed chat message length (bounded). Test suite exercises long-content cases. |
| T-54e-04 | Information Disclosure | Content preservation | mitigate | `\S.*` capture with `s` flag preserves ALL content after the doubled word verbatim including punctuation and newlines — no truncation or leakage into logs. |
| T-54e-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs — pure TypeScript using existing project deps (vitest already installed for the repo). |
</threat_model>
