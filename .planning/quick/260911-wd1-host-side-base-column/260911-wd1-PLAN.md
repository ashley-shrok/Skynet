<objective>
Add a nullable `host_side_base` sibling column to `matrix_admin_creds` and thread it through the identity-birth path so relay.json can carry a URL distinct from the one Skynet uses to reach synapse from inside its container.

Purpose: fleets whose container-internal Matrix URL is NOT reachable from managed hosts (e.g. skynet.aithercloud.com's setup, which uses `http://synapse:8008` inside Docker but hosts need a tailnet URL) can specify a host-reachable override that gets written into per-identity relay.json at birth. When null (default), existing single-URL fleets like t1000 are unaffected — consumers fall back to `homeserverBase`.

This mirrors the existing `server_name` split precedent (schema.ts:730, matrix-admin-routes.ts PATCH `/creds/server-name`, matrix-admin-creds-store.ts `setMatrixAdminServerName`) — same shape, same encryption discipline (this column is plaintext like homeserverBase/serverName), same DatabaseSaveTrigger try/catch save.

Output: schema column, store setter + type propagation, admin-gated PATCH endpoint, GET response extension, orchestrator deps type + call-site swap, two identity-birth deps-block wirings, scoped test coverage for each.
</objective>
