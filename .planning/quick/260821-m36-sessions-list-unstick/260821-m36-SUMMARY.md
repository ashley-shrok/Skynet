# Quick 260821-m36: Sessions List Unstick — SUMMARY

One-liner: split `/sessions/list` backend timeout so a dead phantom host fails
fast at TCP+SSH connect (5s) instead of starving the whole request past axios'
30s ceiling, add a one-line silent-catch flag-flip so cold-cache clients exit
"Loading agents…" on any fetch failure, and drop a one-shot FK-safe phantom-
host DB cleanup script into the plan dir for the deploy sequence to run
inside the container before `docker compose force-recreate`.

Purpose: unstick "Loading agents…" on Ashley's cold-cache desktop + iPad
refreshes; eliminate "Server connection lost, recovering…" toasts caused by
axios 30s rejections; make `/sessions/list` resilient to future dead hosts
without requiring per-incident DB surgery.

## Ops Script Lifecycle Note

`delete-phantom-hosts.mjs` is a **one-shot ops artifact**, NOT to be re-run in
normal operation. Its idempotent short-circuit (0 phantom rows → `OK: 0 rows
to delete, phantoms already gone` + exit 0) makes accidental re-runs safe,
but there is no ongoing operational reason to invoke it after this one
deploy. The file stays in the plan dir as an audit trail — future phantom-
host cleanups should be scoped to a new plan directory with a fresh, target-
