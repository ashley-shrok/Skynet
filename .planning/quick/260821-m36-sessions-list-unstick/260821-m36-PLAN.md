<objective>
Fix two things in one atomic deploy on `feat/tab-title-from-tmux` and one ops-only DB cleanup, so Ashley's desktop + iPad clients stop getting stuck at "Loading agents…" and stop firing "Server connection lost, recovering…" toasts:

1. **Backend timeout split** — the current `PER_HOST_TIMEOUT_MS = 30_000` wraps BOTH the initial TCP+SSH connect AND the three post-connect discovery blocks. When phantom hosts 14 & 15 (created by prior UAT that never got cleaned up, currently pointing at addresses that no longer resolve on tailnet) hang the TCP connect, /sessions/list runs its wall-clock over the frontend's axios 30s timeout, the axios call rejects → PrettyConversationsPanel never receives fleet data → spinner sticks; the axios rejection also triggers the WS-health toast pipeline. Split into `CONNECT_TIMEOUT_MS = 5_000` (fail-fast on TCP connect for unreachable hosts) + keep `PER_HOST_TIMEOUT_MS = 30_000` for the three legitimate discovery-heavy blocks (tanya's patch #477 rationale still holds — a 5-identity host's concurrent recency-signals discovery wall-clocks around 5s, needing the 30s roof).

2. **Frontend flag-flip on fetch failure** — the AppShell useEffect that calls `getSessionList()` has a silent catch (~L646-651) that intentionally does nothing beyond letting `fleetSessions` stay empty. Problem: it also NEVER calls `updateFleetSessions` on the failure path, so `fleetSessionsLoaded` stays `false` — which on a cold-cache client (first visit, cleared storage) means PrettyConversationsPanel keeps rendering "Loading agents…" forever. Add ONE line: `if (!cancelled) updateFleetSessions([])` — under the quick-260727-kbw contract, this unconditionally flips `fleetSessionsLoaded` to `true` even with an empty array, exiting the spinner state. Silent-catch semantics otherwise preserved (no toast, no console.warn, cache untouched).

3. **Phantom host DB cleanup** — hosts.id 14 & 15 are stale rows whose IPs no longer resolve; they are the root cause of the slow /sessions/list responses that trigger the frontend spinner-stick + WS toast. Purge them BEFORE the recreate so the AES-encrypted DB is still open with its live decryption key. One-shot node script, idempotent, FK-safe (aborts loudly if any FK references still point at 14/15 — no cascade-delete without human review). Documented in SUMMARY, NOT committed to src/.

Purpose: Unstick "Loading agents…" on cold-cache desktop/iPad refreshes; eliminate "Server connection lost, recovering…" toasts; make /sessions/list resilient to future dead hosts without requiring per-incident DB surgery.
