Concrete behavior (from TASK.md § What to build § 1 and shape file § Shape):
- Argv: `role-file-watch <identity-dir>` — expanduser + abspath.
- Identity name = last path component (e.g. `tanya` from `/home/ubuntu/.claude/identities/tanya`).
- Read role name from YAML frontmatter `role:` key in `<identity-dir>/<identity-name>.md`. Parse frontmatter as the block between the FIRST two `---` lines (stdlib — do NOT add a yaml dep). Extract the value after `role:` on a line matching `^role:\s*(\S+)`. On missing file / missing frontmatter block / missing role key: print `⚠️ [role-file-watch] <reason>` to stderr, `sys.exit(1)` (cleanly — supervisor decides restart, don't crash pipeline).
- Resolve role-file path = `~/.claude/roles/<role>/<role>.md` (expanduser). Missing → stderr warning + `sys.exit(1)`.
- Baseline dir = `<identity-dir>/role-file-watch/`; baseline file = `<identity-dir>/role-file-watch/last-snapshot`; spill dir = `<identity-dir>/role-file-watch/spilled/`. `os.makedirs(baseline_dir, exist_ok=True)` at startup; spill dir created lazily on first spill.
- Cold-start rule: if `last-snapshot` DOES NOT exist → atomically snapshot current role-file bytes into `last-snapshot` (write to temp in same dir, `os.replace` onto baseline), print NOTHING to stdout, THEN enter the watch loop. This satisfies the shape file's "silent on cold start" invariant.
- Subsequent-run rule: if `last-snapshot` exists → compare current role-file bytes vs baseline bytes at startup; if differ → emit one event (see event format) and atomically update baseline; if match → emit nothing. EITHER way → enter the watch loop.
- Watch loop:
  - Prefer `inotifywait -m -e close_write,move_self,moved_to <role-file>` via `subprocess.Popen`, iterate stdout line-by-line. On each event line: do the diff-and-emit logic (compare current bytes vs baseline, emit iff different, atomically update baseline).
  - If `inotifywait` binary is NOT on PATH (probe via `shutil.which("inotifywait")`) → log a one-time stderr warning at startup that fallback is engaged, and fall back to a 2-second `os.path.getmtime` polling loop; treat mtime change as an event.
  - On `move_self` (atomic replace of the role file by a `mv`) → re-arm the inotify watch on the new inode (kill + respawn the inotifywait subprocess pointed at the same path). Fallback polling handles this naturally via mtime.
  - On role-file DELETE (rare): log stderr warning + `sys.exit(1)`.
  - Orphan-monitor guard AND single-instance pidfile guard must be present, copied line-for-line from the equivalent blocks in `wakeup-scheduler.py` / `context-watch.py`. State-dir for the pidfile = `<identity-dir>/role-file-watch/.state/`; pidfile name = `role-file-watch.pid`. (Different from the siblings' `.state/` locations — those are inside their own subdirs. Same shape, just moved.)
  - `SIGTERM` / `SIGINT` → clean shutdown (kill inotifywait subprocess if running, then exit 0). Register signal handlers early.
  - Any unhandled exception in the watch loop → log traceback to stderr + `sys.exit(1)` (supervisor restarts).
- Baseline update atomicity: always write to `<baseline_dir>/last-snapshot.tmp`, then `os.replace(..., last_snapshot_path)`. Never leave a half-written baseline.
- Event format:
  - Prefix: `📝 [role-file: <role>]` (matches emoji convention of `⏰ [scheduled: ...]` in wakeup-scheduler and `⚠️ [context-watch: ...]` in context-watch).
  - Diff: `subprocess.run(["diff", "-u", str(baseline_path), str(role_file_path)], capture_output=True, text=True)` — capture stdout regardless of exit code (diff exits 1 when files differ; that's the normal signal case).
  - **Spill threshold: match `recv.sh:152` — `INLINE_MAX=460`**, with the ~500-char harness cap rationale from `recv.sh:137`. Cite exactly: `# spill threshold matches recv.sh:152 — INLINE_MAX=460 keeps the whole event line comfortably under the ~500-char harness cap (recv.sh:137)`.
  - Assembly: compute `line = f"📝 [role-file: {role}] {diff_stdout}"`. If `len(line) <= INLINE_MAX` → emit inline as ONE `print(...)` call with `flush=True`. Newlines in the diff stay as literal newlines in the printed body (matches how wakeup-scheduler emits multi-line-in-one-print via file-pointer form — but here for small diffs inline is fine because the ~500-char cap is on the FIRST line and short unified diffs are typically 3-8 lines totaling well under 460 chars). If `len(line) > INLINE_MAX` → spill:
    - `spill_path = <spill_dir>/<UTC ISO timestamp with -%Y-%m-%dT%H-%M-%SZ shape>.diff`.
    - Write full diff to spill_path (create spill_dir with `mkdir -p` semantics on first use).
    - Emit ONLY: `📝 [role-file: <role>] diff too large to inline — read from <spill_path>` (single `print(...)` with `flush=True`).
  - Do NOT auto-clean spilled diffs (matches recv.sh's stashed-message handling — small, useful for debugging).
- Module docstring: match `wakeup-scheduler.py` / `context-watch.py` shape — a one-paragraph "what this is + sibling positioning", then behavior, then "Usage:" line, then "Env:" line if any env vars are honored. Env vars supported: `ROLE_WATCH_POLL_SEC` (default 2, for the fallback polling loop). Reference the shape file `.planning/shapes/shape-role-file-watch.md` in the docstring for rationale (analogous to how wakeup-scheduler's docstring cross-references its design context).
