# Phase 260803-79i Plan 01: Fix 4 Issues from Phase 20 Code Review Summary

Fixed four Phase 20 code review findings with atomic per-fix commits and regression tests.

## CR-03 Fix — Broken SSH probe shell quoting (real bug)

**Commit:** 95a0166

**Problem:** `identity-exists-on-host.ts` line 128 wrapped `${name}` in literal single quotes inside a double-quoted shell string: `"$HOME/.claude/identities/'${name}'"`. Single quotes do NOT nest inside double quotes in POSIX shell — the shell saw a literal directory named `'testname'` (with the apostrophes as part of the name), so the probe always returned `{exists: false}` for SSH hosts, breaking the IDUI-05 target-host collision block.

**Fix:** Removed the inner single quotes. The path is now `"$HOME/.claude/identities/${name}"` — name is interpolated raw inside the double-quoted string. IDENTITY_KEY_RE validation still runs before the SSH command is constructed, so injection defense is unchanged (validate-then-interpolate pattern).

**Test update:** Rewrote Test 10 Part B to assert `command.includes('/identities/testname')` and `command.includes('"$HOME/.claude/identities/testname"')` and `!command.includes("'testname'")`. Updated test title to `"shell safety — name is validated pre-SSH and interpolated raw inside double-quoted path (CR-03 regression)"`.

**Files:** `identity-exists-on-host.ts`, `identity-exists-on-host.test.ts`

## CR-02 Fix — TMUX_SAFE_NAME_RE stricter gate (real risk)

**Commit:** 1ea586f

**Problem:** `IDENTITY_KEY_RE = /^[a-z0-9._=/+-]+$/` accepted names containing `=`, `/`, `+`, `.` which tmux interprets as target syntax metacharacters (`-t =name` = exact match, `.name` = window/pane reference, etc.). Such names would produce malformed tmux targets in `birthIdentity()`.

**Fix:** Added `TMUX_SAFE_NAME_RE = /^[a-z][a-z0-9_-]*$/` immediately after `IDENTITY_KEY_RE` declaration. Added a second check inside `birthIdentity()` immediately after the existing `IDENTITY_KEY_RE` block, throwing `"identity name unsafe for tmux target — must match [a-z][a-z0-9_-]*; got: ..."` before any `getCandidateForBirth`/`createIdentityRecord`/`connectOneShot`/`execCommand`/`execLocal` call.

**Tests:** Added `describe("CR-02: TMUX_SAFE_NAME_RE stricter gate")` with `it.each(["foo=bar", "foo/bar", "foo+bar", "foo.bar"])` asserting rejection with `/unsafe for tmux target/` and no deps called; plus a passing test for `"test-agent1"` confirming `getCandidateForBirth` is reached.

**Files:** `identity-birth-orchestrator.ts`, `identity-birth-orchestrator.test.ts`

## CR-05 Fix — openBirthStream reader leak on error paths (defensive)

**Commit:** 355447d

**Problem:** On non-200 response, `openBirthStream` threw without releasing the `ReadableStream` body, leaking the TCP/HTTP2 connection slot. On 200 response with `body === null`, it used a non-null assertion `response.body!.getReader()` which would throw an unhandled `TypeError` instead of a clear error.

**Fix:**
1. On non-200 path: added `await response.body?.cancel().catch(() => {})` after `response.json()` error extraction and before `throw`. Ordering preserves error message; cancel is a no-op if body was already consumed.
2. On 200 path: replaced `response.body!.getReader()` with an explicit null guard that throws `"birth failed: server returned empty SSE stream"`.

**Tests:** Added `describe("CR-05: openBirthStream error paths")` with `it("cancels response.body on non-200 status")` (asserts `body.cancel` mock called) and `it("throws 'empty SSE stream' when 200 response has null body")`.

**Files:** `identities-api.ts`, `identities-api.test.ts`

## CR-06 Fix — Bounded candidate cache with global + per-user caps (defensive DoS)

**Commit:** 33a80bc

**Problem:** `candidateCache` in `identity-avatar-batch.ts` was an unbounded `Map`. Under sustained abuse, an authenticated user could fill Node's heap with base64 PNG data (OOM risk).

**Fix:**
1. Added `GLOBAL_CACHE_MAX = 100` and `PER_USER_CACHE_MAX = 15` constants.
2. Added `evictIfNeeded(userId: string): void` helper using Map insertion order as age proxy: iterates to find oldest per-user entry, evicts if at `PER_USER_CACHE_MAX`; then evicts oldest global entry if at `GLOBAL_CACHE_MAX`. Logs `console.warn` for each eviction.
3. Called `evictIfNeeded(userId)` before every `candidateCache.set()` in the POST /batch handler (once per image = 3 checks per request).
4. Exported `_evictIfNeededForTest(userId)` gated on `NODE_ENV==="test"`, mirroring existing `_getCandidateCacheForTest`/`_clearCandidateCacheForTest` pattern.

**Tests:** Added `describe("CR-06: candidate cache eviction")` with global-cap test (pre-fill 100 entries, evict+insert, assert oldest gone, size stays 100) and per-user-cap test (15 user-1 entries + 5 user-2 entries, evict+insert for user-1, assert oldest user-1 gone, user-1 stays at 15, user-2's 5 entries untouched).

**Files:** `identity-avatar-batch.ts`, `identity-avatar-batch.test.ts`
