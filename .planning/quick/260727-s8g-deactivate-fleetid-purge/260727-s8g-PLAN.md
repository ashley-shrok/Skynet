<objective>
Fix activeSet id-shape mismatch: when a user taps an ambient fleet row and then
deactivates the resulting active-set row, the fleet-synthetic id
(`fleet::HOSTID::SESSIONNAME`) is orphaned in `state.activeSet` because the
deactivate handler only removes the openTab id shape. Next `computeSnapshot`
pass re-promotes the row to Tier 1 with `.active-set` glow instead of letting
it return to its Tier 3 host group as ambient.

Purpose: Restore the visual contract that "deactivate = row goes back to
ambient". This is the same class of bug as the queued #149 followup-1
pin-nuke (id-shape mismatch in pinnedIds), but scoped to activeSet only.
The pin variant is separately queued; do NOT touch it here.

Output: Two source edits (export helper + double-purge handler), two new tests
(Test 20F + Test 20G), one patch-catalog entry.
</objective>
