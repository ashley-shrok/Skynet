<objective>
Add a single new `visibilitychange` useEffect to Terminal.tsx (patch #143) that fixes the iOS PWA backgrounding failure mode: when Ashley switches away from the Skynet PWA and returns ~1 min later, the SSH terminal's 8-attempt exponential-backoff reconnect budget (2s→4s→8s cap, ~50s total, lines 840-912) has typically burned through against a throttled iOS tab — leaving `shouldNotReconnectRef.current=true` and the manual "Connection lost" overlay stuck on screen. The target's tmux is always up; the reconnect budget is the only thing that failed.

Purpose:
- On `document.hidden === true`: cancel the scheduled reconnect and reset attempt counter so we don't burn attempts against a throttled tab.
- On `document.hidden === false`: if disconnected AND not target-terminated AND not unmounting, do the equivalent of the manual Reconnect button — reset the reconnect state flags, clear the overlay, and call `connectToHost(cols, rows)`. Skip `terminal.clear()` (tmux repaint handles restoration; clearing added flicker in the manual-overlay path).
- CRITICAL boundary: when `wasDisconnectedBySSH.current === true` (auth fail / ssh closed / `~.`), DO NOT auto-reconnect. Manual Reconnect via the overlay stays the correct affordance for that case.

Output:
- Single new `useEffect` in Terminal.tsx (add-only; no modification to `attemptReconnection`, `connectToHost`, or the manual overlay JSX).
- Three new test cases in Terminal.wiring.test.ts covering the three branches of the state machine.
- Single atomic commit on branch `feat/tab-title-from-tmux`, message shape matching recent fork patches (see git log `414b28c`): `feat: patch #143 — SSH terminal auto-reconnect on PWA visibilitychange (iOS backgrounding fix)`.
