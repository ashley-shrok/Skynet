<objective>
Fix the fleet-substrate distributor hang that occurs after `docker compose up --force-recreate skynet` when the serial per-host sweep in `server-substrate-orchestrator.ts` reaches the local Skynet host record (fleetHostId=6 on t1000). SSH-to-self from inside the container sometimes hangs in `deps.acquireChannel(host)`, wedging the entire `for-await` loop and blocking every subsequent host from receiving skill / helper-script updates until the container is manually restarted.

Fix approach: mirror the Phase 116 scanner bypass pattern (`src/backend/utils/local-fleet-scan.ts` + the `isLocalHostId` branch in `src/backend/spawn-requests/scan-orchestrator.ts` and `src/backend/image-gen-requests/scan-orchestrator.ts`) on the distributor side. When `isLocalHostId(parseInt(host.id, 10))` is true, skip `deps.acquireChannel` entirely and delegate to a new local-FS install helper that covers BOTH the sweep (per-catalog-item install) AND the bootstrap (systemd unit + `~/.claude/skynet-parent` + `~/.claude/skynet-hostname` writes). Partial coverage — sweep bypass only — would land a worse failure mode than the current hang: the local host would install skills fine but its own agent-supervisor would remain un-installed because the SSH bootstrap step would still hang on SSH-to-self.

Purpose: unblock the distributor whenever the local host is one of its own sweep targets. Non-local hosts continue to use the SSH path unchanged.

Output: a new local-FS helper module + colocated unit tests + orchestrator branch + integration test extension. Three atomic commits.
</objective>
