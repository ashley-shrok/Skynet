The button appears on cards in the three OPEN partitions (in_progress / rest / other); cards already under the Archive accordion do NOT get an Archive button (unarchive is a separate follow-up, per Ashley's UX call). Semantics are LOCKED per Ashley — the plan does NOT relitigate them.

**Semantics (locked, do not revisit):**

1. **Live-status bounty** (`status ∈ {pinned, in_progress, waiting_on_someone_else}`) — clicking Archive **atomically** does (in order, in one handler call): (a) `status → "done"`, (b) `updated_at → nowIso`, (c) append `<ISO> archived via identity modal (status flipped from <prev> to done)` to `timeline[]`, (d) tmp+rename write the merged JSON to the CURRENT location `bounties/<slug>/bounty.json.tmp` → `bounties/<slug>/bounty.json`, (e) `mkdir -p bounties/archive/` if not present, (f) `mv bounties/<slug>/ bounties/archive/<slug>/`. Handler then re-reads the fresh bounty lists via `readIdentityBounties` and returns them to the modal.

2. **Terminal-status bounty** (`status ∈ {done, dropped}`) still sitting in `bounties/` (not yet under `bounties/archive/`) — clicking Archive does the tmp+rename JSON patch + mv ONLY. NO status flip (preserves `dropped` from being clobbered to `done`). Timeline entry is `<ISO> archived via identity modal (status <prev> preserved)`.

3. **Cards already in `bounties/archive/`** — no Archive button rendered at all. Only OPEN-dir cards get the button (all three open partitions: in_progress, rest, other).

4. **Unarchive** — out of scope for this quick. Follow-up.

**Backend design (locked per Nelly's fleet audit at `~/.claude/identities/nelly/bounties/fleet-archived-bounty-storage-audit/`):**

- **Hardcode `bounties/archive/<slug>/bounty.json`** — fleet is UNIFORM across 27 identities on 4 boxes. No path discovery.
- **`mkdir -p bounties/archive/` on first write** — 4 identities have no `archive/` dir yet; that's a fresh-mkdir case, not an error.
- **Atomic status-flip AND mv in the same operation** — never leave a non-terminal in `archive/`. Enforced by rule #1 above: only terminals or freshly-flipped-to-done end up in `archive/`.
- **Fail loud on unparseable `bounty.json`** — 3 corrupt files exist fleet-wide; the writer must throw a clear `please repair before archiving` error rather than silently skip / write garbage. Handler surfaces the error to the modal; no partial state left on disk.

Purpose: Ashley wants a single-click archive affordance from the modal so she can clear terminal bounties out of the OPEN dir without hand-mv'ing on the box. This is a mechanical extension of the well-tested v0b pattern to an mv-including write path — not a design problem.

Output: Archive button wired end-to-end across the same 5 files v0b touched, plus a new writer unit-test file. First WRITE surface on bounty archival (parallel to how v0b was the first WRITE on bounty status).

**Mirror deviations from v0b (call out explicitly so the executor doesn't fight them):**

1. **Handler + writer must sequence status-write BEFORE mv** — v0b just patched JSON in place. This one patches JSON in place, THEN mv's the folder. If the mv fails mid-way, the JSON patch is already durable at the OLD path (that's fine — semantics say "if archive fails, leave state such that a retry works"; the next retry will re-patch (idempotently: same target status if it needed a flip; timeline gains a second entry — acceptable, better than half-moved).
2. **Skip `.tmp` inside `bounties/archive/`** — the tmp+rename is done at the CURRENT (open) path BEFORE the mv, so `archive/` never sees a `.tmp` file. Do NOT tmp+rename at the destination.
3. **Editable branch (button rendering) is present only when `onArchive` is supplied** — mirror of the `{onStatusChange && (...)}` gate. IdentityModal supplies `onArchive` for the three OPEN render sites and does NOT supply it for the sortedArchive.map — same gating shape as `onPriorityChange` (which is not passed for archived cards, per patch #154).
4. **BOUNTY_STATUS_VALUES stays LOCALLY-DEFINED in the backend reader** — do NOT import from `claude-session-api.ts`. This is the deliberate asymmetry from patch #154 / v0b (see the v0b SUMMARY's "Deviations from Plan" section for the rationale). The new `TERMINAL_BOUNTY_STATUSES` const goes NEXT TO `BOUNTY_STATUS_VALUES` in the reader (not in the api).
5. **Terminal-status detection uses `["done", "dropped"]`** — matches the source-artifact-locked set (`## Semantics` #2). Anything else is a live status and gets the flip.
