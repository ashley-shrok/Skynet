# Quick Task 260719-4p8: Identity-Aware ComposeBox Placeholder Summary

## One-liner

Threaded pane-identity `displayName` through a new optional `identityName` prop on `ComposeBox` so the pretty-view compose textarea placeholder now reads `Message Tina…` / `Message Astrid…` / etc. for panes attached to a registered identity, falling back to `Message Claude…` when no identity is registered (or when `displayName` is an empty string). Fork patch #71.

## What Shipped

Two-file, ~8 LOC pure prop pass-through:

**`src/ui/features/pretty-view/ComposeBox.tsx`** (+5/-1)

1. Added `identityName?: string` to `ComposeBoxProps` (after `tmuxSession?: string | null;`, before `className?: string;`), with an inline comment explaining the fallback semantics.
2. Added `identityName` to the destructured props in the `ComposeBox` function signature (after `tmuxSession,`, before `className,`).
3. Changed the hard-coded `placeholder="Message Claude…"` to `placeholder={`Message ${identityName || "Claude"}…`}`.

**`src/ui/features/pretty-view/PrettyView.tsx`** (+3/-1)

4. Line 168: Changed `const { identityHue: pvIdentityHue } = useSessionIdentity(tmuxSession);` to `const { identity: pvIdentity, identityHue: pvIdentityHue } = useSessionIdentity(tmuxSession);` — mirrors the existing `pvIdentityHue` rename pattern.
5. Added `identityName={pvIdentity?.displayName}` to the `<ComposeBox ... />` invocation, placed between `tmuxSession={tmuxSession}` and `className="shrink-0"` so pane-identity props stay visually grouped.

No changes to any other file in the repo.
