Make the pretty-conversations context menu a "singleton" — only one row's context menu open at a time across the list. Today each `PrettyConversationRow` owns its own `ctxMenu` `useState`, and `PrettyConversationContextMenu`'s outside-click listener is bubbling `click` (load-bearing iOS Safari fix) — long-press does NOT synthesize a click, so opening a second row's menu never closes the first row's menu. Ashley 2026-08-09: "if you hold to bring up a context menu on convo list.. and then hold to bring up another, there aren't multiple open? Like others would close when you open another, if there are any up".

Purpose: eliminate the "two menus open at once" bug without touching the iOS-Safari-safe outside-click plumbing inside `PrettyConversationContextMenu`.

Output:
- Module-scoped singleton (`currentClose` + `notifyMenuOpened` + `notifyMenuClosed`) in `PrettyConversationRow.tsx`.
- Row wiring at BOTH open sites (desktop right-click, mobile long-press timer fire) + single wrapped `onClose` path + unmount cleanup.
- 2 new tests in `PrettyConversationRow.test.tsx` locking the new behavior.

Module-scoped singleton lives INSIDE `PrettyConversationRow.tsx` at module scope (top-level, above the `export function PrettyConversationRow(...)`). No separate helper file. Shape verbatim:

```ts
let currentClose: (() => void) | null = null;

export function notifyMenuOpened(closeFn: () => void): void {
  if (currentClose && currentClose !== closeFn) {
    const prev = currentClose;
    currentClose = null; // prevent re-entry: prev's onClose should not re-register
    prev();
  }
  currentClose = closeFn;
}

export function notifyMenuClosed(closeFn: () => void): void {
  if (currentClose === closeFn) currentClose = null;
}
```
