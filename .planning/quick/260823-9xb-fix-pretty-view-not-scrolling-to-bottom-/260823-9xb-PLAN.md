<objective>
Fix Ashley's 2026-08-23 bug: "When I open sessions for the first time or refresh the page and it brings the session back up on its own, it doesn't put me at the bottom of the scroll of message bubbles."

Root cause: `useAutoScroll`'s mount effect fires when scrollEl transitions null→element and writes `scrollTop = scrollHeight`, but at that moment `messages = []` (PrettyView initializes empty via `useState<StreamEvent[]>([])` at line 342), so scrollHeight ≈ 0 and the write is a no-op on an empty container. Messages then arrive async via WS backfill; messageCount transitions 0→N and the follow effect at lines 90-94 fires — but it is gated on `if (!pinnedRef.current) return`. Any scroll event between mount and first content (browser scroll-restoration, empty-container programmatic write reflow, scrollbar mount reflow) can flip pinnedRef to false via the onScroll listener. Once false, the first-content-arrival follow write is skipped and Ashley lands scrolled-up.

Fix: introduce `didFirstContentScrollRef` (initial false, reset on paneKey/scrollEl change). Bypass the `pinnedRef` gate for the very first content-populate transition (messageCount 0→positive, or observer detects first children while flag still false). Set the flag true after the first-content write so all subsequent messageCount growth respects the pinnedRef gate — preserving Test 5's no-yank invariant post-first-content.

Purpose: restore reliable session-enter and page-refresh "land at bottom" UX. This is a small surgical change to one hook file plus 6 new regression tests — no wire changes, no API changes, no consumer changes in `PrettyView.tsx`.
