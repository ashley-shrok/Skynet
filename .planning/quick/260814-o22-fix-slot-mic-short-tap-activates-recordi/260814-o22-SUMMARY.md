# Quick 260814-o22: Fix Slot Mic Short-Tap Activates Recording — Summary

One-liner: **Wrapped both MicButton onPointerDown handlers in ComposeBox to call `setMicTarget(...)` synchronously before delegating to the hold hook, fixing an iOS-Safari-only bug where short-tapping a queue-slot mic opened RecordingControls in the primary compose area instead of the tapped slot.**

Each wrapped handler has a 12-line explanatory comment above it citing both `quick-260814-iwy` (the preventDefault cause) and `quick-260814-o22` (the fix) and asserting that `setMicTarget` is a synchronous React setState so the D-16-02 iOS Safari sync-gesture invariant is preserved.

### Root cause (confirmed pre-fix)

`useHoldToRecord.onPointerDown` calls `voice.start()` synchronously (D-16-02) but does NOT set `micTarget`. `setMicTarget` only ran inside `beginRecord(target)`, wired to MicButton's `onClick`. Because `MicButton.wrappedPointerDown` calls `e.preventDefault()` (added under `quick-260814-iwy` to suppress the iOS long-press callout), and because preventDefault on pointerdown on a `<button>` in iOS Safari ALSO suppresses the synthesized click event, `onClick={() => beginRecord(slot.id)}` never fires on iPhone — `micTarget` stayed at its default `"primary"` and `showRecordingControls` fired on the PRIMARY compose area. The primary path worked only accidentally because `"primary"` is the default.

### Constraints preserved (verified)

- `useHoldToRecord.ts` — **byte-identical** to pre-edit (`git diff --exit-code` returned 0). Hook stays generic; no micTarget knowledge.
- `MicButton.tsx` — **byte-identical** to pre-edit (`git diff --exit-code` returned 0). The `wrappedPointerDown` preventDefault under quick-260814-iwy remains load-bearing for iOS callout suppression.
- **D-16-02 iOS Safari sync-gesture invariant preserved**: `setMicTarget` is a synchronous React setState call — no `await`, no microtask boundary, no promise chain inserted between the user gesture and `voice.start()`. Precedent already exists inside the hook (`holdInitiatedRef.current = true` runs synchronously before `voice.start()`).

## Test 13 (New Regression Coverage)

**Location:** `src/ui/features/pretty-view/ComposeBox.hold-to-mic.test.tsx` (appended at the end of the existing describe block).

**Assertions (5 total):**

1. **THE regression assertion** — the RecordingControls "Cancel recording" button renders INSIDE the slot's `[data-slot-id]` container, verified via `cancelBtn.closest("[data-slot-id]")?.getAttribute("data-slot-id") === slotId`.
2. Primary compose area's "Send" button is STILL present (proxy for "primary did NOT swap into RecordingControls").
3. Exactly one `getUserMedia` call (matches Test 1's tightened quick-260814-iwy invariant).
4. Exactly one `MockMediaRecorder.instances.length` (belt-and-suspenders).
5. Zero STT fetches (short-tap-keep does not transcribe).

**Discriminator choice — DOM ancestry, not ordering:** `screen.getAllByRole("button", { name: "Record voice" }).find((el) => el.closest("[data-slot-id]") != null)` — robust to future rearrangements of primary vs slot in the DOM.

**Wiring note:** Test 13 flushes the compose-drafts `draft-load` useEffect (via `advanceTimersByTimeAsync(50)` + 4 microtask flushes) BEFORE clicking "Queue a message". Without this, the draft-load's async `.then()` chain calls `setQueueSlots(hydratedSlots)` AFTER our click, clobbering the just-added slot with the empty mocked draft — no slot renders. Debugged live during Task 2 (initial test run failed with "expected a slot-scoped mic button"; adding the flush made the test pass immediately).
