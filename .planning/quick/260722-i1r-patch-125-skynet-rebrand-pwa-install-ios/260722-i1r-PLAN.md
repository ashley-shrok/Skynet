  <action>
    CLAUDE.md nginx caveat: every new frontend static asset that needs a distinct MIME/cache
    treatment must be added to BOTH `docker/nginx.conf` (HTTP conf, port ${PORT}) AND
    `docker/nginx-https.conf` (HTTPS conf) — else it 200s with index.html and crashes on parse.

    In EACH file, locate the existing `location = /manifest.json { ... }` block (in
    nginx.conf this is at line 64). Insert a NEW `location = /manifest.webmanifest { ... }`
    block IMMEDIATELY AFTER the existing `= /manifest.json` block (right before the wildcard
    `location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff|woff2|ttf|eot)$` block).

    The new block:

    ```
            location = /manifest.webmanifest {
                root /app/html;
                types { }
                default_type application/manifest+json;
                expires off;
                add_header Cache-Control "no-store, no-cache, must-revalidate, proxy-revalidate, max-age=0" always;
                try_files $uri =404;
            }
    ```

    Rationale for each directive:
    - `root /app/html;` — matches the other static-file blocks (Docker image serves the
      built vite `dist/` at `/app/html`; the raw `public/` files are copied in during
      the image build).
    - `types { }` + `default_type application/manifest+json;` — the empty types map clears
      inherited mime.types matches so `default_type` wins; this makes the Content-Type
      exactly `application/manifest+json` (the correct MIME per W3C Manifest spec).
      Without this override, nginx would fall back to `application/octet-stream` because
      `.webmanifest` isn't in the container's default mime.types file.
    - `expires off` + `no-store` Cache-Control — matches the existing `= /manifest.json`
      pattern so the manifest can be swapped without cache poisoning.
    - `try_files $uri =404;` — matches sibling blocks; prevents the fallback `location /`
      from returning index.html for a missing manifest.

    Do NOT add any new PNG location — the existing wildcard image block already covers
    the 10 new PNGs (`\.png$` matches). Verified during pre-flight.
