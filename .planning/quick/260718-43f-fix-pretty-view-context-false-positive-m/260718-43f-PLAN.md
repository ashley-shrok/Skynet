<objective>
Patch #56: constrain the pretty-view context% scrape to the bottom 8 lines of
the `tmux capture-pane` output before running `matchAll`, so transcript
pollution (assistant messages quoting status-line strings, past redraw
remnants further up the pane) cannot produce false-positive percentage
matches.

Purpose: patch #52b's context-% poller (patch #52 sub-feature (b)) uses
`matchAll` + last-match-wins over the FULL capture-pane output. The
"last on-screen still takes precedence" comment is aspirational — it only
holds if the true status line at the pane's bottom is the last thing in the
scrape that matches the regex. In practice, any `context)...NN%` string
quoted anywhere in the transcript (assistant messages discussing status
lines, old redraw fragments) creates a false match that can WIN over the
real status line when Claude Code's footer is transiently absent from the
capture (mid-tool-execution redraws). Claude Code's footer is always at the
bottom of the pane, so slicing to the last 8 lines guarantees we only look
at the region where the real status line lives.

Output: one file change in `src/backend/claude-session/claude-session-server.ts`
inside the context-pct poller's `.then((output) => ...)` callback, plus a
comment update to reflect the new (now-actually-true) semantics.
</objective>

Locate the context-% poller's `.then((output) => { ... })` callback (around
lines 378-390, inside `contextPctTimer = setInterval(...)`). Currently:

```
.then((output) => {
  if (stopped || ws.readyState !== WebSocket.OPEN) return;
  const matches = [...output.matchAll(CONTEXT_PCT_REGEX)];
  if (matches.length === 0) return; // hold last on miss
  ...

```

Replace the single `matches` line with a two-line slice-then-match:

```
const bottom = output.split('\n').slice(-8).join('\n');
const matches = [...bottom.matchAll(CONTEXT_PCT_REGEX)];
```

Rationale for N=8: Claude Code's footer is 5 lines (2 separator lines +
prompt line + status line + bypass/permissions line). N=8 gives 3 lines of
buffer for footer variations (e.g., "You've used X% of weekly limit" resets
on the bypass line, or wrap on very narrow terminals). Per Ashley's
guidance: 7 is tight, 8 is defensive.

Also UPDATE the surrounding comment block (currently lines ~351-364) to
reflect the new semantics. The "hold last on miss" note stays accurate.
Add a paragraph explaining:

- Transcript pollution class: any `context)...NN%` string quoted anywhere
  in the pane (assistant messages discussing status lines, past redraw
  fragments still in the scrollback region tmux capture-pane returns) can
  create false matches. `matchAll` + last-wins only produces the correct
  result IF the true status line is the last match — not guaranteed when
  Claude Code's footer is transiently absent (mid-tool-execution redraws).
- Fix: Claude Code's footer is always at the BOTTOM of the pane. Slicing
  to the last 8 lines before matchAll ensures we only look at the footer
  region. If the status line is transiently absent from those bottom 8
  lines, we correctly get zero matches → hold-last semantics apply
  (client keeps its last known value) — much better than silently
  accepting a stale/wrong transcript match from further up.
