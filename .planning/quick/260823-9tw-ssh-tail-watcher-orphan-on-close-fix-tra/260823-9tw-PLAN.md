<objective>
Fix the SSH tail-watcher orphan-process leak in `session-file-tail.ts`. Today, every WS reconnect leaks a remote `tail -F` process (reparented to PPID=1) because `stream.close()` sends `SSH_MSG_CHANNEL_CLOSE` — OpenSSH does not propagate that as SIGHUP to the child, and `tail -F` never notices its stdout pipe is dead. Observed today on workstation: 88 orphan tails, load 143, systemd-logind failures cascading into WS churn.

Ship a two-prong fix (both required — either alone is unreliable per the ssh-server behavior notes):

- Prong A: In `stop()`, call `stream.signal("TERM")` BEFORE `stream.close()`. OpenSSH ignores channel-signal requests, but Tailscale SSH and other servers may honor it. Free win, no cost when ignored.
- Prong B: Replace the raw `tail -F -n +1 <path>` command with a POSIX `sh -c` wrapper that runs tail in the background and traps `EXIT INT HUP TERM` to kill it. When the SSH channel closes and the parent shell dies (SIGHUP or stdout write failure), the trap kills tail regardless of what the server did or didn't propagate.

Purpose: Eliminate the orphan leak so remote hosts (workstation, thenasty, AWS boxes) don't accumulate `tail -F` processes across WS reconnects. Root cause and design constraints in the planning brief.

Output: One code file updated, one test file extended, atomic RED→GREEN commits, no push, no deploy, no full-suite.
</objective>
