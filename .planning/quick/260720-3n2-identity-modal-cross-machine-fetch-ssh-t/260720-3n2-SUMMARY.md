# Quick Task 260720-3n2: Identity Modal Cross-Machine Fetch (SSH to Pane Host) Summary

**One-liner:** JWT-auth-compatible SSH routing for all 5 identity artifact reads (bounties/identity/history/wakeups/handoff) via shared helper with IDENTITIES_LOCAL_HOST_IDS allowlist for tina's bind-mount bypass.

## What Was Built

Patch #92 — identity modal cross-machine fetch. Before this patch, all 5 identity handlers in `claude-session-server.ts` read directly from `IDENTITIES_HOST_DIR` (a bind-mount of termix-ec2's local `/home/ubuntu/.claude/identities/`). Panes on other boxes (workstation, ZoeyBattlestation, GIGAASHLEYPC) showed empty tabs because those identities don't exist on termix-ec2's disk.

After this patch, each of the 5 handlers inspects `hostId` from the WS request, checks it against `IDENTITIES_LOCAL_HOST_IDS`, and either:
- Uses the bind-mount fast-path (LOCAL branch, `conn=null`) — for termix-ec2's own panes (configured via env var at deploy time)
- Opens a one-shot SSH connection to the pane's host and executes the read remotely (REMOTE branch)

## User Setup Required (post-deploy)

Add to `/opt/termix/docker-compose.yml` under the `termix` service `environment:` block:

```yaml
IDENTITIES_LOCAL_HOST_IDS: "5"  # Replace 5 with termix-ec2's actual numeric hostId
                                  # (find via Termix Settings → Hosts or GET /host/db/host)
```

This must be set before deploy or all reads (including tina's) will go via SSH instead of the bind-mount. The SSH loopback to termix-ec2 still works, but the bind-mount fast-path requires this env var.
