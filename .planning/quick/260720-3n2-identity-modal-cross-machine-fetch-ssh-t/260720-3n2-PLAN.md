## R1. Termix has NO "self-host bypass" pattern — tina's local pane works via SSH loopback into 100.99.149.8

Grepped `src/backend/{ssh,claude-session}/**` for `self_host`, `isLocal`, `127.0.0.1`, and hostname/IP matching. Zero hits related to "the pane's host is termix-ec2, skip SSH." The pretty-view JSONL tail for tina's pane on termix-ec2 works because Termix's host DB has a `termix-ec2` entry whose IP is the box's own tailnet address (100.99.149.8). Backend `connectOneShot` opens SSH to that address; sshd IS listening on 0.0.0.0:22 (confirmed via `ss -tln`); the AWS security group blocks public ingress but Tailscale rides at a lower network layer and IS reachable from inside the container (the container is on the same tailnet). So "SSH loopback via tailnet" is the current mechanism — patch #43's session-file discovery does NOT special-case the self host.

**Implication:** the identity handlers COULD in principle drop the bind-mount and just SSH-to-self exactly like pretty-view does, but the task brief locks in "preserve tina's use case byte-for-byte" — so the bind-mount branch must stay. The routing decision is required.

## R2. Routing predicate: env-var allowlist of hostIds (`IDENTITIES_LOCAL_HOST_IDS`)

Two candidate detection mechanisms considered:

- **Hostname/IP matching** — fragile. termix-ec2's tailnet IP could change; DNS name resolution inside the container is not guaranteed; comparing `resolved.ip` against `os.hostname()` requires the container's hostname to match, which it does not (container hostname ≠ EC2 hostname). Rejected.
- **Env-var allowlist of hostIds** — deterministic. `IDENTITIES_LOCAL_HOST_IDS="5,7"` (comma-separated) means "hostIds 5 and 7 point at THIS box's own disk; use the bind-mount for them." Matches patch #89's env-var idiom (`IDENTITIES_HOST_DIR`) and requires zero runtime introspection. Adopted.

Behavioral rules:
- Env unset OR empty OR malformed → routing predicate returns `false` for every hostId → ALL reads go via SSH (still correct for termix-ec2 self-loopback, but the bind-mount fast-path is skipped). Fail-safe: any deploy that forgets the new env still works, just slower for tina.
- Env set with valid CSV of positive integers → parsed once at module load into a `Set<number>`. `isLocalHostId(hostId)` = `set.has(hostId)`.
- Docker-compose override under `/opt/termix/docker-compose.yml` needs one line added under the `environment:` block adjacent to the existing `IDENTITIES_HOST_DIR: /host-identities` line. Value is the numeric hostId(s) of termix-ec2 in Termix's host DB — findable via `GET /host/db/host` (tina has admin creds; runbook is in tina.md § Termix admin credentials).

## R3. SSH exec primitive is `execCommand(conn, cmd)` from `src/backend/ssh/tmux-helper.ts`

Single shared helper. Wraps `conn.exec(cmd, cb)`, accumulates stdout, resolves with trimmed string, rejects if stderr has content AND stdout is empty AND exit code ≠ 0 (see lines 21-50). Every existing pretty-view file read (JSONL tail's `tail -F` in `session-file-tail.ts`, context-pct's `tmux capture-pane`, discovery's `readlink /proc/PID/fd/*`, discovery-repoll — all lines 1571-1734 of `claude-session-server.ts`) goes through this same helper. Reuse — do NOT reinvent.

Notes:
- ssh2 multiplexes exec channels on one Client, so per-artifact reads within one modal open are cheap.
- 3s timeout wrapper pattern (from `session-file-discovery.ts` lines 91-100) — use the same `Promise.race` shape to keep the modal responsive on unreachable boxes.
- Path expansion: use `"$HOME"` inside the remote command string (shell-expanded by the remote sshd's login shell). NOT tilde `~` — tilde expansion is fragile across shells (e.g. `sh -c` with a literal tilde does not expand). `execCommand`'s existing consumers all use `$HOME` (patch #43 lines 79-87).
- Shell escape for the identity key — even though `IDENTITY_KEY_RE = /^[a-z0-9_-]{1,64}$/` already rejects every dangerous character, wrap it in single quotes anyway (`'${identityKey}'`) as defense-in-depth. The regex is validated by both frontend (patch #87 pattern) and backend (line 1036) before the key reaches this layer.

## R4. SSH connection lifecycle: fresh `connectOneShot` per handler, `.end()` after read

Options considered:
- **Reuse the pane's live SSH connection** (pretty-view's `sshConn`). Rejected — the identity handlers are one-shot (patch #87 explicitly independent of `connectToPane`, see lines 1031-1033 comment); they are called on a FRESH WebSocket by `openOneShot` in `IdentityModal.tsx` lines 143-176. There is no `sshConn` in scope. Wiring one up would require plumbing pane state through the identity handlers — architectural regression.
- **Pool the connection via `withConnection`** (from `ssh-connection-pool.ts`). Rejected — modal open triggers 5 parallel reads on 5 separate WebSockets. The pool key is per-host, so the 5 requests would either share one pooled Client (fine but hidden) or serialize (bad). Simpler and clearer to open a fresh `connectOneShot` per handler and `.end()` when done. Cost: 5 SSH handshakes per modal open, ~200ms each in parallel over tailnet — indistinguishable from today's local-disk read UX given the modal already shows loading skeletons.

Adopted: mirror the `connectToPane` shape at lines 1451-1474 — `resolveHostById(hostId, userId)` → `connectOneShot(resolved, 5000)` → do the read → `conn.end()`. Wrap in try/finally so the connection ALWAYS closes even on read error.

## R5. Read commands (remote path expansion)

For each artifact, the SSH-executed command:

- **identity file** (`identity:get-identity-file`): `cat "$HOME/.claude/identities/'<key>'/'<key>'.md" 2>/dev/null`
- **history** (`identity:get-history`): `cat "$HOME/.claude/identities/'<key>'/history.md" 2>/dev/null`
- **handoff** (`identity:get-handoff`): `cat "$HOME/.claude/identities/'<key>'/handoff.md" 2>/dev/null`
- **wakeups** (`identity:list-wakeups`): a single one-liner that enumerates `wakeups/*.json` and cats each with a delimiter so the local parser can split — e.g. `cd "$HOME/.claude/identities/'<key>'/wakeups" 2>/dev/null && for f in *.json; do echo "===FILE:$f==="; cat "$f"; done`. Handler splits on `===FILE:` delimiter, parses each JSON chunk, reuses existing `humanizeWakeupSchedule`.
- **bounties** (`identity:list-bounties`): two commands (parallel `Promise.all`) — one for open bounties, one for archived. Same delimiter pattern:
  - open: `cd "$HOME/.claude/identities/'<key>'/bounties" 2>/dev/null && for d in */; do d="${d%/}"; [ "$d" = "archive" ] && continue; [ -f "$d/bounty.json" ] && echo "===DIR:$d===" && cat "$d/bounty.json"; done`
  - archive: `cd "$HOME/.claude/identities/'<key>'/bounties/archive" 2>/dev/null && for d in */; do d="${d%/}"; [ -f "$d/bounty.json" ] && echo "===DIR:$d===" && cat "$d/bounty.json"; done`
  Handler splits on `===DIR:` delimiter, reuses the existing bounty-normalization mapping (lines 1088-1102 of the current server file).

All commands `2>/dev/null` to suppress "No such file or directory" noise — empty stdout is the empty-state signal, matching the ENOENT → empty semantics of the current local branch.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → WebSocket (`/claude-session/websocket/`) | User-controlled `identityKey` and `hostId` cross into the backend. Both validated. |
| Backend → Remote SSH host | `execCommand` interpolates `identityKey` into a remote shell command; identity key is regex-validated AND single-quoted; remote SSH cred is Termix-DB owned (not client-supplied). |
| Backend → Local disk (bind-mount) | Preserves patch #89 posture — reads confined to `IDENTITIES_HOST_DIR/<key>/{fixed-suffix}` with `<key>` regex-validated. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-3n2-01 | Tampering (path traversal) | `identityKey` in remote `cat` commands | mitigate | `IDENTITY_KEY_RE = /^[a-z0-9_-]{1,64}$/` rejects `/`, `.`, `..`, spaces, and every shell metachar before the key ever reaches the command builder. Defense-in-depth: single-quote wrap via `shellEscape` even though the regex already blocks unsafe chars. |
| T-3n2-02 | Tampering (arbitrary hostId) | `hostId` in identity requests | accept-and-verify | `resolveHostById(hostId, userId)` already enforces user-scoped host ownership (patch #43 lines 14-16 + hostAccess checks). A user cannot request SSH to a host they don't have access to — same enforcement as connectToPane. |
| T-3n2-03 | Information Disclosure (cross-user identity read) | Remote reads on other users' hosts | mitigate | Same `resolveHostById` gate as T-3n2-02. Additionally: identity files live under the SSH user's `$HOME/.claude/identities/` — a user who legitimately SSHes as `ubuntu@workstation` can already read those files via a plain terminal pane. This surface adds no new capability beyond the modal. |
| T-3n2-04 | Denial of Service (slow remote host) | SSH connect + read on unreachable box | mitigate | `connectOneShot` has 5000ms timeout; `execCommand` wrapped in 3000ms Promise.race. Worst case: modal shows loading skeleton for 8s, then per-tab error state; other tabs render independently. |
| T-3n2-05 | Repudiation | Missing audit log for cross-machine reads | mitigate | Existing `sshLogger.info` calls extended to include `{ hostId, useLocal }` metadata so log grep can identify which host + which branch every read hit. |
| T-3n2-06 | Elevation of Privilege | Legacy client sends no hostId, backend runs local branch | accept | Documented behavior: missing/invalid hostId falls back to local branch. This is the current v1 behavior — no privilege change. New frontend always sends hostId. |
| T-3n2-SC | Tampering (supply chain) | npm/pip/cargo installs | n/a | No new packages installed — reuses ssh2 (already in tree) and Node stdlib. Package Legitimacy Gate not required. |
