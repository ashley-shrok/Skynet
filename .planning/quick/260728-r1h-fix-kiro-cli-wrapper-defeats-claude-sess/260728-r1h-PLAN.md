    3. **The descendant walk script** — one exec, one ps call, one awk pass,
       POSIX-portable (works with busybox/dash/bash targets). The awk logic
       marks pane_pid as a valid root, then does fixed-point passes marking
       every descendant valid, then prints the first pid whose comm equals
       'claude' (excluding pane_pid itself unless pane_pid's comm IS
       'claude', because for the backcompat case pane_pid is a valid
       candidate). Structure the awk so `valid[root]=1` is set in BEGIN
       AND the final scan includes `pid[i] == root` as a valid candidate
       — i.e., DROP the `pid[i] != root` guard from the recommended-design
       snippet. This is a deliberate divergence from the recommended-design
       shell block: including pane_pid as a candidate is what makes the
       backcompat "pane_pid IS claude" case work.

       Exact script string (single-quoted bash, no shell interpolation
       hazards; only ${panePid} is interpolated by JS template):

       ```
       PID=${panePid}; ps -eo pid=,ppid=,comm= 2>/dev/null | awk -v root="$PID" '
       BEGIN { valid[root] = 1 }
       { pid[NR] = $1; ppid[NR] = $2; comm[NR] = $3; n = NR }
       END {
         changed = 1
         while (changed) {
           changed = 0
           for (i = 1; i <= n; i++) {
             if (!valid[pid[i]] && valid[ppid[i]]) {
               valid[pid[i]] = 1
               changed = 1
             }
           }
         }
         for (i = 1; i <= n; i++) {
           if (valid[pid[i]] && comm[i] == "claude") {
             print pid[i]; exit
           }
         }
       }'
       ```

       Notes on the awk:
       - `comm` is /proc/<pid>/comm which is truncated to TASK_COMM_LEN-1 = 15
         chars. "claude" is 6 chars so exact-match is safe.
       - `ps -eo comm=` prints ONLY the comm (no trailing space), so `$3`
         parses correctly under awk's default whitespace-split.
       - Fixed-point pass terminates when no new nodes flip to valid; O(n²)
         worst case, fine for the pane-process-tree sizes we see (tens of
         procs).
       - Emits ONE pid on success (via `exit`). Emits NOTHING on no-match.
       - stderr redirected on ps to swallow "unsupported option" noise on
         truly ancient targets.
