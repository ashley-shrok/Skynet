<objective>
Fix relay outbound bubbles rendering the literal text `$WBODY` / `$body_var` / `$PAYLOAD` when the sending shell command holds the message body in a non-canonical shell variable and passes it via `--arg b "$VAR" '{msgtype:...`.

Root cause (diagnosed 2026-08-22 on running production fleet session files, corpus tabitha/tanya/tiffany Aug 20+): Strategy 6 `jq-arg-inline-dq` regex `/--arg\s+\w+\s+"((?:\\.|[^"\\])*)"\s+'\{msgtype:/` captures the raw quoted contents between `--arg <word>` and the opening jq filter — with zero shell-var awareness. When the agent stashes the body in a var (`WBODY='real text'`) and inlines the var reference (`--arg b "$WBODY"`), the extractor returns the literal string `$WBODY`.

Design decision (already made with Ashley, do NOT re-litigate): preprocess `cmd` with a shell-var substitution pass BEFORE the 10 strategies run — same architectural philosophy as patch #473's `sanitizeBashSqEscapeIdioms`. Do NOT tighten Strategy 6's regex to reject `$var` outputs (that path is whack-a-mole). After substitution the existing strategies just work.

Purpose: Ashley's pretty view stops rendering `$WBODY` literals in relay outbound bubbles — the actual human message text appears instead.

Output: `substituteShellVars` helper + wire-up + 6 colocated tests. Scoped test suite green (`vitest --related`) + backend build green (`npm run build:backend`). No deploy motion (orchestrator's remit).
</objective>

       a. Local `Record<string, string>` `assignments` starts empty.

       b. Scan `cmd` for single-quoted assignments using a regex with the `g` flag: `/(^|[\s;\n]|&&|\|\|)([A-Za-z_][A-Za-z0-9_]*)='([\s\S]*?)'/g`. Boundary group `(^|[\s;\n]|&&|\|\|)` prevents matching a var-assign in the middle of an identifier or inside another quoted context (best-effort — this is a preprocess pass, not a shell parser). For each match, if `assignments[name]` is `undefined`, set it to the captured value verbatim (single-quoted shell literals are literal; sanitize pass has already normalized `'\''` and `'"'"'` idioms into `APOS_MARKER`). First-assignment-wins.

       c. Scan `cmd` for double-quoted assignments using a regex with the `g` flag: `/(^|[\s;\n]|&&|\|\|)([A-Za-z_][A-Za-z0-9_]*)="((?:\\.|[^"\\])*)"/g`. For each match, if `assignments[name]` is `undefined`, decode with `value.replace(/\\(.)/g, "$1")` and store. First-assignment-wins across BOTH scans (sq wins over dq if both appear for the same name).

       d. Sort the resulting keys by length DESCENDING before substitution (guards against `$BODY_LONG` being partially substituted by `$BODY`).

       e. Build the substituted string: for each key `name` in the sorted list, first replace all literal `${name}` occurrences (plain `split(...).join(...)` or `replaceAll(...)` — both fine), then replace `$name` occurrences using `new RegExp('\\$' + escapeRegex(name) + '(?![A-Za-z0-9_])', 'g')` for the word-boundary guard.
