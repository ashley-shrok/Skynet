<objective>
Add an inline status editor to `BountyCard` inside the identity modal — a mechanical mirror of patch #154 (priority editor) applied to the `status` field. Adds a `StatusRow` component above the existing `PriorityRow` in the expanded body: 5 pills (pinned / in_progress / waiting_on_someone_else / done / dropped) rendered in their `STATUS_CLASSES` colors; clicking a non-active pill dispatches an `identity:update-bounty-status` WS mutation. Editable for ALL bounties including terminal and archived (supports the resurrect flow). Writer patches `bounty.json` in place — folder is NOT moved.

Purpose: Ashley currently must edit `bounty.json` by hand to change a bounty's status. She reprioritized inline via patch #154 and now wants the parallel status affordance. Also unlocks the resurrect path: click "pinned" on a `done`/`dropped` bounty in the "Other" partition or the Archive accordion and it re-enters her working set.

Output: Status pills wired end-to-end across the same 5 files patch #154 touched, plus a new writer unit-test file. First WRITE surface on bounty status (parallel to how patch #154 was the first WRITE on bounty priority).

This is a MECHANICAL MIRROR. The shape is set by patch #154. Notable deviations from a literal copy — call them out explicitly:

1. **Pill rendering treatment.** `PriorityRow` pills are bare (glyph + label, common border). Per Ashley: status has no glyph — just the label — so each pill uses its own `STATUS_CLASSES` color for the fill/border/text (matching how the status pill in the header row renders). The active pill still gets the "pressed white ring" treatment (`border-white/40 bg-white/10 text-[#f0ebe0] cursor-default`) so it reads as selected against the colored inactive row.
2. **No archived gate.** `PriorityRow` deliberately does not thread `onPriorityChange` for the `other` bucket or the Archive accordion (priority on a closed bounty is meaningless). Status IS meaningful on closed bounties — you resurrect by re-setting it. `IdentityModal.tsx` MUST thread `onStatusChange` for every partition including `other` and the Archive `sortedArchive.map` render.
3. **Writer does NOT move folders.** Even when transitioning to/from `done`/`dropped`, the writer only patches `bounty.json` in place. Folder-moves between `bounties/<slug>/` and `bounties/archive/<slug>/` are out of scope for this quick (Ashley's separate concern; the archive dir is populated by the id skill on its own cadence). This is a deliberate simplification stated in the ask.
</objective>
