<objective>
Add a fifth distributor bootstrap step that writes `~/.claude/skynet-hostname` (single-line file
containing Skynet's canonical `host.name` for this box) on every sweep, and update the id skill's
Skynet file-URL recipe to read from that file instead of running `$(hostname)`. On cloud VMs the OS
hostname is a meaningless string like `ip-172-31-243-143` that never matches Skynet's `host.name`,
so file URLs 404 with `unknown_host`. Writing the exact resolver string from the distributor and
reading it back on the agent side fixes the mismatch at the source of truth.

Purpose: Guarantee that the hostname segment in every Skynet passthrough file URL is the exact
string `resolveHostByName` matches, so file sharing works on cloud VMs regardless of whatever the
OS `hostname` command returns.

Output:
- `run-bootstrap.ts` gains a Step 5 block (mirror of Step 4) plus a `skynetHostnameOk` field on
  `BootstrapResult`.
- `run-bootstrap.test.ts` gains an `hn-1..hn-8` describe block mirroring the `sp-*` suite.
- `substrate/skills/id/SKILL.md` URL recipe swaps `HOST=$(hostname)` for a
  `cat ~/.claude/skynet-hostname` variant with a matching error-fallback branch, prose paragraph,
  and rules-bullet update.
</objective>
