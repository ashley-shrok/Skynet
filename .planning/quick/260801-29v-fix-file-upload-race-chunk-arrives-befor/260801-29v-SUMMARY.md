# Quick Task 260801-29v: fix file-upload race — chunk arrives before start settles — Summary

Server-side defer of `upload_chunk` behind its in-flight parent `upload_start` promise via a per-WS `pendingStarts` map — eliminates the intermittent `upload_failed reason=unknown_temp_id message="no active batch"` on cold-SFTP sessions when a 64 KB chunk lands on the same WS tick as its parent start.

## What Changed

### 1. `src/backend/ssh/terminal.ts` (Task 1, commit `49cba54`)

- **Added** `const pendingStarts = new Map<string, Promise<void>>()` in the per-WS closure, immediately after `ownedUploadBatches`. Self-cleans on start settle (both success and failure) via `.finally()`. Garbage-collected with the WS.
- **`case "upload_start"`:** Captures the `handleUploadStart(...)` promise (no `void`, no `await`) and, when `messageQueueItemId` is a non-empty string, registers it in `pendingStarts` and attaches the `.finally(() => pendingStarts.delete(mqid))` self-clean. Dispatch remains non-blocking — other WS message types (input, resize, ping, tmux_attach, …) keep flowing while SFTP setup runs.
- **`case "upload_chunk"`:** If `pendingStarts.get(mqid)` returns a promise, chains `pending.then(() => handleUploadChunk(...))` with a `.catch(() => {})` so a rejected start doesn't leak an unhandled promise rejection (a rejected start already emitted its own `upload_failed`; `handleUploadChunk` will find no batch and emit `unknown_temp_id` — the correct signal for a truly-failed start, distinct from the race being fixed). If no pending start exists, calls `handleUploadChunk(...)` synchronously — identical to today's code path. **Warm-session fast path preserved.**
- **`case "upload_abort"`:** untouched.
- Inline comments at all three change sites reference the `260801-29v` quick task and mention `"no active batch"` so future greppers land here.

### 2. `src/backend/ssh/pretty-view-upload.test.ts` (Task 2, commit `d46e1bd`)

Two new tests appended in a `describe("Quick-fix 260801-29v: chunk-before-start-settled race")` block. A `beforeEach` fresh-allocates the local `pendingStarts` map. Local helpers `dispatchStart` / `dispatchChunk` mirror the exact terminal.ts wiring so the race is exercised against the same real `handleUploadStart` / `handleUploadChunk` functions terminal.ts calls.

- **Test A — race:** slows the mock `realpath` with `setTimeout(r, 0)` so the start's async chain takes at least one macrotask to reach `activeBatches.set(...)`. Fires `dispatchStart` (no await) and `dispatchChunk` on the SAME tick. Asserts no `upload_failed reason=unknown_temp_id` is emitted and `upload_complete` is emitted with the expected tempId.
- **Test B — fast path:** fully awaits `dispatchStart`, then one extra `setTimeout(r, 20)` macrotask so the `.finally` cleanup runs. Asserts `pendingStarts.has("mqid-test") === false`, then fires `dispatchChunk` and (BEFORE any await) checks `bytesReceived` on the fileState AND `bytesWritten` on the mock writeStream both advanced — proving `handleUploadChunk` ran synchronously with no `.then()` wrapper.

Reuses existing mocks (`makeMockSftp`, `makeMockWs`, `makeMockSshConn`, `makeDeps`, `startPayload`, `waitFor`, `__resetActiveBatchesForTest`) — nothing redefined. No pre-existing test modified. File now has 17 tests (was 15).
