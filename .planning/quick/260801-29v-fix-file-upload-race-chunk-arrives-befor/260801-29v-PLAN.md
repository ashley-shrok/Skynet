<objective>
Fix the intermittent `upload_failed reason=unknown_temp_id message="no active batch"`
that hits when a 64 KB `upload_chunk` frame arrives on the same WebSocket tick as
its parent `upload_start`, before `handleUploadStart` has finished the SFTP
setup (realpath + ensureLandingDir + createWriteStream) and registered the
batch in `activeBatches`.

Root cause is already diagnosed in the problem statement — do NOT re-diagnose.
The fix is server-side only: track pending `handleUploadStart` promises in a
per-WS `pendingStarts` map and defer chunks behind their parent start promise
when one is still in flight. Chunks arriving after the start has settled
continue to run synchronously (fast path preserved).

Purpose: Restore reliable file uploads in pretty-view for the common case of
back-to-back start+chunk frames on cold-SFTP sessions.
Output: Two-file diff (terminal.ts + pretty-view-upload.test.ts), zero client
changes, zero protocol changes, zero new dependencies.
</objective>
