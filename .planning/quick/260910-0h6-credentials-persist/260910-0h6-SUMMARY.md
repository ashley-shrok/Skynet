# Quick 260910-0h6: credentials-persist Summary

**One-liner:** Swapped 4 raw `db.update()` calls in `credentials.ts` for `SimpleDBOps.update()` — routes writes through `DatabaseSaveTrigger.triggerSave` so credential and host changes persist to disk after container restart.

## Root Cause

`credentials.ts` had 4 write sites that used raw Drizzle `db.update()` instead of `SimpleDBOps.update()`. Since Skynet decrypts its SQLite into RAM at startup and only flushes when `DatabaseSaveTrigger.triggerSave` fires, these writes were RAM-only. The `_dirty` flag never set, the 5-min isDirty poller never woke, and any container restart silently discarded all changes made through these 4 endpoints.

**Compounding bug (Sites 3 & 4):** Both `sshCredentials` write sites also skipped the system-key dual-encryption branch in `simple-db-ops.ts:128-140` (`ssh_credentials` table special case). Raw `db.update(sshCredentials)` produced silently unshareable credential rows even when the RAM write "succeeded."

**Concrete impact:** Taylor's Phase 93 container restart 2026-09-09T23:19 UTC wiped SSH-tab-manager host rows 21/22/23 (workstation, thenasty, ZoeyBattlestation) back to `Unsupported authType: key` — exact fingerprint of a write at POST `/:id/apply-to-host/:hostId` (Site 2) surviving only in RAM.

## Sites Fixed

| Site | Line (pre-fix) | Endpoint | Table | From | To |
|------|---------------|----------|-------|------|----|
| 1 | ~647 | DELETE `/credentials/:id` | `hosts` | `db.update(hosts).set(...).where(...)` | `SimpleDBOps.update(hosts, "ssh_data", ...)` |
| 2 | ~779 | POST `/:id/apply-to-host/:hostId` | `hosts` | `db.update(hosts).set(...).where(...)` | `SimpleDBOps.update(hosts, "ssh_data", ...)` |

| 4 | ~986 | PUT `/folders/rename` | `sshCredentials` | `db.update(sshCredentials).set(...).where(...)` | `SimpleDBOps.update(sshCredentials, "ssh_credentials", ...)` |
