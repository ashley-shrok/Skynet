<objective>
Prettify slash-command triplets in pretty-view user bubbles by replacing the raw XML tag runs
(`<command-message>...</command-message>` + `<command-name>...</command-name>` +
`<command-args>...</command-args>`) with an inline `CommandChip` pill. Client-side only —
the backend JSONL parser (`session-file-parser.ts`) stays faithful to the wire format.

Purpose: Ashley's pretty view currently shows the raw XML fallout of Claude Code slash-command
invocations because react-markdown intentionally does NOT parse raw HTML (rehype-raw is disabled
per patch #47 for XSS safety). This turns every `/id tina`, `/exit`, `/help`, etc. into a wall
of escaped tag text in the user bubble. Replacing each triplet with a compact pill preserves
the semantic ("Ashley ran /id tina") while removing the visual noise.

Output: three files — one new pure-utility module, one new inline pill component,
one edit to the existing ChatMessage renderer.
</objective>

    - splitMarkers over non-string children (already-JSX like <em>x</em>) → passed through untouched

  <action>
    Create src/ui/features/pretty-view/commandTags.ts exporting three symbols:

    (a) preprocessCommandTriplets(text: string): string — scans for one-or-more consecutive
    command tag elements. Use a block regex that matches a RUN of one or more
    `<command-(message|name|args)>[^<]*</command-\1>` elements with optional whitespace between
    them (the design_locked COMMAND_BLOCK_RE pattern is a starting point; refine if needed
    for the order-agnostic + name-first vs message-first requirement). For each matched block:
    extract the command-name value via NAME_RE (`<command-name>([^<]*)</command-name>`) and the
    command-args value via ARGS_RE (`<command-args>([^<]*)</command-args>`). If NAME_RE misses,
    return the block unchanged (malformed). Otherwise build the replacement:
      - trimmed name + (" " + trimmed args) if args non-empty
      - trimmed name alone if args empty or missing
    Wrap in `⟨cmd:` (U+27E8) prefix + `⟩` (U+27E9) suffix.

    (b) CMD_MARKER_RE: RegExp — global regex `/⟨cmd:([^⟩]+)⟩/g` for downstream splitting.
    Must be a fresh instance where callers cannot leak lastIndex across calls — either declare
    as a module-level constant and let callers use `.matchAll` (which handles lastIndex safely)
    or export a factory. Prefer matchAll-safe global constant per design_locked.

    (c) splitMarkers(children: React.ReactNode): React.ReactNode — use React.Children.map.
    For each string child: if it does not contain `⟨cmd:`, return the string unchanged. Otherwise
    walk the string with matchAll(CMD_MARKER_RE), interleaving text segments (as strings) and
    `<CommandChip cmd={m[1]} key={...} />` elements. Non-string children (already-JSX from other
    markdown transformations like `<em>`, `<strong>`, anchors) pass through untouched — do NOT
    recursively descend into their `.props.children`; the design intentionally only prettifies
    top-level paragraph text where markers live post-preprocess.

    Import CommandChip from "./CommandChip" (Task 2 file — TypeScript will resolve after Task 2
    lands; execute Task 2 first if the executor wants a strictly-clean per-task tsc pass, or
    execute in any order and rely on the final combined typecheck).

    Also create the sibling test file src/ui/features/pretty-view/commandTags.test.ts covering
    every bullet in <behavior> above using vitest (already the project's test runner per
    patch #4's sshAdapter.test.ts precedent). Tests may render CommandChip via
    @testing-library/react OR simply assert the returned array shape (React.isValidElement +
    props inspection) — either satisfies the behavior contract.

    Do NOT touch session-file-parser.ts. Do NOT enable rehype-raw. Do NOT alter any
    ChatMessage.tsx styling — this task creates the utility module + tests only.
