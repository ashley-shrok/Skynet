# Phase quick-260731-1c8 Plan 01: Add Title + Avatar Editor to Identity Tab Summary

**One-liner:** Inline title + avatar editor wired to the existing `PUT /identities/:id` endpoint via `updateIdentity()`, broadcasting success via `applyIdentityChange()` so all `useIdentities()` consumers re-render live.

## What Was Built

Added an inline edit affordance to the Identity tab of `IdentityModal.tsx`:

1. **Two editable fields** (exactly, per spec): a controlled `<input type="text">` for `title` and a hidden `<input type="file" accept="image/png,image/jpeg,image/webp">` wrapped in a label-driven button for avatar upload.
2. **Save/Cancel buttons**: Save is disabled when neither title nor avatar has changed from committed truth; Cancel resets drafts without closing the modal.
3. **Optimistic avatar preview**: picking a file sets `avatarPreviewUrl = URL.createObjectURL(file)` as the `<img>` src immediately; revoked on save success, cancel, or unmount.
4. **applyIdentityChange broadcast**: on save success, `applyIdentityChange(updated)` propagates the fresh identity to the module-scoped `identities-store`, causing all `useIdentities()` consumers (IdentityBadge, SessionRow, PrettyConversationRow, RelayInboundBubble) to re-render with new title + avatar.
5. **Cache-busted header `<img>`**: `src={identity.avatarUrl}?v=${identity.avatarEtag}` so when a new `avatarEtag` arrives via `applyIdentityChange`, the browser re-fetches rather than serving the stale avatar.
6. **Inline error surfacing**: server error strings from `updateIdentity`'s rejected promise render as `Couldn't save: {message}` in a `<p>` inside the tab; modal stays open; drafts are NOT reset on error.
7. **displayName and colorHue**: remain read-only throughout — no new editable inputs for those fields.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Save button disabled predicate compared against stale prop**
- **Found during:** Task 2 (test 1 failure)
- **Issue:** Save button disabled condition used `identity.title` (the prop received from parent) to compare against `titleDraft`. After a successful save, the parent prop doesn't immediately re-render with the updated title, so the Save button stayed enabled instead of disabling.
- **Fix:** Introduced `committedTitle` state that initializes to `identity.title ?? ""` on open and updates to `updated.title` on each successful save. The Save button disabled predicate, `onCancel`, and the `onSave` meta-payload builder all use `committedTitle` instead of `identity.title`.
- **Files modified:** `src/ui/features/pretty-view/IdentityModal.tsx`
