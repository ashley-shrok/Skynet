<objective>
Add an inline title + avatar editor to the Identity tab of `IdentityModal.tsx`.
Wire the existing `updateIdentity(id, {title}, avatarFile)` frontend API (which
already POSTs the correct multer FormData shape) to a Save button in the tab.
On success, broadcast the fresh Identity to `identities-store` via
`applyIdentityChange` so live `IdentityBadge` instances (and every other
`useIdentities()` consumer — SessionRow, PrettyConversationRow, RelayInboundBubble)
pick up the new title + avatar without a manual refresh. On error, surface
the server error string inline in the tab, keep the modal open, and preserve
the user's typed title + picked file so they can retry.

Purpose: First WRITE path against the `PUT /identities/:id` endpoint from the
identity-modal UI. All backend + API-client plumbing already exists (endpoint
at `src/backend/database/routes/identities.ts:170`, client at
`src/ui/api/identities-api.ts::updateIdentity`). This is a pure frontend
wiring + UX task following the Patch #154 mutation-callback idiom, but using
the HTTP API surface rather than a new WS channel because `updateIdentity`
already exists over HTTP.

Output: Editable Identity tab shipped and covered by a targeted vitest suite;
no backend touch; single atomic commit for code + tests.
</objective>
