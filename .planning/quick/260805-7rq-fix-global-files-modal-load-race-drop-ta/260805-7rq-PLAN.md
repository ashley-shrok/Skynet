<objective>
Fix the Phase 23 useEffect race in `GlobalFilesModal.tsx` (lazy-load effect currently at lines 116-143) that leaves the modal spinning forever whenever `readGlobalFile` takes more than one microtask tick to resolve. The fix is a one-line dep-array change plus an `eslint-disable-next-line` justification comment. Add a regression test that reproduces the race against the CURRENT code and passes only after the fix.

Purpose: My earlier tilde-expansion fix (commit 5e468c8, this session) made SSH reads take ~700ms instead of resolving in the same microtask batch as `setTabData({loading})`. That timing shift exposed the stale race: React re-runs the effect because `tabData` is in the deps, the cleanup fires from the first run and sets `cancelled = true`, and the second run early-returns via the `tabData.has(activeTab)` "already loading" gate without registering a fresh cleanup — so when the original 700ms read finally resolves, `cancelled === true` and the tab never transitions to READY. Ashley confirmed live: nginx access log shows POST /read returned 200 with 3507 bytes but the modal spinner never went away.

Output:
- Edited `src/ui/features/pretty-view/GlobalFilesModal.tsx` (deps line 143 drops `tabData`; one `// eslint-disable-next-line react-hooks/exhaustive-deps` above it with a WHY comment).
- New file `src/ui/features/pretty-view/GlobalFilesModal.test.tsx` reproducing the race with an asynchronous `readGlobalFile` mock and asserting the READY branch renders the textarea with the mocked content.
</objective>
