## Decisions pinned during planning

**D-01 Identity resolution — REUSE existing client-side resolution.** Pretty-view
already resolves the identity via `useSessionIdentity(tmuxSession)` in
`PrettyView.tsx:185` (returns `{ identity, identityHue }`; identity.identityKey
is the lowercased name). NO new backend mechanism needed. The client passes
`identity.identityKey` in the new WS message; the server treats it as an
opaque path segment for `~/.claude/identities/<key>/bounties/`. This
eliminates the largest speculative-work risk in the brief (candidates a/b/c/d
in the task brief).

**D-02 Transport — piggyback on existing claude-session WS.** New client->server
message `{type:"identity:list-bounties", identityKey}` and new server->client
frame `{type:"identity:bounties", bounties, archivedBounties, error?}`. Handled
alongside the existing `connectToPane` router in `claude-session-server.ts`.
Reuses auth (JWT cookie), keepalive (30s ping), and route wiring
(`/claude-session/websocket/` behind nginx). NO new HTTP endpoint => no
`docker/nginx.conf` + `docker/nginx-https.conf` update, dodges the nginx
caveat from CLAUDE.md.

**D-03 Archive treatment — collapsed accordion in the Bounties tab.** Per brief
recommendation ("lean: collapsed accordion section below the open list").
Uses shadcn `accordion.tsx` (available). Header shows count "Archive (N)"; body
lists cards using the same BountyCard component in a de-emphasized style
(opacity-70, no in-progress accent).

**D-04 Modal dimensions — 90vw x 85vh centered, max 1200px wide.** Near-
fullscreen with breathing room per brief anchor. Implemented via `!` important
suffix overrides on shadcn DialogContent's `max-w-*` base classes (see D-06).

**D-05 Expand-from-badge animation — SKIP the FLIP transform in v1.** Ship
shared-language tokens only (same glass gradient using `hsla(var(--pv-id-hue),
45%, 25%, 0.72)`, same `backdrop-blur(24px) saturate(1.4)`, same
`hsla(hue,65%,55%,0.4)` border, same `pv-identity-breathe` slow pulse). The
modal reads as the badge's surface unfolded to fill. A physical FLIP transform
is deferred as a follow-up patch — the risk/reward doesn't clear the v1 bar
(FLIP requires two-render measurement + `getBoundingClientRect` diff +
requestAnimationFrame + z-index gymnastics for the transition anchor).

**D-06 shadcn Dialog override discipline — use `!` important suffix.** Per
learned pref #81 (patch #81 shadcn override rule). DialogContent has
`max-w-[calc(100%-2rem)] sm:max-w-sm bg-popover p-4` in its base className. We
need to override the size AND the background to hit near-fullscreen glass.
Even though `bg-popover` doesn't carry `dark:` variants in the shipped Dialog
wrapper, the SAFE default per the learned rule is `!` on any shadcn-wrapper
override. Apply `!` on size (`w-[90vw]!`, `max-w-[1200px]!`, `h-[85vh]!`,
`max-w-none!` beats `sm:max-w-sm`) and on bg (`bg-transparent!` -> then apply
the glass gradient in a plain style-attribute or a subsequent class). Verify
computed style on the modal element via DevTools before considering the patch
shipped.

**D-07 Read-only checkbox styling.** Use shadcn `<Checkbox>` with
`disabled={true}` + `cursor-default` and `opacity-60`. Do NOT wire onChange.
This looks visually settled ("this is a state, not an action") without
implying broken interactivity.

**D-08 Priority-sort key.** Numeric map:
`urgent=0, high=1, medium=2, low=3, unprioritized=4`. Missing/unrecognized
`priority` value sorts as `unprioritized` (4). Bounties within the same
(status, priority) bucket sort by `updated_at` descending (most recent first).

**D-09 Status group ordering.** Fixed sequence:
`in_progress -> on_deck -> waiting_on_someone_else`. Any bounty with a status
NOT in `{done, dropped}` AND NOT in the three groups above is bucketed at the
end under an "Other" heading (defensive — no known 5th open status today,
but keeps parser tolerant). `done`/`dropped` bounties in the open dir (should
be rare; those normally move to archive) are treated as archived-in-place for
display.

**D-10 Timeline tail.** Show the LAST element of `timeline[]` verbatim (the
array is already ISO-prefixed newest-last per the sample). Truncate to 240
chars with a `title` attribute for the full text on hover.

**D-11 Premise truncation.** Collapse to 4 lines via CSS
`line-clamp-4`; add "Show more"/"Show less" toggle button below when the
premise's raw character length exceeds ~400. Uses local component state.

**D-12 Error + empty states.**
- Backend error (dir unreadable / identityKey missing / etc.): server sends
  `{type:"identity:bounties", bounties:[], archivedBounties:[], error:"<msg>"}`.
  Frontend renders an error card with a Retry button that re-sends the WS
  message. NO thrown-exception surface bleed.
- Backend success + empty: friendly empty state ("No open bounties for
  <displayName>." + subline "Archive will show here when populated.").
- Loading: shadcn Skeleton rows (3 placeholder cards).

**D-13 Refresh behavior — fetch on open, refetch on reopen.** Modal opens ->
send `identity:list-bounties`. Modal closes -> nothing. Modal reopens ->
re-send. NO live subscription; NO refetch button (Retry button appears on
error only). Matches brief "NO real-time subscription — fetch on modal open
(and refresh when reopened)".

**D-14 Badge click affordance.** Wrap the IdentityBadge `lg` variant in a
`<button>` (semantic click target). Remove `hover:opacity-0` from the lg
branch's className ONLY. Preserve the md branch byte-for-byte (patch #38 rule
unchanged for terminal panes). Add:
- `cursor: pointer` (native on button)
- Additional hover ring: bump the existing rim/glow shadow on hover
  (`hover:shadow-[..., 0 0 56px hsla(hue,65%,55%,0.42)]` — same shape,
  richer amber halo)
- Slight scale on hover: `transition-transform hover:scale-[1.015]`
- `aria-label="Open identity info"` (was `aria-hidden="true"` — flip because
  it's now interactive)
- `title="Identity info"` for hover tooltip

**D-15 Placeholder tabs.** Each placeholder tab body is a single centered
paragraph: "Coming soon — <TabName> will show <one-line preview>". No API
call, no fetch, no state. Concrete placeholder blurbs:
- History: "recent activity from this identity's session log"
- Wakeups: "scheduled wake-up prompts and their spec files"
- Handoff: "checkpointed context for handoff to the next session"
- Standing Directives: "long-lived rules this identity carries between sessions"
