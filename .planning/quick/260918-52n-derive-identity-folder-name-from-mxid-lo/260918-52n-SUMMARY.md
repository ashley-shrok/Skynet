# Quick 260918-52n: derive identity folder name from mxid localpart

Refactor identity birth so `~/fleet/identities/<key>/` on the target host is
derived from the MXID localpart (uniqueness-guaranteed via
`deriveMxidWithOrdinal` iterating against Synapse) instead of the short
pool name. Structurally eliminates two production bugs verified live
2026-09-18.

## Files touched (with line-range highlights)

### `src/backend/database/routes/identity-birth-orchestrator.ts` (+253/-111)

- **New shared helper `deriveMxidAndFolderName`** (~L645-740): pure async
  function invoked in Step 1 of `birthIdentity` and by the retry route in
  `identity-birth.ts`. Returns `{ mxid, identityFolderName }` where
  `identityFolderName = mxid.slice(1, mxid.length - serverName.length - 1)`
  (plain slice; leading `@` and `:<serverName>` suffix stripped). Threads
  through the same `matrixServerName ?? extractServerName(matrixHomeserver)`
  branching that used to live inside `runRelayMintAndWrite`. Defense-in-depth
  gate: throws if the derived name fails `IDENTITY_KEY_RE`.
- **`runRelayMintAndWrite` refactored** (~L900-1120): now accepts required
  `mxid: string` and `identityFolderName: string` in `opts`; internal MXID
  derivation block (was L914-950) deleted; `serverName` derivation block (was
  L886-889) deleted. Step 8's `writeIdentityFile` (~L1063 → ~L1116) uses
  `opts.identityFolderName` for the relay.json target path.
- **`birthIdentity` Step 1 grows internal sub-order** (~L1268-1360):
  (a) derive mxid + identityFolderName (new), (b) role-folder probe, (c)
  avatar candidate check, (d) on-disk collision probe using the derived path.
  `let mxid: string` and `let identityFolderName: string` hoisted before the
  outer `try` block (~L1230-1231) so Steps 2/6/7/8 and the supervisor-wait
  block can reference them.
- **Step 1 on-disk collision probe** (~L1400-1440): swapped `opts.name` →
  `identityFolderName` on both LOCAL (`path.join(getLocalIdentitiesRoot(),
  identityFolderName)`) and REMOTE (`$HOME/fleet/identities/${identityFolderName}`)
  branches.
- **Step 2's `identityDir` + `identityFilePath` + `avatarFilename`**
  (~L1500-1615): all three now derive from `identityFolderName`.
- **`deps.writeAvatarSiblingFile` call** (~L1615): second arg (folder-key)
  swapped from `opts.name` → `identityFolderName` (verified against the
  writer's signature at `identity-artifact-reader.ts:2248-2280` — arg IS the
  folder key).
- **Supervisor-wait probe** (~L1670): `deps.discoverIdentitySessionFile(conn,
  opts.name)` → `deps.discoverIdentitySessionFile(conn, identityFolderName)`.
  agent-supervisor.sh's tmux session name matches the folder name, so the
  JSONL discovery path is keyed on `identityFolderName`.
- **Ended event on success** (~L1705): `emit({ type: "ended", ok: true,
  identityId: identityFolderName, sessionName: identityFolderName })` — the
  identity IS its folder name on disk.
- **`runRelayMintAndWrite` call site** (~L1650-1660): passes `mxid` +
  `identityFolderName` from the closure. `displayName` still derives from
  `opts.name` (deliberate; UI badge shows "Anthem", not
  "Anthem-box-maintainer-2").
- **`buildIdentityFileBody` H1 heading** (L581): unchanged (`# ${opts.name}`)
  — H1 is a human-readable title, not a filesystem identifier.

### `src/backend/database/routes/identity-birth.ts` (+29/-3)

- **Retry route `runRelayMintAndWrite` invocation** (~L693-730): derives
  `serverName` inline (mirroring the pre-refactor block), computes
  `retryMxid = @${key}:${serverName}` and passes `identityFolderName = key`
  (the folder that already exists on disk). Retry always takes the legacy
  MXID shape because it operates on a partially-failed birth's folder —
  running a fresh ordinal search would mint a NEW account, not repair the
  existing one.

  file's fixtures (`makeDeps`, `makeOpts`, `mockWriteMarkdownFileAtomicModule`,
  the beforeEach reset train) fit the assertion shape better than the
  isolated derivation test file. This is a placement choice, not a design
  deviation — the test itself asserts everything the plan called for.
