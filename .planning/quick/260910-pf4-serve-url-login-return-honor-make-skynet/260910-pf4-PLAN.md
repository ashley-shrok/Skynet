<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL query string → validateReturnUrl | Untrusted user-controlled input (attacker can craft any `?return=` value and send a victim a phishing link that puts `https://term.example.com/login?return=https://evil.com/`). Validation MUST reject anything that isn't provably same-parent-domain. |
| localStorage `skynet_auth` → mount-time redirect trigger | Trusted for redirect-decision purposes; NOT trusted as an auth proof (destination re-auths via JWT cookie). Even if attacker forges `skynet_auth`, the WORST outcome is a bounce to a URL that then 302s back to /login again — no privilege escalation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-pf4-01 | Tampering (open redirect) | validateReturnUrl accepting plain-suffix hostname bypass | mitigate | Leading-dot suffix rule: `hostname === parent OR hostname.endsWith("." + parent)`. Test R3 (`eviltermexample.com`) is the falsification test. |
| T-pf4-02 | Tampering (protocol downgrade) | validateReturnUrl accepting non-https URLs | mitigate | `parsed.protocol === "https:"` check. Test R6 (http://), R7 (javascript:), R8 (data:) are the falsification tests. |
| T-pf4-03 | Spoofing (userinfo confusion) | Attacker embeds real host in userinfo: `https://term.example.com:9999@evil.com/` | mitigate | Reject any URL with non-empty username or password. Test R11 + R12. |
| T-pf4-04 | Elevation of Privilege | Attacker crafts return= to steal JWT via subdomain that echoes headers | accept | Same-parent-domain check confines redirect targets to Skynet-controlled infra (main app OR serve subdomains). Serve subdomains are ALREADY untrusted third-party content per Phase 103 D-01 origin isolation; a bounce to one is no more dangerous than the user directly typing the URL. No mitigation beyond same-parent-domain confinement. |
| T-pf4-05 | Information Disclosure | Rejected return URL logged to console.warn (dev tools accessible to page JS) | accept | The `?return=` param is already visible in `window.location.search`; logging it does not surface information the page doesn't already have. The log is diagnostic for legitimate users hitting flaky links, not a secret channel. |
| T-pf4-06 | Denial of Service | Extremely long return= URL crashes URL constructor | mitigate | `new URL()` gracefully throws on absurd inputs; the try/catch around it returns null. No explicit length limit needed — browsers cap URL length at ~2 MB and URLSearchParams handles that fine. |
</threat_model>
