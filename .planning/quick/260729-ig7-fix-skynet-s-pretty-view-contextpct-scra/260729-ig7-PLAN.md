<objective>
Fix the pretty-view context% meter false positive: when Claude Code renders a weekly-limit warning on the same status line as the context meter, the current rightmost-wins scraper picks the warning's `95%` instead of the meter's real `17%`. Bar-anchor the regex so `%` must be immediately preceded by a Claude Code meter glyph, and factor the parser into a pure testable helper to lock the fix under vitest.

Purpose: The pretty-view context meter is a load-bearing UX signal — a lying meter costs trust in the whole indicator. This mirrors nelly's vms-apps context-watch pre-fix bug (f88c928) and applies the same bar-anchoring hardening on the skynet side.

Output: New `context-pct-parser.ts` + `.test.ts`, plus a small refactor in `claude-session-server.ts` L2660-2703 to delegate to the helper. No wire-shape change, no behavior change beyond closing the false-positive.
</objective>
