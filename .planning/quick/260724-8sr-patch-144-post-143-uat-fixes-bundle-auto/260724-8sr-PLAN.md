FIX (a) — Terminal.tsx: patch #143 v2, drop the readyState guard
────────────────────────────────────────────────────────────────

Location: `src/ui/features/terminal/Terminal.tsx` visibilitychange useEffect
at approximately lines 339-371 (the `useEffect(() => { const
handleVisibilityChange = () => { ... }` block introduced by patch #143).

Root cause (Ashley's diag): on iOS PWA foreground, JS resumes with the old
`webSocketRef.current` still reading `readyState === OPEN` because the
queued `close` event hasn't been delivered yet → v1 handler short-circuits →
the delayed `close` event then fires `attemptReconnection` → `scheduleReconnect`
burns 8 attempts against a stale WS → user sees "1/8 through 8/8 reconnecting"
flash then the manual overlay.

Precise edits inside the effect:

1. DELETE the two lines:
   ```
   const ws = webSocketRef.current;
   if (ws && ws.readyState === WebSocket.OPEN) return;
   ```
   (they sit between the `if (wasDisconnectedBySSH.current) return;` guard
   and the `shouldNotReconnectRef.current = false;` reset assignments.)

2. Rephrase the JSDoc comment above the useEffect (currently references v1
   spec "auto-recover on foreground when the WS is closed and the target
   did NOT drop us"). Replace with v2 wording:

   ```
   // Patch #143 v2: iOS PWA backgrounding fix — cancel scheduled reconnects
   // when the tab is hidden (throttled iOS tab burns the 8-attempt budget)
   // and UNCONDITIONALLY reset + reconnect on foreground. The v1
   // `readyState === OPEN` guard has been removed: iOS resumes JS with the
   // old WS ref still reading OPEN even when the queued close event hasn't
   // delivered yet, which caused the ~50s "1/8..8/8" auto-reconnect flash
   // followed by the manual overlay. Opening a fresh WS is idempotent —
   // if the old one was genuinely alive it closes cleanly, tmux reattach
   // handles restoration, no user-visible harm. Deliberately does NOT clear
   // the xterm buffer (tmux repaint on reattach handles restoration;
   // clearing was the visible-flicker cause in the manual overlay path).
   // Target-terminated cases (wasDisconnectedBySSH === true) still require
   // manual Reconnect via the overlay at lines ~3014-3049 — that affordance
   // is intentional and unchanged.
   ```

3. KEEP unchanged:
   - The hidden-branch cancellation (clearTimeout + reset attempts + set
     isReconnectingRef=false + early return).
   - The `if (isUnmountingRef.current) return;` guard.
   - The `if (wasDisconnectedBySSH.current) return;` guard (target-terminated
     boundary — this is load-bearing).
   - All the flag-reset assignments (`shouldNotReconnectRef.current = false`
     through `setShowDisconnectedOverlay(false)`).
   - The `if (terminal) { connectToHost(terminal.cols, terminal.rows); }`
     block.
   - Deps array `[terminal, updateConnectionError]`.
   - The listener add/remove pair.
