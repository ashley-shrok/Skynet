# Phase quick-260916-9o3 Plan 01: Switch interrupt button from Escape to Ctrl-C with authoritative per-pane server throttle

One-liner: Interrupt button now sends Ctrl-C via a 2500ms server-side per-pane throttle keyed by sessionKey(hostId, tmuxSession), making it the only keystroke that both interrupts work and clears a multi-line draft in one press without risking harness death.

## What Was Built

### Task 1: Backend changes (claude-session-server.ts)

**New module-scope state** added immediately after `sessionKey`:
- `INTERRUPT_THROTTLE_MS = 2500` — window constant with measured basis (v2.1.150, 2026-09-16; Claude Code's exit-confirm window ~0.8s; 2500ms is ~3×)
- `interruptThrottleByPane = new Map<string, number>()` — AUTHORITATIVE per-pane guard keyed by `sessionKey(hostId, tmuxSession)` → last-fire epoch ms
- `__interruptThrottleForTests` — exported Map identity (following `__activeViewersForTests` pattern) so tests can `.clear()` it

**Rewritten `__applyInterruptMessageForTests`:**
- Added optional `now?: () => number` injectable clock (matching file's existing pattern at :3051, :3721)
- Widened early-return to include `currentHostId == null` (fail-closed: no throttle key = refuse)
- Throttle check BEFORE try/exec: if stored timestamp exists and `nowMs - last < INTERRUPT_THROTTLE_MS`, emit `sshLogger.warn { operation: "interrupt_throttled", hostId, tmuxSession, elapsedMs, windowMs }` and return with zero keystrokes
- Prune stale entries before `set` (entries >= INTERRUPT_THROTTLE_MS old are semantically dead; bounds Map growth per T-9o3-03)
- `interruptThrottleByPane.set(key, nowMs)` **BEFORE** `await exec(...)` — load-bearing: records before unbounded-latency exec call
- Keystroke changed: `Escape` → `C-c`
- Stale Escape/rewind-menu comment replaced with accurate Ctrl-C + harness-death + server-throttle rationale

**Per-pane teardown at BOTH activeViewers.delete sites:**
- In `teardownPane`'s `priorKey` block: `interruptThrottleByPane.delete(priorKey)` added inside `if (priorPeers.size === 0)` — same condition as `activeViewers.delete`
- In `ws.on("close")` loop: `interruptThrottleByPane.delete(key)` added inside `if (peers.delete(ws) && peers.size === 0)` — same condition as `activeViewers.delete`

**Production handler untouched:** `msg.type === "interrupt"` at :7083 continues to call `__applyInterruptMessageForTests` unchanged — it inherits the throttle by construction.

### Task 2: Backend tests (claude-session-server.compose-send.test.ts)

- Added `__interruptThrottleForTests` to named import
- Added `beforeEach(() => __interruptThrottleForTests.clear())` in interrupt describe block
- **Inverted happy-path test:** `toContain("Escape")` → `toContain("C-c")` + `not.toContain("Escape")`
- **Inverted regression guard:** formerly "MUST NOT send C-c" → now "MUST NOT send Escape" with explanation that harness-death hazard is handled by server-side throttle
- **Three new throttle tests using injectable clock (no fake timers):**
  1. Same-pane collapse: second interrupt at +500ms → exec called once + `interrupt_throttled` warn with correct `elapsedMs: 500`
  2. Cross-pane independence: different `tmuxSession` same `hostId`, and different `hostId` same `tmuxSession` → both exec calls fire, no warn
  3. Post-window release: second interrupt at +2600ms → exec called twice, both with C-c, no warn
- Updated file doc header to list all three new cases and the inverted Escape guard
