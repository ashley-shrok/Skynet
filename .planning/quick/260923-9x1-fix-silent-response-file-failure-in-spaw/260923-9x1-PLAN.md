<objective>
Fix the silent response-file failure in the spawn-request worker's REMOTE branch. `parseSpawnRequestBatch` currently sets `userId: ""` on every emitted `PendingBirth`, and `writeResponseFile` passes that empty string to `resolveHostById(hostIdNum, "")` which returns null → the worker warns and gives up, leaving coord to time out on every remote spawn.

Root fix: drop `userId` from `PendingBirth` entirely, and thread the sweep's already-decrypted `_connDetails` bag (produced by `list-substrate-hosts.ts` via the CSKEK path, defense-in-depth filtered) through `scanSpawnRequests` → `parseSpawnRequestBatch` → `PendingBirth.hostConnDetails` → `writeResponseFile`, where it's used directly with `connectOneShot`. The birth path (`resolveHostById` at worker.ts:485, `getHostOwnerUserId` at worker.ts:365) stays UNCHANGED — this fix is response-write only.

Purpose: unblock the coord ↔ substrate spawn-request round-trip. Coord is currently getting timeouts instead of success/failure responses for every remote birth.

Output: response files land on remote hosts; worker.test.ts + scan-orchestrator.test.ts stay green with the new signature.
</objective>
