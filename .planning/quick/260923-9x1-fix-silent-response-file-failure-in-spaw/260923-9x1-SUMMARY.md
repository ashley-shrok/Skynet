# Quick 260923-9x1: Fix silent response-file failure in spawn-request worker

Fixed the silent response-file failure in the spawn-request worker's REMOTE branch by threading the sweep's already-decrypted SSH connection bag (`_connDetails` from `list-substrate-hosts.ts`'s CSKEK path) directly to `writeResponseFile`, replacing the broken `resolveHostById(hostId, "")` call that always returned null and left coord to time out on every remote spawn.

## What changed

### Production code (commit `fc8e2cba`)

**`src/backend/spawn-requests/types.ts`**
- Removed `PendingBirth.userId: string` (was always `""` and only fed the broken resolver call).
- Added `PendingBirth.hostConnDetails?: Record<string, unknown>` with a JSDoc block documenting: (a) sweep-side CSKEK-decrypted origin, (b) optionality because LOCAL branch bypasses SSH, (c) the sweep-side invariant that populates it on every REMOTE-emitted item.

**`src/backend/fleet-status/ssh-poll-orchestrator.ts`**
- `parseSpawnRequestBatch(stdout, hostId, hostConnDetails?)` — third arg threaded onto every emitted PendingBirth (both malformed and valid branches).
- `scanSpawnRequests(host, channel)` — reads `(host as { _connDetails? })._connDetails` off the host record it already receives and forwards it as the third arg.

**`src/backend/spawn-requests/scan-orchestrator.ts`**
- LOCAL branch: comment clarifying no `hostConnDetails` — writeResponseFile bypasses SSH via `isLocalHostId` + bind-mount path.
- REMOTE branch: no call-site change needed (`scanSpawnRequests` now extracts `_connDetails` off the host record); added an explanatory comment.

**`src/backend/spawn-requests/worker.ts::writeResponseFile`**
- REMOTE branch rewrite: uses `item.hostConnDetails` directly with `deps.connectOneShot` — no `deps.resolveHostById` call.
- Missing `hostConnDetails` on a REMOTE item → logs at ERROR level (`spawn_request_response_conn_details_missing`) and gives up. This state should be near-impossible given the sweep-side CSKEK filter, but it's a hard invariant violation worth alerting on.
- Updated the `writeResponseFile` JSDoc block to reflect the new contract.
- Updated the `doBirth` comment block referencing `item.userId` (now removed).
- **Birth path UNCHANGED**: `deps.getHostOwnerUserId(item.hostIdNum)` at worker.ts:382 and `deps.resolveHostById(item.hostIdNum, currentUserId)` at worker.ts:502 are byte-identical to pre-fix.

### Tests (commit `7a591734`)

**`src/backend/spawn-requests/worker.test.ts`**
- `makePendingBirth`: dropped `userId: "user-abc"`, added `hostConnDetails` shaped like listSubstrateHosts' `_connDetails` bag.
- Comment near line 1171: updated to reflect `item.userId` field removal.
- Two new regression tests in the `processBirth` describe:
  1. Asserts `deps.resolveHostById` called EXACTLY 1x after `processBirth` (birth-path enumeration only — pre-fix it would have been called 2x: birth + response-write). Also asserts `deps.connectOneShot` received the sweep bag (`ip: "10.0.0.1"`, `port: 22`).
  2. Missing `hostConnDetails` on a REMOTE item → `writeMarkdownFileAtomic` NOT called; `connectOneShot` called exactly once (birth-path enum only).

**`src/backend/spawn-requests/scan-orchestrator.test.ts`**
- `makePendingBirth`: fixed a latent fixture bug (`role: "test-role"` — non-existent singular field) to the correct `roles: ["test-role"], prompt: ""`. Removed the stale `userId: ""`.

**`src/backend/fleet-status/ssh-poll-orchestrator.test.ts`**
- Updated the "valid request file" assertion from `expect(item.userId).toBe("")` to `expect(item.hostConnDetails).toBeUndefined()` (bare HostRecord without `_connDetails` passed to the test).
- Added a new regression: `scanSpawnRequests` threads `host._connDetails` onto both valid AND malformed emitted PendingBirths (a mixed batch — one valid body, one malformed body — asserts both items carry the same sweep bag).
