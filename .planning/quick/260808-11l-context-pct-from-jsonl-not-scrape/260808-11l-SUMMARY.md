# Quick 260808-11l: context-% from JSONL not scrape — Summary

## What changed

**Three files landed in one atomic commit on `feat/tab-title-from-tmux`:**

1. **NEW `src/backend/claude-session/context-pct-from-jsonl.ts`** — `readContextPctFromJsonl(conn, sessionFile): Promise<number | null>`. Tails 10KB of the JSONL, reverse-scans for the last assistant turn with `message.usage`, sums `input_tokens + cache_creation_input_tokens + cache_read_input_tokens`, applies the 16.5% autocompact-buffer normalization (mirror of `gsd-statusline.js:306-318`), returns the displayed integer or `null`. Never throws.

2. **NEW `src/backend/claude-session/context-pct-from-jsonl.test.ts`** — 8 vitest cases covering: (a) happy path, (b) no assistant turn, (c) assistant without usage, (d) execCommand throw, (e) boundary at 16.5%, (f) over-full clamp, (g) multiple assistant turns (last wins), (h) malformed JSON lines skipped.

3. **MODIFIED `src/backend/claude-session/claude-session-server.ts`** — added static import for `readContextPctFromJsonl`; rewrote the `contextPctTimer` setInterval callback body (around L3441) to try JSONL first when `currentSessionFile` is set, then fall through to `parseContextPct(tmux capture-pane output)` only when JSONL yields null. All four guards preserved (stopped/readyState, !sshConn, contextPctInFlight, post-await stopped/readyState re-check before ws.send). Plan-pending block preserved verbatim inside the new async closure.

## Why

Ashley's mobile PWA collapses the pretty-view pane to ~2 chars wide when the browser is narrow — the statusline pct chars survive but the AND-anchored bar glyphs (`█`/`░`) get truncated. `parseContextPct` requires a bar glyph in the same line (patch #187 hardening against false positives), so on narrow panes it returns `null` and the pretty-view context-% meter freezes on its last-known value.

The JSONL file already resolved by `discoverClaudeSession` (closure-local `currentSessionFile`) is the authoritative source Claude Code itself writes token usage to. Reading it eliminates the pane-width dependency entirely and future-proofs the meter against any upstream statusline-format changes.
