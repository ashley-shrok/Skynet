# Phase 260907-982 Plan 01: pv-claude-session-ws-zombie-after-tmux-teardown Summary

Wired `closeForTornDownSession()` (ws.close(1011, "session_torn_down"), readyState-guarded) into `transitionToDead` and the FALLBACK-01 initial-inactive path so a server-driven tmux teardown produces a client-visible close event that triggers the existing reconnect handler; added `sshLogger.warn("pv_input_drop_no_session", ...)` at the `__applyInputMessageForTests` entry guard so any future teardown path that slips through leaves a forensic trail instead of silently swallowing input frames.

## What Landed

### Edit A — Entry-guard drop log (`claude-session-server.ts:2567`)

Replaced the silent `if (!sshConn || !currentTmuxSession) return;` with a `sshLogger.warn("[pv-input] drop_no_session", ...)` carrying the exact payload from the bounty:

```ts
sshLogger.warn("[pv-input] drop_no_session", {
  operation: "pv_input_drop_no_session",
  mqid: String(deps.messageQueueItemId ?? "none"),
  hostId: currentHostId,
  hasSshConn: !!sshConn,
  hasTmuxSession: !!currentTmuxSession,
  dataLen: (deps.data ?? "").length,
});
```

Also added a comment noting that the outbound broadcaster does NOT need a symmetric log because `activeViewers` (L1058) is keyed by `${hostId}::${tmuxSession}` and membership is torn down inside `teardownPane` (L4001-4006), so orphan WSes are structurally unreachable from broadcast fan-out.

### Edit B — `closeForTornDownSession()` helper + wire-in

New connection-scoped helper declared alongside `teardownPane`:

```ts
const closeForTornDownSession = (): void => {
  if (ws.readyState === WebSocket.OPEN) {
    try {
      ws.close(1011, "session_torn_down");
    } catch { /* ws may be mid-close; teardown proceeds regardless */ }
  }
};
```

Called from two sites:
- `transitionToDead` — AFTER `ws.send({type:"inactive", reason})` and `paneStateEmitter.emit("inactive", reason)`, BEFORE `teardownPane()`. Ordering: the inactive frame + emitter should reach the client before the socket closes; then the close fires and the client reconnects.
- FALLBACK-01 — AFTER `ws.send({type:"inactive", reason: result.reason})` and `paneStateEmitter.emit("inactive", ...)`, BEFORE `sshConn = null`.

Both sites are internally readyState-guarded, so the ws.on("close") teardown re-entry cannot double-close even if this helper is added to a new call site later.

## Regression Tests Added

Three new `it(...)` cases in `describe("__applyInputMessageForTests", ...)` inside `claude-session-server.compose-send.test.ts`, immediately after the two pre-existing guard-null tests. Established a module-level `vi.mock("../utils/logger.js", ...)` full-logger-surface stub (mirrors `context-pct-from-jsonl.test.ts` + `dormant-poll.test.ts`) so `sshLogger.warn` is silent + assertable.

Cases:

1. **sshConn null, currentTmuxSession=`"legit-session"`, data=`"hello"`, mqid=`"pv-optim-123"`** → asserts one `sshLogger.warn` with `{operation:"pv_input_drop_no_session", mqid:"pv-optim-123", hostId:1, hasSshConn:false, hasTmuxSession:true, dataLen:5}`, no exec call.
2. **sshConn=fakeConn, currentTmuxSession=null, data=`"x"`, mqid omitted** → asserts one `sshLogger.warn` with `{mqid:"none", hostId:7, hasSshConn:true, hasTmuxSession:false, dataLen:1}` (documents mqid → "none" default, matches `:2597` idiom).
3. **sshConn=null, currentTmuxSession=null, currentHostId=null, data=`""`** → asserts one `sshLogger.warn` with `{hostId:null, hasSshConn:false, hasTmuxSession:false, dataLen:0, mqid:"none"}`. Comment documents ordering intent: the sshConn/tmuxSession guard runs BEFORE the empty-data guard, so the drop-log fires even for empty data.
