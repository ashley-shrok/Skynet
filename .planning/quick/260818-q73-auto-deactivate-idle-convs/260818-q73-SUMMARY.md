# quick-260818-q73: Auto-deactivate idle convs — Summary

**One-liner:** Per-tab idle sweep in `PrettyConversationsPanel` that silently invokes the existing `handleRowDeactivate(row)` for active-set rows un-selected for > 5 minutes; the currently-selected conv is a hard-invariant exempt.

## What was built

Added a per-tab, in-memory-only idle-deactivate policy inside `PrettyConversationsPanel.tsx`. The sweep is silent (no toast, no console log, no ARIA update, no analytics), per-tab (no persistence, no server call, no cross-tab / cross-device coordination), and reuses the existing `handleRowDeactivate(row)` verbatim — the SAME function the manual red-X click passes to each row's `onDeactivate` prop.

### Module-scope constants (near the top of the panel file, ~L137)

```ts
const IDLE_DEACTIVATE_THRESHOLD_MS = 300_000; // 5 min — shape default
const IDLE_DEACTIVATE_SWEEP_MS = 30_000;
```

Header comment cites `quick-260818-q73` + the shape file and notes that "colocated by convention — this project has no shared app config module; other tunable UI constants live at their consumer's module top (see BACKPRESSURE_POLL_MS in use-pretty-view-uploads.ts, STICK_ARM_MS in use-auto-scroll.ts). Bumping the threshold = editing this constant."

### Component-body additions (placed after `handleRowDeactivate` at ~L847)

- **Refs** (all `useRef`):
  - `lastUnfocusedAtRef: Map<string, number>` — per-tab, in-memory only. Never persisted, never sent to server, never shared. Values are `performance.now()` millisecond timestamps.
  - `previousSelectedIdRef: string | null` — one-slot memory of the previous `selectedId`.
  - `activeSetRef`, `selectedIdRef` — mirrors of the hook-subscribed values so the mount-only sweep reads the LATEST snapshot each tick.
  - `handleRowDeactivateRef` — mirror of `handleRowDeactivate`. Needed because the handler is defined inline (no `useCallback`), so its identity churns every render. Without the ref mirror the mount-only sweep would call the FIRST-render capture of a stale function.

- **Effects** (four short `useEffect` blocks):
  - Three single-line ref-sync effects (deps `[activeSet]`, `[selectedId]`, `[handleRowDeactivate]`).
  - selectedId tracker: on change, stamps the OUTGOING id with `performance.now()` and DELETES the incoming id from the map. Selected conv's clock is not running while selected — closes the "reselect same conv immediately" edge case.
  - Mount-only `setInterval(sweep, IDLE_DEACTIVATE_SWEEP_MS)` with `clearInterval` cleanup. Sweep body: snapshot `now` + `currentSelected` + `currentActive` + `handleRowDeactivate` from refs; for each id in `currentActive` skip if selected, skip if no stamp, skip if fresh; resolve row via `knownRowsRef`; call `handleRowDeactivate(row)` verbatim; delete map entry after firing.

### Tests (three new tests in `PrettyConversationsPanel.test.tsx` ~L3492)

New describe block: `PrettyConversationsPanel (quick-260818-q73): idle sweep`. Uses `vi.useFakeTimers()` scoped to the describe (mirrors the swipe-snap-back test at ~L2694 discipline). Drives selectedId transitions by mutating the shared `snapshot` mock and calling `rerender()` (same pattern as Test 22 at ~L1909).

- **Test SWEEP-1 (HARD INVARIANT):** Currently-selected conv is exempt from the sweep. Mount t1+t2 in active set, select t1, transition to t2 (t1 stamped), advance timers past THRESHOLD+SWEEP+1s, then switch selectedId BACK to t1, clear spies, advance one sweep tick — assert no `handleRowDeactivate` call for t1. Proves the "never deactivate the one you're on" invariant survives a stale earlier timestamp.
- **Test SWEEP-2:** Stale unfocused conv IS deactivated. Same t1→t2 transition, then advance timers past THRESHOLD+SWEEP and assert `removeFromActiveSet` fired with `t1.id` AND `onDeactivateRow` fired with the t1 row shape. Also asserts t2 (currently selected) was NOT touched.
- **Test SWEEP-3:** Fresh (< threshold) unfocused conv is NOT deactivated. Same t1→t2 transition, but advance only one sweep tick (well below threshold). Assert no `handleRowDeactivate` call for t1.

Assertions use `.mock.calls.filter(([id_or_row]) => …)` to isolate per-id spy invocations — makes each assertion about "did T1 get deactivated at all" rather than "was T1 the k-th call" (defensive against multiple sweeps firing during the timer advance window).
