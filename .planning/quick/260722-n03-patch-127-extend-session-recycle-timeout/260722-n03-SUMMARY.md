# Quick task 260722-n03: Patch #127 — extend session-recycle timeout + full-body red overlay error variant

**One-liner:** Extend the patch #122 client-side session-recycle watchdog from 120000ms (2 min) to 300000ms (5 min), and ternary-split the SessionHoldingOverlay bg-gradient + text-color className entries against `error` so the failure variant renders a warm-red card body (not just a red glyph + subtle inset shadow against a neutral navy card).

## Objective (recap)

- Reduce false-positive rate on the belt-and-suspenders "session recycle failed" red-bubble by widening the client-side dwell window from 2 min to 5 min. 2 min was tripping the red-bubble on legitimate slow recycles under real backend load, giving Ashley an incorrect "hit refresh" cue.
- Make the patch #122 error variant of `SessionHoldingOverlay` read RED at a glance from across the pretty-view surface, rather than requiring a look at the glyph to notice. Whole card body flips warm-red on error; neutral variant untouched.

## What changed

### Edit 1 — `src/ui/features/pretty-view/PrettyView.tsx` (patch #122 watchdog)

- The `useEffect` gated on `isHolding` (previously ~lines 500-508) now uses `setTimeout(..., 300000)` instead of `setTimeout(..., 120000)`.
- The comment block above the effect (previously ~lines 492-499):
  - Duration reference updated: `"start a 120000ms timer"` → `"start a 300000ms timer (5 minutes)"`.
  - New four-line `Patch #127:` rationale paragraph appended, explaining why 5 min replaces 2 min (real-world backend recycles under load exceeded 2 min, false-positives).
- Nothing else in the file touched. Verified via `grep 120000` — only remaining occurrence is inside the new Patch #127 explanatory comment (informational, not a live constant). No live-code 120000 remains in the watchdog site.

### Edit 2 — `src/ui/features/pretty-view/SessionHoldingOverlay.tsx` (patch #122 error variant)

- Inside the inner glass card's `cn(...)` block, two entries that patch #122 left as UNCONDITIONAL are now ternaried on the `error` prop:
  - Background gradient: on `error`, `rgba(85,30,35,0.55)` → `rgba(55,20,25,0.6)` (warm-red, slightly higher opacity for substance). On `!error`, preserved BYTE-FOR-BYTE as `rgba(45,55,80,0.5)` → `rgba(28,35,55,0.55)`.
  - Text color: on `error`, `text-[#f5d0d4]` (warm-red-tinted very-light). On `!error`, preserved BYTE-FOR-BYTE as `text-[#dfe3ee]`.
- New six-line `Patch #127:` comment above the ternary explains why the error variant flips the whole card body warm-red and cites the ComposeBox.tsx ~line 981 `hsla(0,72%,55%,1)` hue anchor for palette continuity.
- **NOT touched** (all pre-existing patch #122 or patch #74 code):
  - Border className (`"border border-white/[0.08]"`) — neutral in both variants by design, per patch #122 spec.
  - Shadow ternary — the patch #122 warm-red inset glow logic is already correct.
  - RefreshCcw glyph className ternary — the patch #122 warm-red glyph tint on error is already correct.
  - Scrim wrapper (`absolute inset-0 z-[110] ...`) — unrelated to error variant.
  - Outer div `role`/`aria-label` ternary — already correct in #122.
  - The `<span>` copy ternary — already correct in #122.
  - The file header comment block — the existing "warm-red hue and subtle inset shadow" description remains accurate for the glyph + shadow, and #127 adds descriptive detail at the split-point rather than rewriting the header.
