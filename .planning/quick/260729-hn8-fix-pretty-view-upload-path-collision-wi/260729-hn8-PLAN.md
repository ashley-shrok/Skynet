<objective>
Fix the pretty-view upload path collision bug where two files pasted in the same batch with identical filenames (e.g. two Chrome-clipboard `image.png` files) both resolve to the same `finalPath` and the second overwrites the first at completion. Root cause: `resolveNonCollidingFinal` only checks the disk via `sftpStat`; the first file's finalPath is not claimed until `sftpRename` at completion, so the second file in the same batch stat's "not exists" for the same candidate.

Purpose: Preserve Ashley's data — no silent overwrite when she pastes multiple identically-named clipboard images. This is a backend-only correctness fix bundled onto the pending patch stack.

Output: Modified `pretty-view-upload.ts` (batch-local `reservedFinalPaths` Set threaded into `resolveNonCollidingFinal`) + two new tests in `pretty-view-upload.test.ts` proving batch-local collision resolution works for 2-file and 3-file same-name cases. One atomic commit.
</objective>
