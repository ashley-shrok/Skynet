<objective>
Fix fleet-wide ENOENT bug in `installStopHook`: the Stop hook is never installed on any identity-hosting host because `dist/backend/backend/fleet-status/stop-hook.sh` is not emitted by `tsc` (which only compiles `.ts` → `.js`; sibling `.sh` assets are not copied). Every install attempt fails with ENOENT reading `stop-hook.sh`, so `~/.claude/fleet-status/last-stop-payload.json` is never written, the poll watcher sees empty `backgroundTasks[]` (fail-open), and any session with `status==="shell"` renders as idle in the console.

Fix by inlining the 20-line `stop-hook.sh` contents as a module-level string constant `STOP_HOOK_SCRIPT_CONTENTS`. The runtime path in `installStopHook` (default, when `opts.localHookScriptPath` is unset) will use the constant directly — no `readFileSync`, no `resolveLocalHookScript()`, no `fs`/`path`/`url` imports.

Root cause is already diagnosed (36 identical `fleet_status_hook_install_failed` ENOENT events in `/opt/skynet/console-forward-logs/console-forward.log`). Executor must NOT re-diagnose. Ship the fix.

Purpose: Restore fleet-status visibility across the entire fleet — agents with shells and monitors up will correctly show `isWorking=true` once the Stop hook writes `last-stop-payload.json` on each box.

Output: Modified `remote-hook-install.ts` with inlined script contents; updated tests that don't reference paths that only exist in another identity's worktree.
</objective>
