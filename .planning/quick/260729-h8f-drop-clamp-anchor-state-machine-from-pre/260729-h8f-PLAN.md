<objective>
Revert the clamp-anchor state machine in pretty-view to Phase-01's original follow-bottom-when-near-bottom contract. Patches #96 and #98 added a mode dichotomy (clamp vs user-driving) with a DOM anchor pinned to the top of the viewport as content grew below it; user wants the simpler behavior back: when pinned to bottom, follow new content; when scrolled up, hold position.

Purpose: Restore Phase-01 scroll contract per ROADMAP.md:59. Removes ~200 lines of state-machine complexity from use-auto-scroll.ts and the message-scanning IIFE from PrettyView.tsx.

Output: Rewritten hook (single "pinned to bottom?" state derived from scroll position), rewritten test suite (drops clamp/anchor tests, keeps follow-bottom + gesture + RO + jump-pill tests), updated PrettyView.tsx call site.
</objective>
