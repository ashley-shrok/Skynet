<objective>
Patch #135 — make the pretty-view ComposeBox textarea auto-grow with its
CONTENTS, not just on newlines. Today's code at
`src/ui/features/pretty-view/ComposeBox.tsx:517` uses
`const rows = Math.min(6, Math.max(1, text.split("\n").length));`
which counts NEWLINES only. Result: typing a long message on one line stays
clipped at ~1 row with hidden overflow because the wrapped visual lines never
add a `\n`. Ashley has to hit Enter to expand the box or lose sight of what
she's typing.

The fix is well-understood: replace the newline heuristic with a
`useLayoutEffect` that measures `scrollHeight` and sets `el.style.height`
directly, capped at a 6-row equivalent. See task 1 for the exact mechanic.

Purpose: eliminate the newline-only rows heuristic so Ashley's compose box
grows with any content that increases the wrapped visual line count.
Output: 1 code diff + 2 focused tests + 1 numbered fork commit (patch #135)
on the current branch. NO deploy, NO npm run build, NO skynet-patches.md
write-up (tina handles the pin at deploy time).
