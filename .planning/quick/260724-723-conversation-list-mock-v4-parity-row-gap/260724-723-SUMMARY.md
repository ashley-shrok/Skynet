# Quick Task 260724-723: Conversation List Mock v4 Parity (Patch #142) Summary

One-liner: Five UAT-caught visual/behavioral gaps between the shipped conversation list and locked mock v4 closed in one atomic commit — row spacing, active-set engagement uniformity, RDP avatar icon size, chevron always-visible chrome, and chevron-title clearance.

## Task 1: Land all five mock v4 parity fixes

### Fix 1 — Row gap + side padding (UAT #1 + #3)

**File:** `src/ui/features/pretty-conversations/PrettyConversationsPanel.tsx` (line 283)

The scroll-region div at line 275 was using `className="flex-1 min-h-0 overflow-y-auto flex flex-col"` — pure Tailwind — which shadowed the pre-existing `.pv-panel-scroll` CSS class in `pretty-conversations.css` (L111-118) that already carried `padding:14px 12px 18px` and `gap:8px`. Changed to `className="pv-panel-scroll min-h-0"` — Tailwind duplicates dropped, `min-h-0` retained (not in the CSS class).

### Fix 2 — Active-set engagement on any click (UAT #2)

**Files:** `PrettyConversationsPanel.tsx` (import + handleRowSelect)

patch #137 wired `addToActiveSet` inside `selectConversation`, but `handleRowSelect` branches on `row.rdpHostRow` and `row.fleetOnly` and early-returns BEFORE reaching `selectConversation`. Fleet-defined agents (Ashley's whole active session set) never engaged the active set — rows stayed `.pv-row.ambient` forever.

Two edits:
- Added `addToActiveSet` to the import from `@/state/conversation-store` (alongside `selectConversation`)
- Hoisted `addToActiveSet(row.id)` as the second statement in `handleRowSelect`, immediately after the `isMobileVariant` swipe-reset and BEFORE the branch dispatch

The default branch's inner `selectConversation → addToActiveSet` path is a cheap idempotent no-op (guard at `conversation-store.ts:646`).

### Fix 3 — RDP Monitor icon size in avatar (UAT #5)

**File:** `pretty-conversations.css` (new rule after `.pv-avatar` block)

`tabIcon()` returns lucide icons with hard-coded `className="size-3.5"` (14px) because that's the tab-bar sizing. Mock v4 expects 18×18 inside the 40px disc. Added:

```css
.pv-avatar .pv-avatar-fallback-icon svg {
  width: 18px;
  height: 18px;
}
```

Scoped to `.pv-avatar` ancestor so tab-bar rendering (different container, no `.pv-avatar` ancestor) is unaffected.

### Fix 4 — Sidebar-toggle chevron chrome at rest (UAT #6)

**File:** `src/ui/AppShell.tsx` (line 1425)

The fixed persistent chevron followed the mock's `.pv-pencil` bare-until-hover convention. But the pencil sits inside a bordered panel-header with a base background; the fixed chevron floats over unpredictable content, so bare-until-hover left it visually absent.

Replaced `className` — promoted hover chrome to at-rest state (subtle `rgba(220,225,245,0.06)` bg + `--color-pv-border-quiet` border + muted-fg), bumped hover one notch further (`rgba(220,225,245,0.12)` bg + `--color-pv-border-quiet-strong` border). No `bg-transparent`/`border-transparent` residuals remain.

### Fix 5 — Chevron clears "Conversations" title on desktop with sidebar open (UAT #7)

Three coordinated edits:

**(5a)** `PrettyConversationsPanel.tsx`: Added `sidebarToggleOverlaps?: boolean` prop (default `false` via destructure), emits `data-sidebar-toggle-overlaps={"true"|"false"}` on `.pv-panel-header`.

**(5b)** `pretty-conversations.css`: Added rule after `.pv-panel-header` block:
```css
.pv-panel-header[data-sidebar-toggle-overlaps="true"] {
  padding-left: 48px; /* 8px chevron left + 32px chevron width + 8px breathing */
}
```

**(5c)** `AppShell.tsx` PrettyConversationsPanel mount site: Added `sidebarToggleOverlaps={!isMobile && !isTouchDevice && sidebarOpen}`. The `!isMobile && !isTouchDevice` gate matches the guard on the inline sidebar column — mobile + touchscreen paths never have the fixed sidebar open.

### Test hygiene
