<objective>
Fix the "Server connection lost, recovering…" toast that fires on long-message speak requests by bumping the two TTS timeouts (frontend postSpeak axios call, backend handleSpeak AbortController) from 30s to 300s (5 minutes).

Purpose: Chatterbox TTS synthesis time scales with input length; SPEAK_TEXT_MAX = 25000 chars can take minutes. The current 30s cap (inherited from handleTranscribe's T-16-02 STT timeout when patch #223 added TTS support) trips first, producing either an ECONNABORTED axios error or a 504 "TTS timeout" response. Both paths land in main-axios.ts's response interceptor, which calls dbHealthMonitor.reportDatabaseError. dbHealthMonitor.isBackendUnreachable matches both ECONNABORTED and any error message containing "timeout", so it fires database-connection-degraded → the toast renders in AppShell. This is a pure timeout-tuning fix — dbHealthMonitor/isBackendUnreachable/main-axios global default are all left alone.

Output: Two-line-scale edits to two files. STT and voices timeouts remain 30_000. No test updates expected (the two relevant test files mock postSpeak at the module boundary).
</objective>
