# Phase quick-r81 Plan 01: Fix Speak-Button "Connection Lost" Popup on Long Messages — Summary

**One-liner:** Bump both TTS timeouts (backend `handleSpeak` AbortController + frontend `postSpeak` axios) from 30s → 300s so long-message synthesis (up to `SPEAK_TEXT_MAX = 25000` chars) no longer trips the `dbHealthMonitor` "backend unreachable" heuristic that renders the `common.connectionDegraded` toast.

## Root Cause Recap

Chatterbox TTS synthesis time scales with input length. The old 30s cap (inherited from `handleTranscribe`'s T-16-02 STT timeout when patch #223 added TTS support) fired first on long inputs. That produced either:

- **Frontend path:** axios `ECONNABORTED` "timeout of 30000ms exceeded" → `main-axios.ts` response interceptor → `dbHealthMonitor.reportDatabaseError` → `isBackendUnreachable` matched on `ECONNABORTED` → `database-connection-degraded` fires → AppShell renders the "Server connection lost, recovering…" toast.
- **Backend path:** 504 `{error: "TTS timeout", status: 504}` → same interceptor → `isBackendUnreachable` matched on the `"timeout"` substring rule → same toast.

Both were false positives — the backend was fine; the timeout was just too short for the workload.

## Changes

### `src/backend/database/routes/voice.ts` — `handleSpeak` only

**Before (line 145–147):**

```ts
// (c) AbortController: 30-second TTS timeout
const controller = new AbortController();
const timeoutId = setTimeout(() => controller.abort(), 30_000);
```

**After:**

```ts
// (c) AbortController: 300-second (5 min) TTS timeout — 10x handleTranscribe's 30s cap.
// TTS synthesis time scales with input length, and SPEAK_TEXT_MAX = 25000 chars can
// take minutes at Chatterbox's rate; a shorter cap trips before real long-message
// requests finish and surfaces as a "connection lost" toast on the client
// (dbHealthMonitor.isBackendUnreachable matches the 504 "TTS timeout" via its
// "timeout" substring rule, then fires database-connection-degraded → AppShell toast).
const controller = new AbortController();
const timeoutId = setTimeout(() => controller.abort(), 300_000);
```

`handleTranscribe` (still `30_000`) and `handleListVoices` (still `30_000`) unchanged.

### `src/ui/api/voice-api.ts` — `postSpeak` only

**Before (line 9–11):**

```ts
const response = await authApi.post("/voice/speak", body, {
  responseType: "blob",
});
```

**After:**

```ts
// 300s timeout override — TTS synthesis of long text (up to SPEAK_TEXT_MAX =
// 25000 chars) can exceed authApi's 30s default (main-axios.ts) and surface
// as an ECONNABORTED that dbHealthMonitor.isBackendUnreachable mis-categorises
// as "backend unreachable", firing database-connection-degraded → AppShell toast.
const response = await authApi.post("/voice/speak", body, {
  responseType: "blob",
  timeout: 300_000,
});
```

`getVoices` unchanged (still uses `authApi`'s 30s default — correct for the list-voices call).
