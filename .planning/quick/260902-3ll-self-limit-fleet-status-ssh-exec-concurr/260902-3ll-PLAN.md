<objective>
Self-limit Skynet's own SSH exec-channel concurrency to ≤ 8 in flight per
(host, SSH connection) by wrapping the two channel-adapter `.exec` functions
in `src/backend/starter.ts` (at :360-366 and :402-408) — plus the intermediate
`echo ok` health probe at ~:369 — with a per-channel counting semaphore
(hand-rolled, ~15 lines).

Closes the architectural family started by the wip-indicator SSH-transport
bounty (shipped 2026-09-02 as /gsd:quick 260902-1tu). That fix made the ONE
catastrophic null-return path (stat-read → false session_gone) safe. This
bounty PREVENTS the saturation entirely so no null-return paths from the
adapter fire at all under normal fleet-status polling load. OpenSSH default
MaxSessions=10 (universal since 2008) is per-CONNECTION not per-host-global
(sshd_config man page verbatim, confirmed with Ashley 2026-09-02), so an
8-cap on Skynet's own connection leaves 2 channels of headroom and cannot
starve any other legitimate SSH client on any target box.

Purpose: eliminate the CHANNEL_OPEN_FAILURE bursts from Skynet's fleet-status
poller under any target host's default sshd config, without needing sshd-side
surgery on any polled box (impossible for hosts we don't control, e.g. Aither
Windows). The throttle is INVISIBLE to `ssh-poll-orchestrator.ts` — its
`Promise.all([...])` fan-outs at :1205, :966, sweepOneHost, source-B
enumeration, JSONL tail, etc. queue implicitly with zero call-site changes.

Output: two files touched (`starter.ts` + `starter.test.ts`), one small
hand-rolled semaphore utility, two adapter-site wraps + one health-probe wrap,
one test suite with 4 targeted assertions. No new deps. No worktree. No

    Semaphore primitive (`makeSemaphore(limit)`):
    - Returns an object with a single method: `run<T>(fn: () => Promise<T>): Promise<T>`.
    - Maintains an internal `active` counter and a FIFO `waiters: Array<() => void>`.
    - When `run(fn)` is called: if `active < limit`, increment `active` and invoke `fn()`; else push a resolver onto `waiters` and await it, then increment `active` and invoke `fn()`.
    - In a `try/finally` around the awaited `fn()`: on completion (success OR throw), decrement `active` and if `waiters.length > 0` shift the head waiter and call its resolver. Re-throw any error from `fn()` unchanged (the semaphore does NOT catch or transform errors — the surrounding adapter's existing try/catch → null must remain the SOLE null-conversion point).
