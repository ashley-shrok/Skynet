<objective>
Fix a CSS stacking-context escape bug on the multi-view Pane wrapper. Yesterday's UAT
trace (skynet-patches.md #517 handoff) showed PrettyView's high-z chrome (identity badge
`z-[101]` at IdentityBadge.tsx:90, drop overlay `z-[95]`, session-holding overlay
`z-[99]`) plus a composebox close button visually escaping upward and hovering on top of
an RDP surface after clicking a non-split-tree RDP session while a multi-view split was
active. Root cause: the Pane's outer `<div>` at src/ui/shell/SplitView.tsx:400 does not
establish a stacking context, so its descendants' large z-index values are compared
against the AppShell tree — where the normal-view container's `zIndex: 10` (at
src/ui/AppShell.tsx:2552-2555) is supposed to cover the split when the active tab lives
outside the split tree, but loses to any child z ≥ 11 that has no isolating ancestor.

Purpose: contain PrettyView's z-index budget inside the Pane so the AppShell layout gate
(normal-view zIndex:10) can do its job unambiguously. This is a one-line CSS fix on ONE
file. Add a regression test and a load-bearing comment.

Output:
- `src/ui/shell/SplitView.tsx` — Pane outer wrapper className gains `isolate`; load-bearing comment above the className.
- `src/ui/shell/SplitView.stacking-context.test.tsx` — new co-located regression test.
</objective>
