<objective>
Fix a sidebar cold-reload regression where disk-pinned identities appear unpinned after every remount. The panel's mount hydrate effect at `src/ui/features/pretty-conversations/PrettyConversationsPanel.tsx:502-542` races with the identities-store `GET /identities` fetch: the effect fires on the `fleetSessionsLoaded` false→true flip, but the identities-store's per-identity `pinned: boolean` fanout starts on the SAME event and hasn't resolved yet. Result: `deriveDiskPinnedIds` reads an empty `state.identities`, returns `[]`, and `hydratePinnedIdsFromServer([])` wipes `state.pinnedIds`. Because the effect is one-shot (guarded by `hydratedRef.current`), it never re-derives — every cold reload loses pins.

Purpose: Restore server-authoritative pin persistence across cold reloads. Alice confirmed on t1000 that `~/fleet/identities/ivory/.pinned` exists on disk and `GET /identities?identityHosts={ivory:6,...}` returns `ivory pinned:True` — the write path and backend read path both work end-to-end; only the panel's client-side hydration ordering is broken. The minimal fix is a second gate on `useIdentities().loaded` so the hydrate effect fires exactly once, when BOTH the fleet-sessions store AND the identities store have loaded.

Output:
- Modified `PrettyConversationsPanel.tsx` with the second gate + dep-array addition.
- New regression `describe` block in `PrettyConversationsPanel.test.tsx` locking the ordering (loaded:false → no hydrate; flip to loaded:true → hydrate exactly once with correct id).

Explicit non-goals (per bug diagnosis; do NOT introduce):
- No effect restructure — preserve the one-shot `hydratedRef.current` guard.
- No changes to `deriveDiskPinnedIds`, `buildIdentityHostsFromFleet`, or any backend.
- No retry/re-subscribe pattern for identities-store re-populations from later mutations.
- No changes to worktree behavior (Alice 2026-07-31 directive: never use worktrees on this repo).
- No changes to the hiddenIds fetch behavior (the `getHiddenIds()` block inside the same IIFE stays behind the same combined gate as a natural consequence of living inside the same effect — no separate hidden-slice work needed).
</objective>
