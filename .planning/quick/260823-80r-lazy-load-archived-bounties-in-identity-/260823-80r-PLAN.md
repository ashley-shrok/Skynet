<objective>
Fix the identity-modal timeout for roles with hundreds of archived bounties (Wendy/Molly/Aqua on host 7) by making archive reads opt-in via a new `includeArchived: boolean` request flag. Backend default is false — the expensive `for d in */; do cat "$d/bounty.json"; done` shell one-liner is skipped entirely for the common case where the user never expands the Archive accordion. Frontend only sets the flag to true when the user actually expands Archive.

Purpose: Ashley 2026-08-23: *"if the bounties section enumerates the archived ones when the modal opens, then it definitely shouldn't, because that is such a waste like 99% of the time"* + *"just keep it simple. Keep everything in the interface the way it is, except for the fact that if you go to expand the archived bounties, then it loads them in."* Root cause: `readIdentityBounties` at `identity-artifact-reader.ts:704` unconditionally runs both open+archive shell commands in parallel (line 811 `Promise.all`), the archive command exceeds the 3s `REMOTE_EXEC_TIMEOUT_MS` for large archives, silently swallows to `""` via `.catch(() => "")`, and the modal reports failure via the outer 5000ms `connectOneShot` timeout.

Output: A single quick fix — additive wire-shape change (new optional flag), no response-shape change, no timeout tuning. Callers that don't set the flag get the cheaper behavior automatically.
</objective>
