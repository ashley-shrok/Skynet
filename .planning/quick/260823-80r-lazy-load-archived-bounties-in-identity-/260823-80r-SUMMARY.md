# Quick 260823-80r: Lazy-load Archived Bounties in Identity Modal — Summary

**One-liner:** Additive `includeArchived?: boolean` request flag (default false) on `identity:list-bounties` and all 7 write-then-refetch bounty mutations; backend skips the expensive `for d in */; do cat "$d/bounty.json"; done` shell walk entirely when the flag is unset; frontend only opts in when the user actually expands the Archive accordion.

## Objective

Fix the identity-modal timeout for roles with hundreds of archived bounties (Wendy/Molly/Aqua on host 7). Root cause: `readIdentityBounties` at `identity-artifact-reader.ts:704` unconditionally ran both open+archive shell commands in parallel via `Promise.all`; the archive `for d in */; do cat "$d/bounty.json"; done` exceeds the 3s `REMOTE_EXEC_TIMEOUT_MS` for large archives, silently swallows to `""` via `.catch(() => "")`, and the modal reports failure via the outer 5000ms `connectOneShot` timeout.

Fix shape (Ashley 2026-08-23): additive wire flag, no response-shape change, no timeout tuning. Callers who don't set the flag get the cheaper behavior automatically. Frontend sets the flag to true ONLY when the user expands the Archive accordion (once per modal session — idempotent).

## Files Modified

**Backend:**

`src/backend/claude-session/identity-artifact-reader.ts` — `readIdentityBounties` signature widened to `(conn, identityKey, includeArchived: boolean = false)`. LOCAL branch: `fs.readdir(archiveDir)` + parse loop wrapped in `if (includeArchived) { ... }`. REMOTE branch: `Promise.all([open, archive])` replaced with serial `execWithTimeout(conn, openCmd)` (always runs, no `.catch` swallow) + conditional `if (includeArchived) archiveStdout = await execWithTimeout(conn, archiveCmd).catch(() => "");`. Archive command string preserved verbatim; `.catch(() => "")` safety net preserved on the archive path when flag is true.

`src/backend/claude-session/claude-session-server.ts` — 8 handlers updated (identity:list-bounties + 7 mutations). Each parses `const includeArchived = (msg|raw as { includeArchived?: unknown }).includeArchived === true` (strict boolean check) after existing field parsing, and threads the flag as the third positional arg to BOTH the LOCAL `readIdentityBounties(null, ...)` and REMOTE `readIdentityBounties(conn, ...)` call sites (16 sites total). `identity:list-bounties` also adds `includeArchived` to both `sshLogger.info` calls for diagnostic visibility.

**Wire types:**

`src/ui/api/claude-session-api.ts` — `includeArchived?: boolean` added to 8 payload types: `IdentityListBountiesPayload`, `IdentityUpdateBountyPriorityPayload`, `IdentityUpdateBountyStatusPayload`, `IdentityUpdateBountyPinnedPayload`, `IdentityUpdateBountyNeedsDeskPayload`, `IdentityUpdateBountyFieldsPayload`, `IdentityArchiveBountyPayload`, `IdentityDeleteBountyPayload`. Response types (`Identity*Event`) UNCHANGED per Ashley constraint.

**Frontend:**

`src/ui/features/pretty-view/IdentityModal.tsx` — three new state slots:
- `archivedLoadState: "unloaded" | "loading" | "loaded"` (default "unloaded")
- `archivedError: string | null` (default null)
- `archiveAccordionValue: string` (controlled Radix Accordion value; empty = closed, "archive" = open)

All three reset on modal open / identity switch (added to the initial-fetch effect's reset block). Initial-fetch response handler no longer calls `setArchivedBounties(parsed.archivedBounties ?? [])` — backend now returns `[]` there by design; keeping the setter would clobber whatever `loadArchivedBounties` has populated.

New handler `loadArchivedBounties` (useCallback):
- Idempotent early returns: `archivedLoadState === "loaded" && archivedError === null` OR `archivedLoadState === "loading"` → return.
- Otherwise: `setArchivedLoadState("loading"); setArchivedError(null)`, open fresh WS via `openClaudeSessionSocket`, send `identity:list-bounties` with `includeArchived: true` on onopen, populate `archivedBounties` + set `loaded` on the first `identity:bounties` response, close the WS.
- Failure (onerror or onclose-before-response): `setArchivedError("Failed to load archive")`, `setArchivedLoadState("unloaded")`, AND `setArchiveAccordionValue("")` to programmatically close the accordion so the next trigger click fires `"" → "archive"` (Radix only invokes onValueChange on value changes, so the accordion must be closed for the retry to work).

Archive Accordion gate:
- Old: `hasArchive && (<Accordion>...</Accordion>)` — accordion hidden when no items on frontend.
- New: `(archivedLoadState !== "loaded" || hasArchive) && (<Accordion>...</Accordion>)` — always renders unless we've CONFIRMED empty. Rationale: user must have a click target to trigger the load.

Empty-state branch (`!hasOpen && !hasArchive`) tightened to `!hasOpen && !hasArchive && archivedLoadState === "loaded"` — otherwise the whole Bounties tab body would collapse to the empty message and hide the accordion.

Accordion element itself now controlled (`value={archiveAccordionValue}` + mirrored `setArchiveAccordionValue(val)` inside `onValueChange`) so the failure path can programmatically close the accordion.

Trigger label — 4-way conditional:
- `archivedError !== null` → `Archive (failed to load — click to retry)`
- `archivedLoadState === "loading"` → `Archive (loading…)`
- `archivedLoadState === "loaded"` → `Archive (N)`
- (unloaded, default) → `Archive`

Seven write-then-refetch mutation handlers each:
1. Compute `const archiveLoaded = archivedLoadState === "loaded";`
2. Include `includeArchived: archiveLoaded` in the outgoing payload.
3. Gate `setArchivedBounties(res.archivedBounties)` on `if (archiveLoaded)` — otherwise `res.archivedBounties` is `[]` by design and setting it would clobber the (also-`[]`) local state, but the gate keeps the seam clean and prevents future races if a mutation refetch overlaps a lazy-load.

### Byte-level behavior change on the REMOTE open path (documented, not a regression)

Not a deviation from the plan (Test 6 explicitly locks this), but worth flagging: pre-fix, both open and archive commands were inside a `Promise.all([...])` where each had its own `.catch(() => "")`. Post-fix, when `includeArchived=false`, the open command runs standalone WITHOUT `.catch(() => "")`. A genuine open-side failure (SSH exec timeout, host down) now propagates as an error instead of silently returning an empty bounties list. This is a Rule 2 correctness improvement — the old behavior was accidental (inherited from the parallel-race scaffolding), not intentional. When `includeArchived=true`, the archive path keeps its `.catch(() => "")` per Ashley's constraint.
