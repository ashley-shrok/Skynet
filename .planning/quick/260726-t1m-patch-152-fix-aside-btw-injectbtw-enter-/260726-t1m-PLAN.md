<objective>
Patch #152 — fix aside /btw injectBtw Enter absorbed by Claude Code v2.1.150 REPL paste-mode.

Split the current single `execCommand` in `injectBtw` (which sends `tmux send-keys -t <target> "<full BTW_PROMPT>" Enter` in ONE call — ~300 chars that the Ink REPL treats as a paste, absorbing the trailing Enter into the paste buffer) into TWO separate `execCommand` invocations with a 200ms delay between them. Call #1 sends the BTW_PROMPT text only. Call #2 sends `Enter` alone as a distinct keystroke that arrives AFTER Claude Code's paste-buffer flushes.

Purpose: With the current single-call shape, text lands in Claude Code's input box but /btw never submits — the overlay never opens and the aside pipeline never fires. Reproduced 2026-07-26 against Claude Code v2.1.150; fix verified working live (/btw overlay opens + Haiku begins Answering). This is the ONLY change needed — the rest of the aside subsystem (poller, extractor, WS dispatch, cross-tab broadcast, connect-time re-attach probe) all work correctly.

Output: Two-line source diff to `injectBtw` (plus explanatory comment + small `__injectBtwForTests` re-export test seam) and a new vitest describe block that pins the two-call shape so a future refactor cannot silently regress back to the one-call form. Build + test only — DO NOT deploy (this fix will bundle into the Phase 14 batch deploy of patches #150 A + #150 C + #151 + #152 pending separate Ashley greenlight).
</objective>
