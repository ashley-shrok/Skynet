<objective>
Retire the pin pruner from updateOpenTabs so conversation-list pins persist across deploys (WebSocket reconnect races) regardless of transient openTabs/fleetSessions state. Ashley: *"Pins are pins. Doesn't matter if they are open or anything else."*

Purpose: On deploy, the WebSocket disconnects and reconnects. updateOpenTabs and updateFleetSessions fire with partial/empty data before all managed hosts re-report. In that transient window the pruner nukes legitimate pins from the in-memory Set. Ashley's next pin/unpin action then writes the pruned Set back to the server via `putPinnedIds`, making the loss durable. The render-side skip in computeSnapshot Tier 2 (L639-675) already handles orphan pin ids gracefully — keeping an orphan pin id in the Set costs nothing at render time and lets the pin re-appear the moment the session comes back. Pruning is redundant.

Output: `src/ui/state/conversation-store.ts` with the pruner block deleted (net-negative-lines change) + `src/ui/state/conversation-store.test.ts` with the pruner-anchored tests deleted or re-anchored to the new invariant. `fleetSessionsLoaded` flag machinery preserved end-to-end.
</objective>
