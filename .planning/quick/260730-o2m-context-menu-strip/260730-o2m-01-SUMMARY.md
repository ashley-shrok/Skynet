## Tests: `PrettyConversationRow.test.tsx`

Was 23 `it()` blocks. Now **27 `it()` blocks**.

### Rewritten / augmented tests

- **Test 8** (`desktop pin click via context menu`): pre-strip this test
  queried a `[data-testid="pin-action"]` element and clicked it. Post-strip,
  the assertion dispatches `fireEvent.contextMenu(body, {clientX, clientY})`
  on the row body, uses `screen.getByRole("menuitem", { name: /pin/i })` to
  find the Pin item in the portal, clicks it, then asserts `onTogglePin`
  called once and `onSelect` not called. Inline note documents jsdom BCR
  zero-quirk (no viewport clamp fires in jsdom).
- **Test 10** (`pinned desktop row → context menu carries Unpin label`):
  pre-strip asserted `[data-testid="pin-action"]` presence on a `pinned=true`
  row. Post-strip, keeps the `pinned` class assertion on the row body
  (CSS-driven visual state, independent of the pin action's location) and
  swaps the pin-in-DOM check for a contextmenu → `within(menu).getByRole
  ("menuitem", { name: /unpin/i })` assertion — proves the pinned state
  flows through to the menu label correctly.
- **Test 7b** (`desktop RDP row carries rdp class + no PinAction + no
  onContextMenu wiring`): existing pin-null assertion preserved. Added an
  assertion that dispatching `fireEvent.contextMenu(body, …)` on a desktop
  RDP row does NOT open a portal menu (RDP guard on `onContextMenu` prop
  survives).

### New tests

- **Test 18c** (`desktop non-RDP row has NO PinAction and NO DeactivateAction
  in .pv-meta`): direct regression guard for the strip. Renders with
  `pinned=true`, `inActiveSet=true`, `onDeactivate={vi.fn()}` (which
  pre-strip would have rendered BOTH icons); asserts both testids null in
  container.
- **Test 18d** (`desktop contextmenu opens Pin + Deactivate items when
  inActiveSet + onDeactivate provided`): renders desktop active-set row,
  dispatches contextmenu, uses `within(menu).getByRole("menuitem")` for
  both Pin and Deactivate.
- **Test 18e** (`desktop contextmenu opens Pin only when !inActiveSet`):
  mirrors the source's `if (inActiveSet && onDeactivate) items.push(…
  Deactivate)` predicate — asserts Deactivate is absent from the menu
  when the row is not in active-set.
- **Test 18f** (`mobile row body does NOT wire onContextMenu`): mobile-
  untouched regression guard. Dispatches contextmenu, asserts
  `screen.queryByRole("menu")` is null AND the mobile swipe-strip
  PinAction is still present.

## Tests: `PrettyConversationContextMenu.test.tsx` (NEW)

Fresh file. **13 `it()` blocks** in 8 `describe` groups:

1. Portal mount: `document.body.contains(menu)` true; `container.contains
   (menu)` false.
2. No-clamp positioning: `menu.style.left/top` reflect (x, y) verbatim
   when jsdom BCR zeros → no viewport clamp fires.
3. Right-edge clamp: BCR stubbed to 200×40, x=900 → clamped left = 816.
4. Bottom-edge clamp: BCR stubbed to 200×40, y=730 → clamped top = 720.
5. Escape dismiss: `fireEvent.keyDown(window, { key: "Escape" })` → onClose
   called once (component's window-level capture-phase listener catches it).
6. Outside-mousedown dismiss: `fireEvent.mouseDown(document.body)` → onClose
   called once (predicate `!menuRef.current.contains(document.body)` holds).
7. Inside-mousedown no-dismiss: `fireEvent.mouseDown(menu)` → onClose NOT
   called (menu contains itself).
8. Item click — Pin path: click Pin, `itemPinClick` called once,
   `itemDeactivateClick` NOT called, `onClose` called once.
9. Item click — Deactivate path (mirror of #8).
10. Danger styling: `danger=true` → `item.style.color === "rgb(255, 154,
    138)"` (jsdom normalizes `#ff9a8a` to rgb).
11. `hue=45` → raw `style` attribute contains `--pv-id-hue: 45`.
12. `hue` omitted → no `--pv-id-hue` in raw style attribute.
13. `hue={null}` → no `--pv-id-hue` in raw style attribute.
