## Implementation Decisions (LOCKED — do not revisit)

### Feature spec (Ashley bounty premise)
- A **"+"** button in the compose box aux-button row (Row 1) ADDS an additional textarea below the primary. Each added textarea = a "queue slot" with its own text, its own send button, its own delete (X) button, its own mic wiring.
- Queue slots stack vertically **ABOVE Row 2** (the primary compose bar). Oldest at top, newest at bottom (visually adjacent to primary).
- Each queue slot behaves EXACTLY like the primary EXCEPT:
  * On successful send (via Send button OR mic Send), the slot DISAPPEARS.
  * Each slot has a delete (X) button to drop without sending.
- Mic wiring on each slot mirrors primary: MicButton visible when `voice.state==="idle"`, RecordingControls (cancel/append/send) take over during recording of THAT slot, transcribing shows a disabled Loader. Only ONE recording active at a time (global voice hook — this is a natural constraint, not a bug to fix).
- ⚠️ **Persistence is a HARD requirement** (bounty spec): queue-slot text is cached the same way the primary compose draft already is (patches #57 + #119 — server-side per (userId, hostId, tmuxSession) via `/compose-drafts`, plus localStorage mirror for belt-and-suspenders, plus keepalive PUT on pagehide/visibilitychange, plus 10s retry loop for dirty state). Switching devices, page reloads, container recreates MUST NOT lose queued text.

### Implementation approach (LOCKED — do not redesign)

1. **Extend `compose_drafts` table with a `queue_slots` TEXT column** — JSON-encoded `[{"id":"...","text":"..."}]`, `NOT NULL DEFAULT '[]'`. Zero new endpoint; same GET/PUT/upsert path adds a second field alongside `body`.
2. **Backend**:
   - `src/backend/database/db/schema.ts` gets the column.
   - A Drizzle migration lands under `src/backend/database/migrations/` (follow the existing migration pattern in that folder).
   - `src/backend/database/routes/compose-drafts.ts` extends GET to return `{ body, queueSlots }` (parse JSON, default to `[]` on parse failure), extends PUT to accept `queueSlots` (validate: must be an array of `{id: string, text: string}`; on invalid JSON or shape, `400`).
3. **Frontend wire types**: `src/ui/api/compose-drafts-api.ts` — `ComposeDraft` becomes `{ body: string; queueSlots: Array<{id: string; text: string}> }`; `putComposeDraft` takes both.
4. **`src/ui/features/pretty-view/ComposeBox.tsx`**:
   - Add local state: `queueSlots: Array<{id: string; text: string}>` + `micTarget: "primary" | string`.
   - **"+" button** in the Row 1 aux-button row (leftmost) with `Plus` from `lucide-react`, `title="Add queued message textarea"`. Same button-styling template as the existing aux buttons (ListPlus/Hourglass/etc — warm-neutral gradient, `#165` mobile size bump `max-md:size-12 [&_svg]:max-md:size-6`).
   - **Queue-slot stack** renders in a new `<div className="flex flex-col gap-2">` BETWEEN Row 1's closing `</div>` and Row 2's opening comment. Each slot uses the same Textarea styling as the primary (`bg-[rgba(10,12,20,0.5)]!` etc). Delete X at `absolute left-1 bottom-0.5`. MicButton at `right-11 bottom-0.5` when `voice.state==="idle"`. RecordingControls OR Send button at `right-1 bottom-0.5` (mutex — only one at a time).
   - **Real send**: queue-slot Send button and mic Send BOTH route through the existing `onSend(text)` handler prop (same D-50 newline collapse, same COMPOSE-04 hard-lock, same errorMessage-on-failure). On `onSend` returned `true`, remove the slot; on `false`, keep the slot + surface the "Not connected" error (mirror primary's `handleSend` error handling).
   - **Empty-text guard**: queue-slot Send button is disabled when `slot.text.trim() === ""` (mirrors primary's send-disable).
   - **Voice handlers become target-aware**: `handleVoiceAppend(target)` and `handleVoiceSend(target)` where `target = "primary" | slot.id`. Route transcript to the correct target. `beginRecord(target)` = `setMicTarget(target); voice.start()` (plain function, no `await` before `voice.start` per D-16-02 iOS Safari constraint — `setMicTarget` is a synchronous setState, no microtask, safe to precede `voice.start()`).
   - **Persistence wiring**: extend EVERY existing persistence site to include `queueSlots` — hydrate on mount (GET returns queueSlots, seed state), debounced 400ms autosave (PUT includes queueSlots on any change), onBlur flush (include queueSlots), pagehide/visibilitychange keepalive (include queueSlots), 10s retry loop (dirty tracking for queueSlots too), localStorage mirror per patch #119 (mirror both body AND queueSlots under the same key namespace — extend the LS payload to `{body: string, queueSlots: [...]}`). Successful primary-send clears `body` per the current rule; queue-slot send clears THAT slot from `queueSlots` (which the debounced autosave then persists).
