# Phase quick-260720-7m1 Plan 01: Broaden Harness-Wrapper Filter (Patch #97) Summary

**One-liner:** Strip-all-known-wrappers filter in session-file-parser catches combined `<system-reminder>` + `<task-notification>` relay wake turns that bypassed the old strict startsWith/endsWith check and were resetting the patch #96 scroll anchor.

## What Was Built

Replaced the strict `startsWith`/`endsWith` harness-wrapper filter (lines 232-240 of `session-file-parser.ts`) with a strip-all-known-wrappers approach. The new logic:

1. Strips every `<task-notification>[\s\S]*?<\/task-notification>` block (global, non-greedy, dotall)
2. Strips every `<system-reminder>[\s\S]*?<\/system-reminder>` block (same)
3. Trims whitespace from the remainder
4. If remainder is empty string — skip with `why: "harness_wrapper"`
5. Otherwise falls through (user speech mixed with wrappers is preserved)

The patch #86 image-bypass (`imageRefs.length === 0` outer guard) is preserved unchanged — image-bearing turns bypass the wrapper skip regardless of text content.

## Why This Matters

Combined harness turns (`<system-reminder>` + `<task-notification>` in same user-role event) were bypassing the old filter and reaching pretty-view as user-role messages. These spurious user-role events updated the patch #96 clamp-anchor's `lastUserEventId`, turning it into a moving target under rapid-fire relay wakes. The scroll ceiling had nothing stable to pin against, breaking the patch #96 scroll model. This fix restores anchor stability.
