Final `handleSend` shape (target):

```
const handleSend = useCallback(
  async (item: MessageQueueItem) => {
    await flushDirty(item.id);

    const text = item.body;
    if (!text.trim()) return;
    const collapsed = text.replace(/\r?\n/g, " ");
    setSendingId(item.id);
    const ok = onSend(collapsed);
    if (!ok) {
      setSendingId(null);
      setError("Terminal not connected — message not sent");
      return;
    }
    // Keepalive DELETE — survives tab close mid-send, cannot leave a
    // ghost item on reload the way an axios call cancelled by unload
    // would. Fire-and-forget; local state update is authoritative.
    deleteMessageQueueItemKeepalive(item.id);
    setItems((p) => {
      const next = p.filter((it) => it.id !== item.id);
      if (next.length === 0) onClose?.();
      return next;
    });
    setSendingId(null);
  },
  [onSend, flushDirty, onClose],
);
```

**Change 4 — periodic interval retry in
`src/ui/features/terminal/MessageQueueDrawer.tsx`.**

Add a new `useEffect` immediately after the pagehide/visibilitychange
effect (which ends around line 125 currently — insert this new effect
right before the unmount-cleanup effect at what is currently line 131).

The new effect:

```
// Failed saves put the body back in dirtyBodiesRef with no timer.
// Without this interval, those bodies would only get another chance on
// the next keystroke (which resets a new debounce) or on pagehide/
// unmount. 10s interval retry closes the gap so a transient network
// blip during autosave doesn't leave a dirty body sitting until the
// user closes the tab.
useEffect(() => {
  const interval = setInterval(() => {
    for (const id of dirtyBodiesRef.current.keys()) {
      void flushDirty(id);
    }
  }, 10000);
  return () => clearInterval(interval);
}, [flushDirty]);
```

`flushDirty` is already `useCallback`'d with a stable dep
(`[clearDebounceFor]`), so this effect will not re-fire spuriously.
Snapshot `dirtyBodiesRef.current.keys()` iteration is safe — flushDirty
mutates the map by removing entries, but the iterator over `.keys()` on
a Map handles concurrent-delete-of-visited-key safely (removed-visited
keys are simply not visited again). If flushDirty re-adds a body (its
`.catch` path), the new entry will be picked up on the NEXT tick, which
is exactly what we want.
