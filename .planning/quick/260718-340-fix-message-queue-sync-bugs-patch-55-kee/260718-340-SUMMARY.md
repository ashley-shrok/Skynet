# Patch #55 — Message-queue sync bug fixes

## What shipped

- **Keepalive DELETE in `handleSend`** (`message-queue-api.ts` + `MessageQueueDrawer.tsx`):
  new `deleteMessageQueueItemKeepalive` helper uses `fetch({keepalive:true})` so a Send
  fired seconds before tab close cannot leave a ghost item on next reload. Mirrors the
  existing `flushMessageQueueItemKeepalive` (patch #49) shape exactly. Sent-pending state
  machinery is now dead code from `handleSend`'s path — left in place for minimal-diff.

- **pagehide/unmount flush loops now iterate `dirtyBodiesRef`** (not `debounceTimersRef`):
  the old loop missed the failed-and-re-queued case where `flushDirty`'s `.catch` put a
  body back with no corresponding timer. Applied to both the pagehide/visibilitychange
  effect and the unmount cleanup.

- **10s interval retry** (`MessageQueueDrawer.tsx`): new `useEffect` between the pagehide
  effect and unmount cleanup iterates `dirtyBodiesRef.current.keys()` and calls
  `void flushDirty(id)` every 10s. Closes the gap between a failed autosave and the next
  flush opportunity; interval clears on unmount.

## Files modified

- `src/ui/api/message-queue-api.ts` — new `deleteMessageQueueItemKeepalive` export
- `src/ui/features/terminal/MessageQueueDrawer.tsx` — import, handleSend rewrite, two flush-loop fixes, new interval effect
