# Phase 260720-17g Plan 01: Identity Modal Tabs + Identity Renamed from Standing Directives Summary

**One-liner:** Identity modal v2 — populate 4 placeholder tabs (Identity/History/Wakeups/Handoff) with live WS-fetched data; promote Identity to default tab position 1; remove Standing Directives.

## What Was Built

### Task 1: Backend — 4 identity-artifact WS handlers + humanizeWakeupSchedule helper

Added 4 new message handlers to `claude-session-server.ts` immediately after the existing `identity:list-bounties` block:

- **`identity:get-identity-file` → `identity:identity-file`**: reads `<root>/<key>/<key>.md` as UTF-8; ENOENT → empty markdown; errors logged with `identity_get_identity_file_error` operation.
- **`identity:get-history` → `identity:history`**: reads `<root>/<key>/history.md`; strips blank lines + `#` comments; reverses for most-recent-first; ENOENT → empty entries array.
- **`identity:list-wakeups` → `identity:wakeups`**: enumerates `<root>/<key>/wakeups/*.json`; per-file try/catch (parse failures logged with `identity_list_wakeups_parse_error`, not propagated); calls `humanizeWakeupSchedule()` for each entry.
- **`identity:get-handoff` → `identity:handoff`**: reads `<root>/<key>/handoff.md`; ENOENT → empty markdown string (frontend renders "no handoff carry" message).

`humanizeWakeupSchedule(schedule: unknown): string` helper at module scope handles `interval` (e.g. "Every 2h"), `daily` ("Daily at 14:00 (box-local)"), `weekly` ("Weekly on Mon at 14:00 (box-local)"), and unknown → "custom schedule".

All 4 handlers mirror patch #87's exact pattern: `IDENTITY_KEY_RE` validation, `process.env.IDENTITIES_HOST_DIR || path.join(os.homedir(), ".claude", "identities")` resolution, ENOENT→empty (not error), `sshLogger.info` on success, `sshLogger.error` on non-ENOENT failures, whitelisted file paths only. Wire-protocol JSDoc updated with all 4 client + server message type entries (// patch #17g: prefix).

### Task 2: Frontend — 4 WS type pairs + 4 tab component files

Extended `claude-session-api.ts` with: `Wakeup` type, `IdentityGetIdentityFilePayload`/`IdentityIdentityFileEvent`, `IdentityGetHistoryPayload`/`IdentityHistoryEvent`, `IdentityListWakeupsPayload`/`IdentityWakeupsEvent`, `IdentityGetHandoffPayload`/`IdentityHandoffEvent`. All 4 new event types added to `ClaudeSessionServerEvent` union.

Created 4 tab renderer files (each self-contained with its own loading/error/empty/ready states):

- **`IdentityFileTab.tsx`**: exports `TabState<T>` discriminated union; renders markdown via `ReactMarkdown` + `remarkGfm` + ChatMessage prose class chain (`prose prose-sm max-w-none dark:prose-invert` + prose-pre/prose-code chain); scrollable wrapper.
- **`HistoryTab.tsx`**: `parseHistoryLine()` splits on ` · ` into date/gist/slugs; 2-field and 3-field variants; fallback to raw text; renders as `<ul>` with date (mono), gist (main), slug chips (not clickable).
- **`WakeupsTab.tsx`**: renders `Wakeup[]` as cards with BountyCard glass token family (hue gradient, backdrop-blur, border, boxShadow); name + enabled on/off chip + scheduleHuman (mono) + instruction prose.
- **`HandoffTab.tsx`**: same `ReactMarkdown` scaffold as `IdentityFileTab`; empty markdown → "No handoff carry (fresh session or first run)."

### Task 3: IdentityModal wiring

Modified `IdentityModal.tsx`:
- Default `activeTab`: `"bounties"` → `"identity"`.
- 4 new independent state slots (`identityFileState`, `historyState`, `wakeupsState`, `handoffState`) initialized to `{ status: "loading" }`.
- Single `useEffect` now fires 5 parallel WS requests via `openOneShot<Req, Res>()` helper defined inside the effect. All 5 sockets closed in cleanup return.
- TabsList reordered: **Identity / Bounties / History / Wakeups / Handoff** (`value="directives"` removed entirely).
- New `TabsContent` for each: Identity renders `<IdentityFileTab>`, History renders `<HistoryTab>`, Wakeups renders `<WakeupsTab hue={hue}>`, Handoff renders `<HandoffTab>`.
- Bounties `TabsContent` block (loading skeleton / error+retry / empty state / grouped open bounties / archive accordion / `BountyCard`) preserved byte-for-byte (patch #87 behavior unchanged).
