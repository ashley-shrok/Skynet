<objective>
Patch #98 — replace the scroll-event-based user-vs-programmatic mode-flip in `useAutoScroll` with direct user-gesture listeners (wheel / touchmove / keydown-filtered-to-scroll-keys) on the scroll container.

The current implementation (from patch #96) uses a `programmaticScrollRef` counter with a double-rAF (~32ms) decrement to decide whether an incoming browser `scroll` event was user-driven or programmatic. Ashley's live diagnostic (06:07:31–06:07:44 log excerpts in the brief) proved browser scroll events can arrive 200ms+ (up to 7.9s) after a programmatic `scrollTop` write — well after the counter has decremented — causing delayed scroll events to be misclassified as user gestures, flipping mode to `user-driving`, and defeating the anchor ceiling during subsequent content growth (drift=BROKEN at 06:07:44).

Purpose: Move mode detection off the unreliable `scroll` event and onto direct user-input events, which have no delayed-arrival failure mode. Keep every other piece of the clamp-anchor state machine intact (anchor derivation, clamp rule computation, ResizeObserver dispatch, `scrollToBottomAndFollow`).

Output:
- Rewritten `use-auto-scroll.ts`: `programmaticScrollRef` removed; `doProgScroll` simplified to a bare `scrollTop = newTop`; a new gesture-listener effect attaches wheel/touchmove/keydown to `scrollEl`; `handleScroll` no longer flips mode (only keeps `isPinnedToBottom` + `followBottomRef` synced when already user-driving); header comment updated to describe the gesture-based approach.
- Rewritten `use-auto-scroll.test.ts`: Test F deleted (its subject — the counter's `passive:true` attachment — is gone); Test F' added (delayed scroll event does NOT flip mode — THE regression guard); Tests K (wheel), L (touchmove), M (keydown scroll-key parametrization + non-scroll-key negative case), N (followBottom respects distance after gesture) added. All existing tests A/B/C/D/E/G survive unchanged.
</objective>
