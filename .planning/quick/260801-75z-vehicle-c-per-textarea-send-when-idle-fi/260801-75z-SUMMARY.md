# Phase 260801-75z Plan 01: Vehicle C v2 — Per-Textarea Send-When-Idle Summary

Refactored ComposeBox's send-when-idle mechanism from patch #84's single-slot `queuedText: string | null` to a per-source FIFO queue (`Array<{source: "primary" | string, text: string}>`) keyed by textarea, with per-textarea Arm-idle buttons + click-to-cancel overlays and full removal of the aux-row Queue (Hourglass) button.

## Deviations from Plan

None — plan executed exactly as written. The plan's design spec (twelve edits) was already fully self-contained, so no auto-fixes (Rule 1/2/3) or architectural questions (Rule 4) arose. One micro-adjustment inside the plan's own scope:

- **`sendDisabled` gate migration**: The plan's Edit 11a scoped the primary Textarea's `disabled={queueArmed}` change to `disabled={primaryArmed}`, but did not explicitly call out the same migration in the neighboring `sendDisabled` predicate (~L1281, Patch #129 truth table). Under the old model `queueArmed === primaryArmed` (only one source could be armed), so leaving `sendDisabled` on `queueArmed` would have incorrectly disabled the primary Send whenever ANY slot was armed under Vehicle C v2 — contradicting the "arm N textareas, keep working" workflow the whole vehicle is designed to unlock. Updated `sendDisabled` to `primaryArmed` (source-scoped), with a comment noting the Vehicle C v2 rationale. This is a direct extension of Edit 11a's source-scoping principle applied to the neighboring predicate; not a Rule-4 architectural change.
