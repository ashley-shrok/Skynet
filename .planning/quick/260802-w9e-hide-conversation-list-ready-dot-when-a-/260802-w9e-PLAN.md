<task type="auto">
  <name>Task 1: Create session-queue-pending-store + test</name>

Create `src/ui/state/session-queue-pending-store.ts` as a near-verbatim copy of `src/ui/state/session-working-store.ts` (~125 lines) with these differences:

- Type is `Map<string, boolean>` (NOT `Map<string, boolean | null>`) — no "unknown" middle state; ComposeBox is the sole publisher and always knows.
- Publisher: `export function publishSessionQueuePending(key: string, hasPending: boolean): void`. Same no-op-notify guard shape as `publishSessionWorking` — skip notify if the key was already present AND the value unchanged.
- Hook: `export function useSessionQueuePending(key: string | null): boolean` — returns `false` for `key === null` (short-circuit) or when the key has never been published. `false` is the safe default: "we don't know if there's a queue → let the dot render" is the correct behavior.
- Test-only helpers renamed to `getSessionQueuePendingSnapshot()` and `__resetForTest()`.
- Update the docstring to describe THIS store's semantics:
  (a) module-scoped Map, in-memory only, published by ComposeBox from a `useEffect` on `[queue, sessionKey]`;
  (b) key shape `${hostId}:${tmuxSession ?? ""}` is IDENTICAL to `sessionWorkingKey()` at `src/ui/features/pretty-conversations/PrettyConversationsPanel.tsx:95-98` so consumers can look up either store with the same string;
  (c) publishing `false` OVERWRITES to `false` (does NOT delete the key), same rationale as working-store — a re-mount observing `false` after a known transition is semantically correct.

Create `src/ui/state/session-queue-pending-store.test.ts`, mirroring `src/ui/state/session-working-store.test.ts` verbatim in structure. Test cases:

- Initial `useSessionQueuePending("k")` returns `false` (unknown → false).
- `publishSessionQueuePending("k", true)` → next `useSessionQueuePending("k")` returns `true`.
- `publishSessionQueuePending("k", false)` → returns `false` (key still present, value flipped).
- `useSessionQueuePending(null)` short-circuits to `false` regardless of store state.
- No-op notify guard: two consecutive `publishSessionQueuePending("k", true)` calls produce only ONE notify tick to subscribers.
- `__resetForTest()` clears state and notifies subscribers.
- `getSessionQueuePendingSnapshot()` returns the raw internal Map for test inspection.

Adjust assertions for the boolean-not-nullable return type — the working-store tests distinguish `null` vs `false` vs `true`; this store has only `false` vs `true`.

Verify by running `npm test -- session-queue-pending-store` (all pass) and `npx tsc --noEmit` (clean).
