<objective>
Replace the raw JSON schedule textarea in WakeupsTab.tsx with a form-based
editor per the Ashley-signed-off prototype at
`~/.claude/identities/tina/bounties/identity-modal-wakeup-form-editor/prototype.html`.

- Form fields (in edit-mode): name (text), enabled (checkbox), schedule.type
  (dropdown: interval/daily/weekly/one_shot) + per-type fields, instruction
  (textarea). Live JSON preview on the right on ≥620px viewports.
- Timezone is silently detected via `Intl.DateTimeFormat().resolvedOptions().timeZone`
  (fallback `America/New_York`) — NO tz dropdown UI. Shown as a muted hint on
  daily/weekly/one_shot; OMITTED from the emitted schedule on interval.
- Backend `identity:update-wakeup` currently accepts only `{ enabled?, schedule? }`;
  this plan extends the write path (`WakeupUpdate` type + local branch +
  server-side validator + wire payload + `OnUpdate` type + `updateWakeup`
  handler) to also accept `name?: string` and `instruction?: string`. The
  remote-branch python script already merges arbitrary keys generically, so
  no shell script change is needed.
- Preserves patch #154 behavior: always-visible enabled chip + one-click
  `toggleEnabled`, `useEffect` reset on wakeup identity change (extended for
  name/instruction drafts), "Scheduler reloads every ~30s" hint, glass card
  visual, skeleton/error/empty states.

Purpose: gives Ashley a structured editor for wakeups instead of hand-writing
JSON — the schema (interval/daily/weekly/one_shot + tz) is stable enough now
that patch #154's "raw textarea because schema evolves" hedge is no longer
justified.
Output: single-component refactor + supporting backend/wire extension + new
test file WakeupsTab.test.tsx.
</objective>
