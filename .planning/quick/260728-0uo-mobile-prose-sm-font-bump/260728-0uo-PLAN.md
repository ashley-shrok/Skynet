# 260728-0uo — Mobile `.prose-sm` bump for Telegram parity

## Task boundary

On mobile viewports (`max-width: 768px`), bump `.prose-sm` font-size + line-height so message reading surfaces (ChatMessage bubbles, HandoffTab, AsideBubble, IdentityFileTab) visually match Telegram iOS body text. Explicitly NOT bumping html root — that cascades into composebox button sizes which Ashley flagged as too big at html=24 during the live tuner iteration.

## Motivation

Ashley's ask: "make font bigger across the board on mobile — match Telegram." Live tuner iteration on the running app (via `?fonttune=1` injection) landed at html=24 as her Telegram-parity number. That value cascades `.prose-sm` (which is `text-sm` = 0.875rem) to 21px, which visually matched Telegram iOS's system-body text. But at html=24, composebox buttons + surrounding layout also grew 50% and felt oversized.

Surgical fix: bump `.prose-sm` directly to 21px equivalent on mobile, leaving html at its normal 16px so layout stays unchanged.

## Task

**File:** `src/ui/index.css` (mobile media query addition, ~4-6 lines)

**Action:**
Add a `@media (max-width: 768px)` block after the existing `html.fs-*` scale rules (currently ends line 305):

```css
@media (max-width: 768px) {
  .prose-sm {
    font-size: 1.3125rem !important;
    line-height: 1.55 !important;
  }
}
```

**Why `!important`:** `@tailwindcss/typography`'s `.prose-sm` selector is 0-1-0 specificity; a media-query rule with the same selector has identical specificity and later source order should win, but the typography plugin's CSS gets injected at plugin-registration time which may come after `@import "tailwindcss"` in the compiled output. `!important` is the belt-and-suspenders guarantee. The learned preference from patch #81 (shadcn wrapper `dark:` variants beat plain overrides on specificity) applies here too — better to force it than fight the cascade.

**Why 1.3125rem (21px at html=16):** matches what Ashley's tuner selection of html=24 produced (`.prose-sm` = 0.875rem × 24 = 21px). Exact visual match to her Telegram-parity pick.

**Why line-height 1.55:** prose-sm's default line-height is 24/14 ≈ 1.714. At 21px, that's ~36px per line — vertically very loose. 1.55 keeps line-box height at ~32.5px which reads denser and better matches Telegram's message density.

**Why 768px breakpoint:** Tailwind's default `md:` breakpoint. Everything below 768px CSS px width gets the bump — covers all phones + narrow tablets in portrait. Desktop unaffected.
