<objective>
Persist the pretty-view ComposeBox draft body server-side per pane so
typed text survives page reload / Chrome crash / tab close. Storage
key is `(userId, hostId, tmuxSession)` — one draft row per pane,
tmuxSession nullable for non-tmux SSH hosts. This is fork patch #57.

Purpose: Ashley routinely composes long multi-line messages to Claude
Code sessions across many tabs; anything that eats a mid-typing state
loses real work. The message-queue drawer (patches #39/#49/#55) has
had server-side persistence + debounced autosave + keepalive flush +
10s retry for months and is battle-tested. This patch extends the
same discipline to the ComposeBox itself, mirroring that state
machine exactly.

Output:
- New backend route `/compose-drafts` (cookie-JWT auth) with GET
  and PUT (upsert) endpoints.
- New SQLite table `compose_drafts` with FK cascade on users and
  ssh_data, created via `CREATE TABLE IF NOT EXISTS` in
  `initializeCompleteDatabase()`.
- New frontend axios helpers + fetch-keepalive flush helper.
- ComposeBox gains: load-on-mount, debounced 400ms autosave,
  pagehide/visibilitychange keepalive flush, 10s interval retry,
  clear-on-send in all three send paths.
- nginx `location` blocks in BOTH configs so the route is
  reachable (the trap that bit patches #7/#17/#39/#43).

Ships as ONE atomic code commit matching prior numbered-patch style:
`feat(pretty-view): persist ComposeBox draft body server-side per pane`.
The workflow's docs commit for PLAN.md / SUMMARY.md / STATE.md is
handled separately by the `/gsd:quick` finalize step.
</objective>

               host_id INTEGER NOT NULL,
               tmux_session TEXT NOT NULL DEFAULT '',
               body TEXT NOT NULL DEFAULT '',
               updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,

       **NULL-key rationale (important):** SQLite treats NULL as
       distinct in a UNIQUE / PRIMARY KEY constraint (two rows
       with the same non-null user_id + host_id and NULL
       tmux_session would BOTH be allowed, and an upsert path
       cannot use `ON CONFLICT` to update them). To keep the
       upsert path trivial and correct for non-tmux hosts,
       coalesce NULL to the empty string `''` at the storage
       layer: the table column is `NOT NULL DEFAULT ''`, and the
       route handler maps a nullable request-level `tmuxSession`
       to `''` before insert and back to `null` on GET response
       (see route handler below). This is a widely-used SQLite
       pattern; documented at the top of `compose-drafts.ts`.

       NO migrateSchema work needed — this is a brand-new table,
       so the CREATE TABLE IF NOT EXISTS path in
       `initializeCompleteDatabase()` is sufficient (matches how
       patch #39 landed message_queue_items).
