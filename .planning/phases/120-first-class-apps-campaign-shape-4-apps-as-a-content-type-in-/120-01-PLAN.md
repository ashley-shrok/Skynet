<objective>
Build the two pure-function backend leaves that Wave 2's app-pane router will compose: (per D-13) the Origin-check middleware pure helper `appProxyCsrfCheck` that enforces same-origin on state-changing HTTP methods at the proxy boundary, and (per D-11) the HTML-body transform `injectBaseTag` that Wave 2's proxy `responseInterceptor` invokes to prepend `<base href="/apps/:hostId/:slug/pane/">` into text/html responses so that absolute-path references in the app's HTML/JS resolve correctly under the pane path prefix.

Purpose: These two helpers are stateless, testable in isolation, and share no runtime state with the proxy factory or the router — landing them first gives Wave 2 tested primitives to import.

Output: Two `.ts` modules under `src/backend/apps/` + two `.test.ts` modules under `src/backend/apps/tests/`, all new files with no dependencies on other Phase 120 code.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Skynet proxy | Cross-origin state-changing requests could arrive at `/apps/:hostId/:slug/pane/*` if not gated at proxy boundary. |
| Proxy → Upstream app | Any header not on `HEADER_ALLOWLIST` must NOT reach the app (Cookie / Authorization / X-Skynet-* protection). |
| Proxy → Browser (response body) | HTML response body is rewritten; non-HTML must pass unchanged. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-120-01 | Spoofing / Tampering | `app-proxy-csrf-check` | mitigate | Origin-header exact-string comparison against `PRIMARY_DOMAIN`; state-changing methods only (RFC 9110 §9.2.1 idempotent+safe methods bypass); missing Origin on state-changing method refused (D-13). |
| T-120-02 | Information disclosure | `PRIMARY_DOMAIN` module load | mitigate | Fail-loud IIFE throws at module load when `SKYNET_COOKIE_DOMAIN` env var is unset — prevents silent misconfiguration where check would compare against empty string. |
| T-120-03 | Tampering (data corruption) | `injectBaseTag` on non-HTML content | accept | Content-Type gating is the CALLER's responsibility (Plan 02 factory); `injectBaseTag` is an unconditional transform. Caller-side regression test covers content-type gating. Attempting to gate in both places doubles the audit surface. |
| T-120-04 | Tampering | Slug URL characters in `<base>` href | mitigate | `encodeURIComponent(slug)` applied unconditionally — slugs containing `/`, `?`, `#`, or whitespace cannot break out of the intended URL path segment. `APP_SLUG_RE` at Wave 2's route entry provides defence-in-depth. |
| T-120-05 | Denial of Service | `injectBaseTag` on huge HTML bodies | accept | `responseInterceptor` (Plan 02) buffers full body before invoking this helper; a hostile app could flood a large body. Existing `serve-url` machinery inherits the same DoS surface; no new exposure introduced here. Mitigation would require chunked streaming which is out of scope. |
| T-120-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages installed — Package Legitimacy Gate not applicable per RESEARCH.md § Package Legitimacy Audit. |
</threat_model>
