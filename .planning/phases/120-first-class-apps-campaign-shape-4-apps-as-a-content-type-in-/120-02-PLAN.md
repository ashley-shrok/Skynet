<objective>
Build the app-pane proxy factory (per D-09 sibling, NOT fork, of `proxy-factory.ts`) and the pane-target resolver (per D-10 local-loopback-vs-SSH-tunnel decider). The factory composes existing Phase 103 machinery — `HEADER_ALLOWLIST`, `stripToAllowlist`, `classifyTunnelError`, `interstitial.ts`, the RSV1 WebSocket fix — with two additions unique to the pane path: (a) a per-`(hostId, slug)` cache key (per RESEARCH.md Pitfall 2 — reusing the shared `getOrCreateProxyForTarget` would collide on `pathRewrite`) and (b) a `responseInterceptor` proxyRes hook that gates on Content-Type and delegates to Wave 1 Plan 01's `injectBaseTag` for the D-11 `<base>` injection.

Purpose: These two modules are the second half of the backend leaves layer. They are pure factory + pure helper — no route mount, no auth middleware. Wave 2 Plan 05 composes them into the actual route.

Output: Two `.ts` modules under `src/backend/apps/` + two `.test.ts` modules under `src/backend/apps/tests/`, all new files. All existing `serve-url/*` files are READ-ONLY reuse.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Skynet (via proxy) | HTTP + WebSocket bytes; response body gets HTML rewritten. |
| Skynet → Upstream app (via tunnel or loopback) | Only allowlisted headers forwarded; Cookie/Auth/X-Skynet-* stripped. |
| SSH tunnel → App's home box | Encrypted transport; managed by existing `tunnelCache`. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-120-06 | Information disclosure | `stripToAllowlist` on `proxyReq` and `proxyReqWs` hooks | mitigate | Default-deny allowlist inherited from `HEADER_ALLOWLIST` (proxy-factory.ts D-04); Cookie/Authorization/X-Skynet-* never reach upstream. Test asserts this via mock proxyReq capturing removeHeader calls. |
| T-120-07 | Denial of service | WS upgrade RSV1 permessage-deflate malfunction | mitigate | `proxyReq.setHeader("sec-websocket-extensions", "")` on `proxyReqWs` — R&D Gotcha 1 fix inherited verbatim from `proxy-factory.ts`. Test asserts exact setHeader call. |
| T-120-08 | Tampering (data corruption) | `responseInterceptor` on non-HTML content | mitigate | Content-Type prefix check via `.startsWith("text/html")` — JSON/JS/binary responses pass through unchanged. Both positive (HTML → injected) and negative (JSON → unchanged) cases exercised in tests. |
| T-120-09 | Tampering | Per-slug proxy cache-key collision (Pitfall 2) | mitigate | Cache key includes `${hostId}:${slug}` suffix so different apps on the same host+tunnelPort get distinct middleware with distinct pathRewrite rules. Three cache-key tests exercise the hit and both miss paths. |
| T-120-10 | Information disclosure | Error logging in `on.error` hook | mitigate | Only `.message`/`.code`/`.name`/`.level` fields extracted from thrown error — never `.stack`, never request headers, never user identifiers. | T-120-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages installed. |
