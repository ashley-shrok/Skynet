<objective>
Extend the tab-persistence layer with a nullable `app_slug` column on `user_open_tabs` so app-tab tuples `(hostId, slug)` survive reload via the backend DB path (per D-16 + D-02 + RESEARCH.md Runtime State Inventory). Add the Drizzle mirror, the idempotent runtime migration (matching the Phase 90 `target_tmux_session` addition), and extend the POST/PUT/GET open-tabs routes to read/write the new field. Nullable + optional so legacy rows and non-app tabs continue to parse without error (mirror of Phase 90 `sessionKind` backward-compat rule).

Purpose: Without this schema extension, Phase 120's app tabs restore only from the URL fragment (Plan 04 covers that path). The DB-restored path silently drops the slug and app tabs re-open with `undefined` slug, producing 400s from the proxy's `APP_SLUG_RE` gate on next request. This plan closes that gap.

Output: One new column in the schema + migration + three route handlers extended. No new files created.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → API (POST/PUT /open-tabs) | Authenticated request writes user-owned tab records. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-120-13 | Tampering | SQL injection in `appSlug` column write | mitigate | Drizzle ORM parameterises all `values({...})` inserts — the SQL boundary uses `?` placeholders, never string concatenation. `grep -c '\\$\\{appSlug\\}' src/backend/database/routes/open-tabs.ts` returns 0 (no template-literal SQL concat). |
| T-120-14 | Tampering | Malicious client submits slug that fails `APP_SLUG_RE` at the proxy | accept | The proxy route (Plan 05) enforces `APP_SLUG_RE` at request entry — a persisted malformed slug would fail-loud at next request. Persistence layer accepts any string per RESEARCH.md discipline (no double-validation). |
| T-120-15 | Information disclosure | GET /open-tabs returning `appSlug` to another user's session | mitigate | Existing user-scoping on the GET query (`WHERE userId = ?` — verify preserved by `grep -c 'userId' src/backend/database/routes/open-tabs.ts` remains at its prior count). No new information-disclosure surface. |
| T-120-16 | Denial of service | Unbounded-length `appSlug` in POST body causing DB row bloat | accept | SQLite TEXT has no length constraint at the schema layer; the frontend and proxy enforce `APP_SLUG_RE` (max 64 chars). A malicious authenticated client could bypass and persist a longer string, but the resulting tab would fail the proxy's regex on next request and be unusable. Effective attack surface: one user filling their own DB rows — bounded impact. |
| T-120-17 | Data integrity | Legacy rows without `app_slug` column fail to load after migration | mitigate | `addColumnIfNotExists` runs before any Drizzle SELECT — the column exists (defaulting to NULL) before any read. Idempotent SELECT-probe-then-ALTER shape guarantees the column is present after boot. Existing schema.ts `text("app_slug")` field returns `null` for NULL rows. |
| T-120-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages installed. |
</threat_model>
