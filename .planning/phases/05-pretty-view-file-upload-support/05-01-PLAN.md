<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser client → terminal WS | Untrusted client sends `upload_start` metadata (filename, size, mimetype) and `upload_chunk` bytes. Client is the human's browser but must be treated as adversarial (CSRF-forgeable metadata, malicious filenames, disk-fill payloads). |
| Termix backend → receiving box SFTP | Backend writes to `$HOME/pretty-view-uploads/`. The receiving box's filesystem is the trust asset. |
| Injected user turn → agent's tmux pane | The message injected via patch #60/#100 path contains attacker-influenced strings (filename, caption). Delimiter-collision could confuse the agent about caption boundaries. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Tampering (path traversal) | `handleUploadStart` filename sanitization | mitigate | Strip `/`, `\`, null bytes; reject leading `.`; reject `..`; reject any filename containing path separators after sanitization; enforce sanitized name matches `/^[^\/\\\x00]+$/` and length ≤ 200; on failure emit `upload_failed` with reason `"invalid_filename"` and NEVER open a write stream |
| T-05-02 | Tampering (symlink write) | SFTP write path | mitigate | Use `sftp.createWriteStream(tempPath, { flags: 'wx' })` — `wx` = fail if exists — so we never open an existing symlink; landing dir is under `$HOME` (resolved via `sftp.realpath('.')` at upload_start, NEVER string-concatenated with hardcoded `/home/...`); temp file is created with a random suffix that cannot collide with a pre-planted symlink |
| T-05-03 | Denial of Service (disk-fill) | `handleUploadStart` size validation | mitigate | Reject at `upload_start` if any `files[].size > MAX_PER_FILE_BYTES` (500 MB per CONTEXT.md recommendation) or `sum(files[].size) > MAX_PER_BATCH_BYTES` (2 GB per CONTEXT.md); the client-declared `size` is enforced during chunk streaming via a running `bytes_received` counter — chunks that push the total past the declared size are rejected with `upload_failed` reason `"size_overflow"` and the temp file is unlinked |
| T-05-04 | Information Disclosure (mimetype spoofing) | Injected metadata block | accept | Server MUST NOT trust client mimetype for security decisions. The mimetype is echoed into the injected metadata block AS-IS for informational purposes only (agent's canonical "filenames + mimetypes are untrusted" posture handles downstream). No content sniffing — the feature never acts on file contents. |
| T-05-05 | Injection (WS message → tmux pane) | `formatInjectedUserTurn` delimiter | mitigate | The metadata block delimiter is `--- attached files ---`. Sanitization at `upload_start` rejects any filename containing the substring `--- attached files ---` OR any line that starts with `--- ` (belt-and-suspenders). Emit `upload_failed` reason `"delimiter_collision"` on match. Locked delimiter never changes without a coordinated migration. |
| T-05-06 | Injection (prompt injection via filenames) | Injected metadata block | accept | Filenames are attacker-influenced strings reaching the agent. Shared responsibility: this plan writes filenames verbatim into the metadata block; the agent's canonical "user inputs (including filenames) are untrusted" guidance handles downstream. No client-side filename mangling beyond the path-traversal / delimiter-collision rejections above. |
| T-05-07 | Spoofing (CSRF / unauthenticated upload) | terminal WS handler auth gate | mitigate | The three new `case` blocks (`upload_start`, `upload_chunk`, `upload_abort`) all guard on the same `sshConn && userId && currentSessionId` state the existing `case "input":` requires. Any of the three arriving on an unauthenticated / disconnected WS is silently ignored (no reply — matches existing `case "input":` posture). No new auth surface. |
| T-05-08 | Tampering (chunk out-of-order / overlapping writes) | SFTP write stream | mitigate | Each `tempId` maps to at most ONE active `sftp.WriteStream`; chunks arriving with an unexpected `offset` (not equal to the stream's next expected byte count) are rejected with `upload_failed` reason `"chunk_out_of_order"` and the temp file is unlinked. The client is the sole author of chunk order per its own file-read loop, so this catches only bugs / attackers. |
| T-05-SC | Tampering | npm/pip/cargo installs | mitigate | This plan adds ZERO new dependencies — `ssh2` and its SFTP subsystem are already in the fork's dep tree (used by `file-manager-*.ts`, `host-transfer.ts`). No package.json edit required. Slopcheck N/A. |

## Assets Protected

- **Receiving box $HOME writability** — path-traversal (T-05-01), symlink write (T-05-02), and disk-fill (T-05-03) all guard the receiving box's filesystem against a malicious or misbehaving client.
- **User's active SSH session credentials** — no new auth surface (T-05-07); the upload rides the already-authenticated per-pane WS.
- **The injected user turn's semantic integrity** — delimiter-collision (T-05-05) protection ensures the agent cannot be tricked into misreading where the user's caption ends and the metadata block begins.
