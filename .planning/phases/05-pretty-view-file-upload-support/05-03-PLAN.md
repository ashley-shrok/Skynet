## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Injected user turn → agent (via tmux pane) | The text produced by `formatInjectedUserTurn` (caption + metadata block) is sent through the SAME `sendInput` seam patches #60 + #100 use. The tmux pane's Claude Code REPL sees it as user-typed input. Attacker influence: uploaded filenames + user's own caption. |
| Tailed JSONL → pretty-view render (ChatMessage) | The session tail's MessageEvent may carry a user-role message whose content is an injected turn. ChatMessage parses that content client-side to extract chip metadata. Parser bug could crash the render or misattribute chip metadata to a legitimate user message whose text coincidentally starts with the delimiter. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-09 | Injection (delimiter false-match) | ChatMessage parseInjectedUserTurn | mitigate | Parser requires the FULL exact injected-turn shape to match: the INJECTED_DELIMITER must appear on line 3 (index 2 after splitting by `\n`), preceded by an empty separator line (index 1), preceded by the caption (index 0 — may itself be multi-line, so the parser scans forward from the top for the FIRST occurrence of `\n\n--- attached files ---\n` as a two-line delimiter, not just the delimiter string alone). If the pattern does not match exactly, render as a normal user message (fall through — no chip strip). A user typing the exact delimiter substring in their normal caption is possible but harmless — the parser correctly recognizes that as caption content since the trailing file lines will not match the strict `^\d+\. .+ \(.+, .+\) → .+$` pattern. | T-05-10 | Tampering (WS message forgery — legitimate user turn injected with fake chips) | Injected-turn detection in ChatMessage | accept | The pretty-view render trusts the tailed JSONL. Rendering fake chips does not grant read/write access to any file the agent didn't already know about via its own tool_use calls. |
| T-05-11 | Denial of Service (regex catastrophic backtrack in parser) | parseInjectedUserTurn | mitigate | Use `.split('\n')` and per-line linear scans; NEVER a regex that could backtrack on a malicious input. Length-bound the parse: bail if content > 1MB (an injected turn with 32 files at reasonable filename+path lengths is well under 100KB; anything larger is not a legitimate injected turn). |
| T-05-SC | Tampering | npm/pip/cargo installs | mitigate | Zero new dependencies. No package.json changes. Slopcheck N/A. |

```
} | null {
  if (content.length > 1024 * 1024) return null;  // length bound (T-05-11)

  const marker = `\n\n${INJECTED_DELIMITER}\n`;
  const idx = content.indexOf(marker);
  if (idx === -1) return null;

  const caption = content.slice(0, idx);
  const after = content.slice(idx + marker.length);
  const lines = after.split('\n');

  // File lines come in pairs: index 0 = `N. filename (humanSize, mimetype) → landingPath`, index 1 = `   uploaded <timestamp>`
  // Iterate pairs; require at least ONE valid pair for the parse to succeed.
  const files: Array<{filename: string; size: number; humanSize: string; mimetype: string; landingPath: string; uploadTimestamp: string}> = [];
  const FILE_LINE_RE = /^\d+\. (.+) \((.+), (.+)\) → (.+)$/;
  const TS_LINE_RE = /^\s+uploaded (.+)$/;

  let i = 0;
  while (i < lines.length - 1) {
    const fileMatch = lines[i].match(FILE_LINE_RE);
    if (!fileMatch) break;
    const tsMatch = lines[i + 1].match(TS_LINE_RE);
    if (!tsMatch) break;
    const [, filename, humanSize, mimetype, landingPath] = fileMatch;
    const [, uploadTimestamp] = tsMatch;
    // size is not recoverable from humanSize losslessly (e.g. "1.0 KB" → 1024 or 1000 depending on formatter)
    // Store humanSize verbatim; use 0 for size (chip render uses humanSize anyway).
    files.push({ filename, size: 0, humanSize, mimetype, landingPath, uploadTimestamp });
    i += 2;
  }

  if (files.length === 0) return null;
  return { caption, files };
}
```

Note: `size` cannot be losslessly parsed back from `humanSize`. The chip render uses `humanSize` directly, so `size: 0` is a placeholder. If any downstream code needs the true size, it should pass the file record through from the source. Document in JSDoc.
