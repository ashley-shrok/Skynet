<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Docker image build → runtime | pool.json is baked in at build time; not user-mutable at runtime |
| Filesystem → loader | ENOENT and malformed JSON must not crash the process |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-80-01-01 | Tampering | `/app/pool-defaults/pool.json` at runtime | accept | File lives inside Docker image; only container-root attacker can modify (same threat surface as branding-defaults; documented risk parity) |
| T-80-01-02 | Denial of Service | Loader throws on malformed input causing cascading 500s | mitigate | Loader wraps every failure branch (ENOENT, JSON.parse SyntaxError, shape mismatch, non-string entries) and returns `[]`; NEVER re-throws (unit-tested) |
| T-80-01-03 | Denial of Service | Attacker floods pool-pick endpoint causing repeated disk reads | mitigate | Module-scope memoization: first-call reads; subsequent calls served from `cachedPool` (unit-tested) |
| T-80-01-04 | Info Disclosure | sshLogger accidentally logs pool.json contents on parse error | mitigate | Log only the `path` and error message; do NOT include `raw` file contents in log payload (enforce via test — assert `sshLogger.error` call arg does NOT include the raw file body) |
</threat_model>
