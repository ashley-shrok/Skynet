<objective>
Swap the backend's publishing transport from web-push to ntfy, migrate the push_subscriptions table schema to the ntfy data model, and expose new routes for setup / test / regenerate / delete. Preserves the push-trigger-loop import surface (sendPushToUser) so the UNCHANGED trigger loop (per CONTEXT.md) keeps working with zero edits to its import line. Assumes plan 01's `docker/ntfy/server.yml` has already provisioned the admin user declaratively (HC-2 fix) — this plan's HTTP admin API client talks to that pre-existing identity.

Purpose: This is the backend half of the pure cutover. After this plan + plan 03 (frontend) ship together, a DM arriving at the trigger loop results in an HTTP POST to the internal ntfy container, which relays to ntfy.sh for iOS wake-up, and the preferences pane can issue + rotate reading credentials via the ntfy HTTP admin API.

Output: Rebuilt push_subscriptions schema, FieldCrypto reading_credential encryption, ntfy-admin-client runtime HTTP client, ntfy-sender publisher with null-safe deep-link builder, rebuilt push-subscriptions routes.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Skynet backend REST | JWT-authenticated; untrusted body contents until validated by Zod |
| Skynet backend → ntfy admin API (http://ntfy:2586/v1/*) | Internal Docker network; mutually trusted at network layer; token/basic auth at app layer |
| Skynet backend → ntfy publish (http://ntfy:2586/<topic>) | Internal Docker network; Bearer token auth |
| Skynet backend → SQLite (encrypted on disk via FieldCrypto for reading_credential column) | Trusted; FieldCrypto AES-256-GCM at rest |
| ntfy → ntfy.sh upstream relay (poll_request outbound) | Public internet; TLS; CONTENT not transmitted — only msgId + topic hash per protocol |
