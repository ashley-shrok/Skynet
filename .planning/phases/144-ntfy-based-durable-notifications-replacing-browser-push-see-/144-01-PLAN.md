## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Public internet → Caddy :443 | TLS termination; untrusted. (This plan adds no public path; the Caddyfile snippet documents the future `/ntfy/*` route to be applied by ship-prep.) |
| Caddy → ntfy container (:2586 internal) | Trusted internal Docker network; no auth required at the network layer — ntfy's own token auth is the gate. |
| Compose env-interpolation → container runtime | Trust boundary — missing env vars become empty strings in container env unless fail-loud guards (`:?`) are used. |
| skynet.env (file on host) → compose env → server.yml | Trusted file; secret storage. Must not be committed to git. The env.example is a non-secret template. The bcrypt hash in NTFY_ADMIN_PASS_BCRYPT interpolates into server.yml at container start. |
| Repo-committed docker/ntfy/server.yml → bind mount into container | Trusted; file contains only env-var references (`${NTFY_ADMIN_USER}` etc.) — no literal credentials in git. |
