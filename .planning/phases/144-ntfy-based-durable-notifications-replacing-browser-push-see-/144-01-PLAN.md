<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Public internet → Caddy :443 | TLS termination; untrusted. (This plan adds no public path; the Caddyfile snippet documents the future `/ntfy/*` route to be applied by ship-prep.) |
| Caddy → ntfy container (:2586 internal) | Trusted internal Docker network; no auth required at the network layer — ntfy's own token auth is the gate. |
| Compose env-interpolation → container runtime | Trust boundary — missing env vars become empty strings in container env unless fail-loud guards (`:?`) are used. |
| skynet.env (file on host) → compose env | Trusted file; secret storage. Must not be committed to git. The env.example is a non-secret template. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-144-01 | Information Disclosure | NTFY_PUBLISH_TOKEN in skynet.env.example | mitigate | env.example contains ONLY a placeholder like `NTFY_PUBLISH_TOKEN=<generated-at-first-boot>`; no real token. Verified via `! grep -E "NTFY_PUBLISH_TOKEN=tk_[A-Fa-f0-9]{29}" docker/skynet.env.example`. |
| T-144-02 | Tampering | Compose interpolation of SKYNET_PUBLISH_URL when env is unset | mitigate | Use `${SKYNET_PUBLIC_URL:?...}` fail-loud guard in compose (matches the SKYNET_HOME_MOUNT_SRC pattern at docker-compose.yml:153). Prevents silent empty-string → `/ntfy` → broken poll_request URLs (RESEARCH.md Pitfall 4). |
| T-144-03 | Denial of Service | ntfy container crash-loops if cache.db/auth.db are not persisted | mitigate | Named `ntfy-data` volume mounted at `/var/lib/ntfy` ensures both files survive container recreation. Verified by task 1 acceptance. |
| T-144-04 | Information Disclosure | Content of DMs leaking through ntfy.sh upstream | accept | ntfy's upstream relay protocol sends only msgId + topic hash (verified in RESEARCH.md Q12 against ntfy source). Content is private by protocol design. Accepted trust posture per CONTEXT.md "Content stays private; metadata is visible to ntfy.sh." |
| T-144-05 | Elevation of Privilege | Boot-time missing creds cause silent degraded operation (ntfy container up but Skynet can't publish) | mitigate | `assertNtfyConfigAtBoot` throws on any missing NTFY_* env var — Skynet backend fails to start, same fail-fast posture as Phase 128's VAPID gate. Verified by NC-02..NC-06. |
| T-144-SC | Tampering | binwiederhier/ntfy:v2.28.0 Docker image supply chain | accept | Official project (github.com/binwiederhier/ntfy), 4+ years history, pinned to specific version (not `latest`). RESEARCH.md package-legitimacy audit approved. No new npm packages added. |
