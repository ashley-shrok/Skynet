## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pretty-view WS client → backend WS server (port 30011) | client (WS) sends JSON commands; backend server executes them on the pane's SSH connection |
| backend → identity's tmux (via SSH exec channel) | backend issues tmux commands over an authenticated SSH session already established for that pane |
| tmux pane buffer → backend (capture-pane output) | agent-generated text flows FROM tmux to backend for parsing |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-01-01 | Tampering | injectBtw payload | mitigate | BTW_PROMPT is a COMPILE-TIME CONSTANT — no user input, no session context, no dynamic interpolation. Payload is fixed at module load. Shell-safe via shellQuote which single-quote-wraps + escapes embedded single-quotes (byte-identical to terminal.ts L123 which has shipped since Phase 2). Payload cannot inject shell metacharacters because shellQuote emits a valid POSIX-shell-single-quoted string. |
| T-14-01-02 | Injection | tmuxSession parameter → shell command | mitigate | tmuxSession is shellQuote-wrapped in the shell command. tmuxSession comes from claude-session-server.ts's own currentTmuxSession (set at the WS-handler scope from a validated hostId+sessionKey lookup, not from client WS payloads). If Wave 2 later takes tmuxSession from a client payload, that plan MUST re-audit — but Wave 1 helpers accept a trusted parameter. |
| T-14-01-03 | Injection | extractBtwAnswer regex on paneOutput | mitigate | paneOutput is agent-generated text from tmux — treated as UNTRUSTED. extractBtwAnswer uses non-catastrophic regex `/^\s*(&gt;\s*)?\/btw\b/` with anchored start, bounded quantifier — no ReDoS surface. Function returns a string that Wave 3 will render into React (React auto-escapes). |
| T-14-01-04 | Information Disclosure | log output from sshLogger.info on inject/dismiss failure | accept | Log lines contain tmuxSession identifier + error message. Same posture as the existing execCommand error logging throughout claude-session-server.ts — no new PII surface introduced. |
| T-14-01-05 | Denial of Service | injectBtw called in rapid succession by future Wave 2 code | accept | Wave 2 will gate injectBtw calls on the v1 overlap-policy (per ASIDE-08 — do not re-fire while aside displayed) AND on the frontend-driven aside_arm WS message (per CONTEXT.md § Trigger, locked 2026-07-26). Wave 1's helpers do not enforce this — they are primitives. Wave 2's threat model owns rate-limiting. |
| T-14-01-SC | Tampering | npm/pip/cargo installs | mitigate | Zero new package installs in this plan. No package legitimacy audit required. |
