<objective>
Close the /close verdict `closed-with-misses` finding from `.planning/shapes/shape-deferred-terminal-mount.closed.md`: the pretty-view upload channel is currently sourced from Terminal's SSH WebSocket, so identity panes (where Terminal is deferred and typically unmounted) silently lose upload capability. Rewire the pretty-view upload channel end-to-end so:

1. Frontend `usePrettyViewUploads` receives PrettyView's own claude-session WebSocket (opened via `openClaudeSessionSocket()` at PrettyView.tsx L1213) instead of the terminal SSH WS threaded through the `terminalWs` prop.
2. Backend handler dispatch for `upload_start` / `upload_chunk` / `upload_abort` moves from `src/backend/ssh/terminal.ts` (~L920-1000) to `src/backend/claude-session/claude-session-server.ts` (`ws.on("message")` at L2920), reusing the pane's existing `sshConn` binding (set at ~L4313 in the connectToPane path) for SFTP writes via the reusable `src/backend/ssh/pretty-view-upload.ts` module.

The reusable pretty-view-upload.ts module stays as-is (it already takes `UploadDeps { sshConn, ws, userId, currentSessionId }` per its exports at L129-134). Same wire protocol shape, same `messageQueueItemId` correlation. Only the receiving-server changes.

Purpose: shipped result must not degrade PrettyView's upload capability on identity panes — this is the exact primary risk-area the shape warned against ("chat surface silently degrading because a signal it used to get from the terminal wasn't fully re-sourced"). Ashley's disposition: close in this same phase, not as a follow-up.

Output: PrettyView + IdentitySessionPane + Terminal (backend) + claude-session-server (backend) all rewired; tests updated (PrettyView.compose-send.test.tsx refactored off terminalWs mock; new claude-session-server integration test added); pretty-view-upload.ts module unchanged; REST /uploadFile endpoint unchanged; deploy-prep docs (41-BUILD-VERIFY-LOG.md, 41-UAT-CHECKLIST.md, 41-PATCHES-MD-ENTRY.md) extended with 41-04 posture.
