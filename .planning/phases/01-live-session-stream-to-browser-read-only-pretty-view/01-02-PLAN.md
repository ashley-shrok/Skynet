  <action>
Create `src/backend/claude-session/session-file-tail.ts`.

Exports:
- Type `TailHandle = { stop: () => void }`.
- Function `tailSessionFile(conn: Client, absolutePath: string, onLine: (line: string) => void, onError: (err: Error) => void): TailHandle`.

Implementation:
- Shell-escape `absolutePath` (copy the same 3-line implementation of `shellEscape` from `tmux-helper.ts` lines 216-218 into this file — rather than exporting it from tmux-helper.ts — to keep tmux-helper's public surface minimal).
- Call `conn.exec("tail -F -n +1 " + shellEscape(absolutePath), (err, stream) => { ... })`.
  - `-n +1` starts from the first line of the file (satisfies "read from the beginning" per BACKEND-03).
  - `-F` (capital) follows the file across truncation/renaming — matches Claude Code's write-and-flush pattern; `tail -f` alone is not sufficient because Claude Code may rotate.
- On the `err` in the exec callback, call `onError(err)` and return early.
- Maintain a `buffer = ""` closure variable. On each `stream.on("data", buf)`:
    - Append `buf.toString("utf-8")` to `buffer`.
    - Repeatedly find the next `\n` in `buffer`; for each complete line found, extract it WITHOUT the trailing `\n`, call `onLine(extracted)`, and remove it from the buffer. Leave any partial trailing line in the buffer for the next data chunk.
    - Do NOT trim or strip `\r`; parse-time in Plan 1 handles trimming.
- Attach `stream.on("error", (err) => onError(err))` and `stream.stderr.on("data", ...)` — buffer stderr and if it accumulates >4 KB without any stdout progress, treat as fatal and call `onError(new Error("tail stderr: " + stderrBuf.slice(0, 500)))`.
- The returned `TailHandle.stop` should:
    - Attempt `stream.close?.()` if the ssh2 version supports it, else fall back to `stream.signal?.("KILL")` and then `stream.end?.()`.
    - Idempotent — repeated calls after the first must be no-ops (track a `stopped` boolean).
- Do NOT open the SSH connection here — the caller owns the Client lifecycle and passes an already-connected Client in. `tailSessionFile` is pure "given a connection, tail this path."

Add a top-of-file doc comment naming the two design choices: (1) tail -F over polling because Claude Code writes lines incrementally and polling wastes bandwidth on backfill; (2) newline-buffered because JSON lines can span multiple TCP frames.
