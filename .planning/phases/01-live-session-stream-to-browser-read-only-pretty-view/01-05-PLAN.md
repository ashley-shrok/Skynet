Insert a new `location` block into `docker/nginx.conf` for the `/claude-session/websocket/` prefix. Placement: immediately AFTER the existing `/ssh/websocket/` block (which currently ends at line 361 with its closing `}`), BEFORE the `/guacamole/websocket/` block. This groups the two Skynet-owned WebSocket paths together, ahead of the guacd path.

The new block MUST use the exact shape below (copy verbatim, with the prefix change and port change; comments included for future maintainers to know why this block exists and which patch created it):

    location ^~ /claude-session/websocket/ {
        proxy_pass http://127.0.0.1:30003/;
        proxy_http_version 1.1;

        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $http_host;
        proxy_set_header X-Forwarded-Host $proxy_x_forwarded_host;
        proxy_set_header X-Forwarded-Port $proxy_x_forwarded_port;
        proxy_set_header X-Forwarded-Proto $proxy_x_forwarded_proto;
        proxy_cache_bypass $http_upgrade;

        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

        proxy_read_timeout 86400s;
        proxy_send_timeout 86400s;
        proxy_connect_timeout 10s;

        proxy_buffering off;
        proxy_request_buffering off;

        proxy_next_upstream error timeout invalid_header http_500 http_502 http_503;
    }

The `^~` prefix modifier makes this block take precedence over the regex-based SPA fallback at lines 78-84 (`location ~* \.(js|css|...)$` etc.), avoiding the trap CONTEXT.md documents where a WS path is regex-matched by the static file rule and falls through to `index.html`.

The trailing slash on both the `location` pattern AND the `proxy_pass` URL is DELIBERATE — it makes nginx strip the `/claude-session/websocket/` prefix before forwarding, so the backend WS server (which listens at root `/` on port 30003) receives clean paths and query strings.

Do NOT modify any other line of `nginx.conf`. Do NOT reorder any existing block. Do NOT add a corresponding non-WebSocket `/claude-session(/.*)?$` block — the backend has no HTTP endpoints under that prefix in Phase 1; if a future phase adds one, extend then.
