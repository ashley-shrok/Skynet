Implementation steps inside the function (each wrapped in its own try/catch — a single top-level catch would collapse the reason codes):

1. Call `queryPaneCurrentCommand(conn, sessionName)`. If it returns `null`, return `{ status: "inactive", reason: "no_tmux_session" }`.
2. Trim and compare: if the returned string does NOT equal exactly `"claude"` (case-sensitive literal string equality — matches patch #13's identity-check style documented in AGENTS.md), return `{ status: "inactive", reason: "not_claude" }`. Do NOT do substring matching, do NOT accept `"claude-code"`, do NOT accept wrapper scripts. This is deliberately narrow, matching the same failure-mode-avoidance stance patch #13 took.

4. The pane's foreground `claude` process may itself have children, and the JSONL file may be held open by a child. Locate the open session file by walking descendants: run `execCommand(conn, ...)` with the shell command:

5. If the trimmed stdout is empty, return `{ status: "inactive", reason: "no_open_session_file" }`.
6. Otherwise return `{ status: "active", pid: <PID>, sessionFile: <trimmed stdout> }`.

Wrap the step 4 `execCommand` in a `Promise.race` against a 3000ms `setTimeout` rejection — match the timeout pattern from `sessions.ts` lines 75-86. On timeout or any other exec error caught at steps 4-6, return `{ status: "inactive", reason: "exec_error" }`.

Import `queryPaneCurrentCommand`, `queryPanePid`, `execCommand` from `../ssh/tmux-helper.js`. Import `type { Client }` from `ssh2`. Do NOT import any Node fs / path modules — this function runs REMOTE commands over SSH only.

Create `src/backend/claude-session/session-file-parser.ts` (directory was created by Task 2).

Exports:
- Type `ConversationalMessage = { kind: "message"; role: "user" | "assistant"; content: string; eventId: string; ts: number }`.
- Type `ParsedLine = ConversationalMessage | { kind: "skip"; why: string } | { kind: "malformed" }`.
- Function `parseSessionLine(line: string): ParsedLine`.

Claude Code's JSONL session-file format (per D-05 in CONTEXT.md and delexw/claude-code-trace prior art) uses one JSON object per line, each with at minimum a `type` field. Relevant `type` values in scope for v1:
- `"user"` — user-sent message; `message.content` may be a string OR an array of content blocks (Anthropic API shape). If it is an array, filter to blocks with `type === "text"` and concatenate their `.text` fields; if it is a plain string, use as-is. Skip if the resulting text is empty (Claude Code writes `[]` content for tool-result-only user turns — those are non-conversational).
- `"assistant"` — Claude reply; `message.content` is an array of blocks. Filter to blocks with `type === "text"` and concatenate their `.text` fields. Skip if empty (assistant turn was all tool calls).
- Any other `type` (including but not limited to `"summary"`, `"system"`, tool-result-only turns) — return `{ kind: "skip", why: <the type string, or "unknown"> }`.

Additional fields to extract when returning a message:
- `eventId`: use the top-level `uuid` field if present, else the top-level `messageId` field, else fall back to `String(Date.now()) + "-" + Math.random().toString(36).slice(2, 8)` — this fallback is only for malformed-but-parseable lines.
- `ts`: use `Date.parse(<top-level "timestamp" field>)` if present and finite; else `Date.now()`.

Implementation:
- Trim the line. If empty, return `{ kind: "skip", why: "empty" }`.
- Wrap `JSON.parse(line)` in try/catch. On throw, return `{ kind: "malformed" }`.
- Read `obj.type` — if not `"user"` or `"assistant"`, return `{ kind: "skip", why: String(obj.type ?? "unknown") }`.
- Extract `msg = obj.message`. If `msg == null`, return `{ kind: "skip", why: "no_message" }`.
- Compute content per role rules above. If content is empty string, return `{ kind: "skip", why: "empty_content" }`.
- Return the conversational-message object.

Explicitly do NOT emit `tool_use`, `tool_result`, `thinking`, `image` block content in v1 — the shape file's "aggressive minimalism" language and D-05's HARD LOCK forbid it. If a future v2 phase wants those, this is the ONE place to extend.

Add a top-of-file doc comment (6-10 lines) referencing:
- The v1 scope hard lock (RENDER-01 requirement)
- The Anthropic-content-blocks shape (text/tool_use/tool_result/thinking) and why v1 emits only text
- The `delexw/claude-code-trace` project as informational-only prior art (not a dependency)
