  <action>
Create `src/ui/features/pretty-view/use-auto-scroll.ts`.

Export signature:

    export function useAutoScroll(scrollRef: React.RefObject<HTMLElement | null>): { scrollToBottom: () => void; isPinnedToBottom: boolean }

Behavior (implements RENDER-03):
- `isPinnedToBottom` is a boolean derived from the scroll container's `scrollTop`, `clientHeight`, `scrollHeight`. Consider "at bottom" when `scrollHeight - scrollTop - clientHeight <= 16` pixels (a small tolerance for sub-pixel rounding and 1-line overshoot).
- Track state via `useState`. Update the state on every `scroll` event on the scrollRef element.
- Expose `scrollToBottom()` which sets `scrollRef.current.scrollTop = scrollRef.current.scrollHeight` (imperative, no smooth scroll — the caller invokes this AFTER adding a new message when isPinnedToBottom was true immediately before the addition; smooth scroll would cause visible chase).
- Attach the scroll listener via `useEffect`, cleanup in the returned function. Guard against `scrollRef.current == null` at every access.

Caller usage pattern (documented at top of file as a doc comment, not enforced in code):

    const listRef = useRef<HTMLDivElement>(null);
    const { scrollToBottom, isPinnedToBottom } = useAutoScroll(listRef);

    // When a new message arrives:
    const wasPinned = isPinnedToBottom;  // capture BEFORE setState
    setMessages(prev => [...prev, newMsg]);
    // Then in a useEffect keyed on `messages.length`:
    useEffect(() => {
      if (wasPinnedRef.current) scrollToBottom();
    }, [messages.length]);

Do NOT auto-call `scrollToBottom` inside the hook — leave the timing to the caller. This keeps the hook pure and testable.

Initialize `isPinnedToBottom` to `true` — a fresh mount with an empty list is "at the bottom" trivially, and the first render of loaded messages should pin.

Component signature:

    export interface PrettyViewProps {
      hostId: number;
      tmuxSession: string;
      className?: string;
      style?: React.CSSProperties;
    }

    export function PrettyView(props: PrettyViewProps): JSX.Element

Internal state:
- `messages: MessageEvent[]` — deduped by eventId (see below)
- `status: "connecting" | "streaming" | "inactive" | "error"` (single discriminant instead of a bag of booleans)
- `inactiveReason: string | null`
- `errorMessage: string | null`
- `wasPinnedRef: React.MutableRefObject<boolean>` — captures isPinnedToBottom BEFORE each setMessages call so the post-add effect knows whether to scroll

WebSocket lifecycle (`useEffect` keyed on `[hostId, tmuxSession]`):
- On mount / prop change: call `openClaudeSessionSocket()`, store the WebSocket in a ref, set `status = "connecting"`, clear messages / error / inactiveReason.
- `ws.onopen`: send `JSON.stringify({type:"connectToPane", hostId, tmuxSession})`.
- `ws.onmessage`: parse `event.data` as JSON. Route by `event.type`:
    - `"session"`: ignore for the render, log to console at debug (helpful during dev). Also set `status = "streaming"`.
    - `"message"`: capture `wasPinnedRef.current = isPinnedToBottom` FIRST, then `setMessages(prev => appendDedup(prev, event))`. `appendDedup` is a local pure function: if `event.eventId` matches any existing message's eventId, return `prev` unchanged; else return `[...prev, event]`. Dedup is defensive — the tail loop starting `-n +1` on a rotated/reopened file could replay lines.
    - `"inactive"`: set `status = "inactive"`, `inactiveReason = event.reason`. Do NOT populate messages, do NOT render a message list.
    - `"tail_error"`: set `errorMessage = event.message`, keep `status = "streaming"` — the render below shows a small banner but does not tear down the message list.
    - `"error"`: set `status = "error"`, `errorMessage = event.message`.
- `ws.onerror` / `ws.onclose`: if `status !== "inactive"`, set `status = "error"` and `errorMessage = "Connection closed"`. Do NOT auto-reconnect in Phase 1 — reconnect logic is deferred (would violate the FALLBACK-01 "do nothing else on inactive" letter if it accidentally reconnected past inactive).
- Cleanup: close the WebSocket, null out the ref.

Render structure:

    <div className={cn("h-full w-full flex flex-col bg-background", className)} style={style}>
      {status === "connecting" && <div className="p-4 text-sm text-muted-foreground">Connecting…</div>}
      {status === "inactive" && (
        <div className="flex-1 flex items-center justify-center p-4 text-sm text-muted-foreground">
          no active Claude session
        </div>
      )}
      {status === "error" && errorMessage && (
        <div className="p-4 text-sm text-destructive">{errorMessage}</div>
      )}
      {(status === "streaming" || (status === "connecting" && messages.length > 0)) && (
        <div ref={listRef} className="flex-1 min-h-0 overflow-y-auto px-4 py-3 flex flex-col gap-3">
          {messages.map(m => (
            <ChatMessage key={m.eventId} role={m.role} content={m.content} />
          ))}
        </div>
      )}
      {errorMessage && status === "streaming" && (
        <div className="border-t border-border bg-destructive/10 text-destructive text-xs px-3 py-1">
          {errorMessage}
        </div>
      )}
    </div>
