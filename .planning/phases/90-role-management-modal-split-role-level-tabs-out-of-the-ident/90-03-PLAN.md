<objective>
Add a role-name-keyed WS write path for role-file cosmetic frontmatter (and full body) mutations. The existing `identity:update-role-file` wire type takes `identityKey` and resolves the role via the identity's `role:` frontmatter — awkward and brittle for the role modal (Plan 90-04), which has NO identity context. A companion `role:update-file` wire type keyed directly on `{roleName, hostId?, contents}` is the clean split.

Purpose: implements D-08.3 (shape open — planner picks **new role-name-keyed companion wire type + new backend writer helper**, rejecting the "frontend synthesizes identityKey" fallback because it breaks if the roles-list host has no local identities. Full-overwrite semantics preserved from the current role file editor. No mtime-409 UX in v1 — Alice marked it nice-to-have but discretion; deferred to keep the plan tight.). Enables D-01 (post-creation role cosmetic edit) by giving the role modal's role-file tab a save path that doesn't need an identity.

Output: new `writeRoleFileByName` reader/writer helper + new WS handler + new frontend WS helper + tests.
</objective>
