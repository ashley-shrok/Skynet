## Task 2: `POST /roles/:name/avatar` handler (`roles.ts`)

<read_first>
- src/backend/database/routes/roles.ts (Plan 90-02's GET handler in same file — mirror multer + auth setup)
- src/backend/database/routes/identities.ts (identity avatar upload multipart pattern — mirror multer config, MIME allowlist, size cap)
</read_first>

<action>
Add POST handler to the same router mounted at `/roles`:

```
POST /roles/:name/avatar?hostId=<n>
  multipart/form-data
  fields:
    avatar: <file bytes>
```

Handler flow:
1. Auth via existing `authenticateJWT` middleware chain.
2. Validate `name` against ROLE_NAME_PATTERN → 400 if fail.
3. Validate `hostId` (Number-parse, positive integer) → 400 if fail.
4. Validate multer received a file on `avatar` field → 400 if not.
5. Validate MIME → 415 if not in allowlist (`image/webp`, `image/png`, `image/jpeg`, `image/gif`).
6. Validate size <= 5MB (or whatever ROLE_AVATAR_MAX_BYTES / IDENTITY_AVATAR_MAX_BYTES precedent sets) → 413 if fail.
7. Resolve host via `resolveHostById(hostId, userId)` → 502 if fail (mirrors GET handler's error contract).
8. Derive filename server-side as `<roleName>.<ext>` where `<ext>` is the MIME's canonical extension (`webp`, `png`, `jpg`, `gif`).
9. SSH connectOneShot → call `writeRoleAvatarByName(conn, name, filename, req.file.buffer)`.
10. Read role file markdown via `readRoleFileByName(conn, name)`, splice frontmatter's `avatar:` field to new filename, write back via `writeRoleFileByName(conn, name, updatedMarkdown)`.
11. Cleanup SSH conn.
12. Respond `201 {filename, avatarUrl: '/roles/<name>/avatar?hostId=<n>'}`.

Errors during steps 9-10 → 502 with generic message (no upstream leakage per existing STRIDE T-22-02 pattern).

Mount ordering: `POST /roles/:name/avatar` must be registered BEFORE any `GET /roles/:name/avatar` handler (or at same router level) — Plan 90-02 mounted the GET; verify the POST doesn't shadow it and vice versa.
</action>
