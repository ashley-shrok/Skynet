## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `~/fleet/apps/*/` folder name → argv of `systemctl --user` | Attacker-controlled input (any agent can `mkdir` under `~/fleet/apps/`) crosses into a system-privilege command. |
| `~/fleet/apps/<slug>/app.json` contents → JSONL stdout | Attacker-controlled JSON string (title, description) flows through the sweep into the Skynet backend wire (later filtered per-user, but string contents pass through). |
| `~/.config/systemd/user/app-<slug>.service` PORT env → JSONL stdout | Attacker-controlled string in a systemd unit file's Environment= directive → parsed by regex → shipped on the wire. |
| Sweep exec time budget (8000ms per `ssh-poll-orchestrator.ts:1400`) | Denial-of-service surface: a slow per-app path could push the whole sweep past its budget, causing the orchestrator to abandon the tick. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-118-01-SL | Tampering / EoP | Slug injection into `systemctl --user` argv | mitigate | `APP_SLUG_RE = ^[a-z][a-z0-9-]*$` + 40-char cap enforced in `_enumerate_apps` BEFORE the slug reaches `_build_app_line` or any subprocess. Combined with argv-form `subprocess.run([...], shell=False)` (never shell=True), argv-level injection is not possible. Test case 7 exercises the regex reject path. |
