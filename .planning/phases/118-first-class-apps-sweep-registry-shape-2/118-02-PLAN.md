<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Untrusted JSONL string (from SSH stdout of Python sweep) → typed TS objects | Every line is attacker-controlled if the box's `~/fleet/apps/` is populated by a hostile agent. The parser MUST NOT throw on any input shape. |
| Rolling-deploy window: newer Python vs older TS parser | A managed box may run a Python sweep emitting `app` lines before the container's TS parser has been redeployed. Old parser must degrade cleanly. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-118-02-DS | DoS | `parseSweepJsonl` throwing on malformed app line | mitigate | The dispatch case uses `appLines.push(parsed as SweepAppLine)` — a cast, no runtime validation. The wrapping `try/catch` in `parseSweepJsonl` (existing at ~L280-305) catches JSON.parse failures per line and drops them silently, matching the identity + pid discipline. The lenient parser NEVER throws (documented invariant per PATTERNS § Additive Extension Discipline). |
| T-118-02-RD | DoS / Availability | Rolling-deploy schema drift | mitigate | Not bumping `SWEEP_SCHEMA_VERSION`. Old parsers hit the `else { unknownLines += 1 }` branch for `line_kind: "app"` and continue processing identity + pid lines. Newer parsers with older Python get `appLines: []` (empty is a valid state). RESEARCH § Pitfall 6 covers both directions verbatim. |
| T-118-02-IV | Input Validation | Field-type mismatch on wire (Python emits a string where TS expects number, etc.) | accept (in this plan) | The `SweepAppLine` interface is a TypeScript type — it disappears at runtime. `appLines.push(parsed as SweepAppLine)` does not runtime-validate. If Python drifts and emits `port: "9591"` (string) instead of `port: 9591`, the field flows into 118-04's adapter which will then feed 118-03's Zod schema `AppStateSchema` — that IS the runtime validation gate (Zod rejects → dropped frame, not an exception). Byte-name parity discipline plus Python side's type discipline (D-05) is the defense-in-depth. |
| T-118-02-SC | Tampering | npm/pip/cargo installs | accept | Zero new dependencies. Only existing zod (already imported) used — actually not even zod, since sweep-schema.ts predates the zod refactor and uses hand-rolled type guards. |
</threat_model>
