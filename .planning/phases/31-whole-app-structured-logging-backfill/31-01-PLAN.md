## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `/debug/console-log` | Batched frontend logs cross the WS/HTTP boundary; already authenticated by AuthManager JWT middleware. Extending the envelope adds hostId (numeric) and sessionKey (string) — both already whitelisted by `isValidEntry` in debug.ts. |
| log-dedup memory | In-process Map keyed by string; no persistence, no cross-user leakage possible (client-local). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-31-01 | Information Disclosure | console-forwarder envelope | mitigate | Caller of `setLogContext` MUST pass numeric hostId + opaque sessionKey ONLY. Sensitive fields (SSH keys, passwords, JWT bodies) are NEVER logged — D-05 anti-pattern rule + no PII/creds directive. Plan reviewer greps for `password`/`token`/`secret` substrings in any msg string added by this plan; grep returns 0. |
| T-31-02 | Denial of Service | log-dedup memory growth | accept | Dedup Map is capped in practice by the finite set of subsystem+event keys downstream plans opt into (~10-30 keys). No unbounded growth vector; `flush()` reclaims entries. Explicit reset available via test helper. |
| T-31-03 | Tampering | log-dedup timing accuracy | accept | now() is injectable for tests; production uses Date.now(). Clock skew or NTP jumps could produce a stale window — cost is a wrong summary count line, not a correctness issue in the app. |
| T-31-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages installed in this plan — purely new/edited source files. `package.json` unchanged. Confirmed by acceptance criteria requiring 0 lines changed in package.json. |
