<objective>
Ship the D-03 backend→frontend log unification: create a new backend transport module that buffers `Logger.*` output and appends it to the SAME `console-forward.log` file the frontend already writes to, with a `source=backend` marker so a single `grep` can filter.

Per D-03 Claude's Discretion:
- Cheapest unification path — write DIRECTLY to the file (no HTTP hop back to itself; same-process).
- Mirror the frontend `console-forwarder.ts` shape (MAX_BATCH=20, FLUSH_INTERVAL_MS=500).
- Wire from `logger.ts` so every `Logger.info/warn/error` call also enqueues here (in addition to the existing chalk-formatted console output).
- Add `source` marker to LogEntry envelope on the receiving `debug.ts` module so the wire contract is consistent.

Purpose: unified log file makes cross-side correlation trivial (D-16). When the backend routes a message that affects frontend state (pane_state emit, session-file discovery event), matching sessionId in both entries lets a single `grep sessionId=...` show the full round-trip.

Output: 1 NEW file + tests, 3 EXISTING files modified, 1 boot wiring change.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| backend process → shared log file | Same-process write; file is the same one frontend writes to via `/debug/console-log`; bind-mounted from /opt/skynet/console-forward-logs/ on the host. |
| backend log content → file | Backend log lines carry msg strings composed by Logger.formatMessage — which already incorporates sensitive-field masking per logger.ts existing behavior. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-31-16 | Information Disclosure | backend log payloads | mitigate | Logger.formatMessage already masks sensitive fields (see logger.ts sensitive-field logic — the existing chalk-formatted output is what goes into the enqueued msg). No additional exposure vector introduced by this plan. |
| T-31-17 | Denial of Service | file rotation contention | mitigate | Both frontend handler (debug.ts) and backend transport check file size and rotate at 5 MB. Simultaneous rotation is safe: both use sync fs.writeFileSync which is atomic on Linux for single-write. Worst case a rotation marker line appears twice — no data corruption. |
| T-31-18 | Information Disclosure | shutdown log flush | accept | flushBackendLogs on SIGTERM ensures no pending-in-buffer diagnostic data is lost. Cost is a synchronous write during shutdown — negligible (< 20 lines * few bytes each). |
| T-31-19 | Tampering | source field validation | mitigate | isValidEntry checks the source field against the "frontend"|"backend" enum; malformed source strings rejected at ingress. Cross-source spoofing (frontend claiming source=backend) is possible via the HTTP endpoint but has no security impact — it's just a diagnostic marker. |
| T-31-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages installed. package.json unchanged. |
</threat_model>
