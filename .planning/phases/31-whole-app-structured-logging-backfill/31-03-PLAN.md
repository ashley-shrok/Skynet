## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| /voice/speak-stream → ChatMessage.tsx | Streamed audio bytes cross the WS/HTTP boundary; response body is streamed audio, never logged (byte-sized fields only). |
| MediaElement error → log line | MediaError DOM object's .code and .message extracted explicitly (D-05); no JSON.stringify on the underlying event. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-31-07 | Information Disclosure | TTS log lines | mitigate | Log lines carry: owner (numeric singleton id), textLen (numeric — length only, NOT text body), voice (voice filename string like "Elena.wav" — public), fetch status/statusText, MediaError code/message (browser-provided). Explicitly NOT logged: message text body, audio bytes, JWT tokens, user identity. |
| T-31-08 | Denial of Service | media event log volume | accept | Media events fire once per state transition (canplay/playing/ended once per playback). Stalled/suspend can retrigger under bad network; per-event lines are diagnostic per D-17 (opt out of dedup). Volume is bounded by user-initiated speak actions (~1-10 per session). |
| T-31-09 | Tampering | dedup applicability | accept | No dedup applied to TTS per D-17 — every event is uniquely diagnostic. If future volume analysis shows a hot loop, plan 31-09 grep pass will surface it and a follow-up phase can opt in. |
| T-31-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages installed. package.json unchanged. |
</threat_model>
