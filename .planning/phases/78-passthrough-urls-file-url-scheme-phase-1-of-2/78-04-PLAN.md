<objective>
Rewrite the "Sending files to the user" section in substrate/skills/id/SKILL.md (currently L752-816) to teach agents the new Phase 78 file-URL scheme (per D-01, D-03) and retire the python3 -m http.server recipe entirely (per RESEARCH Pitfall 5).

The section MUST:
- Frame the file-URL scheme as the ONE and ONLY documented way to share files, with no "fallback" or "alternative" for the http.server pattern
- Teach the URL grammar: <skynet-parent>/file/<hostname>/<absolute-path>, where the parent URL is read from `cat ~/.claude/skynet-parent` and hostname comes from `hostname`
- Include an idiomatic construction snippet (a few lines of shell that reads the parent URL, gets the hostname, and emits a Markdown link)
- Document the round-trip semantics: Skynet is READ-ONLY; save-in-modal creates a compose-box attachment on the user's next message; the file at the original path is NEVER overwritten by Skynet
- Include the D-03 missing-file behavior: if `~/.claude/skynet-parent` is absent, surface a clean error to the user (e.g. "I can't share files right now — my parent-Skynet config is missing. Ask the box-maintainer role to check the distributor sweep.") rather than guessing or falling back to http.server
- Preserve the small-text-inline rule (paste inline in a code block for files < ~5 KB) — that behavior is orthogonal to the URL scheme change and remains the right advice
- Explain WHY the rewrite happened, pointing at the shape's stated failure modes (Chrome insecure-download friction, tailnet dependency, agent-side server lifecycle burden) — one short paragraph, so agents don't cognitively drift back to the old pattern

Purpose: Fleet-substrate section-rewrite that makes the Phase 78 URL scheme the natural muscle-memory pattern for agents citing files. The distributor's existing catalog entry (catalog.ts:96-99) delivers the updated SKILL.md to every managed box on the next sweep after container recreate — no new catalog machinery.

Output: One section rewrite in substrate/skills/id/SKILL.md; ~50-70 lines replacing the current ~65-line section at L752-816.

Wave ordering rationale (from planner guidance): This plan is Wave 2 depending on Plan 03 (distributor step-4). The id-skill rewrite ships AFTER the distributor step is live so agents on fresh boxes have `~/.claude/skynet-parent` in place BEFORE they read the rewritten skill telling them to use it. Without the depends_on gating, an agent on a freshly-onboarded box could read the skill, try to `cat ~/.claude/skynet-parent`, find it missing, and surface the D-03 error — technically graceful but pointlessly noisy.
</objective>
