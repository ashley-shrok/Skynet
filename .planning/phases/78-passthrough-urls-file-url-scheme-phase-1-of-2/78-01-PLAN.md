<objective>
Ship the backend half of Phase 78's file-URL feature (per D-01, D-04), providing BOTH surfaces the shape philosophy requires:

- (POST — modal JSON path) `POST /pretty-view/fetch-host-file` at `src/backend/database/routes/pretty-view-fetch-host-file.ts` that accepts `{hostname, absolutePath}`, resolves the host by name (scoped to userId), enforces per-user-per-host read access, opens SSH via the resident pool, SFTP-reads the file with a 2 MB cap, and returns the `TailnetFetchResult` envelope the modal already consumes.

- (GET — verbatim URL path) `GET /file/:host/*` in the SAME route file, sharing the exact same fetch machinery. When Ashley (or any authed user) opens `https://<skynet-domain>/file/<hostname>/<absolute-path>` in a fresh browser tab, they get the raw file bytes served as `text/plain; charset=utf-8` with `X-Content-Type-Options: nosniff` + `Cache-Control: no-store`. This closes the D-01 completeness gap flagged by the checker: agent-cited URLs must work when copied/shared/bookmarked, not only when clicked through the in-app modal. Same auth (`authenticateJWT`), same host resolution, same RBAC, same guardrails, same error taxonomy — errors render as human-readable text bodies (not JSON) since a browser tab is the surface.

- **Split-router mount pattern (per checker W-3):** The route file exports TWO narrow Express routers — `prettyViewFetchHostFileRoutes` (POST-only, mounted at `/pretty-view`) and `fileUrlRoutes` (GET-only, mounted at `/`). Each router owns exactly ONE handler and is mounted at exactly ONE prefix. This eliminates the ghost-alias attack surface the checker flagged: a single-router-mounted-twice design would silently expose `POST /fetch-host-file` at root AND `GET /pretty-view/file/:host/*` — unadvertised URLs that expand attack surface and complicate refactors. With split routers, those aliases return 404 by construction because the wrong router has no matching handler.

- **Shared helper `fetchHostFileBytes(userId, hostname, absolutePath)`** (private to the file) contains ALL auth + resolve + guardrails + SFTP-read logic. BOTH routers import from the same module, so both invoke the same code path. No handler-code duplication. Inside the helper, `sftp.realpath(absolutePath)` is called BEFORE `sftp.stat` — the resolved target is re-checked against the `/^\/(proc|sys|dev)(\/|$)/` regex, which is what actually mitigates T-78-07 symlink-escape (the prior draft's `sftp.stat` return does NOT expose the resolved path; only `sftp.realpath` does).

- New helper `resolveHostByName(name, userId)` in `src/backend/ssh/host-resolver.ts` alongside the existing `resolveHostById`. Used by the shared helper.

- Mount pattern in `src/backend/database/database.ts`: TWO `app.use` lines, each with a narrow router — `app.use("/pretty-view", prettyViewFetchHostFileRoutes)` (POST reachable at `/pretty-view/fetch-host-file` ONLY) and `app.use("/", fileUrlRoutes)` (GET reachable at `/file/:host/*` ONLY, matching what agents write verbatim per D-01).

Purpose: Skynet becomes the delivery surface for file-URL requests via BOTH the modal JSON path (existing UX) AND the verbatim URL path (agent-cited URL opened directly). The shape's core philosophy — "the URL an agent writes into a message is the actual URL the user clicks" — requires the GET route; otherwise agents are subtly lied to when their cited URL only works in one context. The split-router design honors the principle that each URL should have exactly one legitimate way in.

Output: One new route file (~480 lines: shared fetch helper with realpath-then-stat + POST-only router + GET-only router, mirroring `pretty-view-fetch-tailnet-url.ts` structure), one new exported helper function, two mount lines + one import line in `database.ts`.
</objective>
