<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Skynet backend (Node process) → SSH channel → managed host shell | channel.exec runs shell commands on the target box as the SSH user; command string is Skynet-authored (not user-influenced beyond the env var) |
| Operator → /opt/skynet/skynet.env → Skynet backend process.env | New env var SKYNET_PUBLIC_URL is set operator-side; Skynet reads it via process.env at runtime; docker-compose env_file already handles the wiring (RESEARCH § Assumption A2) |
| Managed host filesystem → ~/.claude/skynet-parent → agent's cat/read | Agents read the file via `cat ~/.claude/skynet-parent`; file is world-readable within the host user's home; content is a URL (not a secret) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-78-D1 | Tampering | Shell injection via URL containing single-quote / backslash / backtick | mitigate | URL is shell-escaped via replace(/'/g, "'\\''") pattern before interpolation into the shell command's NEW='<URL>' assignment (standard single-quote-inside-single-quotes escape); command uses single-quoted context so other shell metacharacters (backticks, $, etc.) are literal |
| T-78-D2 | Tampering | Attacker with write access to /opt/skynet/skynet.env sets malicious URL | accept | Write access to skynet.env implies root or Skynet-service-user compromise — that's a higher-level breach than this feature can defend against; the URL is a passive config value (agents render it as a Markdown link; users click) — worst case is a phishing target, mitigated by regex requiring https:// and existing browser TLS trust chain |
| T-78-D3 | Denial of Service | Sweep-cadence rewrite of ~/.claude/skynet-parent (every 2s) triggers watcher noise / mtime churn | mitigate | Idempotent content-diff guard: `[ "$(cat "$SP")" = "$NEW" ]` short-circuits when file matches, no write, no mtime bump — matches step 2/3 pattern (RESEARCH Pitfall 3) |
| T-78-D4 | Denial of Service | Missing SKYNET_PUBLIC_URL causes empty-file write → agents get broken value → downstream URL construction fails silently | mitigate | Guard clause: if unset OR !/^https:\/\//.test(url), skip step 4 entirely; DO NOT write empty string; agents' D-03 fresh-box behavior handles the missing file gracefully with a user-facing error; systemLogger.warn on skip makes the state observable (RESEARCH Pitfall 4) |
| T-78-D5 | Repudiation | Step 4 failure silently swallowed | mitigate | NEVER-THROW contract: every failure wrapped in try/catch; logBootstrapFailed emits structured log with operation "fleet_substrate_bootstrap_failed", step "skynet-parent-write"; result.hadError = true; logBootstrapResult at the end of sweep includes the result including skynetParentOk field |
| T-78-D6 | Information Disclosure | ~/.claude/skynet-parent contents are world-readable | accept | Content is a URL (parent Skynet's public HTTPS endpoint) — already public information (visible in DNS, TLS cert, HTTP responses); no secret content; file lives inside the user's home directory with default umask permissions |
| T-78-D7 | Elevation of Privilege | channel.exec's shell command runs as the SSH user; step 4 doesn't attempt sudo | mitigate | Step 4 writes ONLY inside "$HOME/.claude/" (user-owned directory); no sudo; no /etc, /opt, or system-wide paths touched; matches D-04 "SSH user, no sudo escalation" |
| T-78-D8 | Tampering | Stale URL after Skynet migration (e.g. domain change from term.gigaashley.click to something else) | mitigate | Idempotency guard uses content-diff; on next sweep after operator updates SKYNET_PUBLIC_URL, the new value differs from the file's current contents → rewrite fires → file gets the new URL on the same sweep; no manual per-host action required |
| T-78-DSC | Tampering | Package installs | accept | No new npm packages installed by this plan (only Node built-in process.env + existing systemLogger + existing SshChannel type). RESEARCH § "Package Legitimacy Audit" confirms N/A. |
