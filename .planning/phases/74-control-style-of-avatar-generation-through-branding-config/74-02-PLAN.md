<objective>
Add the boot-time presence check that makes the instance refuse to start when the operator's branding config omits or empties `avatarDirectorSpec`. Per D-03 (74-CONTEXT.md Philosophy "No silent fallbacks. If the config is missing something the app needs, the app refuses to run rather than picking for the admin") and 74-CONTEXT.md "What would make it wrong" §3 (whitespace-only string must NOT pass the check — trim before length-check).

Per Ashley resolution #5 (`<additional_context_from_ashley>`), the boot gate covers `avatarDirectorSpec` ONLY. `avatarGammaDefault` is treated as optional-with-shipped-fallback: the loader's shape guard already requires it be a finite number (Plan 01 Task 1), and the request-time consumer (Plan 03) uses whatever value it reads. No boot gate on gamma.

The boot gate lives in a NEW module `src/backend/branding/assert-boot.ts` — separate from the loader — so the Phase 70 loader stays never-throws (belt-and-suspenders contract that `/api/branding` HTTP route depends on). The gate is invoked from `starter.ts` boot IIFE using the existing `process.exit(1)` fail-fast pattern (starter.ts L757/L764/L770 for reference).

Purpose: closes the "silent fallback silently defeats the whole point" failure mode (74-CONTEXT.md "What would make it wrong" §5) by making the missing-config case crash-fast, not silently-degraded.

Output:
- src/backend/branding/assert-boot.ts (NEW ~30-line module)
- src/backend/branding/assert-boot.test.ts (NEW test file — pass path, missing spec, whitespace-only spec)
- src/backend/starter.ts extended with one dynamic import + one awaited call inside the boot IIFE, placed after dbModule.initializeDatabase() (~L262-266) and before the dbServer import at L292
</objective>
