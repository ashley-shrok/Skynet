<objective>
Extend the Phase 70 branding-config schema with two new fields — avatarDirectorSpec (string, required) and avatarGammaDefault (number, required in shape with sensible bundled 0.7) — as an ATOMIC CONTRACT across the backend loader, the frontend type mirror, the bundled default JSON file, and shape-guard tests. Landing all four files in one plan prevents a stray wave where the backend accepts the shape but the frontend TypeScript blows up on `/api/branding` fetch.

Per D-01 (74-CONTEXT.md Scope Edges "In" bullet 1) — avatarDirectorSpec is a required free-text field. Per Ashley resolution #4 (`<additional_context_from_ashley>`) — bundled default carries avatarDirectorSpec as empty string so the Phase 02 boot gate fires when no operator config is present. NEVER seed the bundled default with real LoL content — that would turn the Phase 70 bundled-default fallback into a silent-fallback backdoor and defeat the whole boot gate.

Purpose: gives Phase 74's boot gate (Plan 02) and route rewire (Plan 03) a schema field to read from. This is the atomic contract Phase 74 stands on.

Output:
- Extended BrandingConfig type at backend loader (branding-config-loader.ts) with two new required fields
- Extended isValidBrandingShape() rejecting configs missing or wrong-typed for either field
- Updated HARDCODED_FALLBACK constant (avatarDirectorSpec: "", avatarGammaDefault: 0.7)
- New test file src/backend/branding/branding-config-loader.test.ts covering the shape guard's new branches
- Extended frontend BrandingConfig type + bundled-default sentinel matching backend byte-for-byte
- Updated docker/branding-defaults/branding.json with the two new fields (avatarDirectorSpec: "", avatarGammaDefault: 0.7)
</objective>
