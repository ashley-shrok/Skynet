|----------|-------------|
| Client → WebSocket (identity:list-bounties / identity:get-history) | Untrusted identityKey + hostId from browser reach the backend WS handlers. |
| Backend → SSH exec on target host | identityKey (validated by IDENTITY_KEY_RE) + role (extracted from identity file, re-validated by IDENTITY_KEY_RE per Task 1 Step 4) are shell-interpolated into `cat`/`ls` commands. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-01-01 | Tampering (shell injection via role name interpolated into SSH exec after frontmatter parse) | `readIdentityBounties` / `readIdentityHistory` REMOTE branch | mitigate | `resolveRoleForIdentity` (Task 1) throws when extracted role fails `IDENTITY_KEY_RE.test(role)`. Defense-in-depth: the same regex gate that guards identityKey shell-safety guards role. |
| T-22-01-02 | Tampering (path traversal via `../` in role frontmatter value) | Frontmatter YAML parser | mitigate | IDENTITY_KEY_RE = `/^[a-z0-9_-]{1,64}$/` blocks dots, slashes, and any traversal syntax. Applied inside resolveRoleForIdentity before role is used in any command. |
| T-22-01-03 | Information Disclosure (reading another user's role folder if hostId is spoofed) | claude-session-server.ts WS handlers (unchanged this plan) | accept | Existing `resolveHostById(hostId, userId)` cross-user isolation at the WS handler layer already gates the SSH connection; this plan does not change that gate. Documented in RESEARCH Security Domain V4. |
| T-22-01-04 | Denial of Truth (silent fallback returns empty bounties list when frontmatter missing, hiding data corruption) | resolveRoleForIdentity | mitigate | Helper THROWS on missing role — never returns null/empty. | T-22-01-05 | Denial of Service (unbounded frontmatter YAML — YAML billion-laughs) | js-yaml `yaml.load` on frontmatter | mitigate | Frontmatter block is regex-extracted (`/^---\r?\n([\s\S]*?)\r?\n---/`) — bounded by the closing `---`.
