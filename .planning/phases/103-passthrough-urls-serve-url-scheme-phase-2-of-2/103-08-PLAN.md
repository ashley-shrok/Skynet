<objective>
Comprehensive CSRF audit of every route in src/backend/database/routes/ (per D-09 "full audit, no partial-audit shipping"), classify state-changing vs read-only, verify preflight-triggering shape, apply remediation for the multipart-upload endpoints (per D-10 origin check) that don't naturally preflight. Produce CSRF-AUDIT.md as a checked artifact for future re-audits. Realizes D-09 + D-10.

Purpose: closes the CSRF hole created by the widened cookie (Plan 02 D-02). Plan 02's CORS reject stops PREFLIGHT-triggering requests from serve subdomains; this audit finds and remediates the ones that DON'T preflight (multipart uploads, form-urlencoded POSTs, GET-with-side-effects). Comprehensive because a single missed route = a live CSRF vector.

**Sharded audit workflow (per W5):** the ~219 route classification is split into 4 sharded sub-tasks (Task 1a-1d) by directory subgroup — each shard produces an audit-fragment table, and Task 1e (the merge step) concatenates them into the single CSRF-AUDIT.md. Sharding keeps per-subtask context under 30% budget so classification quality stays high.

**Wave rationale (wave 3, depends_on 103-02 + 103-06):** this plan MAY modify src/backend/database/routes/host.ts (which Plan 02 also modifies) if the audit finds multipart endpoints there, so it must run AFTER Plan 02 to avoid file conflict. It IMPORTS from Plan 06's src/backend/utils/ws-origin-guard.ts (the SERVE_SUBDOMAIN_ORIGIN_RE / isServeSubdomainOrigin helpers) so it must run AFTER Plan 06.

Output: 4 audit fragments (Task 1a-1d) merged into 1 CSRF-AUDIT.md (Task 1e) + 1 new helper file (Task 2) + N remediated route files (identified during audit — count not knowable pre-audit; frontmatter uses wildcard placeholder per W3; Task 2 acceptance criterion requires exact enumeration in 103-08-SUMMARY.md).
