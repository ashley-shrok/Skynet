    **UAT PROCEDURE — Ashley (or whichever identity is at the box) runs on t1000:**

    1. **SSH into t1000** (or open a terminal on the machine directly if physically present).

    2. **Create the test folder + files:**
       ```
       mkdir -p /tmp/serve-url-uat
       cd /tmp/serve-url-uat
       cat > index.html <<'EOF'
       <!DOCTYPE html>
       <html><head><title>serve URL UAT</title></head>
       <body>
         <h1>serve URL UAT — origin isolation proof</h1>
         <p>If the image below loads, absolute-path assets resolve back through the serve subdomain (origin isolation works).</p>
         <img src="/image.png" alt="test image — MUST load via serve subdomain, not term.gigaashley.click">
       </body></html>
       EOF
       # Grab any small PNG as image.png — a screenshot, a favicon, whatever
       cp ~/.local/share/icons/hicolor/16x16/apps/*.png image.png 2>/dev/null || \
         curl -sSLo image.png https://www.python.org/static/favicon.ico
       ls -la  # verify both index.html and image.png present
       ```

    3. **Start python http.server on port 8899:**
       ```
       python3 -m http.server 8899
       ```
       Leave this running in a terminal — you'll see log output for each incoming request, which is the ground-truth for whether the proxy reached your box.

    4. **Open a fresh browser window** (Firefox or Chrome, INCOGNITO/private mode to ensure clean cookie state — after this you'll sign in fresh with the widened cookie).

    5. **Sign into the primary Skynet at https://term.gigaashley.click** — verify a fresh JWT cookie is issued with `Domain=term.gigaashley.click` (Firefox devtools → Storage → Cookies → look for `skynet_session` with Domain field). This validates D-02 cookie widen.

    6. **Visit https://t1000-8899.serve.term.gigaashley.click/** in the same browser tab. Expected behavior:
       - Browser presents Skynet's HTTPS cert with issuer "Let's Encrypt" (or ZeroSSL fallback per D-21) — verify via padlock click
       - Page loads showing "serve URL UAT — origin isolation proof" heading
       - image.png loads and displays below the heading
       - View source (Ctrl-U): `<img src="/image.png">` — absolute path, NOT rewritten to full URL
       - Devtools Network tab: TWO requests seen — one for `/` (index.html), one for `/image.png` — both going to `t1000-8899.serve.term.gigaashley.click`, both returning 200, both loading correctly

    7. **Cross-check the python http.server terminal** — you should see TWO log lines, both from Skynet's edge IP:
       ```
       127.0.0.1 - - [...] "GET / HTTP/1.1" 200 -
       127.0.0.1 - - [...] "GET /image.png HTTP/1.1" 200 -
       ```
       (127.0.0.1 because Skynet dials the SSH tunnel to your local port; the tunnel makes it appear as loopback from python's perspective.)

    8. **NEGATIVE test — origin isolation confirmation:** in the browser devtools Network tab, verify the /image.png request URL is `https://t1000-8899.serve.term.gigaashley.click/image.png` — NOT `https://term.gigaashley.click/image.png`. If the image loads but from term.gigaashley.click, origin isolation is broken and the whole D-01 wildcard-subdomain-per-(host,port) design failed.

    9. **NEGATIVE test — auth wall:** open a DIFFERENT browser (or clear cookies), visit https://t1000-8899.serve.term.gigaashley.click/ without signing in. Expected: 302 redirect to https://term.gigaashley.click/login?return=<encoded-url> (per D-14 auth_missing interstitial + Plan 03a interstitial.ts). Verify redirect fires.

    10. **NEGATIVE test — port not listening:** in another terminal, kill the python http.server (Ctrl-C). Refresh https://t1000-8899.serve.term.gigaashley.click/. Expected: Skynet-styled interstitial page (NOT bare 502) saying "port 8899 of t1000 isn't responding" per D-14 port_not_listening class + Plan 03a interstitial.ts. Verify interstitial rendered with plain "Try again" button (no auto-refresh per D-14 + specifics L145).
