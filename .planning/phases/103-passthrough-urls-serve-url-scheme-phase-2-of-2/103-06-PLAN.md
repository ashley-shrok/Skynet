<objective>
Add WebSocket Origin-header checks to every WebSocketServer definition so cross-origin WS attempts from *.serve.term.<domain> are refused at the handshake layer. WebSocket doesn't do CORS preflight — WS handshakes are HTTP GET upgrades that fire regardless of CORS policy. Per D-08 this is the WS-layer complement to Plan 02's CORS reject for HTTP endpoints.

Purpose: closes the WebSocket-shaped CSRF hole created by the widened cookie (Plan 02 D-02). Without this check, a malicious agent-supplied page served at foo-3000.serve.term.example.com could open a WS to term.example.com and drive any WS-command surface (terminal, docker-console, relay-room-stream) authenticated as the user.

Output: 1 new helper file (ws-origin-guard.ts + test), 5 modified WS entry points.
</objective>

    Create src/backend/utils/ws-origin-guard.ts. Export:

    ```
    export const SERVE_SUBDOMAIN_ORIGIN_RE = /^https?:\/\/[^/]+\.serve\.term\.[a-zA-Z0-9.-]+$/;

    export function isServeSubdomainOrigin(origin: string | undefined | null): boolean {
      if (!origin) return false;
      return SERVE_SUBDOMAIN_ORIGIN_RE.test(origin);
    }

    export function rejectServeSubdomain(req: { headers: { origin?: string | string[] } }): boolean {
      const origin = req.headers?.origin;
      if (typeof origin !== 'string') return false;
      return isServeSubdomainOrigin(origin);
    }
    ```
