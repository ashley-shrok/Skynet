<objective>
Cover the archive-scan mechanism end-to-end with executable tests. This is the confidence-earning wave: everything Waves 1-3 built is exercised against real fixtures + a stub Matrix homeserver so a future refactor that regresses ANY of the D-01..D-17 contract lines fails loudly, not silently. The test driver is a single self-contained bash script (`substrate/scripts/tests/agent-supervisor-archive-scan.sh`) — no bats harness (the substrate has none), no vitest/playwright coupling (this is shell code, not TypeScript). The driver spins up a scratch `$IDENTITIES_DIR` and `$DORMANCY_STATE_DIR` under `mktemp -d`, populates fixtures, sources the supervisor's functions, invokes them, and asserts against exact log output, counter file contents, sentinel presence, and function return codes.

Purpose: The failure modes named in the shape file's § "What would make it wrong" are all catastrophic — retiring a coordinator, retiring a pinned identity, stopping between retire steps with inconsistent state. Wave 1 built the guards that prevent those failures; Wave 4 is where we PROVE the guards work by exercising every negative case (commented-`coordinator:true`, body-prose-`coordinator:true`, quoted-string-`coordinator:true`, no-frontmatter, `.pinned` present, `.no-dormancy` present, fresh cursor). The test driver also serves as executable documentation: the fixture-construction code shows exactly what shape an identity folder + relay.json takes at retire-time.

The stub matrix homeserver is a small local HTTP responder — either `python3 -m http.server` with a tiny custom handler, or a `nc` (netcat) one-shot script that reads the POST request and returns a canned response. The base URL in the fixture relay.json points at `127.0.0.1:<port>`; retire_identity's curl call hits the stub instead of a real Synapse instance. The stub is scoped per-test — a test that wants a 200 response spawns the stub with a 200 canned reply; a test that wants a 401 spawns it with 401; a test that wants network-fail simply doesn't spawn a stub and points the base URL at a port with no listener. This pattern avoids the fragility (and network dependency) of running tests against a real Matrix homeserver, and it keeps the tests fully hermetic — they can run in CI, in a sandbox, on a laptop without any external state.

Output: two new files under `substrate/scripts/tests/` — the test driver and a README explaining how to run it. No modifications to `agent-supervisor.sh` (Waves 1-3 are the surface; Wave 4 is pure test coverage over that surface). The driver's grep-based static-analysis phase locks the Pitfall gates so a future refactor can't quietly regress them.
</objective>
