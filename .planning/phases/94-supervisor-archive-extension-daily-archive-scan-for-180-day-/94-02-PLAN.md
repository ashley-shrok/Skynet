Purpose: The three-step order is load-bearing. Move-first (D-10) removes the identity from the active tree so the supervisor's own keep-alive loop can no longer race and relaunch it during Steps 2 and 3 — this is the core failure-mode defense per shape file § "What would make it wrong": "a dead matrix account with the folder still in the active tree (agent-supervisor thrashing to keep a dead identity alive) is worse than either alone." Kill-second (D-11) tears down any live process holding the identity before the credential-consuming Step 3. Deactivate-third (D-12) uses the identity's OWN credentials from the now-archived relay.json — never an admin token — because the fleet property that no managed box holds a homeserver admin key must be preserved. Each step is idempotent by construction so the retry-from-top pattern (D-13) is safe on any partial-failure retry.
