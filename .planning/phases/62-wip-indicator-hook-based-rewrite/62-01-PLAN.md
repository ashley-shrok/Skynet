<objective>
Author the two hook shell scripts + their vitest coverage. Both scripts read the harness JSON payload on stdin, extract session_id via a strict character-class regex (path-traversal defense mirrored from the existing stop-hook.sh line 47), and atomically touch a well-known per-session marker file — activity marker for activity-hook.sh, stopped marker for stopped-hook.sh. Purpose: These two scripts are the leaf-level primitives that the Plan 62-02 installer drops onto each managed box, and that the Plan 62-03 backend predicate reads via `stat -c %Y`. They are the entire mechanism by which the harness's lifecycle events become observable server-side state. Getting the file-system contract, path-traversal defense, and fail-open behavior right at this layer means every downstream layer (installer + backend + frontend) sees a single, well-defined signal source — matching the shape's philosophy of "subscribe to authoritative signals and read them directly."

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| harness → hook script stdin | Harness JSON payload is untrusted input from the perspective of the shell script — session_id and other fields could carry attacker content if the harness is compromised. |
| hook script → managed-box filesystem | The script writes marker files under `$HOME`. Path-traversal via a malicious session_id could touch/create files outside the intended marker root. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-62-01-01 | Tampering | activity-hook.sh / stopped-hook.sh session_id extraction | mitigate | Strict bash regex `[a-zA-Z0-9_-]+` on session_id — mirrors the existing stop-hook.sh line 47 defense. Any path-traversal metacharacter (`/`, `.`, `..`, `\`) fails the regex and skips the touch. Verified by Test D + Test E in both test files. |
| T-62-01-02 | Denial-of-Service | Hook script blocking harness turn-completion | mitigate | Outer `timeout 2 bash -c '...' || true` wrapper mirrors stop-hook.sh line 37 — even a full disk or hung mount cannot block the hook indefinitely. Script exits 0 regardless of inner failure. |
| T-62-01-03 | Repudiation | Missing session_id / malformed payload silently ignored | accept | Fail-open discipline is the correct choice per shape §Philosophy — the alternative (fail-closed with logging) would (a) block harness turn-completion on stderr writes and (b) offer no downstream consumer for the log entries (the backend does not read hook-script logs). If a hook fires without a session_id, the affordance simply misses that event; the next event with a valid session_id re-establishes the signal. |
| T-62-01-04 | Elevation-of-Privilege | Shell-metachar session_id executing commands | mitigate | Character-class regex forbids `$`, `` ` ``, `;`, `(`, `)`, `&`, `|`, `>`, `<`, `\n`, `\t`, space — the extracted `sid` is a bash-variable containing only regex-allowed chars, then interpolated into a double-quoted path. Even if bash's `${sid}` expansion were mishandled, the character set is too restrictive to form an executable command. Verified by Test E ($HOME-intact assertion). |
</threat_model>
