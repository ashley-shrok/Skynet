<objective>
Teach the frontend to consume the two new marker mtimes from Plan 62-03 and compute isWorking via the direct-signal predicate `activityMtime > stoppedMtime` when available. Preserve the existing Phase 59 shell-idle-gate predicate as the fallback branch (Option-1 rollout per CONTEXT.md §Rollout, LOCKED for this phase) for sessions on managed boxes that have not yet received the Plan 62-02 installer. Remove the `bg = backgroundTasks.length > 0` axis from the isWorking composition IN THE UPGRADED-BOX DIRECT-SIGNAL BRANCH ONLY — the shape locks the direct-signal predicate to marker mtimes alone. In the fallback branch, `bg` is PRESERVED byte-for-byte to keep unupgraded-box behavior identical to the current Phase 59 predicate (Option-1 rollout's core promise). `backgroundTasks[]` remains on the wire for orthogonal consumers per §Out of scope.

Purpose: This is the plan where the affordance stops lying. Sessions on boxes that have been re-installed with the Plan 62-02 hooks will drive isWorking via the direct signal — no state machine, no smoothing, no oscillation. Sessions on unupgraded boxes continue to drive isWorking via the existing Phase 59 predicate (which has the bug motivating this phase, but Ashley has adapted to it — the blast-radius rule from CLAUDE.md forbids all-at-once retire-and-replace).

Output: Two mirrored type-file additions + one state-store predicate rewrite + comprehensive test coverage. No visual/UI changes (per planning_context — --skip-ui gate applies; this plan touches TS type files + a state store, no components/CSS/render code). The hook signatures (`useSessionIsWorking`, `useSessionIsWorkingRaw`, `useSessionIsDormant`, `useSessionIsRecycling`) all remain byte-identical — the change is internal to the store's predicate.

## Predicate — full specification

Priority order (top wins):
1. **Direct-signal branch** — if `activityMtime !== null || stoppedMtime !== null` (at least one marker mtime present, box has been upgraded via Plan 62-02):
   a. If `activityMtime === null && stoppedMtime !== null` → `isWorking = false` (stop-only observed).
   b. If `activityMtime !== null && stoppedMtime === null` → `isWorking = true` (activity-only observed — no stop means still working).
   c. If both are numbers → `isWorking = (activityMtime > stoppedMtime)`.
   In this branch, `bg` (backgroundTasks.length > 0) does NOT contribute to `isWorking` — the shape's §Philosophy locks the direct-signal predicate to marker mtimes alone (`backgroundTasks[]` stays on the wire per §Out of scope, but no longer feeds the WIP composition on upgraded boxes).
2. **Fallback branch** — otherwise (both mtimes null: no direct signal available, box has NOT been upgraded via Plan 62-02):
   → Execute the EXISTING Phase 59 predicate BYTE-FOR-BYTE, including the `bg` term: `main = (status === "busy") || (status === "shell" && (lastStopAt === null || (lastStatusChangeAt !== null && lastStatusChangeAt > lastStopAt)))`, `bg = state_arg.backgroundTasks.length > 0`, `isWorking = main || bg`. This is Option-1 rollout's core promise per CONTEXT.md §Rollout: unupgraded boxes see zero behavior change. A session currently driven by long-running background tasks (`status=idle`, `bg=true`) continues to show `isWorking=true` on unupgraded boxes — dropping `bg` here would silently flip such sessions to idle, which IS the behavior change Option-1 explicitly promised not to make. The `bg` retirement happens ONLY on upgraded boxes (branch 1), where the direct signal supersedes it; and fleet-wide once the follow-up phase retires the fallback branch entirely.

The `waiting` status axis is preserved — it feeds the separate `session-waiting-store` and is not part of isWorking on either branch (unchanged from current behavior).
</objective>
