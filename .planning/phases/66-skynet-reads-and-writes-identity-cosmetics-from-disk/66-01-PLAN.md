<objective>
Track BIRTH — Skynet's identity-birth-orchestrator emits richer on-disk frontmatter (displayName, title, colorHue, voice, avatar) and writes the uploaded avatar bytes as a sibling file <key>.<ext> inside the identity folder on the target host, over the same SSH connection that already handles Step 2.5's role-frontmatter pre-write.

Purpose: Post-Phase-A the fleet's on-disk identity files carry the full cosmetics schema. Skynet's own birth flow is the ONE remaining place that creates identities without emitting that schema — this plan closes that gap so a Skynet-born identity is byte-shape-indistinguishable on disk from a Nelly-migrated one. This is the READ path's prerequisite (Plan 03): READs derive cosmetics from disk, so BIRTH must put them there.

Output: Grown `identityFileBody` builder in the orchestrator + a new binary-safe SFTP write helper in the artifact-reader + wiring in the SSE route + extended test coverage in the existing role-frontmatter test file + a new describe block in the remote-writes test file pinning the atomic-rename discipline on the avatar writer.
