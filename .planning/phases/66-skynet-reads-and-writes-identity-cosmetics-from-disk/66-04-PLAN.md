<objective>
Migration — drop the seven cosmetic columns from the `identities` table now that Plans 01/02/03/05 have eliminated all runtime reads and writes of them. The row survives as the ownership + user-scoping + timestamp anchor.

Purpose: Closes the shape file's final commitment — "Skynet stops OWNING those values". As long as the columns physically remain, dev-time confusion + future-drift risk stay high (someone might re-introduce a read/write path "just because the column is there"). Dropping the columns makes the disk-authoritative model structurally enforced.

Output: (a) Drizzle schema typing narrowed to surviving columns. (b) db/index.ts CREATE TABLE updated for fresh installs, and migrateSchema() extended with an idempotent ALTER TABLE DROP COLUMN block that safely no-ops on fresh installs and asserts SQLite version support up-front. (c) POST / + birth + clone insert paths pruned of the dropped columns; identity-share.ts insertRow literal pruned. (d) BirthDeps.getIdentityRecord return type narrowed + the birth-orchestrator's GET-verify collapsed to a row-existence sentinel. (e) publicIdentity() constructors in identities.ts + identity-clone.ts PRESERVE Plan 03's safe-defaults contract (`displayName=capitalizeFirst(identityKey)`, `avatarMime=""`, `avatarEtag=""` for the non-nullable Identity type fields; `title=null`, `colorHue=null`, `voice=null` for the nullable ones). Do NOT null-echo the three non-nullable fields — that would break TSC by contradicting the Identity type declared in `src/ui/api/identities-api.ts`. (f) New migration test covering the old-schema-boot → drop → survives-columns-intact contract + SQLite version preflight.
</objective>
