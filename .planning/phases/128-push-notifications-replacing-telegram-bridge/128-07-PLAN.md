<objective>
The user-facing opt-in surface + deep-link plumbing that makes the push loop reachable end-to-end from the PWA. Three pieces:
1. EnableNotificationsButton — user-gesture-gated opt-in button that runs the browser subscription flow.
2. push-subscription-api — thin fetch wrappers for GET /vapid-public-key + POST /push-subscriptions.
3. AppShell — reads the `?openRoom=<roomId>` query param the service worker (Plan 04) navigates to on notificationclick, and opens the corresponding room's pane.

Purpose:
- D-10 opt-in flow requires user gesture (iOS PWA constraint)
- D-11 subscription persisted per-user-per-device
- D-08 tap-to-open-in-room deep-link
- D-12 no in-app off toggle (system-level control suffices)

Output: Frontend slice + AppShell wiring + colocated tests. This is the last consumer-side surface before the phase is end-to-end.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Notification permission grant | User gesture is the authorization; iOS enforces user-gesture requirement |
| URL query param (openRoom) → programmatic room open | Untrusted input; malformed roomId must not crash the app |
| Browser subscription credentials → backend POST | JWT cookie via credentials: "include" |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-126-35 | Elevation of Privilege | requestPermission not inside onClick tick → iOS silently blocks | mitigate | Grep-verified in acceptance_criteria: no `await` before Notification.requestPermission in the onClick handler; task test asserts synchronous invocation |
| T-126-36 | Denial of Service | Malformed openRoom param crashes AppShell mount | mitigate | Basic shape regex check + try/catch on programmatic open; test case covers empty + whitespace |
| T-126-37 | Repudiation | User cannot re-enable notifications after silent iOS rotation | mitigate | Button placed in reachable surface (settings menu) per Pitfall 1 — user can re-trigger the flow to mint a fresh subscription |
| T-126-38 | Confidentiality | ?openRoom param retained in browser history + shared URLs | mitigate | window.history.replaceState strips the param post-open so a copy of the URL after arrival does not embed the roomId; also prevents refresh-triggered re-opens |
| T-126-39 | Availability | Button placed in a hidden path (e.g. dev-only menu) → users can't opt in | mitigate | Task placement is settings/gear menu — visible in normal navigation; recommended over header slot for clutter reasons but visibility is preserved |
