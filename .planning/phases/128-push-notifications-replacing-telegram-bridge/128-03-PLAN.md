<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Untrusted Matrix event.content → preview-text derivation | Body / filename fields could be adversarial |
| Cross-user identity appearance lookup | Wrong identity resolution would mis-attribute the notification title |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-126-12 | Denial of Service | Adversarial 10-MB event.content.body | mitigate | 100-char truncation in derivePreviewText caps memory; upstream Matrix homeserver already enforces event-size limits |
| T-126-13 | Information Disclosure | Filename in preview leaks path structure | accept | Filename is already the user's own content (agent sends the file); D-07 says mirror app rendering — the app already shows filenames |
| T-126-14 | Spoofing | Sender-mxid spoofing via unresolvable identity | mitigate | Fallback to mxid local-part is deterministic + verifiable; the resolveIdentityAppearance cascade is the same one used by the app UI so a mismatch would be caught by any user familiar with the source |
| T-126-15 | Tampering | Preview text rendered on lock screen leaks another user's DM content | mitigate | The trigger loop (Plan 06) filters by `harness_dm` classifier per D-02 — only the human party in a 1:1 DM gets the notification for that room; cross-user leak is prevented at the filter stage, not here |
</threat_model>
