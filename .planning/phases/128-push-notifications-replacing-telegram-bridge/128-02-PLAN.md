<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Backend Node process → web-push npm package | Crypto library boundary; malicious replacement = full spoofing capability |
| Backend Node process → push_subscriptions DB rows | Reads capability URLs; any leak = anyone can send push to those endpoints (with VAPID) |
| Backend Node process → Push provider (fcm.googleapis.com / web.push.apple.com) | Egress; failures gracefully absorbed |
| Environment (process.env) → VAPID keys | Boot-time secret loading |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-126-SC | Tampering | npm install web-push | mitigate | Blocking-human legitimacy checkpoint (Task 1) verifies web-push-libs org + DefinitelyTyped provenance before install. `workflow.auto_advance` does NOT bypass this checkpoint. |
| T-128-06 | Spoofing | VAPID private key handling | mitigate | Loaded from env only; never logged; never written to disk by this code. Boot-time fail-fast on missing/malformed subject (Pitfall 2). |
| T-128-07 | Information Disclosure | endpoint URL logging | mitigate | All log paths use `endpoint.slice(0, 40)` truncation — Security V8 discipline. Verified via grep in acceptance criteria. |
| T-128-08 | Cryptography | Hand-rolled encryption of push payload | mitigate | web-push handles aes128gcm content-encoding + VAPID ES256 JWT signing + ECDH ephemeral keypair. NO custom crypto in this codebase. |
| T-128-09 | Denial of Service | push-sender.ts throws in Wave 2 trigger loop | mitigate | Never-throw contract enforced by tests; all catches are inside the sender; forceSave failures are absorbed to .warn. |
| T-128-10 | Denial of Service | forceSave storm on happy-path sends | mitigate | `if (prunedAny)` gate — forceSave only fires when at least one row was DELETEd. Successful sends do NOT churn disk. |
| T-128-11 | Denial of Service | Subscription-per-user count grows unbounded | mitigate | UNIQUE(user_id, endpoint) at Plan 01 schema level; 410-prune at this plan; ON CONFLICT DO NOTHING at Plan 05 route level. Three-layer defense. |
</threat_model>
