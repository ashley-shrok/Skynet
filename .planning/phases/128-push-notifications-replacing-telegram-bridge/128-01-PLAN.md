<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| DB write path → in-memory SQLite | Schema changes affect all subsequent inserts; malformed schema = silent data loss |
| Drop-migration → previously-populated table | Destructive on hit; per D-20 explicitly accepted |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-128-01 | Tampering | pushSubscriptions FK | mitigate | ON DELETE CASCADE on user_id — orphaned rows impossible; enforced at schema level |
| T-128-02 | Information Disclosure | endpoint column storage | mitigate | Column is stored in in-memory SQLite + DatabaseFileEncryption at rest; NEVER logged in full (log truncation is Plan 02's responsibility on the send side) |
| T-128-03 | Denial of Service | UNIQUE(user_id, endpoint) missing | mitigate | UNIQUE index enforced at CREATE TABLE time — duplicate registrations become ON CONFLICT DO NOTHING (route-level Plan 05 handles this) |
| T-128-04 | Denial of Service | telegram_bot_tokens drop fails mid-flight | accept | Drop wrapped in existing runXxxDrop error-catch pattern; boot continues on failure per file convention; operator sees warn log |
| T-128-05 | Repudiation | Destructive drop of populated table | accept | D-20 documents user acceptance of destructive shutdown; drop is idempotent (no-op on miss) so re-running boot is safe |
</threat_model>
