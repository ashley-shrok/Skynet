<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client (browser) → POST /push-subscriptions | Untrusted body; auth via JWT cookie |
| Client (browser) → GET /vapid-public-key | Untrusted request; public key is public |
| nginx HTTP + HTTPS → backend :30001 | Two configs to keep in sync (Pitfall 5) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-126-21 | Elevation of Privilege | Attacker registers subscription for another user's userId by putting userId in body | mitigate | userId sourced from `authReq.userId` (JWT-verified), request body's userId (if any) is ignored — V4 discipline enforced |
| T-126-22 | Denial of Service | Attacker floods POST to fill push_subscriptions | mitigate | authenticateJWT gate limits to real users; express.json({limit:"8kb"}) caps body; ON CONFLICT DO NOTHING prevents duplicate row explosion; UNIQUE index (Plan 01) caps per-(user,endpoint) at 1 |
| T-126-23 | Input Validation | Malformed subscription body crashes backend | mitigate | Zod SubscriptionSchema validation returns 400 on shape mismatch; endpoint URL length capped at 2048; keys regex-capped |
| T-126-24 | Information Disclosure | Endpoint URL logged in full | mitigate | Log calls use endpoint.slice(0, 40) — same discipline as push-sender.ts; test asserts warn log's endpoint arg is truncated |
| T-126-25 | Availability | nginx block added to HTTP conf only → HTTPS deploys return index.html on API POSTs | mitigate | Dual-conf caveat enforced in acceptance_criteria: both files MUST have the block; verified by grep count == 1 in each file |
| T-126-26 | Confidentiality | GET /vapid-public-key leaks the private key by accident | mitigate | Handler explicitly returns only `{publicKey}` — no private-key path in the handler; test asserts response body has no `privateKey` field |
</threat_model>
