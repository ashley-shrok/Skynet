<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Push service (fcm/apple) → service worker | Payload data trusted only to the extent that our own backend encrypted it with our VAPID key; malformed payload = safe-fallback path |
| Service worker → backend /push-subscriptions | JWT cookie carries auth; endpoint is capability URL (privacy-sensitive) |
| notificationclick → browser navigation | User consent (tap) is the authorization signal |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-126-16 | Denial of Service | Malformed push payload crashes SW handler | mitigate | JSON.parse fallback to `{title: "SKYNET", body: ""}`; showNotification always called; Pitfall 3 discipline enforced |
| T-126-17 | Availability | Silent-push subscription revocation on iOS | mitigate | Every push handler branch calls showNotification (never silent); tag-per-room + event.waitUntil ensures iOS-side compliance |
| T-126-18 | Denial of Service | notificationclick opens too many windows | mitigate | clients.matchAll + focus first-existing-window before openWindow; tag-per-room stacks notifications so click count is bounded per conversation |
| T-126-19 | Spoofing | pushsubscriptionchange re-registers with attacker credentials | mitigate | `credentials: "include"` carries the user's actual JWT cookie; backend's authenticateJWT gate at Plan 05 validates the user-id — attacker cannot re-register on someone else's account |
| T-126-20 | Cryptography | applicationServerKey re-used across rotation | accept | oldSubscription.options.applicationServerKey is the same VAPID pubkey we own — re-using is intended and correct per MDN pushsubscriptionchange docs |
</threat_model>
