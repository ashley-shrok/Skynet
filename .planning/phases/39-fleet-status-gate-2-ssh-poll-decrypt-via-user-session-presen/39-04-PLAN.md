## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Backend → target host filesystem | installStopHook writes ~/.claude/hooks/skynet-fleet-status-stop.sh + updates ~/.claude/settings.json via SSH exec (atomic .tmp + mv per remote-hook-install.ts:181-260). Path is a compile-time const — no user-input in exec commands (RESEARCH §Security §Known Threat Patterns Stop-hook shell injection: mitigated). |
| Backend → orchestrator poll loop | Fire-and-forget install call decouples install lifetime from poll lifetime. Install failure cannot block subsequent poll ticks. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-39-11 | Elevation of Privilege | Remote script execution via installStopHook | mitigate | Uses `installStopHook(channel, opts)` from Phase 34 Plan 04 — canonical implementation with heredoc-quoted writes, fixed compile-time path, .tmp/mv atomic swap, invalid-JSON safeguard. Phase 39 does NOT re-implement any part of the install — it only calls the existing helper. RESEARCH §Security confirms path is a compile-time const, no user input crosses the boundary. |
| T-39-12 | Denial of Service | Repeated install attempts spam SSH | mitigate | hookInstallAttempted Set enforces install-once-per-lifecycle. Even across lifecycles, installStopHook's readAndMergeStopHookSettings alreadyInstalled short-circuit means second run is 5 read-only SSH exec calls with no writes (remote-hook-install.ts:251-260). Wasted round-trips are cheap. |
| T-39-13 | Tampering (settings.json race) | Concurrent stop-hook install writes | mitigate | Install-once-per-lifecycle Set prevents concurrent installs against the same host from the same starter process. Cross-process concurrency (impossible on this single-container box) would also be safe: readAndMergeStopHookSettings is idempotent and .tmp+mv is atomic on POSIX. |
| T-39-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages — Phase 39 is a pure in-tree refactor. RESEARCH §Package Legitimacy Audit "Not applicable". |
