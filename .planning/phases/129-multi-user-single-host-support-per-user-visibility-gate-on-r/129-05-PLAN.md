<objective>
Close the WS surface leak per D-7. The `AppFrameFilter` (created in Phase 118 Plan 118-05) currently gates every frame on host access via `canUserSee(hostIdStr)`. Every frame type that carries an identity name also needs to gate on the identity's visibility — otherwise a hidden identity's live status heartbeat / archive event / project change leaks through the WS to a user who should not see it (shape §"What would make it wrong" bullet 2 — "orphan indication that a process is running").

Purpose: Wave-2 closer for the WS surface. Together with 129-02/03/04 the deep gate covers every "YES" row in RESEARCH's no-leak audit table.

Two-file split (app-frame-filter.ts + fleet-status-server.ts) is unavoidable because the filter file MUST stay free of DB and SSH imports per its own file-header discipline (L66-68). The gate resolver is injected as a closure from the production wiring site (fleet-status-server.ts).

Output: filterAppFrame extended with identity-gate branches on 5 frame types + injected resolveIdentityGate closure + tests covering each frame branch and fail-closed resolver-error path.
</objective>
