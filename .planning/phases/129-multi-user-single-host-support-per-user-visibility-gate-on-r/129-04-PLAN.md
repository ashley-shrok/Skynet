<objective>
Close the search-surface leak per D-7. `conversation-search.ts` currently reads across `~/fleet/identities/` and `~/fleet/identities-archive/` on every host the caller has access to (RESEARCH Pitfall 4). Without a gate, a hidden identity's transcript matches a query, its identityKey + hostId leak in the response — the D-7 "if the gate hides you, the gate hides you everywhere" invariant fails.

Purpose: Wave-2 closer for the search surface. With this plus 129-02 (/identities), 129-03 (/sessions + /roles-picker), and 129-05 (WS frames), every "YES" row in RESEARCH's no-leak audit table is covered.

Key design choice per RESEARCH § Pitfall 4: batch-fetch the identity+role frontmatter for the UNIQUE identityKeys in each host's result page — O(unique identities in the response) not O(all identities on the host). Result count is bounded by DEFAULT_LIMIT, so the SSH cost stays predictable.

Fail-closed exception documented per PATTERNS.md § Shared Patterns "Read-path fail-open, write-path fail-closed" — the search surface is an INFORMATION-DISCLOSURE risk where a leaked hit is more visible than a dropped hit; opposite of list endpoints where a dropped row would feel like a broken product.

Output: conversation-search.ts POST handler extended with per-request callerUsername + per-host batched gate lookup + post-filter, with matching integration tests.
</objective>
