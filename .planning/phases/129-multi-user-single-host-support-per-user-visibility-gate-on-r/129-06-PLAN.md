<objective>
Implement the write-side half of D-4 for role creation. When a user creates a new role via `POST /roles` on a host with more than one Skynet user with access, backend auto-tags the role file's frontmatter with `users: [creatorUsername]`. On single-user hosts, no auto-tag — file looks exactly like a pre-129 role file (D-4 + shape §"invisible in the majority case").

Design guardrails per D-5 + RESEARCH Pitfall 5:
- Auto-tag runs AFTER the collision probe (L472-496) — it never touches an existing file.
- Auto-tag runs INSIDE the initial yaml.dump build path — no separate "add username to existing frontmatter" helper that could accidentally be called on a live file.
- Never rewrites values on existing files (PUT /roles or elsewhere).

Purpose: Wave-3 write-side seam. Together with 129-07 (identity-birth auto-tag), this makes new roles + identities on shared hosts self-managing per shape §"self-managing in the shared case".

Output: roles-create.ts POST handler extended with the 3-line pre-yaml.dump auto-tag branch + matching integration tests.
</objective>
