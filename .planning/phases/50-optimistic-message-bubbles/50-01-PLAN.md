<objective>
Teach the JSONL parser to treat a normal-content `type:"queue-operation"` + `operation:"enqueue"` entry as a first-class `kind:"message"` (role:"user") emission, and add per-session dedup so the queued message does not render twice when the harness later re-emits it as a normal `type:"user"` turn on dequeue.

Purpose (D-09/D-10/D-11 from 50-CONTEXT.md): This is the backend half of the "specific signal that makes optimistic bubbles honest" — the frontend spinner clears the instant the harness accepts a message, whether it processed straight away (normal user turn) or slotted the message into its own queue (enqueue entry). Load-bearing invariant: exactly ONE message frame per accepted user message, regardless of the two shapes the harness writes.

Output: Extended parser branch + per-session dedup Map + unit tests. No wire-protocol change (existing `MessageEvent` shape reused).

**Hash-derivation contract (load-bearing across Plans 50-01, 50-02, 50-04):** This plan introduces TWO DISTINCT hashes that must NOT be conflated:
- `eventId` = sha256(`${sessionId}\n${timestamp}\n${content}`).slice(0, 32) — used ONLY by the frontend per-eventId dedup Set (Plan 50-03) so a re-play of the same enqueue line collapses. Includes sessionId + timestamp because it is the frontend's line-level dedup key.
- `contentHash` = sha256(content).slice(0, 32) — content-only. Used by BOTH the parser's dedup Map key (this plan, Task 2) AND the watchdog's arm-time key + notifyMatched key (Plan 50-02) AND the integration test helper (Plan 50-04). Content-only because the enqueue timestamp (~T+0) and the later dequeue timestamp (~T+2min) are different, so any timestamp-inclusive key would fail to match across the enqueue→dequeue span.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tmux JSONL file → parser | Session file is written by the local Claude Code harness on the remote host; content strings can contain arbitrary UTF-8 including markdown, XML-like wrappers, and null bytes. Parser must not allow content strings to escape their JSON string context or to be interpreted as shell input. |
| parser output → WebSocket frame | ParsedLine content is forwarded verbatim in the MessageEvent.content field to the frontend; existing PrettyView render path handles sanitization (react-markdown default disables raw HTML, no XSS surface). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-50-01-01 | Tampering | queue-operation enqueue parsing branch | mitigate | The new branch reads only `obj.type`, `obj.operation`, `obj.content` — no shell interpolation, no filesystem access, no network egress. Content string is passed through unchanged to the same wire path the existing user-turn branch uses (already sanitization-tested via PrettyView react-markdown default). |
| T-50-01-02 | Denial-of-Service | queueEnqueueDedup Map | mitigate | Map is capped at 100 entries with oldest-first eviction and 10-minute lazy TTL. Memory footprint bounded at ~100 * (~48-byte key + 8-byte value) = ~5.6KB per session. |
| T-50-01-03 | Repudiation | Dedup key collision (contentHash truncation) | accept | 32-hex-char sha256 truncation yields 128-bit collision resistance; the per-session Map bound + 10-minute TTL keep the entry-space small. A collision would result in a legitimate second message being suppressed — surfaces as a "missing bubble" bug, not a security event. |
| T-50-01-04 | Information Disclosure | sessionId passed to parseSessionLine | accept | sessionId is already available to the tail-watcher and is used only for local hash derivation of the eventId (never logged in the deterministic-eventId path beyond the standard session-classify info log; no PII in sessionId). Note the contentHash uses content only — sessionId is NOT part of the dedup key. |
| T-50-01-SC | Tampering | npm/pip/cargo installs | mitigate | Zero new dependencies added (uses node's built-in `crypto` module for sha256). No package legitimacy gate required. |
