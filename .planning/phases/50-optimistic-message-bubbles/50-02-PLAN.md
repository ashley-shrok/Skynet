<objective>
Rip out the PTY-activity-proxy send watchdog on the terminal-layer send path (patch quick 260803-1xw) and replace it with a signal-driven watchdog on the claude-session WS that keys off the same parser emission Plan 50-01 introduces. Same three-stage escalation shape (retry Enter → full re-send → give-up-and-emit-frame) with a specific-signal trigger instead of the noisy PTY-activity proxy.

Purpose (D-12 through D-17, D-21 from 50-CONTEXT.md): The existing watchdog "occasionally concludes wrongly" because PTY-activity is a proxy for "the Enter landed" that mis-fires on unrelated pane output. The new watchdog fires the retry only when the specific "harness accepted the message" signal (kind:'message' role:'user' from either the direct or the enqueue path) has NOT arrived — the same signal that clears the frontend spinner in Plan 50-03. One signal, two consumers, no drift.

Output: New watchdog module + tests + wiring in the claude-session-server input handler + removal of the old terminal-layer watchdog. The wire shape `paste_send_failed` is PRESERVED for frontend backward compatibility; a new sibling `send_keys_error` frame is added for the D-21 execCommand-throw path.

**Hash-derivation contract:** This plan's watchdog uses `contentHash = sha256(content).slice(0, 32)` (content-only) as BOTH the arm-time key and the notifyMatched match key. This derivation MUST be byte-for-byte identical to Plan 50-01 Task 2's dedup Map key derivation — if the two drift, watchdogs never notify and every real send escalates through the full timing chain even on the happy path. See 50-01-PLAN.md § objective "Hash-derivation contract" for the full statement.
</objective>
