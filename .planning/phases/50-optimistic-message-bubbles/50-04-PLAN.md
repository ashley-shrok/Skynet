<objective>
In-process end-to-end integration tests that wire the four seams from Plans 50-01, 50-02, and 50-03 (backend-side) together and exercise every path described in D-22 under fake timers. Deliberately NOT a frontend UAT — this is the backend correctness gate for the signal contract that the frontend consumes. The frontend-side D-22(f) latest-only test lives in Plan 50-03's PrettyView.optimistic-bubbles.test.tsx (Test 14 in the Task 3b block) and is verified by cross-referencing rather than re-tested here.

Purpose (D-22, D-23 from 50-CONTEXT.md): Unit tests on each seam individually cover their internal contracts. This plan verifies the contracts compose correctly — the parser's dedup + the watchdog's notifyMatched + the input handler's arm all agree on the same content-hash derivation and the same session-scope. If any pair drifts (e.g., dedup uses per-session-scope but notifyMatched uses per-mqid-scope), unit tests pass but the composition breaks; only an integration test catches it.

**Hash-derivation contract:** This plan's `computeContentHash` helper MUST match Plan 50-01 Task 2's dedup Map key derivation AND Plan 50-02 Task 1's watchdog arm-time key derivation byte-for-byte: `sha256(content).slice(0, 32)` — content-only, no sessionId, no timestamp. Warning #9 (checker iteration 1) revised the parser dedup from a ±2-second-bucket key to a content-only key with 10-minute wall-clock TTL after empirical evidence showed enqueue→dequeue spans of ~2 minutes; scenario (b) below uses that empirical 2-minute span to prove the fix holds. This derivation is DIFFERENT from Plan 50-01 Task 1's eventId derivation (which uses sessionId+timestamp+content).

Output: One new integration test file with 7 scenarios (a-g from D-22). Plus a light adaptation pass to make sure D-23 holds — no wholesale test deletion, only comment-text assertions updated where the new breadcrumb replaced the COMPOSE-04 HARD LOCK.
