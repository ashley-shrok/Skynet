<objective>
Ship the entire backend surface for Phase 44 skill editing: the 7-endpoint Express router at `src/backend/database/routes/skills-editor.ts`, its Vitest test file, the router mount in `database.ts`, and the twin nginx `location ~ ^/skills-editor(/.*)?$` blocks in BOTH `docker/nginx.conf` AND `docker/nginx-https.conf`. This wave delivers every backend capability the Wave 2 frontend will call.

Purpose: give the frontend a mirror of Phase 23's global-files backend surface, with the one novel dimension a skill picker introduces (per-user path-safety gate replacing Phase 23's static JSON whitelist) — implements D-14 (plain-editor rule), D-15 (scope discipline), D-16 (7 endpoints), and enables D-07..D-11 (text edit, non-text placeholder, add file, delete file, delete skill) from the frontend layer.

Output: production-ready backend that:
- Enumerates skills on a host (`GET /skills-editor/skills`)
- Enumerates files inside a skill recursively with path-relative labels (`GET /skills-editor/files`)
- Reads a file with isText byte-sniff detection (`POST /skills-editor/read`)
- Writes a file atomically with mtime-conflict 409 protocol (`PUT /skills-editor/write`)
- Creates an empty file, rejecting duplicates with 409 (`POST /skills-editor/create`)
- Deletes a file idempotently (`DELETE /skills-editor/file`)
- Deletes an entire skill folder (`DELETE /skills-editor/skill`)
- Rejects every path-escape attack input with 400 BEFORE opening SSH
- Reaches the backend from the browser in both HTTP and HTTPS Skynet environments (nginx location blocks in both configs)
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → nginx | User-supplied `hostId` (query), `skill` (query/body), `path` (body), `content` (body), `expectedMtime` (body) cross from the untrusted client into the reverse proxy. |
| nginx → Express | Requests cross the container-internal proxy_pass boundary — auth cookies + payload arrive intact. |
| Express handler → SSH exec / SFTP channel on managed host | User-supplied `skill` and `path` values are composed into remote shell commands (`cat`, `stat`, `find`, `rm -f`, `rm -rf`, `touch`, `mkdir -p`) and SFTP write paths. This is the highest-severity boundary in the phase — a bypassed gate could `rm -rf ~/`. |
| Express handler → Skynet SQLite (via `resolveHostById`) | userId (extracted from validated JWT) queries the host-credential store — never accepts unvalidated user input. |
