<objective>
Extend the conversation-store's data source from "browser-tab's openTabs mirror" to "fleet-discovered tmux sessions unioned with openTabs (deduplicated by session identity)" and wire the fleet-discovery signal at page-load. Add a click-a-detached-row transparent-attach path that maps a fleet-only ConversationRow → Host lookup → openTab('terminal') + selectConversationDeferred, exactly reusing the tab-lifecycle machinery Phase 6 established. Zero visual distinction between attached and detached rows. Snapshot-on-load only — no polling, no interval, no focus/visibility refetch.

Purpose: TG-12, TG-13, TG-14, TG-17. Phase 6's UAT gap was that a fresh mobile page-load showed "no active conversations" even when the fleet had running tmux sessions. This plan makes the list mirror the fleet (like the current sidebar host-tree + double-shift menu already do), while preserving every Phase 6 chrome + persistence contract verbatim.

Output: An extended conversation-store with FleetSession input + host-flat lookup, unit-tested at the store level; ConversationsPanel row-click plumbing that distinguishes attached (has openTabs entry — direct selectConversation) from detached (fleet-only — resolve to Host + openTab + selectConversationDeferred); AppShell one-shot fetch + onDetachedRowClick handler. Zero user-visible RDP row rendering (that's Plan 07-02); zero visual pencil change (also 07-02); zero mobile gear fix (also 07-02). This plan is the DATA source reshape and the DETACHED-CLICK plumbing, isolated.
</objective>
