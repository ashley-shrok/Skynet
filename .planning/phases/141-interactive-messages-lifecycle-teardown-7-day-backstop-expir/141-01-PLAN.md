<objective>
Ship `teardown-widget.sh` — the agent-driven, one-command atomic teardown for
interactive-message widgets. Inverse of `create-widget.sh`: stops the systemd
unit, disables it, removes the unit file, removes the widget dir, and runs
daemon-reload so systemd forgets the freed port.

Purpose: Phase 141's core deliverable A. The seven-day backstop timer (Plan 03)
will shell out to this script, so it is the load-bearing foundation of the
lifecycle system. Agents also invoke it directly whenever they finish reading
a widget's state.

Output: A tested, substrate-shipped shell script agents can invoke as
`bash ~/.claude/skills/interactive-messages/teardown-widget.sh <slug>`
(after the next distributor sweep — but distribution wiring is Plan 03's job,
not this plan's).
</objective>

  <action>
Create `substrate/skills/interactive-messages/teardown-widget.sh` mirroring
create-widget.sh's shell conventions (set -euo pipefail, `log()`/`die()`
helpers with `[teardown-widget]` prefix, `SCRIPT_DIR` computation, executable
bit 0755 via `chmod +x` on the file after write).

Behavior (in order):

1. **Argv parsing.** Support both:
   - Positional: `teardown-widget.sh <slug>` (mirror create-widget.sh's Form A).
   - Flag: `teardown-widget.sh --slug <slug>` (mirror Form B).
   Additional flag: `--force` (boolean). Refuse unknown flags with a `die` call
   naming the correct usage.

2. **Slug validation.** Same regex as create-widget.sh: `^[a-z][a-z0-9-]*$`,
   max 40 chars. A slug that could not have been created is not a real teardown
   target — die with the same error text create-widget.sh uses.

3. **Path resolution.** Compute `WIDGET_DIR="$HOME/fleet/interactive-messages/$SLUG"`
   and `UNIT_FILE="$HOME/.config/systemd/user/im-$SLUG.service"`. These are the
   two pieces of on-disk state a create-widget.sh happy-path leaves behind.

4. **Existence check (skipped under --force).** If `--force` is NOT set, require
   AT LEAST ONE of `WIDGET_DIR` or `UNIT_FILE` to exist. If neither exists, die
   with `"no widget found for slug '<slug>' — pass --force to skip existence check"`.
   Rationale: without --force, a typo'd slug silently no-ops today is a bug —
   the agent needs to know their teardown was on nothing. With --force, the sweep
   (Plan 03) can invoke us blindly.

5. **Systemd stop + disable (fail-soft).** If `SKIP_SYSTEMCTL` env var is set to
   "1" (test-env escape hatch, matches create-widget.sh's convention), skip this
   entire block and log a note. Otherwise run:
     - `systemctl --user stop "im-$SLUG.service" 2>/dev/null || true`
     - `systemctl --user disable "im-$SLUG.service" 2>/dev/null || true`
   Both are fail-soft (`|| true`) — a widget whose unit was never enabled, or
   was already stopped, must not fail the teardown.

6. **Unit file removal.** `rm -f "$UNIT_FILE"` — unconditional (`rm -f` is
   idempotent). Log the path removed at DEBUG-equivalent level.

7. **Widget dir removal.** `rm -rf "$WIDGET_DIR"` — unconditional. Log the path.

8. **daemon-reload.** If `SKIP_SYSTEMCTL` != "1", run
   `systemctl --user daemon-reload 2>/dev/null || true`. Reason: systemd
   otherwise caches the removed unit's ExecStart and the port claim in
   create-widget.sh's `grep -h '^Environment=PORT=' im-*.service` scan would
   miss that this port is now free until next `daemon-reload`.

9. **Success output.** Print `TORN_DOWN=<slug>` to stdout (machine-parseable,
   matching create-widget.sh's `SLUG=` and `URL=` stdout convention). Log the
   summary to stderr.

Include a doc-comment banner at the top of the file summarizing the invocation
forms, exit conditions, and the SKIP_SYSTEMCTL escape hatch — parallel structure
to create-widget.sh's banner.

After writing, `chmod +x` the file so the git-committed mode is 0755
(distributor mirrors mode bits — see catalog.ts SHAPE docstring on
mode-preservation).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent shell → teardown-widget.sh argv | Slug values may be attacker-influenced if a compromised session invokes teardown |
| teardown-widget.sh → filesystem | rm -rf on a computed path |
| teardown-widget.sh → systemctl --user | Unit name derived from slug |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-141-01-SL | Tampering | slug argv | mitigate | Kebab-case + max-40 regex mirrors create-widget.sh — no `..`, no `/`, no shell metacharacters can pass validation. |
| T-141-01-RMWildcard | Tampering | rm -rf path | mitigate | Path is always `$HOME/fleet/interactive-messages/$SLUG` with SLUG regex-validated first — no traversal possible. |
| T-141-01-SystemctlInj | Tampering | systemctl unit arg | mitigate | Unit name is `im-$SLUG.service`; SLUG is already regex-validated. Same posture as create-widget.sh. |
| T-141-01-PartialStateDoS | Denial of Service | partial state from crashed create-widget | mitigate | Teardown fail-softs on missing systemd state AND missing filesystem state independently — cleans whatever exists. |
</threat_model>
