  <how-to-verify>
    **Prerequisite:** Ashley either (a) opens a Vite dev server locally (`cd ~/termix &amp;&amp; sudo npm run dev` — port varies, check terminal output) OR (b) builds + deploys the fork per deploy-runbook.md and opens https://term.gigaashley.click. Both work equivalently for visual UAT; dev server is faster for iteration.

    Open any Claude-Code-attached terminal tab in Termix (e.g. Tina's own pane) so the ComposeBox mounts (compose only mounts when `status === "streaming"`).

    **UAT checklist — walk each and note any misses:**

    1. **Rest height (2-tall shell).** ComposeBox at rest with empty textarea should read as ~2 button heights tall (top instrument row + bottom compose row + the outer wrapper's `px-2 py-2` padding). Roughly 64px + padding vs pre-Phase-9's ~96px + padding. If it looks like 3 rows instead of 2, something in Plan 09-01's row split is wrong.

    2. **Row 1 layout.** Top row, left-to-right: horizontal meter well (reset ⟲ button on the far left as the leftmost cell, then a strip of 12 segments filling to the right), a stretch of blank space (the flex-1 spacer for future buttons), then the aux button group on the right (👍 ThumbsUp and ⏳ Hourglass Queue on desktop; 📎 Paperclip prepended on touch).

    3. **Row 2 layout.** Bottom row, left-to-right: the textarea filling most of the width, the vibrant amber ▸ Send button on the right pinned to the textarea's bottom edge.

    4. **Horizontal meter fill L→R.** Watch the meter as Claude works and the context % climbs. Segments should light one at a time from the LEFT edge toward the right, using the green (low) → amber (mid) → red (high) color banding. If it fills top-down or right-to-left, Plan 09-02's iteration order is inverted.

    5. **Meter width feels right at 160px.** The meter should read as compact — not stretching across the whole row. If Ashley wants to tune, open DevTools, select the meter well div (find via `role="meter"` in the elements panel), and change the inline `--meter-width` custom prop live. If a different width feels obviously better, note it in the resume-signal — this is exactly the case the CSS var was exposed for.

    6. **Reset click drain sweep R→L.** Click the ⟲ reset cell (leftmost cell of the meter). Expected: (a) the reset cell holds lit-green during the ~800ms drain window, peaking with a pulse at ~420-770ms, (b) segments dim from RIGHT to LEFT (rightmost segment fades first, leftmost fades last), (c) the /id reset payload dispatches through the WS (Claude Code will show the session recycling — this is the existing patch #83 behavior). If the sweep runs L→R instead, Plan 09-02's `transitionDelay` formula is wrong.

    7. **Uniform button sizing.** All four aux + Send buttons on their respective rows should be visually the same size (icon-sm = 32×32). Only Send's vibrant amber gradient distinguishes it from the warm-neutral glass aux buttons. If Send looks obviously bigger or smaller than the aux group, someone violated the § Additional prototype-locked decisions #3 uniform-size rule.

    8. **Chip strip as Row 3.** Drag a small file (any PDF or text file) into the pretty view. Chip strip should pop above the top instrument row, showing filename + human size + × remove button. Removing the chip should remove the row entirely (Row 3 is ephemeral). If chips render in the wrong position (below Row 1 or below Row 2), the DOM order is wrong.

    9. **Mobile touch target.** Chrome DevTools → Toggle device toolbar (Ctrl+Shift+M) → pick an iPhone or Android profile. Because `useIsTouchDevice()` returns true, the 📎 paperclip button should appear in Row 1 and the top row should visually be taller — measure the top row's bounding box, should be ≥44px tall (Ashley can eyeball or use DevTools' inspect panel).

    10. **All existing behaviors still work.** Confirm each of the following still works exactly as before:
        - **Draft persistence:** type some text, refresh the tab, the text should reappear
        - **Send:** type "hello" and press Enter — should send and clear
        - **Shift-Enter:** Shift-Enter should insert a newline
        - **Queue button:** click ⏳ with text in the box — button should turn amber and pulse; the textarea shows the "Queued — waiting for idle" overlay
        - **Thumbs-up quick-send:** click 👍 without typing — should send the literal payload "yes" (visible in Claude Code); in the pretty-view stream, that user bubble renders as a ThumbsUp glyph
        - **Reset-send with text:** type some hint text, click ⟲ — should send `/id reset (hint text)` and trigger the drain sweep
        - **Attachment upload flow:** drop a file, chip appears with progress, upload completes, Send button becomes enabled even with empty caption text — pressing Send fires the injected user turn (visible in Claude Code)
        - **Retry button:** if an upload fails (e.g. simulate by dropping a huge file and killing the WS), a "Retry upload" button appears above the chip strip — clicking it re-issues the batch
        - **Error message on disconnect:** turn off WiFi briefly, press Enter — the "Not connected — try again in a moment" red text should appear below the compose bar
  </how-to-verify>
