## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| branding-store → WipBubble render | Same-origin in-memory read via useSyncExternalStore. `wipIndicatorPath` is guaranteed to be a string by Plan 82-03's isBrandingConfig shape guard + sentinel initial state. |
| WipBubble → DOM `<img src>` | The rendered src is a URL string that the browser fetches from the same-origin backend `/branding/*` route. Path-containment (V5/V12) enforced by Phase 70's resolveAssetPath — no new surface here. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-82-04-01 | Tampering | Operator-authored `wipIndicatorPath` value in `/etc/skynet/branding/branding.json` (e.g. `"javascript:alert(1)"` or an external-origin URL) | accept | Per 74-CONTEXT.md philosophy "Trust the admin who writes the branding config" — same disposition as Phase 70's iconPath / wordmarkPath / faviconPath, which are already used as `<img src>` / favicon href values without input sanitization. Operator has FS write access to the config; they already have root-equivalent capability. The React JSX renderer performs standard attribute escaping (no eval), and browsers do not execute `javascript:` URIs in `<img src>` per HTML spec. External-origin URLs would fetch cross-origin — no code execution, just a broken image. |
| T-82-04-02 | Denial of Service | wipIndicatorPath resolves to a missing asset (typo in operator config, deleted override file) | mitigate | Phase 70's resolveAssetPath returns `{ source: "missing" }` → route returns 404 → browser renders broken-image icon. Non-fatal — the surrounding PrettyView UI continues to function. Recovery is operator-side (fix the config / restore the file). Acceptance criteria for Plan 82-01 + 82-02 ensure the DEFAULT path (`/branding/wip-cube.webp`) always resolves to a real bundled file, so out-of-the-box deployments cannot hit this case. |
| T-82-04-03 | Information Disclosure | wipIndicatorPath value exposed to client via `/api/branding` response and rendered into the DOM | accept | Same public-URL disposition as Phase 70's iconPath / wordmarkPath / faviconPath. No PII, no credentials. |
| T-82-04-SC | Tampering | Zero new npm installs in this plan | accept | Pure JSX/TSX edit + one import statement — no package installs. |
