<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host operator → /opt/skynet/branding.json | Operator writes the config file on host; container reads bind-mounted read-only. Mount permissions determine who can rewrite the file post-deploy (typically root/operator). |
| Docker daemon → host filesystem (create_host_path) | Docker will create empty /opt/skynet/branding.json and /opt/skynet/branding on first container start if they don't exist. Ownership of the created empty artifacts is Docker-daemon-user (typically root). Non-issue for MVP: operator owns the box and can chown/chmod as needed. |
| nginx → backend (port 30001) | Requests to /api/branding, /branding/*, /manifest.webmanifest are proxied loopback (127.0.0.1). No network exposure of backend port; nginx is the only ingress. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-70-02-01 | Elevation of Privilege | create_host_path creates /opt/skynet/branding.json as root on first t1000 boot; if operator later needs to write it as non-root user, they need sudo | accept | Operator context. On t1000 the file never gets written (defaults are fine). On AI+ deploy, Ivy runs provisioning as root anyway. Non-issue for MVP. |
| T-70-02-02 | Denial of Service | Missing bind source without create_host_path would fail container start | mitigate | create_host_path: true on both bind entries — Docker creates empty file/dir if missing. Backend loader's ENOENT-is-normal contract (Plan 70-01) handles the empty-file case gracefully. |
| T-70-02-03 | Information Disclosure | Nginx serves /branding/foo.png with default MIME sniffing headers | accept | Backend sets Content-Type via res.sendFile (Express-inferred from extension) — nginx passes it through. No X-Content-Type-Options: nosniff added in this phase; consistent with other backend-proxied routes in the codebase. Deferrable enhancement. |
| T-70-02-04 | Tampering | Attacker overwrites /opt/skynet/branding.json to change displayed branding | accept | Requires host-level write access, which is out-of-scope (operator's server security). No integrity signing planned — branding is display-only, no auth/session impact. |
| T-70-02-05 | Denial of Service | Nginx proxy_pass without upstream failover — if backend port 30001 is down, /manifest.webmanifest 502s (whereas the old static-serve served regardless) | accept | Backend not being up is a broader outage; PWA manifest not loading is not the critical failure in that state. Skynet has no health-check-driven failover for other backend routes either; consistent behavior. |
| T-70-02-06 | Configuration drift | Only ONE of nginx.conf and nginx-https.conf edited — deployment goes out with mismatched routing | mitigate | Task 2 EXPLICITLY updates both files in the same commit. <done> gate requires grep counts to be equal across both files. CLAUDE.md nginx-caveat mirror rule encoded in three prior features (usage, skills-editor, relay-pointer) — Phase 70 continues the pattern. |
| T-70-02-SC | Tampering | Docker image tampering during build | accept | No new package installs, no new external image dependencies. COPY layers use only files from the build context (repo tree). |
</threat_model>
