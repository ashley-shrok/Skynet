<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| backend /api/branding response → frontend store | Network response is parsed as JSON and coerced through an inline shape guard before publishing. Malformed or unexpected shapes are dropped silently (retain defaults). |
| branding config values → DOM src attributes | iconPath/wordmarkPath/faviconPath values flow directly into <img src> and <link href>. Backend controls these strings; browser SOP prevents cross-origin loads unless nginx routes them, so injection surface is bounded to same-origin paths. |
| unauthenticated GET → module-singleton write | publishBrandingConfig is a module-scope writer that any code in the frontend bundle could call. Frontend code is trusted-in-scope (single bundle, no third-party plugins). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-70-03-01 | Tampering | Malformed /api/branding response causes JSON.parse throw or unexpected store state | mitigate | branding-fetch.ts wraps everything in try/catch; isBrandingConfig type guard rejects unexpected shapes; on any failure the store retains the bundled-default sentinel (never a partial or invalid state). |
| T-70-03-02 | Denial of Service | Very large /api/branding response body blocks the boot fetch | accept | Backend loader (Plan 70-01) caps config file at 256 KB via MAX_CONFIG_BYTES; the response body is bounded. Additional client-side response-size limits deferred as low-value. |
| T-70-03-03 | Information Disclosure | Console.info logs branding.appName transitions — could leak operator name if console is shared | accept | appName is inherently a public display value (rendered in the browser tab title and header for all users). Logging it in dev-tools does not leak anything a user wouldn't already see. |
| T-70-03-04 | Injection | iconPath/wordmarkPath/faviconPath values used as <img src> or <link href> — javascript: URLs or data: URLs could be smuggled by a malicious operator config | mitigate | Config source is the operator's own file (trusted-in-scope per T-70-01-02 in Plan 70-01). Additional frontend defense: if worried, add a "starts with /branding/" prefix check before publishing (deferred as low-value MVP — operator can already own their own deploy). |
| T-70-03-05 | Compatibility | fetchBrandingConfig failing to resolve blocks first-paint if the promise is awaited | mitigate | main.tsx call is void fetchBrandingConfig(); — no await. Initial store state is the bundled-default sentinel, so first-paint renders "Skynet" branding correctly even if the fetch never resolves. |
| T-70-03-SC | Tampering | Frontend package installs | mitigate | NO NEW PACKAGES. Verify at task done gate by checking git diff of package.json is empty. |
</threat_model>
