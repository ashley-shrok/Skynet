<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator → filesystem | Operator authors /opt/skynet/branding.json on host; container reads it read-only. Config file contents are trusted-in-scope (operator-authored) but MUST NOT be echoed into response headers or error messages. |
| unauthenticated client → /branding/* | Any pre-login browser request can hit /branding/*. The `req.params[0]` wildcard capture is user-controlled — path-traversal defense mandatory. |
| unauthenticated client → /api/branding, /manifest.webmanifest | Read-only GETs; no client input beyond the URL itself. Response bodies contain display strings only (no PII, no secrets). |
| container → /etc/skynet/branding/ | Bind-mounted read-only from host; symlink escape from within is a residual threat (accepted for MVP — operator controls the mount source). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-70-01-01 | Tampering / Information Disclosure | GET /branding/* path-traversal (e.g. /branding/../../etc/passwd, URL-encoded ..) | mitigate | resolveAssetPath() uses path.resolve + `.startsWith(baseDir + path.sep)` containment guard for BOTH the override path AND the bundled-default path. Route handler returns 400 (no body) on containment violation; never accesses the filesystem for escaped paths. Verified in <verify> automated test. |
| T-70-01-02 | Information Disclosure | Symlink escape from within /etc/skynet/branding/ | accept | Bind-mount is read-only and operator-controlled per D-12. Adding fs.realpath containment re-check would harden this but the mount is trusted-in-scope for MVP (operator authors both the JSON and the assets).
