<objective>
Extend the existing 5-step `identity-birth-orchestrator` with three new steps (6: admin-mint, 7: build relay.json body, 8: SFTP-write relay.json) so Skynet-driven remote agent birth ATOMICALLY creates the relay account and lands `~/.claude/identities/<name>/relay.json` in one operation. This is the MXA-03 completion criterion.

Also land the Q2 partial-failure retry surface: `POST /identities/birth/retry/:key` re-runs steps 6+8 for an existing identity folder (per D-OQ1 lock: mount under `/identities/birth` to inherit existing nginx coverage; extract shared helper so orchestrator and retry share one code path).

Purpose: this is the phase's headline behavioral change. Without it, agent birth stays as two independent worlds (identity folder + relay account) — the design fork the phase exists to eliminate.

Output: extended orchestrator with three new steps + BirthEvent union widening + BirthDeps widening + shared helper for reuse; wiring in identity-birth.ts with the second route; new unit test cases proving happy path + Q2 partial-tolerated behavior + local-branch skip + retry idempotency.

Decisions locked here per RESEARCH.md open questions:
- D-OQ1 (retry surface): POST /identities/birth/retry/:key mounted inside identity-birth.ts's router (already mounted at /identities/birth). Body: `{ hostId: number }`. Inherits nginx /identities coverage. Admin-gated inside handler.
- D-OQ2 (displayname on mint): set displayname = identity's frontmatter displayName if present, else omit — trivial extra JSON field, better Element rendering. Falls back gracefully when displayName is absent.
- D-OQ3 (local-branch self-birth for relay account): SKIP steps 6-8 in useLocal branch — mirror the existing pre-write skip (identity-birth-orchestrator.ts:507-509). Phase A UAT is remote fleet hosts only.
- D-OQ4 (client style): free functions — already locked in Plan 02.

Failure mode locked (Q2): PARTIAL-TOLERATED, NO ROLLBACK. Do NOT add any rm -rf logic in a catch block. The agent-supervisor race is real (Pitfall 6) — deleting a folder the supervisor is already spinning up on is worse than leaving a partial state. The id skill's existing self-register fallback handles the partial-state case gracefully.
</objective>
