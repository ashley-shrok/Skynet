## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| network → multer | untrusted multipart bytes cross here (validated by fileFilter + fileSize before touching disk) |
| helper → filesystem | server-controlled userId + whitelisted-mime-derived ext cross here (no user-supplied filename ever reaches path.join per T-85-02 mitigation) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-85-01 | Tampering | multer upload path | mitigate | multer fileFilter enforces mime whitelist `{image/png, image/jpeg, image/webp}` (D-14); `limits.fileSize = 5 * 1024 * 1024` caps input at 5 MB (D-15); `memoryStorage()` means bytes never touch disk until validation passes (D-16). All three enforced BEFORE bytes reach writeUserAvatar per RESEARCH.md § Pitfall 6. |
| T-85-02 | Tampering | filename → filesystem path | mitigate | writeUserAvatar composes filename from `userId` (caller-supplied, but caller is Plan 03/04 endpoint handlers where userId is either the freshly-generated nanoid at create OR the authenticated own-or-admin-verified targetUserId at change) + `MIME_TO_EXT[mime]` (whitelisted lookup, throws on unknown mime). `req.file.originalname` is NEVER used. readUserAvatar takes only the DB-stored filename (which is always the server-composed form). Path traversal impossible by construction. |
| T-85-SVG | Tampering / XSS | serve pipeline | mitigate | SVG explicitly NOT in ALLOWED_USER_AVATAR_MIMES (D-14); readUserAvatar derives Content-Type from extension via EXT_TO_MIME (no svg/xml mapping). A mislabeled file cannot serve as SVG per RESEARCH.md § Security Domain "SVG-with-embedded-script". |
| T-85-DOS-1 | Denial of Service | disk fill via upload flood | mitigate | 5 MB per-user cap; change endpoint (Plan 04) unlinks old file so per-user footprint stays bounded; registration flood requires bypassing `allow_registration` gate (D-05 pre-existing). Verified in RESEARCH.md § Security Domain. |
| T-85-DOS-2 | Denial of Service | memory bomb via memoryStorage | mitigate | multer's `limits.fileSize` truncates the request BEFORE buffering completes — no 100MB-in-RAM path. |
| T-85-SC | Tampering | npm package installs | mitigate | No new packages — helper reuses in-tree `multer`, `node:fs/promises`, `node:path`. RESEARCH.md § Package Legitimacy Audit confirms `not applicable`. |
| T-85-CORRUPT | Info disclosure | corrupted-file serve path | accept | readUserAvatar throws on unrecognized extension rather than serving `application/octet-stream` — fails closed. Storage corruption is an operator-observable state, not a data leak (only files placed by writeUserAvatar exist in that dir). |
</threat_model>
