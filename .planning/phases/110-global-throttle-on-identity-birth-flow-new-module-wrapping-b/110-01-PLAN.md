    Module state (all module-scope, NOT exported):
    - `let active = 0;` — count of currently-held slots.
    - `const waiters: Array<{ resolve: () => void; reject: (e: Error) => void; source: ThrottleSource; requestId?: string; }> = [];`
    - `let lastReleaseAt = 0;` — epoch ms of the most recent release. `0` means "never released" — first acquire skips the min-interval gate.
    - `let config: { maxConcurrent: number; minIntervalMs: number; maxQueueDepth: number; expectedBirthDurationMs: number; };` — resolved once via `loadConfig()` and re-resolved on `__resetForTests()`.

    Env-var loader `function loadConfig(): typeof config`:
    - Read `process.env.IDENTITY_BIRTH_MAX_CONCURRENT`, parse `Number.parseInt(raw, 10)`. If `Number.isNaN(parsed)` OR `parsed < 1`, `systemLogger.warn("identity-birth-throttle: IDENTITY_BIRTH_MAX_CONCURRENT malformed, falling back to default", { operation: "identity_birth_throttle_env_malformed", envVar: "IDENTITY_BIRTH_MAX_CONCURRENT", rawValue: raw, defaultValue: 1 })` and use `1`. Same shape for `IDENTITY_BIRTH_MIN_INTERVAL_MS` (default `0`, min `0`) and `IDENTITY_BIRTH_MAX_QUEUE_DEPTH` (default `100`, min `1`). Also read `IDENTITY_BIRTH_EXPECTED_DURATION_MS` (default `30000`, min `1`) — used to compute `retryAfterMs` in the reject error.
    - Emit ONE `systemLogger.info("identity-birth-throttle: config loaded", { operation: "identity_birth_throttle_config_loaded", maxConcurrent, minIntervalMs, maxQueueDepth, expectedBirthDurationMs })` after resolution. This is the one-shot startup line the operator greps when triaging "births are slow today."
    - Return the resolved config object.

    Module init: `config = loadConfig();` at top level so the config-loaded log fires exactly once on module import.

    Public API `export async function acquireBirthSlot(ctx: AcquireContext): Promise<() => void>`:
    - If `active < config.maxConcurrent`: proceed to grant path (see below) synchronously — no wait, no queue.
    - Else (all slots busy):
      - If `waiters.length >= config.maxQueueDepth AND ctx.bypassQueueDepth !== true`:
        - Compute `retryAfterMs = waiters.length * config.expectedBirthDurationMs` (rough estimate; documented in the comment).
        - `systemLogger.warn("identity-birth-throttle: reject (queue full)", { operation: "identity_birth_throttle_reject", source: ctx.source, requestId: ctx.requestId, queueDepth: waiters.length, maxQueueDepth: config.maxQueueDepth, retryAfterMs })`.
        - `throw new ThrottleRejectedError(retryAfterMs);`
      - Else: enqueue the waiter (log wait, then await the queued Promise, then fall through to grant path):
        - `systemLogger.info("identity-birth-throttle: waiting for slot", { operation: "identity_birth_throttle_wait", source: ctx.source, requestId: ctx.requestId, reason: "concurrency", queueDepth: waiters.length + 1, active })`.
        - Push `{ resolve, reject, source: ctx.source, requestId: ctx.requestId }` to `waiters` where `resolve`/`reject` come from `new Promise<void>((res, rej) => ...)` — then `await` that promise. When it resolves, fall through to the grant path.
    - Grant path (either synchronous or post-await):
      - Compute `sinceLastRelease = lastReleaseAt === 0 ? Number.POSITIVE_INFINITY : Date.now() - lastReleaseAt;`.
      - If `sinceLastRelease < config.minIntervalMs`:
        - `const delayMs = config.minIntervalMs - sinceLastRelease;`
        - `systemLogger.info("identity-birth-throttle: waiting for min-interval spacing", { operation: "identity_birth_throttle_wait", source: ctx.source, requestId: ctx.requestId, reason: "min_interval", delayMs })`.
        - `await new Promise<void>((res) => setTimeout(res, delayMs));`
      - `active++;`
      - `systemLogger.info("identity-birth-throttle: slot granted", { operation: "identity_birth_throttle_grant", source: ctx.source, requestId: ctx.requestId, active, maxConcurrent: config.maxConcurrent })`.
      - Build the release closure: `let released = false;` `const release = () => { if (released) return; released = true; active--; lastReleaseAt = Date.now(); systemLogger.info("identity-birth-throttle: slot released", { operation: "identity_birth_throttle_release", source: ctx.source, requestId: ctx.requestId, active, waitersRemaining: waiters.length }); const next = waiters.shift(); if (next) next.resolve(); };` — the idempotency guard is the `released` flag captured per-acquire (must-have "double-release doesn't spuriously increment free count"). Return `release`.

    Test-only helper `export function __resetForTests(): void`:
    - `active = 0;`
    - `waiters.length = 0;`
    - `lastReleaseAt = 0;`
    - `config = loadConfig();` — re-resolves env vars so tests that mutate `process.env` see the new values on the next `acquireBirthSlot` call.
