<objective>
Rewrite the four route handlers in `src/backend/database/routes/voice.ts` to consume the AWS-backed adapters (Plan 04) and pure kernels (Plan 02) built earlier in this phase, while preserving the outer route registrations, disk-bank, and slash-command transform integration BYTE-FOR-BYTE. This is the heart of Phase 98 — the visible client contract stays identical (multipart POST /voice/transcribe, JSON POST /voice/speak-stream, JSON POST /voice/speak, GET /voice/voices) but the implementation swaps from Chatterbox proxy to AWS SDK calls.

Handlers:
- `handleTranscribe`: multipart → disk-bank (raw bytes) → webmToOggOpus → transcribeBuffer → slashCommandTransform → JSON `{text}`.
- `handleSpeak`: JSON `{text, voice?}` → single Polly SynthesizeSpeech call → audio bytes as response body.
- `handleSpeakStream`: JSON `{text, voice?}` → chunk-and-stitch orchestrator → per-chunk synthesizeToPcm → RIFF header on first chunk + raw PCM on subsequent chunks → sequential pipe with prefetch of N+1 for gapless playback.
- `handleListVoices`: return the hardcoded 7-voice POLLY_VOICES (dual with frontend inline; RESEARCH accepts both since frontend already inlines in Plan 03).

Rewrite `voice.test.ts` to mock the AWS SDK v3 modules (not `fetch`) and preserve the existing test structure (disk-bank ordering test, slash-transform integration test, add AccessDenied → 503 test).

Purpose: The user-visible feature switch. This is where "Skynet no longer talks to Chatterbox for voice" becomes true (though `media-endpoints.ts` itself lives on until Plan 10 for tg-bridge coordination).
Output: Rewritten voice.ts + rewritten voice.test.ts, both green.
</objective>
