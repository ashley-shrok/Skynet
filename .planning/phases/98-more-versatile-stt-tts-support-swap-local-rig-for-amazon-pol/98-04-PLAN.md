<objective>
Build the three AWS-side adapter modules that translate the invariant client contract into Polly + Transcribe streaming calls, plus a shared `aws-errors.ts` helper for the AccessDenied off-switch (per D-Provider-access "off-switch is policy-absence" + P98-OFF-01). This plan lands the actual SDK-touching code — depends on Plan 01 (SDK installed, ffmpeg in image) and Plan 02 (chunk-and-stitch + polly-voice-catalog + riff-header-builder kernels).

Modules:
1. `polly-adapter.ts` — module-level PollyClient (IMDS-authenticated per RESEARCH § Pitfall 2), `synthesizeToPcm(text, voiceId)` returning a Node Readable of PCM 16-bit LE mono @ 16kHz.
2. `transcribe-adapter.ts` — `TranscribeStreamingClient`, `transcribeBuffer(audio, encoding, sampleRate)` opening a stream and concatenating final (non-partial) transcripts.
3. `audio-transcode.ts` — `webmToOggOpus` (remux via `-c:a copy`) + `webmToFlac` (full transcode fallback) — both spawn ffmpeg subprocesses.
4. `aws-errors.ts` — `isAwsAccessDenied(err)` shared helper (kept separate so both adapters + voice.ts can consume without circular imports).

Purpose: Complete the backend-adapter layer that Plan 06 (voice.ts route rewrite) will call. Adapters expose stable in-process functions; upstream handlers stay thin.
Output: Four source modules + four test files (mocked) + two integration test files (real-AWS, env-gated).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Backend adapter → AWS Polly service | Outbound TLS, SDK-signed with IMDS-derived credentials |
| Backend adapter → AWS Transcribe streaming service | Outbound HTTP/2, SDK-signed with IMDS-derived credentials |
| Backend adapter → local ffmpeg subprocess | Child process spawn; buffer piped via stdin |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-98-04-01 | Elevation of Privilege | AWS SDK credentials misconfig | mitigate | Client constructor MUST NOT pass `credentials` field (Pitfall 2 — passing anything explicit disables IMDS-inclusive default chain); asserted in unit tests |
| T-98-04-02 | Server-Side Request Forgery | attacker-controlled endpoint | mitigate | Region hardcoded `us-east-1` in code; no user input reaches SDK client construction |
| T-98-04-03 | Information Disclosure | AWS error messages leak credential hints | mitigate | Adapters throw plain errors; upstream voice.ts wraps and returns fixed `{error, status}` shape (Plan 06 responsibility) |
| T-98-04-04 | Tampering | ffmpeg command injection via voice ID/text | mitigate | ffmpeg args are all literal strings; only stdin receives user data (audio buffer); no argv interpolation of user input |
| T-98-04-05 | Denial of Service | pathological ffmpeg input | mitigate | Upstream multer 25MB cap limits ffmpeg input size; ffmpeg subprocess isolated (crash won't take down parent) |
| T-98-04-06 | Elevation of Privilege | Transcribe partial-result accumulation → hallucinated transcript | mitigate | `IsPartial === false` filter enforced (Pitfall 3); asserted in unit tests |
| T-98-04-07 | Information Disclosure | log audio content / transcript text | mitigate | Adapters log only sizes / lengths / voice IDs (RESEARCH § V7 + § Security → Log Injection); NEVER log transcript body or text content |
</threat_model>
