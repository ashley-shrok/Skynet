<objective>
Rewire the Telegram bridge STT path per D-Telegram-bridge-STT (locked 2026-09-10): "the telegram bridge is supposed to use whatever STT that Skynet is configured with for STT on the front end." Bridge currently POSTs voice notes directly to Chatterbox (`bridge.sh:225 → $STT_URL`). New path: bridge POSTs to Skynet's own `/voice/transcribe` endpoint with a bridge-scoped service JWT, and Skynet handles the AWS Transcribe leg.

CRITICAL SEQUENCING: This plan MUST land atomically with the config-writer change (RESEARCH § Pitfall 8 — if bridge.sh updates but bridge-config-writer.ts doesn't, the bridge sources a missing SKYNET_BASE and FATAL-exits, crash-looping the tg-bridge Docker service). Both file changes ship together, tested together.

Purpose: Provider-transparency for the bridge (it no longer knows AWS is behind the endpoint) + kill list execution for the `STT_URL` config plumbing.
Output: Bridge points to Skynet; config.env carries SKYNET_BASE + service token; bridge.sh updated; README updated.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tg-bridge Docker service → Skynet backend | Authenticated via long-lived bridge-scoped JWT (SKYNET_BRIDGE_TOKEN) |
| Bridge service token → config.env | Written atomically to shared /state volume; readable by bridge (0644) |
| Bridge JWT → Skynet authenticateJWT middleware | Same signature/verification path as user JWTs |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-98-08-01 | Spoofing | attacker mints their own bridge JWT | mitigate | Signed with system JWT secret (from AuthManager.systemCrypto.getJWTSecret) — attacker without secret cannot forge |
| T-98-08-02 | Information Disclosure | bridge token leaked via bridge stdout logs | mitigate | echo line updated to NOT echo the token (only SKYNET_BASE is echoed) |
| T-98-08-03 | Information Disclosure | token stored in /state/config.env | accept | 0644 file in bind-mounted volume shared between Skynet and tg-bridge containers only; equivalent trust to bot tokens already stored there |
| T-98-08-04 | Denial of Service | bridge crash-loop on missing SKYNET_BASE | mitigate | Bridge config-check FATALs fast (existing pattern); ship-motion sequencing gate — config-writer + bridge.sh MUST land in same deploy |
| T-98-08-05 | Replay | attacker replays captured bridge JWT | mitigate | 30-day expiry limits window; JWT hits authenticateJWT which validates signature + expiry (same protection as user tokens) |
| T-98-08-06 | Elevation of Privilege | bridge token used for non-voice endpoints | accept | bridge-scoped claims (subject: "tg-bridge") are additive not restrictive — token has same access as any authed user, since authenticateJWT is not scope-aware; acceptable because a compromised bridge already has network access to all /voice/* routes; future work could add scope-aware middleware |
| T-98-08-07 | Denial of Service | 120s timeout tolerated by nginx / caddy | accept | Existing timeout for /voice/speak-stream is 300s per Phase 19; 120s well within existing tolerances |
</threat_model>
