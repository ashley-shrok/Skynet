<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Frontend user input → chunk-and-stitch | text goes through packChunks before Polly synthesis (SPEAK_TEXT_MAX 25000 cap enforced upstream in voice.ts) |
| Backend PCM stream → client player | RIFF header must be exactly what riffPcmDecode expects; malformed header could crash the player |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-98-02-01 | Denial of Service | packChunks(very long input) | mitigate | SPEAK_TEXT_MAX=25000 upstream cap in voice.ts caps input; word-boundary fallback guarantees termination |
| T-98-02-02 | Tampering | isValidPollyVoice bypass | mitigate | Set-based exact-match check; no regex, no URL-decoding surface; case-sensitive by design (RESEARCH § V5) |
| T-98-02-03 | Information Disclosure | log content of user text | accept | Kernels are pure functions with no logging; upstream voice.ts logs only lengths per existing pattern |
| T-98-02-04 | Tampering | RIFF header injection | mitigate | Header is synthesized from typed numeric params (channels, sampleRate, bitDepth) — no user input reaches the buffer builder; Buffer writes are bounded (allocation is 44 bytes) |
</threat_model>
