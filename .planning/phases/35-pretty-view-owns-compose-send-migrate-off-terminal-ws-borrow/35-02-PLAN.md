## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Terminal.tsx (parent) → PrettyView.tsx (child) via registration props | Unidirectional callback registration — parent supplies write-into-my-ref callbacks; child stores fn in a mount effect and clears on unmount. Parent is the only caller of the ref post-registration. No untrusted input crosses this boundary. |
| PrettyView.tsx sendInput/sendInterrupt → wsRef.current | In-process function call; wsRef is a stable React ref lifecycle-managed by PrettyView's existing WS-setup effect (patch #148). The `ws.readyState !== WebSocket.OPEN` guard is the enforcement point. No untrusted input crosses. |
| Frontend → claude-session WS (port 30011) | Untrusted client-side JavaScript sends `type:"input"` / `type:"interrupt"` frames. Backend enforcement lives in Plan 35-01's handlers (connection-scoped currentTmuxSession, 16KB cap, shellQuote wrapping). This plan does not change the wire protocol Plan 35-01 established — only which frontend socket writes those frames. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-35-02-01 | Tampering | Terminal.tsx ref registration → PrettyView | accept | Registration callbacks are only writable by Terminal.tsx (React parent-child prop passing). No external actor can inject a different fn into `pvSendInputRef.current`. |
| T-35-02-02 | Elevation of Privilege | Frontend spoofing target pane via `input` frame | mitigate | Backend enforcement (Plan 35-01) uses connection-scoped `currentTmuxSession`; client-supplied fields ignored. Frontend simply cannot send an `input` frame to another pane's WS because it doesn't have a WebSocket handle to another pane's claude-session server connection — each PrettyView instance opens its own WS keyed to its `(hostId, tmuxSession)` prop pair. |
| T-35-02-03 | Denial of Service | Rapid ref-current swap during PrettyView unmount/remount | accept | The mount effect registers on mount; the cleanup nulls on unmount. If a call site fires exactly during the mount/unmount race window, the null guard (`if (!send) return;`) silently no-ops — same posture as the pre-cutover `if (!ws || ws.readyState !== 1) return` guard. | T-35-02-04 | Information Disclosure | ws.send catch swallowing errors that might contain PII | accept | Existing sibling callbacks (handleAsideDismiss, handleWake, handlePlanApprove, handlePlanFeedback) use identical try/swallow posture. No new leak surface added. |
| T-35-02-05 | Repudiation | Frontend action attributed to wrong session | accept | Each PrettyView instance has its own wsRef pointing at its own claude-session WS connection, which is bound at connect time to the hostId/tmuxSession the pane was mounted with. Frontend cannot cause a cross-pane misattribution because the WS itself is per-pane. |
| T-35-02-SC | Tampering | npm/pip/cargo installs | n/a | No new packages installed in this plan; no legitimacy gate required. |
