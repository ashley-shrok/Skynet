<objective>
Add two additive message handlers — `type:"input"` and `type:"interrupt"` — to the claude-session WebSocket server's per-connection dispatch block in `src/backend/claude-session/claude-session-server.ts`. Both handlers write into the pane via `tmux send-keys` under a strict trust boundary (connection-scoped `currentTmuxSession` only) and mirror the validated 250ms split-send timing from `src/backend/ssh/terminal.ts:842` (patch #111 → per D-PVWS-01). Extract the pure logic as exported test seams (`__applyInputMessageForTests`, `__applyInterruptMessageForTests`) modeled on `__applyWakeMessageForTests` at :1088 (per D-PVWS-06), and cover them with a new Vitest file that gates the 250ms boundary via fake timers.

Purpose: This is the backend half of Phase 35's fix for the silent-death-of-borrowed-terminal-WS bug. Pretty-view compose-send currently borrows the terminal SSH WS (`webSocketRef.current`) via `Terminal.tsx` and its first send after a long-idle window fails with `submit-failed err="not-connected"` because Caddy / TCP keepalive / mobile-tower NAT rebind silently killed the socket. This plan lands the receiving handlers on pretty-view's OWN WS (claude-session server, port 30011) so plan 35-02 can atomically flip the frontend's four call sites onto them. Strictly additive — the existing terminal-WS `type:"input"` handler at `terminal.ts:499` STAYS because terminal-mode keystrokes still route through it.

Output: One modified source file (`claude-session-server.ts` — two new handlers + two new exported test seams + one new constant) and one new test file (`claude-session-server.compose-send.test.ts`). Zero frontend changes in this plan. Zero deletions.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client browser → claude-session WS (port 30011) | Untrusted client-controlled payloads cross the WebSocket — including any newly-accepted `type:"input"` and `type:"interrupt"` frames. The connection is JWT-authenticated at connection open (:1415 verified earlier per RESEARCH.md § Security Domain) but individual message payloads remain untrusted per-message. |
| claude-session-server → SSH exec channel → tmux send-keys | The command string handed to `execCommand` is interpolated shell — any un-quoted client-controlled string is command injection surface. |
