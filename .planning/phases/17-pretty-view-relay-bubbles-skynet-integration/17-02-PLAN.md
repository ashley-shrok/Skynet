<objective>
Add a small backend HTTP endpoint that lets the browser fetch a
recv.sh-written relay body file from the pane's remote host, gated by a
strict path whitelist, per-user host ownership, and a server-side
bounded remote read. Register matching `location` blocks in BOTH
docker/nginx.conf and docker/nginx-https.conf so the route is reachable
in production.

Purpose: RELAYBUB-04 requires pretty-view to inline the full body when
recv.sh spilled to a file (long messages exceed the JSONL line budget).
The browser cannot reach `/tmp/relay-msg-*.txt` on the remote host
directly — only Skynet's backend has SSH access. This plan lands the
SSRF-safe proxy so plan 17-03's `RelayInboundBubble` can call it.

The handler lives on the **main Express backend (port 30001)**, NOT on
the bare `WebSocketServer` claude-session-server (port 30011). The
claude-session-server has no HTTP surface — it is `new WebSocketServer({
port: 30011 })` at `src/backend/claude-session/claude-session-server.ts:628`.
Mounting a new HTTP route there would require adding
`http.createServer(...)` + a route table + a JWT-cookie middleware
duplicated from the main backend — versus a one-line `app.use()` mount
on the main backend that reuses the entire existing plumbing (JWT
`authenticateJWT`, host-ownership `resolveHostById(hostId, userId)`,
SSH one-shot `connectOneShot` + `execCommand`). The existing
`src/backend/database/routes/sessions.ts` is the exact-shape prior-art
for this idiom.

**Critical safety property (checker iter-2 finding #3):** the SSH remote
read uses `head -c $((MAX_POINTER_SIZE_BYTES + 1))` (server-side
truncation) — NOT bare `cat`. `cat` would stream the whole file into
backend RAM before the size cap fires, so a 10 GB adversarial file (or
a runaway sender writing a huge legit body) would OOM the shared
Skynet backend serving Ashley's whole fleet. `head -c` bounds
bytes-transferred at the SSH exec channel, so backend memory is bounded
by construction, not by post-read check. This directly protects the
CLAUDE.md "Ashley never loses access to her fleet" hard constraint.

Output: A new `relay-pointer.ts` router module + adapter, a one-line
mount in database.ts, unit tests covering the four authorisation paths,
matching location blocks in BOTH nginx configs (regex-form matching
neighbouring blocks for pattern consistency), and an end-to-end curl
smoke test (in acceptance criteria) proving the endpoint returns HTTP
400 OR 401 (not HTTP 200 index.html) on a request the backend rejects.
</objective>
