<objective>
Wire the CSKEK credential model into the two runtime paths that touch substrate-host credentials:

1. **API layer (host.ts)** — enforce that any host with `runsFleetSubstrate:true` MUST use a named credential (`credentialId` non-null). Reject with 400 otherwise. This solves the "inline credentials on hosts table have no CSKEK columns" fork identified in RESEARCH.md § Critical Finding and PATTERNS.md § pitfall 5.

2. **Browser-terminal decrypt path (host-resolver.ts)** — add an EXPLICIT branch that reads the sshCredentials.system_* columns using CSKEK when `host.runsFleetSubstrate === true`. This is what makes D-09 real: the owner's browser terminal to a substrate host works even if the owner's DEK is not loaded in memory.

The wrap side (SimpleDBOps.insert for ssh_credentials tableName) already writes system_* columns via `DataCrypto.encryptRecordWithSystemKey` — RESEARCH.md verified this at simple-db-ops.ts:14-55. So the STORE side of D-08 works today for credentialId-based hosts (with no code change). What we're adding is: (a) the guard that forces substrate hosts down that path, and (b) the READ side that decrypts through CSKEK.

Purpose: Deliver D-08 (store side already there — this plan adds the guard that enforces the credentialId-only path), D-09 (read side — the new host-resolver branch), D-10 (enforced by the explicit `host.runsFleetSubstrate === true` check in host-resolver — non-substrate hosts unchanged), D-16 (tests for both paths). RESEARCH open Q1 is resolved AT CODE TIME via the 400 guard — no user question needed.

Output: Two modified files + their tests, with the guard preventing the "inline-credential substrate host" state from ever coming into existence and the resolver correctly routing substrate-host reads through CSKEK.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP client → POST/PUT /host/db/host | untrusted input (body fields incl. runsFleetSubstrate, credentialId, password, key). Guard rejects the "runsFleetSubstrate:true + no credentialId" combination at the API boundary. |
| browser terminal → host-resolver → CSKEK | authorised user requesting a substrate host's credentials. CSKEK decrypt path returns plaintext to the SSH connection layer; plaintext MUST NOT be logged. |
| host-resolver → SystemCrypto | CSKEK Buffer flows into the resolver; MUST NOT be logged or included in any error message. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-75-04-01 | Elevation of privilege | Without the 400 guard, an operator could create a substrate host with inline creds; the server-context orchestrator's CSKEK decrypt (75-03) would then filter it out (unmigrated-credential warn) — but the OWNER's browser terminal (host-resolver.ts) would silently fall through to the user-DEK path, giving DIFFERENT behavior than the server-context path. This inconsistency is a foot-gun. | mitigate | Task 1 400 guard prevents new such rows.
