<objective>
Extend the per-identity-file primitive whitelist so `.hidden` becomes a legal relPath alongside the existing `relay.json` and `.pinned` entries. This is the smallest possible change to unblock every downstream Phase 107 plan (backend fanout, backend read enrichment, frontend rewire) — a one-entry Set addition plus test coverage that exercises the sentinel through the same LOCAL/REMOTE branches `.pinned` already flows through.

Purpose: The primitive owns the ONE audit surface for `~/fleet/identities/<name>/<relPath>` writes per Phase 92 Plan 01's D-05 wire-generalization rule. Every downstream Phase 107 write (Plan 02's fanout) and read (Plan 02's disk probe, Plan 04's hydrate projection) routes through the primitive's three exports. Widening ALLOWED_REL_PATHS is the single-line permission that opens `.hidden` to the same audit surface without introducing a parallel wire, a new gate, or a new function.

CRITICAL invariants (inherited verbatim from Phase 92 Plan 01 — do NOT re-derive):
- Empty contents `''` are threaded through unchanged (D-01 presence-is-meaning: `.hidden` body is NEVER read; presence IS the meaning). Do NOT insert any `contents || fallback` shim.
- IDENTITY_KEY_RE remains imported from identity-artifact-reader (H1 write⇔read parity lock, Phase 92 Plan 01). Do NOT redefine the regex here; do NOT loosen the gate for `.hidden`.
- LOCAL branch uses `getLocalIdentitiesRoot()` for the path root (honors IDENTITIES_HOST_DIR env). REMOTE branch uses the LITERAL `$HOME/fleet/identities/<name>/<relPath>` string shape.
- `.hidden` gets no chmod. `opts.chmod` stays opt-in; the Plan 02 caller passes nothing. `.pinned` also passes nothing today — this preserves that parallel-treatment shape.

Output: A single-line whitelist entry in per-identity-file.ts adding `".hidden"` to `ALLOWED_REL_PATHS`, plus a `Phase 107 Plan 01` describe block in per-identity-file.test.ts that exercises `.hidden` through the four primitive contracts (whitelist admission, LOCAL write/remove/exists, REMOTE write/remove/exists, empty-body zero-byte contract).
