Affordance narrowing discriminator selection (planner call per CONTEXT.md § Constraints): the gate at the render site is `row.id.startsWith("fleet::") && row.kind !== "relay-room" && row.rdpHostRow !== true`. Rationale:
- **`row.id.startsWith("fleet::")`** — fleet-synthetic identity harness rows emit `id = fleetRowId(hostId, sessionName)` = `fleet::${hostId}::${sessionName}` (conversation-store.ts:594). Dev-created openTab rows have id shape `<hostname>-terminal-<Date.now()>-<counter>` (no `fleet::` prefix — will be excluded by this gate).
- **`row.kind !== "relay-room"`** — belt-and-suspenders. Relay-room rows use `id: session.id` (a Matrix event id shape) which does NOT start with `fleet::`, so the first condition already excludes them. Explicit kind check is defensive against any future refactor that might route relay-room rows through fleetRowId by mistake.
- **`row.rdpHostRow !== true`** — RDP rows already have onToggleHide=undefined at the render sites (line 1859 today: `row.rdpHostRow === true ? undefined : () => handleToggleHide(row)`). This condition preserves that exclusion when it's folded into the new gate. RDP rows are also excluded by the `startsWith("fleet::")` check (RDP rows use rdpHostRow id shape not fleet::), but the explicit check documents the intent.
- **Combined:** the composite gate keeps the Hide affordance for `pinned` displayedPinned rows (some are fleet-synthetic + some are openTab-derived — the openTab-derived ones lose the button, which is the correct behavior per SC-7), for `displayedMiddle` fleet-synthetic rows, for `hiddenRows` (already-hidden rows in the Hidden section — they need Unhide, so the gate treats them as identity-shaped once they're in the hidden set), and for `searchMatches` fleet-synthetic rows.
