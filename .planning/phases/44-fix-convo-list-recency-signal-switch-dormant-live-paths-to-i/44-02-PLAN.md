<objective>
Swap the JSONL path derivation inside `ssh-poll-orchestrator.ts` from `jsonlPathForSession(sessionJson.cwd, sessionJson.sessionId)` (fragile against cwd drift and Claude Code sessionId rotation on compaction/resume) to `discoverIdentitySessionFile(<exec>, tmuxSession)` — the Phase 32 byte-pattern mechanism that walks `~/.claude/projects/*/` mtime-descending and returns the newest JSONL whose first user-role line matches `/id <tmuxSession>`.

The discovered path is cached in `PidCacheEntry.jsonlPath` and reused across ticks (no re-discovery per tick — the cost bound in 43-CONTEXT.md § ssh-poll-orchestrator.ts swap). Re-discovery is triggered by a stale-threshold: if N consecutive ticks tail the cached path AND the session HAD a cached `lastMessageAt` that the tail failed to advance, the counter increments; on threshold, invalidate the cached path so the next tick rediscovers — the defense against Claude Code JSONL rotation mid-session. Sessions with a null cached `lastMessageAt` (genuinely no message-bearing history) do NOT tick the counter — the stale-threshold is a rotation-defense, not a "kick discovery when we haven't seen a message yet" mechanism.

Purpose: This is the LIVE-identity feed for the recency signal. Currently a live session can silently point at a stale JSONL after a compaction/resume event (the cached sessionId in ~/.claude/sessions/<pid>.json no longer matches the JSONL Claude Code is writing to). This plan closes that gap; Plan 44-01 does the same for the dormant-side /sessions/list route; Plans 44-03 + 44-04 wire both feeds into the working-store max-wins reconciliation and flip the comparator.

Output: Orchestrator swap + PidCacheEntry extension + test coverage. Zero wire-protocol change. Zero PID-enumeration / status-axis / hook-payload change.
</objective>
