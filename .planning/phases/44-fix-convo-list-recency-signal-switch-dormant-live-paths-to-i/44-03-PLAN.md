<objective>
Build the client-side reconciliation chokepoint for the two-feed recency signal. This plan does NOT wire the AppShell fetch handler yet (that's Plan 44-04); it only exposes the API surface that Plan 44-04 will call and refactors the pre-existing WS-publish path to route through it.

Contract per 43-CONTEXT.md § Reconciliation helper:
- `advanceSessionLastMessageAt(key, ts)` is the ONLY writer of `WorkingRecord.lastMessageAt` in the store. It compares `ts` against the cached value: if `ts` is newer OR cached is null, write + notify; else no-op + no-notify. Null-ts input is a no-op (never regresses the cache to null).
- `seedSessionLastMessageAt(hostId, tmuxSession, ts)` is the public API for the `/sessions/list` seed path. Computes the working-store key format `${hostId}:${tmuxSession ?? ""}` (matching the existing convention documented at session-working-store.ts:28), then routes through `advanceSessionLastMessageAt`. If no WorkingRecord exists yet for the key, creates one with `isWorking: false` (dormant sessions have no isWorking signal).
- `publishFleetStatusSessionState` is refactored: the isWorking axis is still handled inline (swap-and-notify on isWorking change, unchanged from today's semantics). AFTER the isWorking block, the function calls `advanceSessionLastMessageAt(key, state_arg.lastMessageAt ?? null)` — the lastMessageAt axis funnels through the SAME chokepoint the seed path uses. Rationale per 43-CONTEXT.md § "Reconciliation helper (working-store API surface)": "The existing publishFleetStatusSessionState internal write of lastMessageAt should be refactored to call advanceSessionLastMessageAt so both paths funnel through the same reconciliation."

Purpose: This is the reconciliation layer. Once landed, both feeds (WS-live from ssh-poll-orchestrator and /sessions/list-seed from AppShell) can write freely and the store guarantees monotonicity via a SINGLE code path implementing the max-wins predicate. Any future contract tweak (e.g., accepting `null` as "clear the value") becomes a one-place change.

Output: New API surface + refactored publish path + test coverage. Also extends `RemoteTmuxSession` type in sessions-api.ts so the Plan 44-01 route response deserializes into a shape carrying the new field.
</objective>
