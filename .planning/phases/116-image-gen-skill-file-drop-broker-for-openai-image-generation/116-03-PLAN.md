## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Managed-host filesystem → backend scan exec | Untrusted JSON bytes cross via `cat` in the atomic-mv scan; parser gate rejects malformed |
| Companion `.ref.<ext>` file → backend refImage Buffer | Untrusted binary bytes cross via base64 cat; size-cap enforcement lives in adapter (Plan 01 done in adapter multipart build) |
| Adapter → OpenAI HTTPS | Outbound credentialed call (bearer token from env) |
| Worker → managed-host SFTP (response JSON + PNGs) | Outbound writes via connectOneShot on the same $HOME/fleet folder — trust boundary matches the read side |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-116-03-01 | Tampering | scan-orchestrator parses caller-supplied JSON | mitigate | Every batch entry goes through parseRequestBody (from Plan 01); unknown-key rejection produces `malformedReason` which the worker converts to a `malformed` failure file. |
| T-116-03-02 | Denial of Service | Unbounded queue growth if scan runs faster than worker drains | mitigate | In-memory FIFO with 5 workers + token bucket. 5-min TTL at dequeue drops backlog. Filesystem `mv`-based claim is per-tick, so the same host cannot re-enqueue an already-claimed request. |
| T-116-03-03 | Information Disclosure | Companion-fetch exposes ref bytes to backend log | accept | Companion is user-provided image bytes; backend receives them anyway (that's the whole feature). Scan does not log the bytes, only the filename + size. |
| T-116-03-04 | Tampering | Caller-supplied ref filename triggers cat outside fleet dir | mitigate | parseRequestBody restricts `ref` to shape `^[0-9a-f]{36}\.ref\.(png|jpg|jpeg|webp)$` (Plan 01); scan-orchestrator prepends `$HOME/fleet/image-gen-requests/` before shell-interpolating. No path traversal possible. Additional check: assert the uuid in the ref matches the request's own uuid (defense in depth). |
| T-116-03-05 | Denial of Service | Slow OpenAI stalls one of 5 worker slots | mitigate | Adapter (Plan 01) has 60s AbortController timeout. Worst-case: 5 stalled workers for 60s, then all return provider_unavailable, resume normal drain. |
| T-116-03-06 | Denial of Service | Slow SSH host blocks all scans | mitigate | Per-host in-flight guard (wilma pattern) — a slow host's still-awaiting tick doesn't block scans for other hosts on the same tick. |
| T-116-03-07 | Tampering | writeBinaryFileAtomic export widens attack surface if abused | mitigate | New wrapper delegates to existing private sftpWriteBinaryAtomic; no new SFTP behavior introduced. Path is fully caller-controlled (matches writeMarkdownFileAtomic — no path allowlist in that helper either), so audit shows no regression vs. status quo. |
| T-116-03-08 | Information Disclosure | Response-file write races leak partial images | mitigate | Write PNGs FIRST, then success JSON LAST (commit-order = observe-order). Helper polls for `.success.json` as the completion signal, so a partial-PNG state is invisible to the caller unless the JSON already lists it. |
