<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Backend process → OpenAI API | Outbound HTTPS with bearer token; credentialed leg leaves the deployment |
| Parsed request body → adapter | Untrusted string payload from managed-host caller crosses via parse-request-body's ok/malformed gate |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-116-01-01 | Information Disclosure | adapter.ts logging | mitigate | Never log Authorization header, OPENAI_API_KEY value, or full URL with query in any log statement (V13). Verified by grep + code review. |
| T-116-01-02 | Denial of Service | adapter.ts hung upstream | mitigate | AbortController with 60_000ms timeout on every fetch call (Pitfall 6). On timeout return `provider_unavailable` — never stall the worker pool. |
| T-116-01-03 | Tampering | parse-request-body.ts silent-drop of unknown fields | mitigate | Explicit reject with `reason:"malformed", message:"unrecognized field: <k>"` per D-06. Fail-explicit prevents caller from thinking a mistyped param took effect. |
| T-116-01-04 | Denial of Service | parse-request-body.ts oversized prompt | mitigate | Reject `prompt.length > 4000` (matches OpenAI 4000-char cap, prevents memory blowup, matches V5). |
| T-116-01-05 | Elevation of Privilege | adapter.ts caller-supplied model field | mitigate | Model is hardcoded `OPENAI_MODEL = "gpt-image-1"` per D-26; parse-request-body has no `model` key in KNOWN_KEYS so caller cannot smuggle it in. |
| T-116-01-06 | Tampering | ref field points at cross-caller companion file | mitigate | parse-request-body enforces `ref` matches `^[0-9a-f]{36}\.ref\.(png|jpg|jpeg|webp)$`; scan-orchestrator (plan 03) enforces uuid-in-ref == request uuid. Cannot traverse to another caller's payload. |
| T-116-01-07 | Information Disclosure | Backend logs leak prompt content to log aggregation | accept | Prompts are user-authored content, not credentials. Logging prompt.length is fine; logging prompt itself is not required and should be avoided in normal operation. Deployment-level compliance is agent's responsibility via SKILL.md PHI directive (D-17). |
</threat_model>
