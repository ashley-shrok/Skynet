## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-88-01 | Tampering | sanitizer collision (two distinct usernames → same localpart) | mitigate | Escape-the-escape-char-first ordering (D-07): the `_` → `__` entry in ESCAPE_TABLE runs FIRST. Test 4/5/6 in the test suite explicitly prove `"foo@bar"` and `"foo_at_bar"` map to DISTINCT outputs. Upstream `username` uniqueness in the users table (existing check) plus sanitizer bijectivity together guarantee no two Skynet users can map to the same mxid. |
| T-88-02 | Tampering | mxid injection via malicious username char (control chars, `/`, `:`, colon-splitter attack against Synapse URL) | mitigate | Sanitizer's regex-based escape table maps every non-`[a-z0-9._=/+-]` char to a whitelisted escape form BEFORE the mxid is constructed. Test 9 (MXID_RE gate) proves output on three fixtures satisfies the Synapse localpart regex. Plan 02's `deactivateUser` primitive additionally applies `encodeURIComponent(mxid)` at the URL-construction site (defense in depth against any sanitizer bypass). |
| T-88-03 | Information Disclosure | relayPassword logged or persisted | mitigate | `generateHumanRelayPassword` returns a plain string with no logging side effects. The JSDoc mandates "discarded on the spot per D-08 — never logged, never stored." Plan 03's route integration must also never log the value; Plan 03's threat model re-enforces T-88-03. |
| T-88-04 | Denial of Service | pathological username (extreme length, ReDoS-triggering pattern) | accept | Username length is already gated upstream at username validation in POST /users/create (existing `isNonEmptyString` + reasonable length limit inherited from the users table schema). The three regexes in ESCAPE_TABLE (`/_/g`, `/@/g`, `/\./g`) are all single-character literals with no backtracking — provably ReDoS-safe. |
| T-88-SC | Tampering | npm package installs | mitigate | No new packages installed in this plan. Only `node:crypto` (Node built-in) is imported. RESEARCH.md § Package Legitimacy Audit confirms "not applicable" for this phase. |
</threat_model>
