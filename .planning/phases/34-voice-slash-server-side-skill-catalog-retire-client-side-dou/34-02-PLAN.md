## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34-02-01 | Tampering | `ls ~/.claude/skills/` output → parsed skill names | mitigate | kebab-case regex filter `/^[a-z0-9-]+$/` at parse time — an attacker who controls the target box's `~/.claude/skills/` could not inject anything past the filter (no `..`, no `/`, no special chars) that the Plan 34-03 matcher would then use to build a `/foo bar` slash-command. Slash-command names are constrained to kebab-case set by construction. |
| T-34-02-02 | Denial of Service | Hung SSH connect or slow `ls` on a wedged host | mitigate | Outer Promise.race with setTimeout enforces a hard `timeoutMs` deadline (default 10s) across BOTH connect AND exec. On timeout, fail-open to empty Set — user-visible effect is "voice slash rewrite didn't happen" (silent passthrough per CONTEXT.md § decisions "Fail-open"). |
| T-34-02-03 | Information Disclosure | SSH stderr containing sensitive filesystem info leaking into logs | accept | The `2>/dev/null` redirect on the `ls` command suppresses stderr entirely; execCommand captures stderr separately but on success returns only stdout, so stderr never reaches our logs unless exit code != 0, in which case stderr is included in the thrown Error which we log at warn level — acceptable because the message on a "no such dir" case is a benign path-not-found. |
