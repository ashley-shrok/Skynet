<objective>
Fork the `/apps/<hostId>/<slug>/pane/*` proxy plumbing to a parallel `/interactive/<hostId>/<slug>/pane/*` path. Reuses the existing `getOrCreateAppPaneProxyForTarget` factory verbatim (with a disambiguated slug prefix), `resolvePaneTarget` verbatim (shared SSH tunnel cache), `authenticateJWT` verbatim, `checkHostAccess` verbatim, `appProxyCsrfCheck` verbatim — everything is REUSE, not fork. The new router only differs in the URL prefix, the registry lookup call, and the slug-prefix passed to the proxy factory to keep cache keys separate.

Combined WebSocket upgrade dispatcher in database.ts routes both `/apps/*/pane/*` and `/interactive/*/pane/*` upgrades before destroying any non-matching socket (RESEARCH Pitfall 6). Nginx gains a `location ^~ /interactive/` block byte-parallel to the existing `/apps/` block (mirror in both nginx.conf AND nginx-https.conf per CLAUDE.md nginx-parity rule).

Purpose: without this, the widget iframe has no path to reach the widget's local HTTP server on the agent's box. This is the final backend piece; after this plan lands, `/interactive/<hostId>/<slug>/pane/` returns the widget's rendered HTML.
Output: end-to-end HTTP + WS reachability from the browser to a widget running on the agent's box.
</objective>
