<objective>
Wire the source-D sweep lines from Plan 01 into the SubscriptionRegistry as a `WidgetState` map keyed by `${hostId}:${slug}`, parallel to but SEPARATE from the existing apps map. Expose `getWidgetSnapshot()` for the /interactive/ proxy router (Plan 03) to look up widget ports. The registry keeps widgets off the sidebar by keeping the widget map + snapshot API SEPARATE from `apps` — the existing frontend sidebar consumers already subscribe only to app frames, so widgets never leak into that surface.

Purpose: the /interactive/ proxy needs port discovery. Reusing `getAppSnapshot()` would collide widget slugs with app slugs (Pitfall 1 of RESEARCH). This plan is the "type-tagged separate lane" that keeps the two concepts cleanly apart.
Output: registry has a widget lane; orchestrator adapts + publishes per tick; frontend never sees widgets on the sidebar.
</objective>
