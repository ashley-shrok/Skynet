<objective>
Route WidgetBubble's onSubmit callback through PrettyView's existing WS send-input path with a `/widget-submit ` prefix that the render-blacklist gate suppresses — the message reaches the backend and wakes the agent, but no bubble is drawn.

Purpose: the whole point of an interactive widget is that clicking it fires an invisible message to wake the agent. Without this plan, WidgetBubble's postMessage submit signal has nowhere to go. This plan is the semantic other-half of Plan 04 (which wires WidgetBubble to the parent) and Plan 03 (which enables the widget to load in the first place).
Output: clicking a poll option on the widget fires an invisible-message wake through the invisible-submit routing; the agent's session wakes; the agent reads the widget's state.json.
</objective>
