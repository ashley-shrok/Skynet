<objective>
Extend the frontend URL-detection layer with a URL-type discriminator so widget URLs are recognized synchronously (regex-only, no backend fetch), then render them as in-bubble WidgetBubble iframes instead of anchor tags. The change is additive to the existing editable-file affordance: file URLs still get the pencil, widget URLs get swapped for the iframe.

Purpose: agents write widget URLs into their messages. The frontend needs to recognize those URLs and render them as embedded iframes (not clickable links). This plan is the frontend counterpart to Plan 03's backend proxy — after this lands, the ChatMessage bubble renders the widget in-place.
Output: a widget URL in an agent's message body appears as an inline iframe (sized for chat flow, 200px tall), retries on load failure, and dispatches submit signals via postMessage.
</objective>
