## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Row dragstart → dataTransfer | Row's tab id (a string generated client-side by AppShell openTabCounter at L346) is written to `text/plain`. The receiving side (SplitView's Pane onDrop) trusts this string only as far as passing it to AppShell's `openSessionInTree` — which validates by looking it up in the current `tabs` array. If the id doesn't match a real tab, insertAtEdge would attempt to add it as a leaf but no PrettyView would render for it (unknown tab id → no matching Tab record → renderTabContent returns nothing). Non-issue in practice, but flagged for completeness. |

|-----------|----------|-----------|-------------|-----------------|
| T-56-09 | Tampering | Adversarial dataTransfer payload from cross-origin drag | mitigate | Chrome + Firefox block cross-origin drag payloads by default (same-origin policy on drag data). If a same-origin bad actor page could set arbitrary text/plain and drop it on Skynet, the id-vs-tabs lookup in openSessionInTree (Plan 56-02) drops the drop as a no-op.
