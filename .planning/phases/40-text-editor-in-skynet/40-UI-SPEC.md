# Phase 40 — UI Design Contract

> Visual and interaction contract for the in-app text editor inside Skynet's pretty-view chat surface. Reuses the existing Global Files edit modal shell + editor guts; adds a per-link edit affordance in message bubbles; on save, deposits an edited file into the ComposeBox as a new attachment. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Load-bearing case: **mobile (iPhone PWA)**. Every contract below has been checked against desktop AND mobile viability.

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Icon-to-label gap in the per-link edit affordance; edit button internal padding |
| sm | 8px | Chip strip gap (inherited from `AttachmentChipStrip`); modal header inner-element gap |
| md | 16px | Modal content padding; textarea internal padding (inherited from `GlobalFileTab` `p-3` = 12px, promoted to `p-4` = 16px inside the reused shell — see Exceptions) |
| lg | 24px | Modal header horizontal padding (`px-6` on `DialogHeader` — matches `GlobalFilesModal.tsx` L223) |
| xl | 32px | Vertical rhythm between the editor error-state message and the save button row (not used inline; reserved for the fail-state layout below) |
| 2xl | 48px | Reserved (not used in this phase) |
| 3xl | 64px | Reserved (not used in this phase) |

**Exceptions (justified — carried over from reused Global Files modal chrome):**
- Editor textarea uses `min-h-[400px]` (400px) — carried verbatim from `GlobalFileTab.tsx` L90 (established, tuned for iOS Safari + desktop viewports). Not on the 4-scale but is a viewport minimum, not a spacing token.
- Modal outer positioning uses `inset-4` (16px on every edge — matches `GlobalFilesModal.tsx` L204). On-scale.
- Modal border-radius `24px` (`rounded-[24px]`) — matches existing modal chrome; on 4-scale.
- Per-link edit button **minimum touch target 44×44px** on mobile (touch-target exception per the researcher instructions — icon-only buttons under Apple HIG). Desktop renders at 28×28px hover-reveal.

## Copywriting Contract

All copy is **verb-first, second-person-implicit** — the fleet's established voice (see `GlobalFilesModal.tsx` "Global files" / "Pick a host to load its configured files.").

| Element | Copy | Where |
|---------|------|-------|
| Per-link edit affordance — visible label (desktop hover-reveal) | `Edit` | Below/beside the pencil glyph on desktop when the affordance is revealed on link hover |
| Per-link edit affordance — accessible label (screen readers + mobile tooltip) | `Edit {filename}` — e.g. `Edit config.yaml` | `aria-label` + `title` on the icon button (both viewports). Filename comes from the URL's last path segment per the id-skill serve pattern. |
| Editor modal title (screen-reader) | `Edit {filename}` | `<DialogTitle>` (sr-only, same pattern as `GlobalFilesModal.tsx` L219) |
| Editor modal header (visible) | `Edit {filename}` | Visible header line in place of "Global files" — same slot, same style (`text-[15px] font-semibold text-[#f0ebe0]`). Filename truncates with ellipsis + full-name `title` tooltip on the header element if it overflows. |
| Editor sub-header (visible, muted) | `from {agentIdentityName}` — e.g. `from tanya` | Right of title, `text-xs text-[#a89a80]`. Sources from the message's identity resolution (already available — see `relay-mxid-resolve.ts` / `useSessionIdentity`). Falls back to `from {hostname}` when identity is unresolvable, then drops entirely if neither is knowable. |
| Save CTA (rest) | `Save` | Right-aligned button, identity-hue fill. Verbatim from `GlobalFileTab.tsx` L103. |
| Save CTA (in-flight) | `Saving…` | Same button, disabled state. Verbatim from L103. |
| Save CTA (post-save success state) | Modal closes; sonner success toast: `Attached {filename} to your reply` | Toast fires from the save handler, then modal closes. Sonner is the fleet's established convention (see `ShareIdentityPicker.tsx` L120). |
| Loading state — during re-fetch at edit-open | Three stacked skeletons (verbatim from `GlobalFileTab.tsx` L58-66 loading branch) | No text — visual skeleton only. This is the reused pattern and doesn't need re-copywriting. |
| Empty state — should never happen | (n/a) | The editor is only opened on an already-eligible link; no empty-file-list branch exists here. |
| **Error state — re-fetch failure at edit-open (server auto-killed / network fail / etc.)** | Modal opens with a clear in-body error message replacing the textarea. Heading: `Can't fetch the current file.` Body: `The agent's temporary server may have shut down (they auto-kill after 30 minutes) or the network is unreachable. Ask the agent to re-share the file if you still want to edit it.` A single dismiss button: `Close`. Also fires a sonner error toast: `Couldn't fetch {filename} — see modal.` | This is the LOCKED "visible failure over silent maybe-stale" behavior. Modal opens (Ashley intended to edit), shows the error explicitly, gives her the concrete next step. Never silently uses detection-time cached bytes. |
| Error state — save failure (network / permission / etc.) | Inline red text below the textarea (verbatim from `GlobalFileTab.tsx` L94: `<div className="text-sm text-red-400 px-1">{saveError}</div>`) with the actual error message. Save button re-enables. | Same pattern as Global Files modal save-fail — Ashley can retry or copy her draft out and close. |
| Destructive action — Cancel-with-unsaved-changes on modal close | `Discard unsaved changes?` (window.confirm) | Only fires if the draft differs from the initial fetched content. Matches the IDMEDIT-01 idiom (`window.confirm("Discard unsaved changes?")` per REQUIREMENTS.md IDMEDIT-01). Confirming closes; canceling keeps the modal open with draft intact. |

**No destructive actions in the primary flow.** Save deposits an attachment (additive); ComposeBox's existing remove-chip affordance handles "changed my mind." The only destructive-flavored gate is the discard-draft confirm above, which uses the fleet's established `window.confirm` pattern.

## Component Inventory

Components this phase introduces or modifies, in the order the executor will touch them:

### New

1. **`EditableFileAffordance`** (new) — per-link inline UI element rendered adjacent to eligible URLs inside the ReactMarkdown `a` component override in `ChatMessage.tsx`. Icon-only on mobile (44×44px min touch target, `Pencil size={16}`), icon + label on desktop hover-reveal (28×28px target when revealed, 0 opacity → 100% on message-bubble hover). Uses lucide `Pencil` icon. Warm-coral (`#ffb896`) at rest → identity-hue on hover with 4-8px drop-shadow (`filter: drop-shadow(0 0 6px hsla(var(--pv-id-hue), 80%, 60%, 0.55))` — mirrors `PinAction.tsx` locked pattern from Phase 13 SHAPE-03). Click opens `EditableFileModal` keyed to `{messageEventId, linkUrl, filename}`.

2. **`EditableFileModal`** (new) — reuses `DialogPrimitive` + editor guts (see below) but is a distinct component that owns the fetch-at-open lifecycle, the re-fetch-fail branch, and the save-to-ComposeBox handler. Chrome copied verbatim from `GlobalFilesModal.tsx` L186-217 (Portal, Overlay, Content, backdrop-filter, box-shadow, blue-glass gradient — all reused). Header copied from L221-271 (DialogHeader + title + sub-header + glass X close button) with **host picker stripped** (per LOCKED decision — Skynet already knows which file). Body branches: (a) loading — three skeletons per `GlobalFileTab.tsx` L58-66, (b) re-fetch-fail — the copywritten error state above, (c) ready — reused editor textarea + save button. **No bottom tabs bar** (per LOCKED decision — one file at a time). Modal closes on save-success, close-X, Esc, and `onInteractOutside` uses the same `e.preventDefault()` guard as `GlobalFilesModal.tsx` L199 (so composebox clicks don't dismiss it).

### Reused verbatim

3. **`GlobalFileTab` editor body** — the textarea + save-button + error-line assembly at `GlobalFileTab.tsx` L85-107 is lifted intact. `EditableFileModal` renders it inside its own body slot. `onSave` handler differs (deposits to ComposeBox vs. writing to disk) but the component contract is unchanged — hand it a `TabState<{content, mtime}>` and an `onSave(content, mtime)`. **For the editor-in-skynet case, mtime is unused** (nothing to conflict-check against — the fetched file is a snapshot at open-time, not a persistent host file), so pass `mtime: Date.now()` as a sentinel and ignore the `expectedMtime` on save.

4. **`AttachmentChipStrip` / staged-attachment shape** — save deposits into ComposeBox's existing `stagedAttachments` store using the same `StagedAttachment` shape it already accepts. No changes to the chip strip surface itself; the deposit produces a chip indistinguishable from a user-picked one. Filename is preserved from the URL's last path segment.

### Modified

5. **`ChatMessage.tsx` `a` component override** (L398-404) — extend to render `EditableFileAffordance` alongside the existing anchor when the URL matches the id-skill tailnet-serve pattern AND the eligibility check (extension whitelist OR byte-sniff at detection time) returned positive. Anchor behavior is preserved verbatim (target="_blank" rel="noopener noreferrer"). Affordance is a sibling to the `<a>`, not a wrapper, so link click semantics are untouched.

## Interaction Contract

### Per-link edit affordance visibility

| Viewport | Rest state | Interactive state |
|----------|------------|-------------------|
| Desktop (hover-capable, `useIsTouchDevice() === false`) | Affordance opacity 0. Message bubble on hover → affordance fades to opacity 1 over 120ms (matches speak-button convention at `ChatMessage.tsx` L493 `transition: "opacity 120ms"`). Pencil glyph at 16px, warm-coral. Hover the affordance itself → glyph brightens to identity-hue with drop-shadow glow, label text `Edit` slides in beside the glyph. | Focus-visible outline uses identity-hue at 0.5 alpha (matches textarea focus ring). Click opens `EditableFileModal`. |
| Mobile / touch (`useIsTouchDevice() === true`) | Affordance always visible at opacity 0.72 (matches speak-button `[@media(hover:none)]:!opacity-[0.72]` convention). Icon-only, 44×44px touch target, coral glyph at 16px. No label text. | Tap opens `EditableFileModal`. Tap on the underlying `<a>` (not the affordance) still opens/downloads the link in a new tab per the additive-not-replacive LOCKED decision. |

**Positioning:** Affordance renders inline after the link's closing text — same visual line, `margin-left: 6px`, `vertical-align: baseline`. On links that wrap to multiple lines, the affordance rides the last line naturally. Do NOT reflow the link itself.

### Editor modal open transition

- Modal fades in (100ms, matches `data-open:animate-in data-open:fade-in-0 data-open:zoom-in-95 duration-100` from `GlobalFilesModal.tsx` L206-207 — verbatim).
- Body starts in loading state (three skeletons — 200-300ms typical fetch on tailnet).
- On fetch success: skeletons cross-fade to textarea populated with content. Textarea auto-focuses.
- On fetch failure: skeletons cross-fade to the copywritten error state. Close button auto-focuses.

### Editor modal save flow

- Save button disabled until `draft !== initialFetchedContent` (verbatim behavior from `GlobalFileTab.tsx` L100).
- On save click: button label → `Saving…`, disabled state.
- Save handler: deposit `{filename, content, mtime: now, ...}` into ComposeBox's staged attachments store; if successful, close modal + fire sonner success toast `Attached {filename} to your reply`; if failed (unlikely — this is client-side state), show inline red error below textarea and re-enable save.
- Modal close focuses the ComposeBox textarea (so Ashley can immediately type her reply caption).

### Editor modal close (Cancel path)

- Close via X button, Esc key, or outside-click (guarded — matches `GlobalFilesModal.tsx` L199 `e.preventDefault()`).
- If draft differs from initial content: `window.confirm("Discard unsaved changes?")` — cancel keeps modal open, confirm closes.
- If draft matches initial content: close silently.

### Re-fetch-fail behavior (LOCKED — visible failure over silent maybe-stale)

- Detection-time cached bytes are used ONLY for the eligibility check. They are **never** served to the editor. This is a hard rule.
- On edit-open, a fresh HTTP GET fires to the agent's tailnet URL.
- On failure (network error, DNS fail, 404, 503, timeout > 8s): modal switches to the copywritten error state described above. No silent fallback. No cached-bytes reuse. Sonner error toast fires simultaneously so Ashley knows about the failure even if the modal is briefly obscured.

### Multi-file per message

- Each eligible link independently renders its own `EditableFileAffordance` sibling.
- Each affordance opens its own modal instance keyed by `{messageEventId, linkUrl}`.
- Each save produces one distinct attachment. Editing three links + saving three times → three chips in ComposeBox. This is the LOCKED deliberate multi-version support.

## Deferred Decisions Nailed Down (from CONTEXT §Deferred)

The CONTEXT flagged three items as TBD-for-UI-SPEC. This document resolves them:

1. **Exact visual form of the edit affordance on the link** → RESOLVED: bare `Pencil` glyph in warm-coral, hover-reveal on desktop (opacity 0 → 1 on message-bubble hover, `Edit` label appears on affordance hover), always-visible-at-72%-opacity on mobile (icon-only, 44×44px touch target). Rationale: mirrors the locked speak-button opacity/hover treatment on the same bubbles (`ChatMessage.tsx` L493-496), mirrors the `PinAction.tsx` bare-glyph-with-hue-drop-shadow idiom Ashley signed off on for Phase 13, and matches the fleet's established Pencil-as-edit convention (BountyCard, WakeupsTab, IdentityModal).

2. **Exact UI presentation of the re-fetch-fail error** → RESOLVED: modal opens with the loading skeletons, then swaps to a full-body error message with heading + explanatory body + `Close` button. Sonner error toast fires in parallel. Rationale: Ashley intended to edit (she tapped the affordance), so opening the modal-and-explaining is more honest than a bare toast that pretends nothing happened. The dual toast is defense-in-depth so the failure is visible even if the modal is somehow dismissed before she reads it. This matches "visible failure over silent maybe-stale" from the LOCKED shape decision.

3. **Platform parity (desktop vs mobile affordance)** → RESOLVED: **same component, viewport-branched visibility only**. Rationale: any structural difference (different icon, different position, different interaction model) would create a per-platform maintenance drag that the pretty-view surface has systematically avoided (see `useIsTouchDevice`-gated show/hide patterns in ComposeBox paperclip and AttachmentChipStrip — never different components). The single affordance's visibility (opacity + label) branches on `useIsTouchDevice()`; nothing else does.
