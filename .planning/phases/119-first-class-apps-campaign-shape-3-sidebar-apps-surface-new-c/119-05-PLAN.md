<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP client → backend route | User-supplied `hostId` (URL path) and `slug` (URL path) — both must be gated before any SSH interpolation or filesystem access |
| Backend → target box SSH | Interpolated shell command `ls "${targetPath}"` — `${slug}` MUST be regex-gated to prevent injection |
| Backend → local filesystem | `fs.readFile(path.join(root, slug, "icon.webp"))` — `${slug}` MUST be regex-gated to prevent traversal |
| Backend → response | Icon bytes streamed back with Content-Type header authored by backend, not by disk metadata |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-119-05-01 | Tampering | Path traversal via `slug` parameter → read outside `~/fleet/apps/` | mitigate | `APP_SLUG_RE = /^[a-z0-9-]{1,64}$/` gate on every entrypoint — route validates before host resolution; `readAppIconFile` re-validates as defence-in-depth. No path characters (`/`, `.`, `..`) accepted. |
| T-119-05-02 | Tampering | Shell / command injection via `slug` in the SSH `ls` probe | mitigate | Same `APP_SLUG_RE` gate; `ls "${targetPath}"` uses double-quoted interpolation and slug regex forbids shell metacharacters (`$`, `;`, `&`, backtick). Regex enforcement is the sole shell-safety gate — Pitfall equivalent to the identity-key path in the same file. |
| T-119-05-03 | Elevation of Privilege | Cross-tenant hostId → serve icon from a box the user has no access to | mitigate | `resolveHostById(hostId, userId)` returns null when user lacks access; route responds 502 with a canned "unreachable" message (does NOT distinguish "not found" from "not authorized") — matches identity-avatar discipline per RESEARCH.md §Security V4. |
| T-119-05-04 | Denial of Service | Rapid navigation causes many concurrent SSH connections | accept | Identity-avatar route has the same shape and has not been abused (RESEARCH.md §Security DoS row). Follow-up: if fleet grows large enough to matter, add a lightweight per-user rate limit. |
| T-119-05-05 | Information Disclosure | Byte-length leak / timing side channel | accept | Standard HTTP response; icon files are public within the user's fleet by design. |
| T-119-05-06 | Denial of Service | Icon file on disk is corrupted or oversized | mitigate | `IDMEDIT_MAX_AVATAR_BYTES` size gate throws in `readAppIconFile` before response is streamed; route's catch-all returns 502 rather than crashing. |
| T-119-05-07 | Tampering | SSH connection leaked (not cleaned up) | mitigate | `finally { if (conn) { try { conn.end(); } catch { /* ignore */ } } }` block; grep-gated in acceptance criteria; test spy verifies `conn.end()` invocation on every REMOTE-branch code path. |
| T-119-05-08 | Injection (XSS) | icon bytes echoed with an incorrect Content-Type | mitigate | Content-Type is hardcoded `image/webp` — not derived from file metadata; browser cannot re-interpret as HTML/JS. |
| T-119-05-SC | Tampering | npm/pip/cargo installs | accept | No package installs in this plan; every dependency (express, crypto, ssh2, path, fs, os) is already established in-repo. |
</threat_model>
