Wire the audio primitive from Plan 01 into the WIP-clear signal per D-01..D-06 latch rule, D-08..D-12 arming taxonomy, D-18 iOS unlock installation site, D-22..D-24 state placement, and D-25..D-27 test coverage.

Four coordinated changes:

1. **New store `src/ui/state/ready-cue-latch-store.ts`** — module-scope `Map<sessionKey, boolean>` with `armRow`, `disarmRow`, `isRowArmed`, `__resetForTest`. Pure in-memory session state per D-22 (not persisted, not Zustand-published, no useSyncExternalStore — the latch is read/written imperatively from a useEffect, not rendered). The store is a companion to `session-working-store.ts` but lives in its own file so the mutation surface is narrow and the D-25 tests can drive it in isolation.

2. **PrettyView.tsx** grows two effects: (a) arm-on-new-assistant-bubble — watches `messages` growth, and for each newly-appended `MessageEvent` with `role === "assistant"`, calls `armRow(sessionWorkingKey)` (D-02, D-08); (b) fire-on-WIP-true→false — reads `useSessionIsWorking(sessionWorkingKey)`, tracks the previous value in a ref, and on the true→false edge if `isRowArmed(key) && isVisible` calls `playTink()` + `disarmRow(key)` (D-03, D-05).

3. **AppShell.tsx** grows a one-shot mount-effect calling `initReadyCueAudioUnlock()` (D-18) — installs the first-gesture listeners so `playTink()` from any mounted PrettyView will actually play once the user has interacted.

4. **Two colocated test files** — `ready-cue-latch-store.test.ts` (five tests, D-25) + `PrettyView.ready-cue.test.tsx` (seven tests, D-25 arming + D-26 visibility gate + D-04 flicker collapse).

Plan 01 shipped the audio module in isolation with zero consumers; Plan 02 wires the latch, the arming signal, the fire gate, and the unlock installer. After this plan, opening a conversation pane, watching an assistant reply arrive, watching WIP clear, and hearing the tink chime is a real end-to-end user-observable flow.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-126-04 | Denial of Service | WIP true↔false oscillation (Phase 59 shell-idle-gate churn causing many flips) | mitigate | The latch state machine (D-04) collapses multi-flicker cycles into one chime per (arm event + terminal WIP-off) pair. A flicker with no intervening assistant bubble fires zero chimes; a flicker with N intervening assistant bubbles fires exactly one chime at the terminal WIP-off. The predicate is `isRowArmed && isVisible && wasWorking && !isNowWorking` — three of four terms are false on flicker, so no spam. |
| T-126-05 | Denial of Service | RelayInbound floods in a busy relay room misfiring arming | mitigate | D-12 lock: `RelayInboundEvent` does NOT arm the latch. The arm predicate explicitly filters on `event.type === "message" && event.role === "assistant"` — relay inbound events have `type !== "message"` (they're `type: "relay_inbound"`), so the type discriminator naturally excludes them without a special case. Verified via the ChatMessageEvent vs RelayInboundEvent taxonomy in PrettyView.tsx:349-354. |
| T-126-06 | Information Disclosure | Latch state leaks between users on shared browsers | accept | LOW: latch is per browser session in-memory; page refresh clears it. Same posture as `session-working-store` (which also isn't persisted). If two users share a browser without page-refresh, the latch would carry over — but so does every other in-memory state including logged-in user identity, so this isn't a novel risk. |
| T-126-07 | Repudiation | User claims "I didn't hear the tink but the WIP cleared" | mitigate | Diagnostic log (`console.info("[ready-cue] fired for key=<key>")` OR `console.info("[ready-cue] skipped for key=<key> reason=<...>")` on each considered edge) makes the decision reconstructable from console-forward logs. Log the reason on skip: `unarmed`, `not-visible`, `already-fired`, `pre-unlock`. Log level matches the existing `console.info` diagnostic convention in session-working-store.ts:278. |
| T-126-08 | Tampering | User devtools-modifies the latch Map | accept | LOW: silencing your own chime is not a security-relevant action. There is no cross-user impact. Not worth defending against. |
| T-126-SC | Tampering | npm/pip/cargo installs | mitigate | No new dependencies. Web Audio API is a browser built-in. Store pattern is the pre-existing session-working-store.ts shape. Legit-audit not needed. |

Shape 1's backend + payload threats are not applicable — no backend changes in this phase.
