<task type="checkpoint:human-verify" gate="blocking">
  <name>Task 1: Mobile UAT — iPhone PWA</name>
  <what-built>
    Slice C ships a new-conversation flow: header three-dot menu on the pretty-conversations panel gains a 'New conversation' item; clicking it opens a modal (variant D — sectioned list + search filter); the user names the room, picks participants from Humans + Agents sections, clicks Create; a Matrix room is created via the user's relay identity + participants are invited + a session row is materialized; the sidebar surfaces the row on the next poll cycle; clicking the row opens the RelayRoomPane (Slice D).
  </what-built>
  <how-to-verify>
    1. On Alice's iPhone PWA: open Skynet, navigate to the pretty-conversations panel.
    2. Tap the header three-dot menu button. Confirm a 'New conversation' item is visible. Tap it.
    3. Confirm the modal fills the phone screen (16px margin all sides) with a legible header 'New conversation' + X close button.
    4. Confirm the room-name field is autofocused (keyboard is up).
    5. Type a room name like 'iPhone UAT 91-07' — confirm the character-by-character update lands cleanly (no lag, no cursor jumping).
    6. Tap the search input, type a partial name of a known human (e.g. 'a' if Alice is in the fleet). Confirm the humans section narrows and the section header updates to 'Humans (N of M)'. Tap the X-clear button in the search — confirm the full list returns.
    7. Tap a human row. Confirm they appear as a chip above the search field (with color swatch + X-remove). Tap the chip's X — confirm they disappear from chips AND their row's check-circle un-fills.
    8. Re-tap the human. Tap an agent row. Confirm both chips render. Confirm the Create button is enabled with a name + both participants set.
    9. Try the §What would make it wrong branches:
       - Clear the room name. Confirm Create disables + hint text says 'name required' (or equivalent).
       - Re-enter the name. Deselect all participants. Confirm Create disables + hint says 'pick at least one participant'.
       - Select only an agent (no humans). Confirm Create disables + hint says 'single-agent conversation already exists' (or equivalent).
       - Add a human. Confirm Create enables.
    10. Double-tap Create rapidly. Confirm only ONE room is created (verify by checking the sidebar 10s later: exactly one new row appears, not two). This is the T-91-FE-01 debounce validation.
    11. Wait for the modal to close post-Create. Within ~10 seconds, confirm the sidebar shows a new relay-room row with the name you entered. Tap it — confirm it opens the RelayRoomPane (Slice D) with the presence row + message list + compose box.
    12. Send a smoke-test message from the compose box to confirm the room is live.
    13. Report back with the room ID and any observations. Screenshot the modal open + the sidebar row + the pane if there's anything visually off.
  </how-to-verify>
