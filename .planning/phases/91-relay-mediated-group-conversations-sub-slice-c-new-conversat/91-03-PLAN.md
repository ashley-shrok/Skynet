<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Skynet backend | Authenticated via JWT cookie/Bearer; authManager.createAuthMiddleware() enforces on every request. |
| Skynet backend → Matrix homeserver | Existing outbound trust boundary; uses createRoomAsUser (per-user token via loginAsUser) + inviteToRoom (either admin token or per-user token). |
| Skynet backend → SQLite DB | Local process; materializeRelayRoomSession uses parameterized inserts via drizzle-orm. No injection surface. |
| userId (from JWT) → viewerMxid (from users.mxid) | Server-side lookup; the request body never carries viewerMxid — a client cannot spoof identity. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-91-BE-01 | Spoofing | Unauthenticated create | mitigate | authenticateJWT middleware on the route (same as relay-room-participants); Test 1 asserts 401 on missing JWT. |
| T-91-BE-02 | Elevation of Privilege | User creates room as another user | mitigate | viewerMxid is derived server-side from userId (JWT) → users.mxid lookup. Request body never carries viewerMxid — impossible to spoof. Test 7 asserts refusal when viewer has no mxid. |
| T-91-BE-03 | Denial of Service | Invite spray / DoS via huge participant list | mitigate | MAX_PARTICIPANTS = 32 cap enforced BEFORE any Matrix call. Test 8 asserts 400 too_many_participants. Cap tuned to shape file's fleet-size heuristic ("v1 doesn't need to scale to thousands"). |
| T-91-BE-04 | Tampering | Invite targets outside fleet (arbitrary mxid injection) | mitigate | Two-layer defense: (a) MXID_RE grammar filter drops malformed strings; (b) fleet-registry (users.mxid + identities-with-mxid) filter drops mxids not in the fleet. Every dropped mxid is logged for triage. Tests 9 + 10 assert both layers. |
| T-91-BE-05 | Information Disclosure | Response body leaks Matrix/admin data | mitigate | Response fields are ONLY Skynet-owned identifiers { ok, roomId, sessionId, roomTitle }. Test 14 asserts the exact response shape. |
| T-91-BE-06 | Repudiation | Missing audit trail | mitigate | Structured log on every success (`relay_room_create_ok`) + every failure branch. Grep gate ensures 5+ operations. Follows shared pattern #2. |
| T-91-BE-07 | Denial of Service | Slow Matrix hangs the request | mitigate | AbortController + REQUEST_TIMEOUT_MS baked into matrix-admin-client primitives (Plan 02). Route inherits the 30s cap per invite; participant cap keeps total worst-case bounded at 32 × 30s. |
| T-91-BE-08 | Tampering | Fleet-registry load fails open | mitigate | loadFleetMxidRegistry fails CLOSED — a DB failure returns empty Sets, which filters out ALL invites, resulting in a zero-participant response (400 no_participants) rather than a "allow all" fallback. Test coverage: mock db failure in one test case (piggybacked into Test 10). |
| T-91-BE-SC | Supply Chain | New route added | accept | Zero new packages. Uses existing express + drizzle + matrix-admin-client + relay-sessions-store. |
