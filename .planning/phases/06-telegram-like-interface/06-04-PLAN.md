<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Session-name text input to tmux session name | Name flows through openTab into backend `tmux new-session -s <name>`. Malicious names (shell metacharacters, backticks) could inject if backend unescapes. |
| Host selection to remote box connection | User picks from host list; connection uses existing SSH creds. No new trust surface. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation |
|-----------|----------|-----------|-------------|-----------|
| T-06-04-01 | Injection (session name to shell) | NewSessionDialog session-name input | mitigate | Client-side belt-and-suspenders: input enforces /^[\\w-]{0,64}$/; Open button disabled while invalid. Backend tmux path UNCHANGED and remains the security boundary. Empty name allowed (bypasses tmux new-session name-passing entirely, so no injection surface for auto-fill path). |
| T-06-04-02 | DoS (host list flood) | Modal host list | accept | Bounded by Ashley's fleet (~50 hosts). Search input present for usability, not DoS. |
| T-06-04-03 | Info Disclosure (host list) | Modal renders full tree | accept | Same list Ashley sees in HostsPanel. No new disclosure. |
| T-06-04-04 | Race (setState then select) | onCreateSession flow | mitigate | selectConversationDeferred + pendingSelectId in store; updateOpenTabs applies when new tab id arrives. Deterministic, avoids microtask-race workarounds. |
| T-06-04-SC | Tampering | npm/pip/cargo installs | mitigate | Zero new deps. Reuses `@/components/dialog` (or fork's existing modal wrapper), Plus + Search icons from lucide-react. |

## Assets Protected
- **Backend tmux session-name integrity** (T-06-04-01) — client-side character-set validation before crossing to backend.
- **Deterministic auto-navigate on session creation** (T-06-04-04) — pendingSelectId ensures new session becomes visible without React batching race.
</threat_model>
