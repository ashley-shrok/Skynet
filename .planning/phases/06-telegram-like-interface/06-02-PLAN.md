## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| React tree ↔ DOM node stability | The tabNodesRef mechanism keeps DOM nodes for un-selected conversations mounted; a mistake here (unmount on switch) would destroy live WebSocket + terminal buffer + pretty-view scroll. This is THE load-bearing correctness constraint of this phase. |
| Browser URL fragment ↔ AppShell URL-sync effect | The URL-sync effect at AppShell.tsx lines 420-440 emits `#tab=X&tab=Y&active=N`. Under this plan the mental model is "conversations" not "tabs" but the wire URL scheme is preserved for now (Plan 06-03 introduces `#conv=<id>` layered over it for mobile). Any subtle change here can wedge Chrome's window-restore path (patch #25 fix). |
| AppShell.tabs ↔ conversation-store.openTabs | Two representations of the same data (React state in AppShell; a mirror in the store's module). If they get out of sync, the sidebar list and the view diverge. Solved by making the store a pure DERIVATION from AppShell state (updateOpenTabs called synchronously in the effect that reacts to `tabs` changes); NEVER two writers to the same data. |
