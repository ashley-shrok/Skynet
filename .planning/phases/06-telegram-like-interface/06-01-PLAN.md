| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01-01 | Tampering (stale selection pointer) | conversation-store single-select | mitigate | On every render of the derived conversation list, if the current `selectedId` no longer matches any live conversation id, the store coerces `selectedId` to `null` in the same microtask (not a re-render loop — a memoized guard inside the derived-list selector). Create `src/ui/state/conversation-store.ts`. This is a module-scoped store following the SAME pattern as `src/ui/state/identities-store.ts` (which the ConversationRow will consume from separately for identity avatars). No React imports at the module level for state; only hooks (`useSyncExternalStore`) live inside the exported hook functions.

**Module-scoped state:**

```
const state = {
  hostTree: null as HostFolder | null,
  openTabs: [] as Tab[],
  pinnedIds: new Set<string>(),
  selectedId: null as string | null,
};
const emitter = new EventTarget();
```

**Public API (all named exports, no default):**

1. **`updateHostTree(tree: HostFolder | null): void`** — called by AppShell on `setRealHostTree` (Plan 06-02 wiring). Idempotent by reference-equality; if `tree === state.hostTree` no emit.

2. **`updateOpenTabs(tabs: Tab[]): void`** — called by AppShell on `setTabs` (Plan 06-02 wiring). After update:
   - Prune `pinnedIds` — any id no longer in `tabs` is removed from the set (session-end clears pin, Test 5).
   - Coerce `selectedId` — if `selectedId` is not in `tabs`, set to `null` (T-06-01-01, Test 5).
   - Emit change event.

3. **`selectConversation(id: string | null): void`** — sets `selectedId`. If `id` is non-null and NOT in `openTabs`, treat as no-op (Test 6). Emits on change.

4. **`pinConversation(id: string): void`** — no-op if id is not in openTabs. Adds to pinnedIds. Emits.

5. **`unpinConversation(id: string): void`** — removes from pinnedIds. Emits.

6. **`togglePinConversation(id: string): void`** — convenience helper for ConversationRow's click handler.

7. **`useConversations(): { pinned: ConversationRow[]; grouped: HostGroup[] }`** — the derived shape. Uses `useSyncExternalStore(subscribe, getSnapshot)` where `getSnapshot` returns a memoized derived value. Recompute is O(N) over openTabs — acceptable at Ashley's fleet scale (~20 sessions).
   - Derived shape:
     - `ConversationRow = { id: string; type: TabType; label: string; host: Host | undefined; targetTmuxSession: string | null }`
     - `HostGroup = { hostId: string; hostName: string; rows: ConversationRow[] }`
   - Order of `grouped`: iterate hostTree depth-first (matches the visual order SidebarTree already renders), for each host emit a HostGroup containing all openTabs whose `host?.id === thatHost.id` and whose type is in `["terminal", "rdp", "vnc", "telnet"]` (session types — NOT dashboard, host-manager, user-profile, admin-settings, tunnel; see Tests 9, 10, 11). Skip empty groups. Tabs pinned via pinnedIds are EXCLUDED from grouped (they appear in `pinned` instead).
   - Order of `pinned`: iterate openTabs in their existing order, filter to those whose id is in pinnedIds. (Documented tie-break: pins keep their pin-creation-relative order, which happens to be openTabs order — this is fine per shape lock "no drag-to-reorder"; Ashley pins/unpins to nudge order if she cares.)

8. **`useSelectedConversationId(): string | null`** — thin wrapper on useSyncExternalStore.

9. **`usePinnedIds(): ReadonlySet<string>`** — thin wrapper. ConversationRow uses this to render its pin toggle's current state.

**Snapshot stability:** the internal state cache must return the SAME object reference across renders when nothing has changed, so `useSyncExternalStore` doesn't tear. Track a `snapshotVersion` counter that bumps on every real mutation; the memoized snapshot key includes it. The identities-store.ts file demonstrates this exact pattern — mirror it.
