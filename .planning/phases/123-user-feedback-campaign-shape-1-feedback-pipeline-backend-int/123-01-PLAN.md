<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| process.env → feedback-config module scope | operator-controlled env values enter the runtime — treat all as strings, no shell interpolation on any code path |
| BrandingConfig.appName → email subject line | operator-supplied string interpolated into an SMTP header — CRLF injection risk |
| userNote / exchangeText → email body | user-supplied and (for exchangeText) assistant-supplied markdown flows verbatim into email body (per D-21) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-123-01 | Information Disclosure | feedback-config.ts INCLUDE_CONTENT parser | mitigate | Explicit default `false` when env unset or non-truthy; test asserts this default per D-02. Any parser change requires the "empty string → false" test to still pass. |
| T-123-02 | Tampering (SMTP header injection) | feedback-email.ts composeSubject | mitigate | `appName.replace(/[\r\n]/g, "")` before interpolation into subject. Nodemailer 10.x also rejects CRLF in headers as defense-in-depth; this is belt-and-suspenders. |
| T-123-03 | Information Disclosure | feedback-config.ts sshLogger.info payload | mitigate | Never log the SMTP password. Test asserts that the log payload passed to sshLogger.info does not contain the password value. |
| T-123-04 | Denial-of-Service (env parse hostile) | feedback-config.ts loadFeedbackConfig | mitigate | Never-throws contract per D-07 — even hostile env access (getter that throws) returns disabled sentinel. Test wraps a getter-throw env case. |
</threat_model>
