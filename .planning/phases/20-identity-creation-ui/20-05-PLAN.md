<objective>
Extend the primary sidebar `NewSessionDialog.tsx` with the full identity-birth field
cluster (IDUI-01, IDUI-02, IDUI-03, IDUI-10) and wire up the avatar batch fetch +
required-pick UI (IDUI-04 frontend half) + both-side name collision precheck (IDUI-05
frontend half). This plan stops short of wiring the Create button to the birth endpoint
— that's plan 06's job.

Purpose: The compound birth flow needs the field cluster fully assembled and validated
before it makes sense to hit the birth endpoint. Splitting the modal work into two plans
lets this one focus on field state + validation + collision UI + avatar loop without also
managing SSE consumption and step-checklist rendering.

- Extended `NewSessionDialog.tsx` with path field, identity-mode checkbox (default ON),
  and identity-birth field cluster (title, brief, avatar picker, VoicePicker, ColorPicker).
- New api helpers `postGenerateAvatarBatch` and `getIdentityExistsOnHost` in
  `identities-api.ts`.
- Expanded `NewSessionDialog.test.tsx` covering all new UI behaviors.
- Create button click emits an `onCreate` payload with all birth fields — plan 06 replaces
  the AppShell handler to consume this new shape. This plan keeps the existing
  regular-session onCreate contract intact when identity-mode is OFF.
</objective>
