<objective>
Ship the backend compound-birth orchestrator (IDUI-06, IDUI-08, IDUI-09 backend halves):
one POST /identities/birth endpoint that runs the 5-step Nelly-cribbed sequence
(Skynet record → tmux session → claude CLI + trust-flag pre-set → blind Enter train →
/id <name>) and streams SSE progress events as it goes.

Purpose: The frontend (plan 06) consumes this SSE stream to render the 5-checkbox
progress UI. Backend owns the orchestration because (a) it holds SSH credentials for
target hosts, (b) it runs adjacent to the Skynet identity record it must create at
step 1, and (c) Nelly explicitly recommended inline-over-Tailscale-SSH vs a separate
supervisor endpoint (D-CONTEXT §"SSH orchestration shape").

Split rationale: The orchestrator is a pure function (options + emit callback →
sequence execution) with all the timing constants, tmux command shapes, and
failure taxonomy. The route file is thin SSE glue. Splitting means the ~15 unit
tests target the orchestrator directly without SSE plumbing, and the ~5 route tests
verify SSE framing without duplicating orchestration logic.

Output:
- `identity-birth-orchestrator.ts` — pure `birthIdentity(options, emit)` async function.
- `identity-birth.ts` — express route with SSE transport + JWT + POST body parsing.
- Both mounted / wired in database.ts.
- Nginx blocks with SSE-appropriate directives (proxy_buffering off, chunked_transfer_encoding on) mirroring /voice/speak-stream at nginx.conf:252-263.
- Unit tests for orchestrator (SSH-branch mocked, local-branch fs+exec mocked, fake timers for Enter train).
- Unit tests for route SSE framing.
