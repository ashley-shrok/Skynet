<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| planFilePath argument → SFTP call | The path string arrives from parser (Plan 01) which extracted it from PTY output. Adversarial pane output could inject traversal, shell metacharacters, or absolute paths. This module is the fail-closed security boundary. |
| SFTP subsystem | SSH channel. No shell interpretation. Path-injection surface is zero as long as we never fall back to a shell command. |
| File contents → memory | Untrusted plan file bytes read into a Node Buffer. Bounded by MAX_PLAN_BYTES cap. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-01 | Tampering | validatePlanPath | mitigate | Slug regex `/^[a-z0-9-]+$/`; explicit rejection of `..`, backtick, quote, `$`; full-path string-compare after `~/` normalization; test suite fails-closed assertions verify no SFTP contact on rejection. |
| T-24-02 | Information Disclosure | fetchPlanFile network path | mitigate | Format validation runs BEFORE `resolveHomeDir` / `openSftp` — invalid input never touches the SSH channel. Tests assert `.sftp` / `.realpath` / `.readFile` NOT called on rejection paths. |
| T-24-03 | Denial of Service | sftpReadFileCapped | mitigate | `sftp.stat` called first to read size; MAX_PLAN_BYTES = 500KB cap on Buffer; truncate + `[truncated]` marker prevents OOM if pointed at `/dev/zero` or similar. |
| T-24-04 | Elevation of Privilege | SFTP vs shell | mitigate | SFTP subsystem exclusively — no `execCommand`, no `cat`, no shell parsing. Verify: `grep -cE '(execCommand\|\bcat\b)' plan-file-fetch.ts` returns 0. |
</threat_model>
