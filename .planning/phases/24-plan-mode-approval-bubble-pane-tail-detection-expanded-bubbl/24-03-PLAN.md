<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → raw_keystrokes handler | Untrusted browser WS payload with a `bytes` string. Could contain arbitrary content. The handler MUST use connection-captured currentTmuxSession — never msg.tmuxSession — and must funnel through `tmux send-keys -l` (literal) to prevent tmux from interpreting `\r`, `1`, `3`, etc. as key-names. |
| SFTP fetch async completion → WS emit | Stale results if the pending window closed mid-fetch. Guarded by `planPendingLastSerialized === "null"` check before applying the cache result. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-03-01 | Tampering | raw_keystrokes handler | mitigate | Uses `currentTmuxSession` captured during `connectToPane`, IGNORES client-supplied session names (T-14-02-01 pattern from aside_dismissed handler). `bytes` payload is passed through `shellQuote` before tmux invocation. `tmux send-keys -l` (literal flag) prevents key-name interpretation. |
| T-24-03-02 | Denial of Service | fetch flood | mitigate | `planPendingFetchInFlightForPath` set prevents duplicate concurrent fetches for the same slug within one pending window. `planPendingContentByPath` map caches results so identical pane-scrape ticks don't re-fetch. |
| T-24-03-03 | Information Disclosure | stale fetch result on closed window | mitigate | `planPendingLastSerialized === "null"` short-circuit in the async .then() drops results whose pending-window has closed. No stale content emit. |
</threat_model>
