<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Server → client WS message | Server-stamped `build` field is untrusted (any server could set it) — but a mismatch always means either version drift OR MITM. Either is a fail-closed reload scenario. |
| Server → client CloseEvent | DOM CloseEvent's `code` and `reason` are set by the server per RFC 6455; the browser passes them through. |
| Guacamole error instruction stream | Third-party framing; the SKYNET_ prefix pattern is a Skynet-owned convention on top of it. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-132-22 | Spoofing | Malicious server sends `parsed.build = <wrong>` to force client reload | accept | Requires attacker to control the WS server — outside our trust boundary. Legitimate scenarios (drift + MITM) both correctly trigger reload. |
| T-132-23 | Tampering | Structured close log leaks reason/wasClean to console | accept | Non-sensitive; matches existing debug-log discipline. |
| T-132-24 | Denial of Service | Reconnect storm if client keeps hitting a 4409 server | mitigate | Task 1's onclose handler explicitly `return`s BEFORE reconnect-backoff logic when isSkew is true. Reload-loop sentinel (Plan 02 Task 2) additionally caps at 4 reloads/60s. |
| T-132-25 | Information Disclosure | `parsed.build` value in the error log reveals server's SHA | accept | Public info (same value in HTTP response headers). |
| T-132-SC | Tampering | Supply chain — new npm/pip/cargo installs | accept | Zero new packages. Uses `WebSocket`, `URL` (DOM), `console` (standard). |
</threat_model>
