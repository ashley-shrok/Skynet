Middleware body (adapt from RESEARCH.md § Pattern 3):

```
import type { Request, Response, NextFunction } from "express";
import { getServerBuildId } from "../config/server-build-id.js";
import { apiLogger } from "../logging/logger.js"; // exact path per grep

export function createSkewLockMiddleware() {
  const serverBuild = getServerBuildId();
  const isProd = process.env.NODE_ENV === "production";

  return function skewLockMiddleware(req: Request, res: Response, next: NextFunction) {
    // Always stamp the response first — clients rely on the header for
    // out-of-band drift detection (D-01 lane B: response tag mismatch).
    res.setHeader("X-Skynet-Server-Build", serverBuild);

    const raw = req.headers["x-skynet-client-build"];
    // Array-typed header (Express allows string | string[]) is treated as absence.
    const clientBuild = typeof raw === "string" ? raw : null;

    if (clientBuild === null || clientBuild === serverBuild) {
      // D-06: absence and match both pass through.
      return next();
    }

    // Mismatch. In dev, still stamp but skip refusal (SKEW-13).
    if (!isProd) {
      return next();
    }

    // Prod mismatch — refuse. Log with byte-length-capped clientBuild (V5).
    const clientBuildForLog =
      clientBuild.length > 32
        ? clientBuild.slice(0, 32) + "..."
        : clientBuild;

    apiLogger.warn("Rejected stale client request", {
      operation: "skew_lock_stale_client_refused",
      clientBuild: clientBuildForLog,
      serverBuild,
      method: req.method,
      url: req.url,
    });

    return res
      .status(409)
      .json({ error: "stale_client", clientBuild, serverBuild });
  };
}
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Untrusted HTTP client → Express middleware chain | Header value is user-controlled input; must validate (type-check string, byte-length cap on logs) |
| Middleware → downstream route handlers | On refusal, response is sent + `next()` NOT called (short-circuit); prevents route handlers from seeing the request. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-132-09 | Denial of Service | Log-flooding via long `X-Skynet-Client-Build` header values | mitigate | Task 1 caps `clientBuildForLog` at 32 chars in the structured log payload (V5 hardening per RESEARCH.md § Security Domain). |
| T-132-10 | Tampering | Attacker crafts a `X-Skynet-Client-Build` value matching the server's current SHA to bypass the check | accept | Not a real threat — matching the server's SHA means the attacker's request is treated identically to a real browser's. The check gates ONLY on version drift, not on auth. Underlying auth (JWT, session cookie) is unaffected. |
| T-132-11 | Denial of Service | Fail-open on middleware exception (e.g. `getServerBuildId()` throws) leaves server unable to enforce drift | accept | `getServerBuildId()` from Plan 01 cannot throw (const read; fallback to `"dev-unknown"`). If somehow it did, the middleware throws → Express default error handler returns 500 → caller sees error → no false-positive refusal. Fail-closed on error, safe. |
| T-132-12 | Elevation of Privilege | Middleware bypasses auth for `/health` or other endpoints | accept | Middleware is header-check only; does not consume/modify `req.user` or grant access. Runs BEFORE auth middleware but does not gate on auth — auth still gets its own middleware pass downstream. No new privilege escalation. |
| T-132-SPOOF | Spoofing | Hostile client suppresses `X-Skynet-Client-Build` on every request to evade mismatch refusal (planning_context threat) | accept | This threat is explicitly mitigated by DESIGN — the client-side interceptor (Plan 04) guarantees the header on legitimate browsers. A hostile client running stale code was already outside the trust boundary (D-06 rationale). Non-browser callers (fleet substrate, curl testing) legitimately omit the header and pass through — exactly the intended semantics. |
| T-132-SC | Tampering | Supply chain — new npm/pip/cargo installs | accept | Zero new packages. Uses only `express` types + existing project logger. |
</threat_model>
