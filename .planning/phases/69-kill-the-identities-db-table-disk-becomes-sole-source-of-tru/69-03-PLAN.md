<objective>
Rewire the birth + clone flows to disk-only. Both flows currently do their "real work" (create the folder on the target host, write the frontmatter, save the avatar bytes) AND insert a bookkeeping row into the Skynet identities table. This plan removes the bookkeeping row insertion in both flows. Nothing on the disk-side changes — the frontmatter emission, avatar sibling file write, tmux session launch, /id command send, harness bootstrap dance all stay verbatim. Only the DB touches disappear.

Purpose: Post-plan-03, all three code paths that used to INSERT into identities are gone (share deleted in 69-01, birth + clone rewired here). This is the precondition for Wave 4's schema DROP TABLE — the table can only be dropped safely once no live code path writes to it. This plan also converts identity-clone.ts's publicIdentity() to the Phase 69 shape so the clone response matches what GET / fanout would return for the same identityKey on the next enumeration.

Output: (a) identity-birth-orchestrator.ts BirthDeps interface loses createIdentityRecord + getIdentityRecord fields; Step 1 rewires to on-disk collision probe; final ended event's identityId carries opts.name (the identityKey). (b) identity-birth.ts loses its DB-direct helpers + drops its drizzle imports + drops its DatabaseSaveTrigger call. (c) identity-clone.ts loses source-row lookup + newName precheck + DB INSERT + re-select + forceSave call; publicIdentity() rewritten to Phase 69 shape with disk-re-read cosmetics. (d) The four birth-family and clone test files update to the narrower BirthDeps shape + removed DB assertions.
</objective>
