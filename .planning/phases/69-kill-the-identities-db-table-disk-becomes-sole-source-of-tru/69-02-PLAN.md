<objective>
Rewire the four surviving generic identities routes (GET /, POST /, PUT /:identityKey, GET /:identityKey/avatar) to the disk-authoritative model. This is the biggest single change in the phase — the whole "identity IS its disk folder" shift lands here. GET / stops running a DB SELECT and instead fans out to each host in the caller-supplied identityHosts map, reading each host's ~/.claude/identities/ folder listing and stitching a merged view. PUT + GET-avatar rekey their URL params from :id (nanoid row PK) to :identityKey (the lowercase name). publicIdentity() drops the three DB-only fields (id, createdAt, updatedAt) and rebuilds avatarUrl to carry hostId as a baked-in query param.

Purpose: Post-plan, the backend serves an identity roster that is genuinely disk-derived — an identity created directly on-disk (never inserted into the Skynet table) appears in the fleet list on next enumeration. That is the motivating bug the phase closes (per CONTEXT.md § Prior context). This plan does NOT yet drop the identities table (Wave 4 does) or rewire birth/clone (Wave 2 Plan 03 does) — those are separate concerns.

Output: (a) identities.ts fully rewired per the shape file's "Roster elimination" + "Name is the key" bullets. (b) New listIdentityKeysOnHost primitive in identity-artifact-reader.ts. (c) Two test files (get-disk + put-disk) updated to match the new contract. POST / handler is left temporarily still writing to the table (Wave 4 finishes the removal along with the schema drop); executor chooses at implementation time whether to swap it to 410 GONE now or defer that removal.
</objective>
