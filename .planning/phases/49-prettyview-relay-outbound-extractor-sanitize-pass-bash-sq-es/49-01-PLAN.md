<objective>
Port the validated Python sanitize-pass prototype from
`~/.claude/roles/box-maintainer/bounties/extractor-sanitize-pass/parsers.py`
into `src/backend/claude-session/session-file-parser.ts`, so PrettyView's
relay-outbound bubble stops truncating messages that use bash's `'"'"'`
apostrophe-escape idiom (Nelly's bug, plus 12 corpus rescues across
tanya/tiffany JSONLs, per REPORT.md).

Purpose: PrettyView currently renders only the pre-apostrophe prefix of
Nelly's ~1000-char body ("relaying Ashley") because Strategy 1 (BODY-sq) of
`extractOutboundBody` isn't shell-quoting-aware — the first bare `'` inside
the shell close-single/open-single reopening sequence terminates the regex
capture. Ashley's chosen fix (verbatim 2026-08-19: *"what if we strip the
characters from the entire command instead of just the body?"*) is an
upfront sanitize pass over the WHOLE command that replaces both bash
single-quote-escape idioms (`'"'"'` and `'\''`) with a private-use-area
placeholder character (`U+E000`) before the regex battery runs, then
restores the apostrophes at return time. Corpus-validated against 182
real sends: 92.9% identical output, 6.6% rescues (biggest 3.4× more body
preserved), 0 regressions, 0 fidelity loss.

refactored extractor + 4 regex simplifications + 4 dropped `.replace` calls,
one test file extended with NELLY-SHAPE + SELF-REFERENTIAL fixtures, full
vitest suite green.
