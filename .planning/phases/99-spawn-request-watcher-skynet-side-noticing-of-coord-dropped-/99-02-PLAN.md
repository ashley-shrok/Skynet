| SSH channel exec result → PendingBirth object | stdout content is coordinator-controlled (filenames + JSON bodies); parser must be defensive |
| PendingBirth → Plan 99-01 worker | worker trusts the sweep to have validated uuid shape; documented cross-plan contract |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-99-06 | Tampering | Atomic scan shell command (SPAWN_REQUESTS_SCAN_CMD in ssh-poll-orchestrator.ts) | mitigate | Command is a module-level constant, no interpolation of untrusted data into shell. Filenames go through `$f` in the shell which is variable-expanded, not eval'd. UUID length guard `[ ${#base} -eq 36 ]` filters filenames to hex+dash 36-char shape before the shell touches them, preventing `../` traversal from a malicious filename. Double-guarded in TS via `UUID_RE = /^[0-9a-f-]{36}$/i` check in parseSpawnRequestBatch |
| T-99-07 | Tampering | parseSpawnRequestBatch (ssh-poll-orchestrator.ts) | mitigate | Rejects lines without a TAB separator; rejects filenames whose basename fails UUID_RE; catches JSON.parse exceptions and skips the line with a warn log; type-narrows all fields with `typeof` checks before assigning to PendingBirth. Defense-in-depth for the worker's own parseRequestBody (Plan 99-01) |
| T-99-08 | Denial of service | Large stdout from scan exec (rogue coord flooding the folder) | accept | No explicit stdout cap yet — the exec's per-file output is `<uuid>.json\t<body>\n` where body is bounded by whatever the coord wrote. Justification: coordinators are Claude actors under adult supervision (out of threat model); if it happens, the birth-worker's per-request processing serializes cleanly and the operator sees log spam. RESEARCH V5 flags size-capping stdout as a future hardening (>512KB) — deferred as it does not affect Phase 99 correctness |
| T-99-09 | Tampering | Response file writes (delegated to Plan 99-01 worker) | mitigate | See T-99-02 in Plan 99-01. This plan's sweep tier validates uuid at parseSpawnRequestBatch — worker inherits validated-uuid contract |
| T-99-10 | Elevation of privilege | Coord requesting birth under wrong userId | mitigate | Ownership attribution (D-14): userId is derived from the host record via direct Drizzle query, NOT from the request body. Coord cannot influence which userId slice its births run under — the userId is the host-owner's userId by construction. Multi-user isolation is preserved |
