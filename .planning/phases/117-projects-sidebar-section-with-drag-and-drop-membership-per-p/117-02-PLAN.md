<objective>
Add `src/backend/matrix/matrix-room-tag-client.ts` — the Matrix account_data m.tag read/write layer for relay-room project membership, per D-05 (relay-room membership carrier) and D-05a (read-modify-write discipline: preserve non-project tags, strip existing u.project.*, add new u.project.<slug>). Two functions: `getRoomTags` (GET /user/{mxid}/rooms/{roomId}/account_data/m.tag) and `setRoomProjectTag` (5-step read-modify-write cycle). Both extend matrix-admin-client's fetch shape (AbortController + AdminOk/AdminErr union + ensureUserToken cache) and use a per-user token — the Matrix spec makes `m.tag` a per-user event, so admin-token writes would attach tags to `@skynet-admin` instead of the acting user.

Purpose: this is the relay-room half of the project-membership carrier. Identity conversations use identity-file frontmatter (117-01 handled that); relay-room conversations use Matrix account_data (this plan handles that). Wave 2's route layer (117-05) invokes setRoomProjectTag from the /relay-rooms/:roomId/project endpoint.

Output: new module at `src/backend/matrix/matrix-room-tag-client.ts` exporting 2 functions, with colocated vitest test file covering the full read-modify-write cycle.
</objective>
