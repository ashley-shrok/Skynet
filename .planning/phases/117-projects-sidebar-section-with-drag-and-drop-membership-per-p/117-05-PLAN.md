## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP client → /identities/:key/project | JSON body carries hostId, project — user-controlled |
| HTTP client → /relay-rooms/:roomId/project | JSON body carries userMxid, project — user-controlled |
| /session-project-write → identity-artifact-reader | key + slug flow into filesystem/SSH exec |
| /relay-room-project-tag → matrix-room-tag-client | userMxid + roomId + slug flow into Matrix HTTP calls |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-117-05-01 | Elevation of Privilege | Cross-user hostId on session-project-write | mitigate | resolveHostById(hostId, userId) → 404 on cross-user. Test 8 asserts. |
| T-117-05-02 | Elevation of Privilege | Writing m.tag as a different user's mxid | mitigate | Body's userMxid checked against the authenticated user's mxid via the auth surface's userId→mxid resolver. 403 on mismatch. Matrix homeserver enforces this too (double-defense). Test 4 asserts. |
| T-117-05-03 | Tampering | Malicious roomId injection into Matrix URL | mitigate | Minimal Matrix roomId regex (`/^!.+:.+$/`) + encodeURIComponent inside setRoomProjectTag (verified in 117-02). Test 5 asserts. |
| T-117-05-04 | Tampering | Malicious slug injecting into u.project.<slug> tag key | mitigate | PROJECT_SLUG_RE gate at both this route AND setRoomProjectTag. Tag key becomes `u.project.<validated-slug>` — no path or shell metacharacters possible. Test 6 asserts. |
| T-117-05-05 | Tampering | Terminal session assigned to a project via forged endpoint call | mitigate | The frontend gates via `rdpHostRow` (D-08) but the backend does NOT know if an identity is a terminal (per RESEARCH § Pitfall 3). | T-117-05-SC | Tampering | npm installs | accept | No new packages installed. |
