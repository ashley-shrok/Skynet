<objective>
Extend the fleet-status wire protocol with a distinct frame kind `project-list-changed` (byte-shape parallel to Phase 115's `identity-archived` frame at wire-protocol.ts:577-591) and add subscription-registry publish + snapshot-on-subscribe machinery for it. Wire event carries the full project array on every emit (per RESEARCH § Open Q #4 — full array, not delta — projects are cheap and this matches the Phase 115 registry-cache-then-fanout discipline). Cache is a single cell that byte-compares on publish to prevent per-tick churn.

Purpose: this is the wire between backend project state changes (create/archive/session-project-write from Wave 2+3) and the frontend sidebar re-render (Wave 3+4). Without this, project mutations happen server-side but the sidebar never learns about them.

Output: two extended files (wire-protocol + subscription-registry) plus two extended test files with new coverage.
</objective>
