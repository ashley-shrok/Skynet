<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → server (fetch layer) | Every un-archive/list call carries a user's session cookie; the backend re-validates auth + host-ownership per endpoint. |
| Response body → typed error | The `UnarchiveError` construction trusts the server's `reason` string; a rogue proxy could inject a reason. Constrained to a closed literal-union type in TS but the runtime carries whatever string arrives. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-143-05-01 | Tampering | encodeURIComponent on path segments | mitigate | Each `*-unarchive-api.ts` wraps `identityKey`/`roleName`/`slug` with `encodeURIComponent` (matches `identity-archive-api.ts:26`, `role-archive-api.ts:28`) — url-injection defense at the boundary. |
| T-143-05-02 | Spoofing | Rogue 409 reason spoofs missing_roles | accept | Backend is the sole authority; a compromised network can already forge any response. Client behavior on rogue reason: shows the missing_roles alert copy incorrectly — user-visible failure mode, not a security failure. |
| T-143-05-03 | Repudiation | No audit trail on frontend action | accept | Backend logs the action (`databaseLogger.info` in plan 143-04's routes); frontend is a UI-only surface. |
</threat_model>
