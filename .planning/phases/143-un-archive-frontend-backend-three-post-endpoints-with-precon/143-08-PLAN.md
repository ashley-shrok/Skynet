This is the surface that most crucially exercises the missing_roles precondition — an identity un-archive can fail because one of its held roles is still archived, and the D-17 alert copy must name the missing role(s) inline.

Two coordinated edits:

1. **`ConversationSearchModal.tsx` L158-182 (`handleRowClick`)** — retire the archived-branch alert at L158-172. New behavior on archived-row left-click: either no-op OR a very lightweight console-log-only hint. Do NOT drill in. The kebab is now the sole visible action path.

The click stops propagation; the item fires `handleUnarchive(result)` which follows the endpoint-first sequence (call `unarchiveIdentity` FIRST, remove row only on 200 per CONTEXT.md Risk Summary).

The plan modifies both `ConversationSearchModal.tsx` (parent state + handler + modal-stays-open discipline) AND `ConversationSearchRow.tsx` (per-row render seam to accept the kebab in the archived case).

Purpose: land the third and final surface. Together with plans 143-06 (apps) and 143-07 (roles), completes D-11-through-D-19 across all three archived-item surfaces.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Search-result row → un-archive fetch | Only server-vetted identityKey + hostId cross the seam; both were returned by an authenticated fetch. |
| `UnarchiveError.reason` string → user-facing alert copy | The client trusts the reason literal; the alert copy branches on it. Failure mode from a rogue reason is: user sees the "unknown" generic copy — no security failure. |
| Endpoint-first sequence vs failure | Row is never removed until 200 (CONTEXT.md Risk Summary) — no client-side desync possible by construction. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-143-08-01 | Tampering | XSS via missingRoles string in alert | mitigate | `window.alert` renders as text; join with `,` is a plain string interpolation, no HTML. |
| T-143-08-02 | Information Disclosure | Missing-role name leak to caller | accept | The missingRoles list is scoped to what the caller was already authorized to see (they got the archived-identity row via the fleet-wide fetch, which is auth-gated per plan 143-03). |
| T-143-08-03 | Elevation of Privilege | Un-archive triggered from a spoofed archived-row | mitigate | Server-side preconditions (plan 143-04) enforce archive-exists + no-collision + all-roles-live regardless of client state. |
</threat_model>
