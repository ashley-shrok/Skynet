<objective>
Three POST un-archive endpoints per D-01/D-02/D-03/D-04. Each parallels the shape of its archive counterpart (`identity-archive.ts`, `role-archive.ts`, `apps-archive.ts`) byte-for-byte, but with:
1. Endpoint path suffix `/unarchive` instead of `/archive`.
2. Sentinel filename `.unarchive-requested` (not `.archive-requested`).
3. Writer target = archive tree (via plan 143-01 primitives) not live tree.
4. Three (identity) or two (role/app) fast-path preconditions BEFORE the sentinel drop.
5. Structured 409 `{ reason, missingRoles? }` failure response shape.

**Preconditions (D-02):**
- archive-exists: archived folder present under `~/fleet/{identities,roles,apps}-archive/<name>/`. If absent → 409 `{ reason: "archive_not_found" }`.
- name-collision: no live-tree object exists at the same name/slug. If present → 409 `{ reason: "name_collision" }`.
- all-roles-live (identity only): parse the archived identity's `role:` frontmatter (scalar or flow-list or block-list — SAME Python inline shape 1 uses in the supervisor scanner; agent-supervisor-archive-scan.sh); if ANY listed role is still archived → 409 `{ reason: "missing_roles", missingRoles: string[] }`.

Reconciler stays authoritative on-tick (D-04) — this is a fast-path defense so the app can surface the realistic failure immediately.

Purpose: implement D-01, D-02, D-03, D-04.

Output: three route modules with tests covering happy path + each 409 precondition + non-409 errors + idempotency.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP body → route params | Untrusted key/name/slug + hostId cross this seam; regex + numeric gates at entry. |
| Route → SSH one-shot | Each remote call opens its own conn; try/finally scopes lifetime. |
| Route → archive-tree writer (plan 143-01) | Writer re-validates key/name/slug + relPath whitelist as defense in depth. |
| Route → precondition read | `test -d` on REMOTE uses only regex-vetted names (no shell-metachar interpolation risk). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-143-04-01 | Elevation of Privilege | Unauth caller triggers un-archive | mitigate | authenticateJWT middleware runs first; `resolveHostById(hostId, userId)` → 404 on cross-user hostId (mirrors identity-archive.ts T-115-03-01 shape). |
| T-143-04-02 | Tampering | Path traversal via key/name/slug | mitigate | Domain regex gate at route entry (IDENTITY_KEY_RE / ROLE_NAME_PATTERN / APP_SLUG_RE) AND primitive-layer re-validation (plan 143-01). All `test -d` and `cat` shell interpolations use regex-vetted values only. |
| T-143-04-03 | Tampering | Archive-tree writer path traversal via relPath | mitigate | Writer whitelist locked to `.unarchive-requested` (plan 143-01) — route only ever passes that literal string; whitelist gate at write layer would reject any drift. |
| T-143-04-04 | Elevation of Privilege | Precondition bypass — client-triggered un-archive that fails on reconciler tick with broken feedback path | mitigate | Endpoint precheck is fast-path defense; reconciler on-disk enforces the SAME preconditions independently (D-04). Endpoint MUST return 409 with reason BEFORE dropping the sentinel — never drop-then-check. Test 4/5 (missing_roles) locks writer-NOT-called on precondition failure. |
| T-143-04-05 | Race Condition | Concurrent un-archives from two clients | accept | Endpoint's name-collision check is not sufficient defense (racy check-then-write) but reconciler is idempotent + archive-tree writer only accepts the sentinel + tmp+rename is atomic. Residual race: both requests may return 200; reconciler consumes on tick without harm. Documented in CONTEXT §Risk Summary. |
| T-143-04-06 | Information Disclosure | 500 error text leak | mitigate | Generic `{ error: "failed to drop unarchive sentinel" }`; server-side detail via `databaseLogger.error`. |
| T-143-04-07 | Repudiation | No audit trail on un-archive | mitigate | `databaseLogger.info` on success with userId + hostId + key/name/slug (parallels T-115-03-05). |
