<objective>
Add three sibling archive-tree writer primitives per D-08. Each writer parallels the shape of its live-tree counterpart (`per-{identity,role,app}-file.ts`) but with:
1. A NARROWER whitelist — `ALLOWED_*_ARCHIVE_REL_PATHS` = `Set([".unarchive-requested"])` (one entry, not three or more).
2. Target root at `~/fleet/{identities,roles,apps}-archive/<key-or-name-or-slug>/` instead of the live tree.
3. Same LOCAL vs REMOTE branch discipline, same tmp+rename atomicity, same "conn required for remote host" contract, same domain-regex gate at the write layer.

These are the primitives the three POST un-archive endpoints (plan 143-04) call to drop the sentinel inside the archive folder. Live-tree writers stay unchanged.

Purpose: implement D-08 cleanly by SIDING with sibling functions rather than boolean-flagging existing writers — the whitelists differ (live tree allows several files today; archive tree allows exactly one), and adding a "which tree?" parameter at a call site that only ever writes one file obscures intent.

Output: three new writer modules + three tests each exercising LOCAL happy path + relPath-whitelist reject + name/key/slug-regex reject. No mutation of existing per-*-file writers.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP route handler → primitive | Untrusted body values (key/name/slug + relPath) cross this seam; the primitive is called only AFTER route-layer gates but re-validates as defense in depth. |
| Primitive → filesystem/SSH | The primitive is the last gate before disk; a bug here would let a caller in the same repo (route handler or agent) write outside the allowed basename set. |
