<objective>
Widen the pinned-bounty counter into a bounty-counts counter that returns both pinned AND needs-desk counts on the SAME fs walk, and widen the WS response payload accordingly. Backwards-compatible additive widening: pinnedCount stays; needsDeskCount is added. Renaming is scoped to the reader function (per CONTEXT.md D-05 discretion) — the WS message type strings (identity:count-bounties, identity:bounty-counts) do NOT change.

Purpose: bounty schema gained an independent boolean `needs_desk` on 2026-08-06. The conversation-list per-row bounty pill needs both counts so the row can render the combined `pin·desk` pill (Plan 03) and the filter popover can AND-intersect on either predicate (Plan 04). Doing this on a single fs walk avoids doubling backend IO for what is the same directory iteration.

Output:
- `readIdentityBountyCounts(conn, identityKey): Promise<{pinnedCount: number; needsDeskCount: number}>` replaces `readIdentityPinnedBountyCount`.
- `identity:bounty-counts` WS payload per-target entries carry `{identityKey, hostId, pinnedCount, needsDeskCount, error?}`.
- Frontend `BountyCountResult` / `IdentityBountyCountsEvent` types in `claude-session-api.ts` widen to match.
- All three existing test files updated; new orthogonality test added to prove pinned + needs_desk are counted independently.
</objective>
