## CRITICAL ARCHITECTURAL FIX — Two enumeration sources (plan-checker B-1 fix, 2026-08-20)

**Prior draft assumption was factually wrong.** The ssh-poll orchestrator's `pollOneHost`
enumerates PIDs from `~/.claude/sessions/*.json` (see line 443-466 — live-claude PID
manifests). A dormant identity has NO live claude process running → there is NO
`sessions/<pid>.json` file for it → `pollOneHost` does NOT invoke `processPid` for it →
NO SessionState frame with `dormant:true` is ever emitted. The rebuttal "supervisor keeps
tmux alive so ssh-poll sees the session" is factually wrong (tmux liveness is orthogonal
to `sessions/<pid>.json` existence — the PID manifest exists ⇔ a `claude` process is
running, not ⇔ a tmux session exists).

**Fix:** Add a SECOND enumeration source to `pollOneHost` that iterates
`~/.claude/identities/*/` per host and stats each `.dormant` sentinel. For any identity
whose folder holds a `.dormant` sentinel AND has no live PID in the current tick, emit a
SessionState frame keyed by the identity name (as `tmuxSession`, matching the sessionKey
shape the working-store already uses per session-working-store.ts:28) with `dormant:true`,
`status:idle`, `pid:null`. Live identities that stat as `dormant=false` still get their
existing PID-based SessionState frame from source A (the frame carries `dormant:false`).

Both paths merge at the store consumer via the existing per-key working-store record —
whichever source published last wins on the dormant axis, which is correct because:
- A live identity (source A fires) has an authoritative dormant value from the actual
  stat done on the identity folder in that same tick.
- A dormant-only identity (source B fires) has an authoritative dormant:true value from
  the sentinel stat.
- The two sources are DISJOINT per tick by construction: source B skips any identity
  name that appeared in source A's PID-derived tmuxSession set (see Task 3 action step 3).

Because ssh-poll now covers BOTH live-with-dormant-flag AND dormant-only-no-live-PID
paths, the frontend Ready filter (Plan 03) sees a wire signal for every identity that
has a `.dormant` sentinel present, regardless of live-process state.

Purpose: unblock Plan 03's Ready predicate (`!isWorking && !dormant`) with a real
supervisor-dormancy signal, not the deferred time-threshold approximation.
Output: One new hook (`useSessionIsDormant`), one new wire field (`SessionState.dormant`),
one new sentinel stat per ssh-poll PID-tick (source A), one new identity-folder-listing +
per-identity sentinel stat per ssh-poll host-tick (source B), one new publish path for
dormant-only identities that have no live PID.
