## CRITICAL DEFAULT — Fail-CLOSED for undefined rowState (plan-checker W-3 fix, 2026-08-20)

Prior draft had `readyOk = !readyOnly || (!rowState?.isWorking && !rowState?.isDormant)`
which evaluates to `true` when `rowState === undefined` (row never published to
working-store) — a false positive: rows with no wire signal appear as Ready when the
Ready toggle is on. That's the wrong default. The Ready toggle should be conservative:
a row with no observed wire signal is NOT known to be ready.

**Corrected predicate (fail-CLOSED):**
```
const readyOk = !readyOnly || (rowState !== undefined && !rowState.isWorking && !rowState.isDormant);
```

Interaction with Plan 01's source B: with source B in place, EVERY identity with a
`.dormant` sentinel gets a wire frame (source B publishes dormant:true) AND every
live-PID identity gets a wire frame (source A publishes with dormant true/false).
So the rowState-undefined case now genuinely means "no wire signal at all for this
key" — which for the Ready filter is correctly treated as "not confirmed ready" and
filtered out. Dormant-only identities remain correctly filtered out (rowState defined
with dormant=true → the second-clause AND short-circuits on the dormant check).
