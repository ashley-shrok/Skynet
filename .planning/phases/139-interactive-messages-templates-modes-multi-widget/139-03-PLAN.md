<objective>
Ship the form template in terminal-on-submit mode: a labeled input for each declared field plus a submit button. Agents declare fields via repeatable `--field name:type[:options]` flags; supported types v1 are `text`, `number`, and `select:<comma-separated-options>`. Follows the poll template's file layout and terminal-on-submit affordance rules verbatim.

Purpose: Second of the five templates. Form is the natural shape when the agent needs several distinct values and typing feels heavier than clicking around a small structured layout — creating a config, choosing between named alternatives, entering a threshold. The `select:...` sub-type keeps the tight-choice UX inside form fields where a full radio-group would be visual overkill.

Output: Fully-scaffolded template directory + per-template test file.
</objective>

**args.sh:**
- `declare -gA TEMPLATE_ARGS` at top; also `declare -ga TEMPLATE_FIELDS_LIST=()` (indexed array, one entry per --field flag encountered, preserving order).
- `template_parse_args`:
  - Recognizes `--prompt <p>` (required, non-empty).
  - Recognizes `--field <spec>` (repeatable, at least one required). Spec format: `<name>:<type>[:<comma-separated-options>]`.
    - Split on `:` (max 3 parts). Field name must match `^[a-z_][a-z0-9_]*$` (die: `--field name must be lowercase snake_case: got '<name>'`). Length cap 40.
    - Type must be one of `text`, `number`, `select` (die: `--field type must be one of text|number|select: got '<type>'`).
    - For `select`: third part is required and must be a non-empty comma-separated list with >= 2 items (die: `--field select requires >=2 comma-separated options: got '<spec>'`); split into an array.
    - For `text`/`number`: third part MUST be absent (die: `--field type '<type>' does not accept options: '<spec>'`).
    - Append the parsed spec to `TEMPLATE_FIELDS_LIST` as a JSON-encoded object (produced via `python3 -c "import json,sys; print(json.dumps(...))"`).
  - Recognizes `--submit-label <text>` (optional, default `"Submit"`).
  - Populates `TEMPLATE_ARGS[prompt]`, `TEMPLATE_ARGS[submit_label]`. Fields go into `TEMPLATE_FIELDS_LIST`.
  - After parsing, if `TEMPLATE_FIELDS_LIST` is empty, die: `at least one --field is required`.
- `template_substitute`:
  - Build a single JSON array of field descriptors via python3 inline (from TEMPLATE_FIELDS_LIST).
  - Substitute in widget.html: `__PROMPT_JSON__`, `__FIELDS_JSON__`, `__WIDGET_ID__`, `__PANE_BASE__`, `__SUBMIT_LABEL_JSON__`.
  - Set `TEMPLATE_CONFIG_JSON` to `{"prompt": ..., "fields": [...], "submit_label": ...}` (JSON via python3).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| widget.html field-list substitution | Agent-supplied field names/types/options flowing into inline JS via JSON encoding |
| POST /submit body | Untrusted JSON from widget frame — same-origin, still parsed with try/except |
| --field spec parsing | Colon-separated string parsing in args.sh — malformed input must fail fast, not fall through |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-139-03-HTMLInject | Tampering | field names/options substituted into widget.html JS | mitigate | All substitutions via python3 inline with `json.dumps`. Field name regex enforces `^[a-z_][a-z0-9_]*$` before substitution (defense-in-depth). |
| T-139-03-postMsgWildcard | Information Disclosure | widget.html postMessage target | mitigate | Explicit `window.location.origin` target (grep-checked). |
| T-139-03-FieldSpecInj | Tampering | --field parsing splitting on `:` | mitigate | Field-type whitelist (text/number/select) checked immediately after split; option string flows only through JSON encoding, never raw HTML/shell. |
| T-139-03-DoubleSubmit | Tampering | Submit button rapid-fire | mitigate | Submit button + all inputs disabled synchronously before fetch. |
| T-139-03-BadJSON | Denial of Service | POST /submit malformed body | mitigate | server.py parses with try/except (inherited pattern). |
</threat_model>
