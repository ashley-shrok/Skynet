<objective>
Ship the color-picker template in terminal-on-click mode. Mirrors poll's affordance philosophy: the interaction IS the submit — no separate button. Users see a grid of colored swatches and click one to pick it. The click ends the interaction; the widget disables all swatches and fires the submit.

Purpose: Fifth (and final) template. color-picker is the shape for "pick one color" — a case where any text-reply UI would be strictly worse (naming a specific hex is fiddly; describing "the reddish-orange one" is ambiguous). Buttons/swatches read as clickable-to-submit, matching the terminal-on-click mode.

The 12-swatch default palette (from the arc's shape-file tasting decision, referenced in the phase_scope) is curated for a general-purpose color-picking need: a spread across the hue wheel plus a few useful neutrals. When agents need a specific palette (e.g. brand colors, ANSI 16), they pass `--palette hex,hex,...`.

Output: Fully-scaffolded template directory + per-template test file.
</objective>

**widget.html:**
- Substitution markers: `__PROMPT_JSON__` (may be null/empty string — prompt is optional), `__PALETTE_JSON__` (JSON array of hex strings, e.g. `["#ef4444", "#f97316", ...]`), `__WIDGET_ID__`, `__PANE_BASE__`.

- CSS: reuse poll's base + dark-mode. Add:
  - `#palette { display: grid; grid-template-columns: repeat(auto-fill, minmax(48px, 1fr)); gap: 8px; margin-top: 8px; }`
  - `.swatch { width: 100%; aspect-ratio: 1 / 1; min-width: 44px; min-height: 44px; padding: 0; cursor: pointer; border: 2px solid rgba(0,0,0,0.15); border-radius: 8px; background-color: var(--sw); transition: transform 0.1s, border-color 0.1s; }`
  - `.swatch:hover:not(:disabled) { transform: scale(1.06); border-color: rgba(0,0,0,0.4); }`
  - `.swatch.selected { border-color: #000; border-width: 3px; }`
  - `.swatch:disabled { opacity: 0.55; cursor: default; }`
  - Dark-mode: `.swatch { border-color: rgba(255,255,255,0.15); }` and `.swatch:hover:not(:disabled) { border-color: rgba(255,255,255,0.5); }`, `.swatch.selected { border-color: #fff; }`.
- JS:
  - Parse `PROMPT` (may be null/empty), `PALETTE` (array of hex strings), `WIDGET_ID`, `PANE_BASE`.
  - If PROMPT is a non-empty string, set `<h2>` text and remove `hidden`; otherwise leave the h2 hidden.
  - Render one `<button class="swatch">` per palette entry with inline CSS custom property.
  - Attach `click` on each swatch: disable ALL swatches immediately, add `.selected` to the clicked one, POST `{color: hex, submitted_at: new Date().toISOString()}` to `${PANE_BASE}/submit`, fire postMessage `{type:"widget-submit", widgetId, value:{color: hex}}` to `window.location.origin` AFTER the POST resolves.
  - On fetch failure: re-enable all swatches, remove `.selected`, set status "Submission failed — please try again."
  - On success: leave swatches disabled, set status "Submitted."

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| widget.html palette substitution | Agent-supplied hex strings flowing into inline JS via JSON encoding + inline CSS custom properties |
| --palette validation | Agent-supplied comma-separated string parsed and regex-checked before substitution |
| POST /submit body | Untrusted JSON — same-origin, parsed with try/except |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-139-06-CSSInject | Tampering | Palette hex flowed into inline `style="--sw:..."` | mitigate | Hex regex `^#[0-9a-fA-F]{6}$` enforced in args.sh BEFORE substitution. Impossible for a non-hex string to reach the CSS custom property. |
| T-139-06-HTMLInject | Tampering | Palette + prompt substituted into widget.html JS | mitigate | python3 inline `json.dumps` for all substitutions + hex regex for palette entries. |
| T-139-06-postMsgWildcard | Information Disclosure | postMessage target | mitigate | `window.location.origin` explicitly. |
| T-139-06-DoubleSubmit | Tampering | Multiple rapid swatch clicks | mitigate | All swatches disabled synchronously before fetch begins. |
| T-139-06-AffordanceMatch | (Design) | Terminal-on-click with no submit button | mitigate | Widget has NO submit-btn/done-btn (grep-checked). Click IS the terminal act; swatches are the affordance the user sees, matching poll's proven pattern. |
| T-139-06-BadJSON | Denial of Service | POST /submit malformed body | mitigate | server.py parses with try/except. |
</threat_model>
