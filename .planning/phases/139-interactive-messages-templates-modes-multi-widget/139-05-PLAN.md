<objective>
Ship the list-actions template in terminal-on-submit mode. Users see a list of items where each row has per-row action buttons (agent-declared: e.g. "Merge", "Skip", "Delete"). Clicking a per-row action selects it for that row but does NOT submit; only the widget-level "Done" button submits. Both interaction elements are buttons — but the row buttons are passive-selectors (they do not end the interaction), so their visual weight is distinct from the primary Done button.

Purpose: Fourth of the five templates. list-actions is the shape for "for each of these, tell me what to do" — a review-and-batch-decide workflow. Example: reviewing PRs and marking each Merge/Skip/Comment. The submit-on-Done rather than submit-on-per-row-click is what lets the user reconsider before firing; otherwise the widget would race the user.

Design nuance from the shape file: this template's affordance is a delicate case. Buttons that don't end the interaction (per-row) live alongside a button that does (Done). To not "lie to the user" (arc invariant), the per-row buttons visually differentiate from Done: outline-style with the action name, while Done is filled/primary. The tests grep for both classes of button and their distinctness.

Output: Fully-scaffolded template directory + per-template test file.
</objective>
