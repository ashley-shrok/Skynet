<objective>
Ship the ranking template in terminal-on-submit mode. Users reorder a list of items via drag-and-drop (desktop) or up/down arrow buttons (mobile/touch fallback) and hit a submit button. Both interaction modes MUST be present — this is a load-bearing decision from the arc's shape file: "Ranking specifically renders both drag-handles and arrow buttons so it works on every input mode."

Purpose: Third of the five templates. Ranking is the shape for "give me a preferred order among these" — a scenario where typing "I want A first, then C, then B" is objectively worse UX than dragging. The mobile-first-class discipline dictates the arrow fallback: touch devices without native drag-and-drop must still be productive.

Output: Fully-scaffolded template directory + per-template test file.
</objective>

**widget.html:**
- Substitution markers: `__PROMPT_JSON__`, `__ITEMS_JSON__` (JSON array of item label strings, in the agent's initial order), `__WIDGET_ID__`, `__PANE_BASE__`, `__SUBMIT_LABEL_JSON__` (defaults to `"Submit order"`).

- Each row `<li class="rank-row" draggable="true" data-idx="N">` contains:
  - `<span class="drag-handle" aria-hidden="true">☰</span>` (the visual drag handle glyph; `⋮⋮` or `☰` — pick one, stay consistent)
  - `<span class="rank-label">LABEL</span>`
  - `<button type="button" class="up-btn" aria-label="Move up">▲</button>`
  - `<button type="button" class="down-btn" aria-label="Move down">▼</button>`
- CSS: reuse poll's base + dark-mode. Add:
  - `#rank-list { list-style: none; padding: 0; margin: 0; display: flex; flex-direction: column; gap: 6px; }`
  - `.rank-row { display: flex; align-items: center; gap: 8px; padding: 8px 10px; border: 1px solid #ccc; border-radius: 6px; background: #f9f9f9; cursor: grab; }`
  - `.rank-row.dragging { opacity: 0.5; }`
  - `.rank-row.drop-target { border-color: #3b82f6; }`
  - `.drag-handle { flex-shrink: 0; color: #888; font-size: 18px; cursor: grab; user-select: none; }`
  - `.rank-label { flex: 1; }`
  - `.up-btn, .down-btn { flex-shrink: 0; width: 44px; height: 44px; padding: 0; font-size: 16px; cursor: pointer; border: 1px solid #ccc; border-radius: 6px; background: #fff; }`

  - Submit button style identical to checklist/form (`.submit-btn`).
  - Dark-mode variants.
- JS:
  - Parse `PROMPT`, `ITEMS`, `WIDGET_ID`, `PANE_BASE`, `SUBMIT_LABEL`.
  - Render prompt and one row per ITEMS entry, in initial order.
  - Attach drag events (`dragstart`, `dragover`, `drop`, `dragend`) on each row to support desktop drag-to-reorder — on drop, reorder the DOM (`insertBefore` the drop target).
  - Attach `click` handler on up/down buttons: swap the row with its previous/next sibling via `insertBefore`.
  - After every reorder (drag OR arrow), refresh the disabled state of all up/down buttons (row-0's up is disabled; last row's down is disabled).
  - On submit-btn click: disable all interaction (buttons + drag), collect the current DOM order into an array of labels, POST `{order: <arr>, submitted_at: new Date().toISOString()}` to `${PANE_BASE}/submit`, fire postMessage `{type:"widget-submit", widgetId, value:{order:<arr>}}` to `window.location.origin` after fetch resolves.
  - Same failure handling: re-enable + retry status on fetch fail; set submit label to "Submitted." on success.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| widget.html items substitution | Agent-supplied item labels flowing into inline JS via JSON encoding |
| POST /submit body (order array) | Untrusted JSON from widget frame — same-origin, parsed with try/except |
| Drag-and-drop DOM manipulation | Runs entirely in the widget's iframe origin — no cross-frame data movement |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-139-04-postMsgWildcard | Information Disclosure | postMessage target | mitigate | `window.location.origin` explicitly (grep-checked). |
| T-139-04-DoubleSubmit | Tampering | Submit button rapid-fire | mitigate | All buttons + drag disabled synchronously before fetch. |
| T-139-04-MobileBlackout | Denial of Service (functional) | Mobile users without drag-and-drop support | mitigate | Up/down arrow buttons are always present (grep-checked in acceptance criteria). |
| T-139-04-BadJSON | Denial of Service | POST /submit malformed body | mitigate | server.py parses with try/except. |
