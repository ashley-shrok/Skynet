## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| React component render → user's browser DOM | Client-side rendering of thumbs affordance; no server data involved |
| ChatMessage local state → parent callbacks | eventId (already-existing prop, string) is forwarded via callback; no new payload wire format at this layer |

## STRIDE Threat Register

Shape 1's backend + payload threats (T-121-*) cover the transport, backend, injection, and payload-cap surface. Shape 3 changes NONE of that surface — no new payload fields, no new backend routes, no new modal variants, no new toast primitives (per D-36/D-37/D-41/D-43). The threats below are shape-3-scope-specific and all LOW severity.

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-125-01 | Tampering | Client-side `thumbsUpPressed`/`thumbsDownPressed` useState in ChatMessage | accept | LOW: pressed state is client-only UI hint (D-30 explicitly no server record). Manipulating it via devtools only affects that user's DOM; no cross-user or persisted impact. Second-tap-no-op is a UX contract, not a security boundary. |
| T-125-02 | Denial of Service | Rapid thumbs-up clicks from a user | accept | LOW: shape 1 D-28 already accepted the risk of no rate limiting; second-tap-no-op mitigates casual double-fire but not intentional spam. | T-124-SC | Tampering | npm/pip/cargo installs | accept | LOW: no new dependencies added in this plan. All imports (`lucide-react`, `sonner`, `@/feedback/feedback-store`) already exist in the repo — no install step. |
