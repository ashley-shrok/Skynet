<objective>
Ship a new test file `substrate/skills/interactive-messages/tests/mobile-audit.test.sh` that automatically audits every template widget.html for mobile-friendly patterns, and wire it into `tests/run-all.sh`.

The audit is grep-based (like the existing `all-templates-non-terminal-scaffold.test.sh` cross-cutting invariants), not a headless-browser test. Grep-audit is sufficient because the patterns being asserted are static CSS + JS invariants — no runtime behavior is being measured.

Per template widget.html, the audit asserts:

1. **Viewport meta tag present** — `<meta name="viewport" content="width=device-width, initial-scale=1">` must appear. This is what makes CSS media queries work on real mobile browsers.

2. **At least one 44px touch target** — at least one occurrence of `min-height:\s*44px` (or `min-height: 44px`) on an interactive element (not counting the `#status` spacer which is `min-height: 18px`).

3. **No horizontal-scroll hacks** — no `overflow-x: auto` or `overflow-x: scroll` anywhere. If a template has these, the layout has bugs being papered over instead of fixed.

4. **postMessage origin discipline** — if the file contains any `postMessage(` call, it must NOT use `"*"` as the origin argument. Must use `window.location.origin`. Non-terminal templates should have zero `postMessage` calls at all (already asserted by `all-templates-non-terminal-scaffold.test.sh`, but re-checking here is defensive and correct).

5. **No infinite-scroll or streaming markers** — no `EventSource`, no `WebSocket`, no `setInterval` (widgets render atomically and never poll).

Purpose: locks in the mobile-first-class invariant so future template edits or new custom-widget authoring cannot regress silently. Plan 01's manual audit produced the initial correctness; Plan 03's test keeps it correct across future changes.

Output: One new test file, one one-line addition to `run-all.sh`, and a green test run against the current post-Plan-01 template set.

Depends on Plan 01 shipping first — the audit's `min-height: 44px` assertion will fail against the pre-Plan-01 templates (8 of 12 didn't have it).
</objective>

    Create a new test file at `substrate/skills/interactive-messages/tests/mobile-audit.test.sh`. Model its structure on the existing `all-templates-non-terminal-scaffold.test.sh` (same `pass`/`fail`/`assert_file_contains`/`assert_file_not_contains` helpers, same `set -uo pipefail`, same PASS/FAIL counter + FAIL summary at end, exit 0/1). The test does NOT scaffold widgets — it audits the SOURCE templates in `substrate/skills/interactive-messages/templates/*/widget.html` directly. This avoids needing `SKIP_SYSTEMCTL` or a temp `HOME`.

    Test body:

    Enumerate all 12 template dirs by globbing `SCRIPT_DIR/../templates/*/widget.html`. For each `widget.html`, run five audit checks (in order):

    **Check 1: viewport meta present.**
    Grep for `<meta name="viewport"` — must exist. Use `assert_file_contains "$html" '<meta name="viewport"' "<template>: viewport meta present"`.

    **Check 2: ≥44px touch target.**
    Extended-regex grep for `min-height:\s*44px` — must exist at least once. Use `grep -qE 'min-height:\s*44px' "$html"` and pass/fail accordingly. Label the assertion `<template>: has min-height 44px on interactive element`.

    **Check 3: no horizontal-scroll hacks.**
    Extended-regex grep for `overflow-x:\s*(auto|scroll)` — must NOT match. Use `grep -qE 'overflow-x:\s*(auto|scroll)' "$html"` and invert. Label `<template>: no overflow-x hack`.

    **Check 4: postMessage origin discipline.**
    Two sub-assertions:

    (a) Count `postMessage(` occurrences. If zero, skip sub-assertion (b) — non-terminal templates legitimately have zero postMessage calls.

    (b) If any `postMessage(` calls exist, assert:
    - Zero occurrences of `postMessage\(.*,\s*['"]\\*['"]` (regex for `postMessage(anything, "*")` or single-quote variant). Use `grep -cE "postMessage\\(.*,\\s*['\\\"]\\*['\\\"]" "$html"` and require count `-eq 0`.
    - At least one occurrence of `window\\.location\\.origin` in the file (the correct target). Use `grep -qE 'window\\.location\\.origin' "$html"`.

    Label the assertions: `<template>: postMessage never uses "*" origin` and `<template>: postMessage uses window.location.origin`.

    **Check 5: no streaming/polling markers.**
    Three sub-assertions, each asserting zero occurrences:
    - `EventSource\(` — SSE client.
    - `new WebSocket\(` — WebSocket client.
    - `setInterval\(` — client-side polling (fetch loops).

    Note: this check excludes `setTimeout` which is legitimately used for the retry-load-fail case in the widget frame wrapper (which lives OUTSIDE the widget.html files, in `WidgetBubble.tsx`); widgets themselves never poll.

    Use extended-regex greps: `grep -cE 'EventSource\('`, `grep -cE 'new WebSocket\('`, `grep -cE 'setInterval\('`. Each must return `0`.

    Label: `<template>: no EventSource`, `<template>: no WebSocket`, `<template>: no setInterval`.

    ── Test summary format ──

    At end of script, print `mobile-audit.test.sh: N/M assertions passed` where N=PASS, M=PASS+FAIL. If FAIL > 0, print the FAILURES list and exit 1. Otherwise exit 0.

    ── Robustness ──

    - Use `set -uo pipefail` (NOT `set -e` — the test must accumulate failures, not abort on first).
    - Use `SCRIPT_DIR=$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)` to be re-runnable from any cwd.
    - The `TEMPLATES_DIR="$SCRIPT_DIR/../templates"` resolves to `substrate/skills/interactive-messages/templates/`.
    - Emit `[PASS]` / `[FAIL]` lines exactly matching the pattern the rest of the test suite uses (so `run-all.sh` prints consistent output).

    ── Non-goals ──

    - Do NOT run the templates through `create-widget.sh` — the templates are the source of truth being audited, not the substituted output.
    - Do NOT check color contrast, keyboard-focus rings, ARIA labels, or non-touch accessibility. Those may deserve future audits; this plan's scope is the four disciplines listed above.
    - Do NOT add a viewport-width playwright test. Grep-audit is sufficient for the invariants being enforced.

    Make the script executable: `chmod +x` is unnecessary (the test suite invokes with `bash <path>`), but do not add a bash-only construct that breaks on POSIX sh — the shebang is `#!/usr/bin/env bash` and the rest of the tests all rely on Bashisms.
