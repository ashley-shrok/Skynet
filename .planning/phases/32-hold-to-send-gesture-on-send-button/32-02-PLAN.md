<objective>
Wire the `useHoldToRecord` hook (created in Plan 32-01) into BOTH send-button render sites inside ComposeBox.tsx — the primary send button at L2380-2437 and the slot-mode send button inside the QueuedRow subcomponent at L2807-2846 — with symmetric behavior. **Three critical wiring details** (fixes for checker blockers B-2, B-3, and M-2):

1. **B-2 fix — preserve aside-dismiss onClick on the primary button**: Because the useHoldToRecord hook's guard chain short-circuits pointerdown when `asideActive=true` (returning before `startedRecordingRef` is set), the hook's own short-tap callback would never fire when asideActive. That means moving the aside-dismiss into the hook's onShortTap would leave the X button dead (tap does nothing). Fix: the button KEEPS its native `onClick={asideActive ? () => onAsideDismiss?.() : undefined}` alongside the hook's pointer handlers. When asideActive, the hook is inert AND the browser fires a synthetic click event from the valid pointerdown/pointerup pair — that click triggers the preserved onClick and dismisses the aside. When !asideActive, onClick is undefined and the hook governs everything.

2. **B-3 fix — gate showRecordingControls on !holdInitiatedRef**: `showRecordingControls = isPrimaryRecording = voice.state === "recording" && micTarget === "primary"` (L1587/L1603) — the moment voice.state flips to "recording" via the hold-record path, RecordingControls swaps in and replaces the primary send button. That violates CONTEXT.md L19/L54 "Do NOT swap in RecordingControls under the pointer." Fix: `showRecordingControls = isPrimaryRecording && !primaryHold.holdInitiatedRef.current`. Same treatment for `showSlotRecording` inside QueuedRow (`showSlotRecording && !slotHold.holdInitiatedRef.current`). Because holdInitiatedRef is a ref (not state), it doesn't cause re-renders on write, but voice.state IS state — so when voice.state flips to "recording" (triggering a re-render), the predicate reads the ref (already set true synchronously in pointerdown by Plan 32-01 Task 2) and skips the RecordingControls swap.

3. **M-2 fix — extract shared slot disabled expression**: The current slot button disabled expression at L2810-2818 is a 7-clause boolean. Duplicating it inline as the hook's `disabled` arg risks silent drift. Extract it once into a local `const slotSendDisabled = showSlotTranscribingSend || slot.text.trim() === "" || slotArmed || recycleActive === true || planPendingActive === true || reconnectingActive === true || dormantActive === true;` and use it in BOTH the JSX `disabled={slotSendDisabled}` prop AND the hook's `disabled: slotSendDisabled` arg.

Both render sites are handled in a single plan because they touch the same file (`ComposeBox.tsx`) — same-wave parallelism is not viable for two plans that both edit ComposeBox.tsx. The two sites are logically symmetric (same hook, different callbacks per target), so a single executor gets to hold the mental model for both.
