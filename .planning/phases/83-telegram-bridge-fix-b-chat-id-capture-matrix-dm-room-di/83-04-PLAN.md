<objective>
Populate `humans[].room` in the bridge's registry.json with the actual Matrix DM room_id whenever discoverable via Plan 83-02's `getSharedDMRoom`. Two-step change:

1. **registry-writer.ts**: extend `buildRegistryFromRows` to accept an optional `roomByAgentHumanMxidPair` map. When present, look up each `(agentMxid, humanMxid)` pair; the resolved room_id replaces the hardcoded `room: null` at L95. Absent map = old behavior (backward compatible).

2. **bridge-config-writer.ts**: inside `rewriteRegistryFromCurrentState`, after the mint loop and before calling `buildRegistryFromRows`, iterate the (agentMxid, humanMxid) pairs, `Promise.all` over `getSharedDMRoom` per pair (with individual .catch collapsing to null), assemble the map, pass to buildRegistryFromRows.

Purpose: The second half of FIXB. Without this, even when Plan 83-03 successfully populates telegram_bot_tokens.telegramChatId, registry.json will still show `room: null` for every human and MX→TG routing stays broken (bridge's `tg_poller` at bridge.sh:243 selects only rooms with `chat_id!=null and room!=null` — both gates must open).
