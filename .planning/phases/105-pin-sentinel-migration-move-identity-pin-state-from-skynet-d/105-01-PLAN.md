<objective>
Generalize the identity-birth SFTP wire (Phase 77) into a per-identity file-touch primitive with two callers per D-05: identity-birth (existing, unchanged in behavior) and pin action (new, wired in Plan 02). This plan lands the primitive AND refactors identity-birth's Step 8 relay.json write to go through it — proving the byte-identical wire preservation quality-gate before Plan 02 introduces the second caller.

Purpose: Isolate the shared "write / remove / probe a file inside ~/.claude/identities/<name>/" mechanism into ONE audit surface. Phase 77's SFTP write to relay.json has proven at production identity-birth cadence; the primitive lifts its auth path, error handling, and connection lifecycle without introducing a second parallel wire (per shape file § "Vehicle notes").

CRITICAL invariant (write⇔read parity): the primitive's identityKey gate MUST use the stricter reader-side regex `/^[a-z0-9_-]{1,64}$/` (identity-artifact-reader.ts:174) — NOT the looser identity-birth route-level regex `/^[a-z0-9._=/+-]+$/` at identity-birth.ts:64. Rationale: the loose route-level regex is a defense-in-depth gate BEFORE the orchestrator runs; it permits characters (`.`, `/`, `+`, `=`) that the on-disk readers (identity-artifact-reader IDENTITY_KEY_RE) do NOT accept. If the primitive accepted the loose set, a pin write could succeed on disk for an identity name containing `.` or `/`, but every subsequent read (identityFileExists, publicIdentity fanout, agent-supervisor sentinel probe) would reject the same key — pin sticks silently on disk with no rendered effect. Locking the primitive to the stricter reader regex eliminates the whole class of silent divergence. It also removes the `.` and `/` characters that were the only path-traversal-adjacent characters in the loose set — the relPath whitelist is now belt-and-suspenders rather than the sole traversal defense.

Output: New `per-identity-file.ts` module with three exported functions + colocated tests + identity-birth-orchestrator.ts Step 8 refactored to route through it. Behavior byte-for-byte identical to pre-refactor (regression trap in tests enforces this).
</objective>
