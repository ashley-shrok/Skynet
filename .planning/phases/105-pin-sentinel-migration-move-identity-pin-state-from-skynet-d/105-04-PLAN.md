<objective>
Rewire the frontend to consume disk-authoritative pin state from the identity-metadata payload per D-04, and to submit the identityHosts map alongside pin toggles so the backend fanout (Plan 02 Task 2) can resolve each identity's host. UI feel is unchanged from current pin toggle behavior per D-06: same right-click menu, same optimistic-flip, same fire-and-forget write, same hydrate-on-mount reconciliation — only the DATA SOURCE for the reconciliation shifts.

Purpose: Complete the two-sources-of-truth elimination on the read side. Post-Plan-04, the frontend's `pinnedIds` Set is derived by reading each identity's `pinned` field from the identity-metadata response (populated on-demand from disk by Plan 02 Task 1). The dedicated `getPinnedIds()` fetch to GET /user-preferences is retired — the projection over identity metadata replaces it.

H2 identityHosts derivation lock — the map that carries identityKey → hostId at BOTH the write side (putPinnedIds second arg) AND the read-side projection (deriveDiskPinnedIds argument) is built by the SINGLE EXISTING helper `buildIdentityHostsFromFleet(fleetSessions: FleetSession[])` exported from src/ui/state/identities-store.ts at L74-85. That helper's derivation logic is `sessionMatchKey(session.sessionName)` (imported from src/ui/features/terminal/session-hue.ts:4-10) — a helper that returns null for `null/undefined/empty` sessionName, lowercases the result, and lets the identities-store's caller skip the entry via `if (identityKey === null) continue`. Relay-room sessions have `sessionName === undefined` on the wire (per conversation-store.ts L710-731 relay-room branch) so they fall through sessionMatchKey's `if (!name) return null` gate at session-hue.ts:7. Plan 04 MUST NOT introduce a parallel `deriveIdentityHostsMap` helper that iterates fleetSessions with `session.sessionName.toLowerCase()` — that pattern (a) crashes on `undefined.toLowerCase()` for relay-room sessions, (b) diverges from the semantics the identities-store already ships to the backend for its own fanout, and (c) risks silent drift if sessionMatchKey ever tightens (e.g. to reject session names that don't match a known identity). Reusing buildIdentityHostsFromFleet is the H2 fix — one derivation, one audit surface, one place to change if the mapping ever shifts.

Output: user-preferences-api.ts (getPinnedIds removed, putPinnedIds signature extended with identityHosts); identities-store.ts (deriveDiskPinnedIds selector exported alongside the already-existing buildIdentityHostsFromFleet); conversation-store.ts (pin toggle callsites REUSE buildIdentityHostsFromFleet — no new derivation helper); PrettyConversationsPanel.tsx (hydrate effect uses buildIdentityHostsFromFleet → deriveDiskPinnedIds); conversation-store.test.ts updated for the new shape plus H2 regression trap.
