<objective>
Rewire the backend: sever every read/write of `pinnedConversationIds` from the DB row and reroute both to Plan 01's per-identity file primitive per D-03/D-04/D-05. After this plan:

- Read path: `publicIdentity` grows a `pinned: boolean` field, populated by `identityFileExists(name, ".pinned", ...)` at request time — on-demand disk read from the same host / conn / auth path the role-cosmetic-read (Phase 85) already uses.
- Write path: `PUT /user-preferences` with `pinnedConversationIds: string[]` compares the incoming set against a snapshot derived from disk-read fanout, then writes `.pinned` for keys that entered the set and removes `.pinned` for keys that left — synchronous per D-06, UI feel unchanged.
- The `pinnedConversationIds` column on the row is NO LONGER READ or WRITTEN. Plan 03 physically drops the column now that nothing consumes it.

Purpose: Cross the two-sources-of-truth gap. Until this plan lands, both the DB column AND the disk sentinel could exist independently; after this plan, disk is authoritative and DB is unreferenced. Plan 03 (wave 3) then physically drops the dead column safely.

H3 invariant lock — lowercase-on-disk (fleet-wide, documented HERE for the first time in the phase): every identity folder Skynet interacts with is named with a lowercase identityKey. This is enforced BOTH by identity-artifact-reader.ts:174's `IDENTITY_KEY_RE = /^[a-z0-9_-]{1,64}$/` (the reader-side gate — Phase 92 Plan 01 also uses this exact regex for its writer gate per H1 fix, closing the write⇔read parity trap) AND by listIdentityKeysOnHost (identity-artifact-reader's directory enumerator) which lists folder names via `find ... -type d -printf '%f\n'` — folder names are read raw, and any capitalized folder would fail the downstream IDENTITY_KEY_RE narrowing at every existing reader anyway. The identityHosts map arriving at this backend from the frontend is pre-lowercased by parseIdentityHosts at identities.ts:248 (`out[k.toLowerCase()] = v`), so the keys threaded into the primitive fanout are ALREADY lowercase. This plan's fanout MUST pass those keys VERBATIM to writeIdentityFile / removeIdentityFile / identityFileExists — no re-uppercasing, no case-insensitive glob scan, no defensive .toLowerCase() call that could mask an upstream case-coercion regression. The regression traps (Test PUT-92-08 + PUB-92-06) assert the identityKey argument passed to each primitive call matches the identityHosts key BYTE-FOR-BYTE.

Output: user-preferences.ts (both handlers rewired), identities.ts (publicIdentity + disk-fanout extended), colocated test suites updated to cover the new contract INCLUDING the lowercase-on-disk verbatim-passthrough regression traps.
</objective>
