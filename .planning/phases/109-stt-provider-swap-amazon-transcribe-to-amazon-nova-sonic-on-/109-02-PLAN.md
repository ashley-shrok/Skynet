<objective>
Add `webmToPcm16k(webmBuffer: Buffer): Promise<Buffer>` to `src/backend/voice/audio-transcode.ts` — a thin new ffmpeg-wrapper helper that decodes a browser WebM/Opus blob into raw LPCM 16 kHz s16le mono bytes, the exact format Amazon Nova Sonic's `audioInput` events expect (D-AUDIO). This is a purely additive change: `webmToOggOpus`, `webmToFlac`, `runFfmpeg`, and the `SILENCE_TRIM_*` tuning exports are untouched.

This plan is INDEPENDENT of Plan 01 (nova-sonic-adapter) — the two share no files. Wave 1 runs both in parallel.

Purpose: give Plan 03's rewired `handleTranscribe` a single-shot transcode function that produces exactly the byte shape the Nova Sonic adapter needs, using the same ffmpeg subprocess pattern already established by the sibling helpers. The SILENCE_FILTER is preserved because Nova Sonic bills per audio token — trimming long silences pre-transcode still saves cost.

Output: `audio-transcode.ts` grows by ~20 lines (the new function + docstring); `audio-transcode.test.ts` grows by ~40 lines (5 new test cases mirroring the webmToFlac topology).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| voice.ts → webmToPcm16k | Caller (Plan 03's rewired `handleTranscribe`) hands an untrusted-origin WebM buffer to this helper. The buffer originated from a multipart upload (25 MB cap already applied via multer). |
| webmToPcm16k → ffmpeg subprocess | Buffer is piped to stdin (bytes only). ffmpeg argv is entirely literal — no user data is interpolated into argv. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-109-02-01 | Tampering (command injection) | ffmpeg argv construction | mitigate | argv is a literal string array; user bytes flow through stdin only. Mirrors the invariant already enforced by `webmToOggOpus` / `webmToFlac` (see audio-transcode.ts docblock lines 60-63). No user-controlled interpolation into argv. |
| T-109-02-02 | Denial of service | Oversized input buffer | inherit | multer's 25 MB fileSize cap in voice.ts is the upstream guard. ffmpeg's memory profile on a 25 MB WebM decode is bounded and does not require a second guard here. |
| T-109-02-03 | Denial of service | ffmpeg subprocess hangs | mitigate | Inherits from `runFfmpeg`: process is spawned with 'pipe' stdio and `close`/`error` events are wired. If ffmpeg exits non-zero, the promise rejects with the stderr text (caller returns 502). No timeout is added — Skynet's request handler will time out at the Express layer; adding a subprocess timeout is a broader refactor out of scope for this phase. |
| T-109-02-04 | Information disclosure | ffmpeg stderr leaked in error text | accept | Error message includes ffmpeg stderr, which contains no user data (only ffmpeg's internal diagnostics). Caller in voice.ts already wraps this in a fixed 502 `{ error: "STT error", status: 502 }` shape (Plan 03). |
| T-109-02-SC | Tampering | npm/pip/cargo installs | mitigate | No new npm deps in this plan (ffmpeg is a Docker-installed system binary). N/A. |
</threat_model>
