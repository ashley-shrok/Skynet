<objective>
Extend the form editor in `src/ui/features/pretty-view/WakeupsTab.tsx` so an optional top-level `days: Weekday[]` gate is preserved through the hydrate→edit→build round trip and surfaced as a chip UI under the daily + weekly variant renders. Today the FormSchedule discriminated union (L47-51) has no `days` field, `hydrateFormSchedule` (L89-131) drops `s.days`, `buildSchedule` (L135-147) never emits it, and the UI has no chip affordance — so opening a weekdays-only wakeup card in edit mode and pressing Save silently strips the gate off the wire, turning the spec into a plain daily/weekly one (DATA LOSS bug half of Phase 65).

Purpose: fixes ROUND-TRIP half of the Phase 65 symmetric bug pair. Wave-2 placement gives this plan an independent, clean review lens after Plan 65-01 lands the display fix — the two plans touch disjoint files (`src/backend/claude-session/identity-artifact-reader.ts` vs `src/ui/features/pretty-view/WakeupsTab.tsx`) with no import chain between them at the changed regions, so they COULD run in parallel; sequencing them keeps the diff surface easy to reason about.

Output:
- `FormSchedule` union extended with `days?: Weekday[]` on interval/daily/weekly variants; one_shot unchanged.
- `hydrateFormSchedule` normalizes raw `s.days` to canonical mon→sun order (defensive dedup + isWeekday filter).
- `buildSchedule` emits `days: fs.days` only when non-empty AND not full-7 (D-02 + D-04 drop-the-field).
- `validateForm` unchanged behavior — no blocking check on `days` (D-04).
- New chip UI row mounted under daily variant (currently at L519-543) and weekly variant (currently at L545-596), matching the on/off enabled-chip family styling from L354-362 (D-06).
- Extended `WakeupsTab.test.tsx` with 5+ new tests covering round-trip preservation, chip-toggle-to-payload, full-7 drop, empty-subset drop, and defensive hydrate normalization (Success Criteria #2, #3).
- Zero changes to interval/one_shot UI, backend, wire schema, scheduler, or `Wakeup` type.
</objective>
