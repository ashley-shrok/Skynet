<objective>
Ship the poll template in non-terminal mode. Non-terminal poll = radio-style selectors that persist the user's current choice on every change without firing any submit signal. The widget stays interactive indefinitely; the user can change their choice as often as they want. The agent reads `state.json` on demand alongside the user's next text reply — no wake signal fires from the widget.

Purpose: First of six non-terminal templates. Poll is the closest structural sibling to color-picker (both terminal-on-click in Phase 138) but the non-terminal inversion applies identically to both. This plan establishes the non-terminal contract every sibling plan (140-03 through 140-07) will follow: radio/passive affordance, `/update` server endpoint, `updated_at` instead of `submitted_at`, zero `postMessage` calls, indefinite editability.

The affordance shift from Phase 138 poll matters: Phase 138 poll rendered button-style options (clicking IS the submit — terminal-on-click). Non-terminal poll renders radio-style options (clicking updates a persisted selection — the user's own next text message is what wakes the agent). Same underlying data — different affordance because the mode changed.

Output: Fully-scaffolded `templates/poll-non-terminal/` directory + per-template test file.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| widget.html substitution | Agent-supplied prompt + options flowed into inline JS via JSON encoding |
| POST /update body | Untrusted JSON — same-origin, parsed with try/except |
| state.json persistence | Overwrite-on-every-update semantic — no append, no history |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-140-02-HTMLInject | Tampering | Prompt/options substituted into widget.html JS | mitigate | `json.dumps` for all inline JS substitutions (inherited from poll-terminal-on-click's args.sh which this reuses verbatim). |
| T-140-02-BadJSON | Denial of Service | POST /update malformed body | mitigate | `try/except (json.JSONDecodeError, ValueError)` in server.py POST handler; 400 response on bad JSON without state.json write. |
| T-140-02-AffordanceViolation | (Design) | Passive-looking radios must not fire postMessage | mitigate | widget.html has ZERO `postMessage` calls (grep-checked); ZERO `window.parent` references. Radios are visually passive AND behaviorally passive. This is the arc-wide "affordance matches behavior" invariant. |
| T-140-02-StaleStateRead | Information Disclosure | Agent reads state.json before user finalizes | accept | Non-terminal mode's whole point is on-demand read. The agent must decide when to read; there is no wake signal. The updated_at timestamp lets the agent detect staleness. Documented in SKILL.md (Plan 08). |
| T-140-02-LockContention | Denial of Service | Rapid change events could race on state.json write | mitigate | `threading.Lock` in server.py (inherited from poll-terminal-on-click) serializes writes. |
</threat_model>
