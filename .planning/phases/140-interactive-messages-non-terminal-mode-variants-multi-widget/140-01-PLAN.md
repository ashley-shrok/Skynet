<objective>
Extend `create-widget.sh` to accept an explicit `--mode <terminal-on-click|terminal-on-submit|non-terminal>` flag while preserving Phase 137/138 back-compat where mode was implicit. Enforce the curated per-template mode set from the shape file — a request like `--template form --mode terminal-on-click` errors clearly because no `form-terminal-on-click/` template dir exists.

Purpose: Unblocks Wave 2 by giving the six non-terminal template plans a working dispatch path — each Wave 2 plan simply creates its `<template>-non-terminal/` directory and it becomes reachable via `--mode non-terminal`. Also preserves every Phase 138 caller (which never passed `--mode`) by falling back to each template's canonical default mode.

Currently the dispatcher resolves `TEMPLATE_DIR` by globbing `templates/<name>-*` and taking the first match (Phase 138 line 154). With only one directory per template that behavior worked. In Phase 140 each template gets two directories, so the glob is no longer sufficient and must be replaced with explicit `<template>-<mode>` resolution + a default-mode table for the omitted case.

Output: `create-widget.sh` rewritten with mode-aware dispatch and a per-template default-mode map. Base test harness (`tests/create-widget.test.sh`) extended with new cases covering `--mode` explicit dispatch, default-mode fallback (poll → terminal-on-click), and clear-error rejection of unsupported combos.
</objective>

**3. Introduce a supported-modes-per-template map for validation.**

Add a bash function `is_supported_combo()` that returns 0 for supported (template, mode) pairs and 1 otherwise. Supported combos:

- `checklist`: terminal-on-submit, non-terminal
- `form`: terminal-on-submit, non-terminal
- `ranking`: terminal-on-submit, non-terminal
- `list-actions`: terminal-on-submit, non-terminal
- `color-picker`: terminal-on-click, non-terminal

```
is_supported_combo() {
    local t="$1" m="$2"
    case "$t:$m" in
        poll:terminal-on-click|poll:non-terminal) return 0 ;;
        checklist:terminal-on-submit|checklist:non-terminal) return 0 ;;
        form:terminal-on-submit|form:non-terminal) return 0 ;;
        ranking:terminal-on-submit|ranking:non-terminal) return 0 ;;
        list-actions:terminal-on-submit|list-actions:non-terminal) return 0 ;;
        color-picker:terminal-on-click|color-picker:non-terminal) return 0 ;;
        *) return 1 ;;
    esac
}
```

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-140-01-PathInject | Tampering | `$SCRIPT_DIR/templates/$TEMPLATE-$MODE` filesystem path | mitigate | `--mode` value validated against a literal allowlist of three strings (`terminal-on-click|terminal-on-submit|non-terminal`) BEFORE it's used in the path. `$TEMPLATE` was already validated in Phase 138 (six-name allowlist). Both must pass their allowlists before path composition. |
| T-140-01-SilentFallback | Tampering | Default-mode fallback when --mode is omitted | mitigate | `default_mode_for_template()` uses a `case` statement with an explicit `*)` catch-all that returns 1.
