<objective>
Ship the form template in non-terminal mode. Non-terminal form = a set of labeled text/number/select inputs with live persistence on every input/change event. The user can edit any field as often as they want; each change POSTs the full current fields snapshot to `/update` and overwrites state.json. Ideal for scratch-pad-style data collection where the user's own text reply signals completion.

Purpose: Third of six non-terminal templates. Form's `--field` spec parser (name:type[:options] validation) is complex and must be preserved byte-identically from the terminal sibling. The mode inversion applies only to submit-flow: no submit button, no postMessage, `/update` instead of `/submit`, `updated_at` instead of `submitted_at`.

Debouncing note: unlike checklist (where a toggle is a discrete event) and poll (where selection change is discrete), text inputs fire many events on every keystroke. The widget MUST debounce input events on `text` and `number` fields to avoid POST spam. Select fields fire on change (not input) which is naturally discrete.

Output: Fully-scaffolded `templates/form-non-terminal/` directory + per-template test file.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| widget.html substitution | Agent-supplied prompt + fields into inline JS |
| POST /update body | Untrusted JSON, same-origin |
| Field value input | User text/number can be arbitrary strings until server-side agent reads them |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-140-04-HTMLInject | Tampering | Prompt/fields into widget.html JS | mitigate | `json.dumps` inline substitution inherited from form-terminal-on-submit args.sh |
| T-140-04-InputFlood | Denial of Service | Rapid keystroke events on text/number fields | mitigate | 400ms debounce on text/number input events; only the trailing edit persists. Select fields naturally discrete. |
| T-140-04-BadJSON | Denial of Service | POST /update malformed body | mitigate | `try/except` in server.py |
| T-140-04-SubmitLabelStale | Denial of Service | Agent passes --submit-label from Phase 138 memory | mitigate | args.sh explicitly rejects --submit-label |
| T-140-04-LockContention | Denial of Service | Overlapping /update writes | mitigate | threading.Lock in server.py |
| T-140-04-PartialStateWindow | Information Disclosure | Agent reads state.json mid-edit | accept | Agent decides when to read; updated_at timestamp signals recency; documented in SKILL.md |
</threat_model>
