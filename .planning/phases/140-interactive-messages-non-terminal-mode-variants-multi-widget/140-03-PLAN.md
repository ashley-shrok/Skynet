<objective>
Ship the checklist template in non-terminal mode. Non-terminal checklist = a list of checkboxes with live persistence on every toggle. The user can check, uncheck, and re-check as often as they want; each change POSTs the current full set of checked values to `/update` and overwrites state.json. The agent reads state.json on demand alongside the user's next text reply.

Purpose: Second of six non-terminal templates. Checklist-terminal-on-submit already renders passive checkboxes (no click-to-submit), so the affordance stays the same — the mode change removes the submit button entirely, changes the endpoint to /update, and replaces submitted_at with updated_at. This is a cleaner inversion than poll (which had to switch from buttons to radios) because checklist's affordance was already passive.

Output: Fully-scaffolded `templates/checklist-non-terminal/` directory + per-template test file.
</objective>
