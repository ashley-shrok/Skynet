<objective>
Extend the existing 5-step `identity-birth-orchestrator` with three new steps (6: admin-mint, 7: build relay.json body, 8: SFTP-write relay.json + chmod 600) so Skynet-driven remote agent birth ATOMICALLY creates the relay account and lands `~/.claude/identities/<name>/relay.json` in one operation with a real (non-empty) access_token. This is the MXA-03 completion criterion.

Also land the Q2 partial-failure retry surface: `POST /identities/birth/retry/:key` re-runs steps 6+8 for an existing identity folder (per D-OQ1 lock: mount under `/identities/birth` to inherit existing nginx coverage; extract shared helper so orchestrator and retry share one code path).

Purpose: this is the phase's headline behavioral change. Without it, agent birth stays as two independent worlds (identity folder + relay account) — the design fork the phase exists to eliminate. The Q2 lock (partial-tolerated, NO rollback) is documented inline at every catch surface to prevent a future reviewer from "helpfully" adding rm -rf logic — see 77-CONTEXT.md § Storage failure mode + agent-supervisor race.

Output: extended orchestrator with three new steps + login-inside-runRelayMintAndWrite + BirthEvent union widening + BirthDeps widening (four new deps: matrixCreateOrUpdateUser, matrixLoginAsUser, matrixHomeserver, buildRelayJsonBody) + shared helper for reuse; wiring in identity-birth.ts with 503 fail-early on missing admin creds and the second route; new unit test cases proving happy path + Q2 partial-tolerated behavior (with rationale in test names) + local-branch skip + retry idempotency + chmod-600 applied.

Decisions locked here per RESEARCH.md open questions:
- D-OQ1 (retry surface): POST /identities/birth/retry/:key mounted inside identity-birth.ts's router (already mounted at /identities/birth). Body: `{ hostId: number }`. Inherits nginx /identities coverage. Admin-gated inside handler.
- D-OQ2 (displayname on mint): set displayname = identity's frontmatter displayName if present, else omit — trivial extra JSON field, better Element rendering. Falls back gracefully when displayName is absent.
- D-OQ3 (local-branch self-birth for relay account): SKIP steps 6-8 in useLocal branch — mirror the existing pre-write skip (identity-birth-orchestrator.ts:507-509). Phase A UAT is remote fleet hosts only.
- D-OQ4 (client style): free functions — already locked in Plan 02.
- **D-OQ6 (accessToken sourcing — locked here in this revision): the orchestrator's runRelayMintAndWrite helper calls `deps.matrixLoginAsUser(mxid)` between step 6 (createOrUpdateUser) and step 7 (buildRelayJsonBody). matrixLoginAsUser is added as a FOURTH BirthDeps field, wired in Task 2 to Plan 02's exported `loginAsUser` primitive. This preserves Plan 02's "each primitive is one endpoint" contract (no retroactive change to Plan 02 required) AND ensures the relay.json body carries a real (non-empty) access_token so recv.sh does not have to relogin on first read. Rejected alternative: coupling loginAsUser into Plan 02's createOrUpdateUser — that would dilute Plan 02's already-locked primitives-are-one-endpoint shape.**
- **D-OQ7 (missing-admin-creds handling — locked here in this revision): when `getMatrixAdminCreds()` returns null at birth-request deps-assembly time, identity-birth.ts fails the request early with HTTP 503 and error message "matrix admin foundation not ingested — see deploy runbook". Do NOT fall through with a hardcoded homeserver. Rationale: (a) CONTEXT.md § Philosophy — "Each Skynet box is its own island; nothing federates, nothing shares" — hardcoding `thenasty.taild9b663.ts.net` bakes t1000-specific state into shipped code; (b) silent-divergence risk on any non-ingested deployment; (c) fail-early gives operators a clear signal to run the ingestion runbook step rather than surface a broken mint call several steps later.**

Failure mode locked (Q2): PARTIAL-TOLERATED, NO ROLLBACK. Do NOT add any rm -rf logic in a catch block. The agent-supervisor race is real (Pitfall 6) — deleting a folder the supervisor is already spinning up on is worse than leaving a partial state. The id skill's existing self-register fallback handles the partial-state case gracefully. Every catch surface at steps 6/7/8 MUST carry an inline code comment citing this rationale, and test names MUST include the "Q2 agent-supervisor race" phrase — this prevents drift as the code ages.
</objective>
