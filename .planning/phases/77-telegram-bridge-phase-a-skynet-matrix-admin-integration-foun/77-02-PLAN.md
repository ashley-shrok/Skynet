<objective>
Land the Matrix admin client: five free async functions that wrap the exact five Synapse admin API endpoints Skynet needs (createOrUpdateUser, loginAsUser, joinRoom, makeRoomAdmin, listRooms), plus a pure `buildRelayJsonBody` helper for constructing the relay.json body that recv.sh expects. All calls use Node 22's built-in fetch with AbortController-based timeouts and return a discriminated union `{ok:true, ...} | {ok:false, status, error}`.

Purpose: this is the primitive layer for MXA-01 and MXA-05. Every downstream feature — birth-orchestrator step 6 (mint), the retry endpoint, Phase B token-minting for humans — sits on top of these five functions. No Matrix SDK, no e2ee, no room-cryptography — just the admin endpoints we need.

Output: `matrix-admin-client.ts` (~150 lines, mirroring voice.ts's fetch shape) + `matrix-admin-client.test.ts` with mocked-fetch unit tests covering happy path, non-2xx, timeout, and network-error branches for every primitive.

Decision D-OQ4 (locked here by planner per RESEARCH.md Open Question 4): FREE FUNCTIONS, not a class. Matches voice.ts precedent; trivially mockable via vi.mock on getMatrixAdminCreds. No state beyond the credentials, which the store owns.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Skynet backend → Synapse admin API | Tailnet-only; @skynet-admin Bearer token auth; every request carries admin power over the entire relay |
| external caller-supplied mxid / roomId → URL construction | Input MUST be validated + encodeURIComponent'd; direct interpolation is a path-traversal risk |
| Synapse response body → log/return | Upstream body may contain sensitive relay state; NEVER leak in error returns or log lines |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-75-05 | Tampering | mxid / roomId → URL path | mitigate | encodeURIComponent() at every URL interpolation site; regex-gate at the handler boundaries in Plan 03/04 provides defense-in-depth |
| T-75-06 | Information Disclosure | error logging | mitigate | Log only status codes + operation name; NEVER log Bearer token, request body, or response body — voice.ts precedent enforced |
| T-75-07 | Denial of Service | slow Synapse response ties up Node event loop | mitigate | 30_000ms AbortController timeout on every primitive; timeout returns 504 stably |
| T-75-08 | Information Disclosure | listRooms returning entire relay's room list | accept | Caller is admin-gated at handler layer (Plan 03/04); the room list is inherently admin-visible; default limit=200 caps single-response size |
| T-75-09 | Repudiation | admin action without audit trail | mitigate | Every non-2xx logs status + operation via databaseLogger; caller (birth orchestrator / retry endpoint / mxid endpoint) adds admin-user audit trail on top |
| T-75-SC | Tampering | npm/pip/cargo installs | mitigate | Zero new packages in this plan; RESEARCH.md § Package Legitimacy Audit records none |
