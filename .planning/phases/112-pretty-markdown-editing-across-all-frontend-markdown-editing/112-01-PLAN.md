<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user keyboard → MDXEditor Lexical state tree | User-typed markdown content flows into Lexical's parser; must not permit arbitrary HTML/script execution |
| user-supplied markdown content (e.g. `[x](javascript:...)`) → rendered DOM | Markdown link URLs are parsed and rendered as `<a href>` — must sanitize `javascript:` and `data:` schemes |
| npm registry → build (supply-chain) | `@mdxeditor/editor` is a new dependency; slopcheck unavailable, [ASSUMED] tag applied |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-112-01 | Tampering | MDXEditor link rendering | mitigate | Task 2 test 8 asserts `javascript:` URLs in markdown content never emit an anchor with `href^="javascript:"` in the rendered DOM. MDXEditor + Lexical strip these schemes by default; test is a regression canary. |
| T-112-02 | Tampering | MDXEditor markdown → HTML rendering | mitigate | Lexical renders from AST, not raw HTML strings; no `dangerouslySetInnerHTML` in `MdxEditorImpl.tsx`. Verified by grep in acceptance criteria (implicit — file is under our control). |
| T-112-03 | Tampering | `js-yaml` frontmatter parsing (bundled by MDXEditor) | accept | js-yaml modern versions default to safe-mode; MDXEditor bundles a recent version. Malformed YAML (Pitfall 3) is a UX concern, not a security concern — worst case is the frontmatter dialog opens empty, not code execution. |
| T-111-SC | Tampering | npm install of `@mdxeditor/editor` | mitigate | Task 1 is a `checkpoint:human-verify gate="blocking-human"` per Skynet Package Legitimacy Gate protocol. Manual audit evidence in RESEARCH §Package Legitimacy Audit is strong (3+ years, ~892k weekly downloads, real repo, no postinstall hook), but slopcheck is unavailable so the gate is human-gated per policy. |
