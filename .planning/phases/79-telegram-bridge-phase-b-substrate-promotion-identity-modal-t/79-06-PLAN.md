<objective>
Create the canonical repository copy of the Skynet Docker Compose file, adding the new `tg-bridge` service and the shared named volume `tg-bridge-state` that both `skynet` and `tg-bridge` mount at `/state`. Parametrize all host-varying paths (bind-mount sources, env_file, Caddyfile location) via `${SKYNET_HOST_DIR:-/opt/skynet}` env-var substitution so `docker compose config` against the repo file does not fail on non-existent bind-mount sources (blocker B-5 fix).

Purpose: This is the deployment surface that wires the bridge into the Skynet fleet. Without it, the bridge image built in Plan 05 has no runtime and the /state/ files written by Plan 04 have no reader. Once this lands + is deployed (orchestrator-owned push cycle, per fleet rule), a fresh `docker compose up` brings up a working bridge with zero operator burden.

**Important context about compose-file location (unchanged from pre-revision):** the LIVE compose file today lives ONLY at `/opt/skynet/docker-compose.yml` on the host (verified via `cat /opt/skynet/docker-compose.yml`). The repo has `docker/compose-dev.yml` for local dev but NO `docker/docker-compose.yml`. This plan creates that canonical file.

**Blocker B-5 resolution:** the live file has host-absolute bind-mounts:
- `- /opt/skynet/console-forward-logs:/var/log/skynet/console-forward`
- `- /opt/skynet/stt-recordings:/app/stt-recordings`
- `source: /opt/skynet/branding` (branding bind-mount)
- `env_file: - /opt/skynet/skynet.env`
- `- /opt/skynet/keys:/keys:ro` 
- `- /opt/skynet/Caddyfile:/etc/caddy/Caddyfile:ro` (caddy service)

None of these paths exist in the repo tree. Two viable strategies were considered:
- **(A) Env-var substitution** — `${SKYNET_HOST_DIR:-/opt/skynet}/console-forward-logs` etc. Single file works for both repo `docker compose config` (with default) and live deploy (default matches live). No two-file drift.
- **(B) Split into `compose-base.yml` + overlay** — two files, deployment merges them. More flexible but adds moving parts.

**Chosen strategy:** (A) — env-var substitution with the default value matching the current live config. Justification: (1) zero additional moving parts, (2) `docker compose -f docker/docker-compose.yml config` passes cleanly against the default because the paths ARE `/opt/skynet/...` which do exist on the deploy target, (3) if a future deploy needs a different host layout (e.g., Stacy's T800 with `/srv/skynet`), the operator sets `SKYNET_HOST_DIR=/srv/skynet` in their shell env or `/srv/skynet/.env-compose` and everything else works.

Output:
- `docker/docker-compose.yml` — NEW canonical Compose file. Copy of the current live `/opt/skynet/docker-compose.yml` (verbatim, preserving all four existing services + four existing named volumes) with the six host-varying paths parametrized via `${SKYNET_HOST_DIR:-/opt/skynet}`, plus the new `tg-bridge` service block + the new `tg-bridge-state` named volume + the mount edit to the `skynet` service.
