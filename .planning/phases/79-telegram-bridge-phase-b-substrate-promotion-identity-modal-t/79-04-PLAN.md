<objective>
Land the Skynet-side writers that populate the shared Docker volume `/state/` (mounted by both `skynet` and `tg-bridge` containers) with the config file, the registry, per-human Matrix tokens, AND per-agent `<identityKey>.bottoken` plaintext files that the bridge reads for Telegram bot auth.

Purpose: The tg-bridge (Plan 05 + 06) reads its Matrix homeserver URL + STT URL from `/state/config.env` (never hardcoded — enforced by ship-gate). It reads `/state/registry.json` to know which agents to serve. It reads `/state/<human>.token` to authenticate to Matrix as each human. **It reads `/state/<identityKey>.bottoken` to authenticate to Telegram as each bot** — Nina's live convention, preserved verbatim in Phase B (see revision blocker B-1: bot tokens do NOT live in `registry.json` in Phase B, they live in per-agent `.bottoken` files so the registry can stay untouched by encrypted secrets). All four writers are Skynet-owned; the bridge is a pure consumer. Plan 08's reconcile-dead-tokens loop calls `mintAndWriteHumanToken` to refresh dead tokens.

**Post-blocker-B-2 change:** `ensureBridgeConfigWritten()` was originally scoped as "startup one-shot only." That silently breaks the wrist-reachability flow because `/telegram/activate` (Plan 03) writes a DB row and returns 200 with no side-effect on `/state/`. This plan now exports `rewriteRegistryFromCurrentState()` as a re-callable function that Plan 03 wires into activate + disconnect. The bridge's inotifywait picks up the new registry.json within a second (per Plan 05).

Output:
- `src/backend/telegram/bridge-config-writer.ts` + test — writes `/state/config.env` (with `MATRIX_ROOT` and `STT_URL` env-var-style lines); `ensureBridgeConfigWritten()` is the startup one-shot; `rewriteRegistryFromCurrentState()` is the re-callable export.
- `src/backend/telegram/registry-writer.ts` + test — takes `TelegramBotToken[]` (from `listTelegramBotTokens`), plus the humans list from `users.mxid`, and writes `/state/registry.json` in Nina's shape minus bot_token and .cred fields.
- `src/backend/telegram/human-token-writer.ts` + test — mints a token via `matrix-admin-client.loginAsUser(mxid)` and writes `/state/<human>.token` with mode 0600, using atomic write (`.tmp` + rename).
- `src/backend/telegram/bot-token-file-writer.ts` + test — writes `/state/<identityKey>.bottoken` (0600, plaintext bot token) atomically; deletes on disconnect. `syncAllBotTokenFiles()` walks all rows in one pass for startup.
- `src/backend/starter.ts` — one added block that fires `ensureBridgeConfigWritten()` fire-and-forget after DB init (non-fatal on failure — bridge retries for 5 min).
</objective>
