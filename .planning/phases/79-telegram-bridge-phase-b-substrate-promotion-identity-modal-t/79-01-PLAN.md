<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| memory ↔ disk (SQLite) | Bot tokens sit in RAM then flush to AES-encrypted disk file; if the disk file leaks, the encryption is the last line of defense |
| test fixture ↔ production data | Tests write real (fake) tokens; must never touch production `skynet-data` volume |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-79-01-01 | Information Disclosure | tokens-store.ts logging | mitigate | Never log the `botToken` value; only log `operation` name + `botUsername` (display-safe). Enforced by acceptance-criteria grep count. |
| T-79-01-02 | Information Disclosure | SQLite disk file | mitigate | FieldCrypto AES-256-GCM at rest; token column encrypted before INSERT (per PATTERNS.md § FieldCrypto). Enforced by tokens-store.test.ts Test 2 (raw-column-does-not-contain-plaintext assertion). |
| T-79-01-03 | Tampering | ENCRYPTED_FIELDS registration | mitigate | Add `telegram_bot_tokens: new Set(["bot_token"])` — without this, the FieldCrypto middleware would not encrypt on write, silently shipping plaintext. Grep gate in acceptance criteria catches missing registration. |
| T-79-01-04 | Denial of Service | forceSave failure on first boot | accept | Wrapped in try/catch/warn (non-fatal) — CREATE TABLE is idempotent; next boot retries. Matches phase-75 handling. |
| T-79-01-SC | Tampering | npm/pip/cargo installs | mitigate | Zero new packages. All deps (`drizzle-orm`, `better-sqlite3`, `FieldCrypto`, `SystemCrypto`) already in-tree (Phase 75/77). |
</threat_model>
