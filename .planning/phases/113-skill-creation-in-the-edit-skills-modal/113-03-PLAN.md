## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser (React modal) → user (window.prompt) | User-typed skill name is slugified client-side before submit; user-typed description is sent as-is (validation on backend). |
| Browser (React modal) → Skynet backend (`POST /skills-editor/skill`) via `createSkill` | Enforcement is backend-side per plan 113-01; this plan trusts the createSkill contract. |
| React DOM (`+ New file` button) → `activeTab` state | The button MUST NEVER touch `activeTab` — an accidental `setActiveTab("__new_file_tab")` would trigger the file-content lazy-load effect at L188-225 and 400 the readSkillFile call (Pitfall 9). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-113-14 | Tampering | `handleNewSkill`: user input escapes slugifier | mitigate | `slugifyRoleName` produces `/^[a-z0-9-]+$/` — a strict subset of the backend's `SKILL_NAME_RE`. Backend re-validates with `isValidSkillName` as defense-in-depth. |
| T-113-15 | Denial of Service | `handleNewSkill`: infinite prompt loop | mitigate | Both loops break on cancel (`rawName == null` / `rawDesc == null`). Only reprompt is on empty-slug or empty-description; user always has a cancel path. |
| T-113-16 | Integrity | `+ New file` button hijacks `activeTab` (Pitfall 9) | mitigate | Task 2 acceptance criteria explicitly forbid any `setActiveTab("__new_file_tab")` call; button's onClick is strictly `handleAddFile()`. |
| T-113-17 | Information Disclosure | `handleNewSkill` catch block leaks error details | mitigate | Error messages are constructed from typed error class OR sanitized `err.message`; backend already redacts stderr/paths per plan 113-01 T-113-04. |
| T-113-SC | Tampering | npm/pip/cargo installs | accept | No new packages introduced this phase. |
