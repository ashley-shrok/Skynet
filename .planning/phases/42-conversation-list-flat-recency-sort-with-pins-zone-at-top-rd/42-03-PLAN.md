<objective>
Extend the fleet-status WebSocket protocol to carry a per-session `lastMessageAt` recency signal derived from the underlying JSONL, then wire the frontend to consume it and drive the middle-zone `compareByRecencyDesc` comparator that Plan 01 installed with a null-only fallback.

Purpose: This is the full-stack plan that closes the "activity = message either direction, and only that" contract Ashley locked. Plans 01 and 02 ship the shape and search independently; this plan lands the real recency data whenever it's ready. The middle zone gracefully upgrades from insertion-order-fallback to real-recency-DESC the moment this ships.

Output: `SessionStateSchema` extended with an optional `lastMessageAt` field; backend derivation from JSONL that reflects message-either-direction only (never lifecycle/status/background-task events); frontend cache in `session-working-store`; row-derivation in `conversation-store` stamps `lastMessageAt` on each row; middle-zone sort observably re-orders on message activity.

Depends on 42-01: Plan 01 lands the `compareByRecencyDesc` comparator, the flat middle-zone shape, and the ambient-CSS retirement. This plan wires real data into the comparator.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| watcher → backend WS | Existing fleet-status WS is already authenticated + gated per RESEARCH §Security Domain. New `lastMessageAt` field piggybacks on the authenticated channel; no new endpoint or auth boundary. |
| backend → browser WS frame | Extending an existing frame schema; JWT auth on the fleet-status route is unchanged. New payload field is a numeric timestamp — no PII embedded. |
| JSONL file → orchestrator parse | Backend reads its own users' JSONL files over the established SSH exec channel; no new file access. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-42-03-01 | Information Disclosure | `lastMessageAt` reveals conversation timing pattern | accept | The signal is per-session and only reaches the authenticated user who owns the session. No cross-user visibility. Meta-info leak surface is identical to the existing `updatedAt` field. |
| T-42-03-02 | Tampering | crafted JSONL line with bogus `ts` field | mitigate | Existing `session-file-parser.ts` already validates JSONL line shape; ts is a `z.number()` post-parse. Backend accepts any numeric value from the user's own file, so worst case is a self-inflicted "row jumps to fake position in my own list". No cross-user impact. |
