<objective>
Build the pure-library modules that back the Skynet-backend fleet-status watcher. These sit alongside the Plan 02 wire-protocol.ts / subscription-registry.ts / fleet-status-server.ts modules already shipped in `src/backend/fleet-status/`. All modules are pure functions or dependency-injected orchestrators — SSH access and `/proc` reads happen in Plan 04's `ssh-poll-orchestrator.ts` and are passed into these modules as callbacks. That split (pure library + injected transport) is what makes the whole pipeline testable without a real box.

Per D-CTX § PIVOT 2026-08-13 (LOCKED): there is NO per-box daemon. The watcher runs INSIDE the Skynet backend, polls the identity-hosting boxes over the existing SSH pool every 2s, and uses THESE modules to parse the pulled bytes. The original Plan 01 built a standalone Node.js subpackage; that entire subpackage was reverted in `d72f4bd`. This new plan rebuilds the same conceptual primitives (types, liveness, correlation, ambient filter) as ordinary Skynet-backend modules in `src/backend/fleet-status/*`.

Purpose: Establish the pure-parsing / pure-logic layer that Plan 04's SSH-driven orchestrator will drive. All five modules are TDD from the first commit. Every module is unit-tested independently; no module reaches for real SSH, real filesystem, or real tmux.

Output: Five new TypeScript modules + five paired test files under `src/backend/fleet-status/`. No changes to any other file in the repo. No `starter.ts` wire-in (Plan 04 owns that). No modifications to the Plan 02 modules (`wire-protocol.ts`, `subscription-registry.ts`, `fleet-status-server.ts`, `host-id-resolver.ts`).

Non-goal: This plan does NOT open any SSH connection, does NOT read any `/proc` file, does NOT invoke tmux, does NOT publish any SessionState, does NOT touch `starter.ts`. All of that is Plan 04.
</objective>
