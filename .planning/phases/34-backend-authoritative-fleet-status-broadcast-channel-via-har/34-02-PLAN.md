<objective>
Build the Skynet backend fleet-status broadcast WebSocket server. This is the single always-on control channel D-CTX names as the target delivery topology — the frontend opens one connection to it at boot, and every per-box watcher (Plan 01) opens one connection per host to publish SessionState. The server maintains an in-memory subscription registry keyed on `(hostId, tmuxSession)`, sends every new frontend consumer a snapshot of current state, and fans out incremental updates as watchers publish. Wire protocol is versioned so we can iterate without breaking already-deployed watchers on managed boxes.

Purpose: This is the second half of the "backend-authoritative" leg of Phase 34 (Plan 01 built the box-side signal source; this plan builds the aggregator that gives the frontend a single subscription surface). Runs parallel to Plan 01 because they touch entirely disjoint code (Plan 01 is a new subpackage; this plan is a new backend module).

Output: New `src/backend/fleet-status/` module with a WebSocket server, subscription registry, wire-protocol types, and host-id resolver. Frontend cutover (Plan 06) is what makes it observable end-to-end. Watcher-to-backend wiring is Plan 04.

Non-goal: This plan does NOT modify per-pane WS lifecycle, does NOT touch Terminal.tsx / PrettyView.tsx, does NOT retire the old feeders (all those are Plan 06). This plan produces a running server that answers "give me the current state of the fleet" and accepts publishes from watchers, no consumers yet.
</objective>

| Boundary | Description |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34-06 | Spoofing | Frontend WS ingress | mitigate | JWT auth chain reused verbatim from terminal.ts (cookie regex + Bearer fallback → AuthManager.verify) — same code path, no drift |
| T-34-07 | Spoofing | Watcher WS ingress | mitigate | hostname → resolveHostRecordByName gate; unknown hostnames closed with 1008; only allowlisted Skynet host records can publish state |
| T-34-08 | Tampering | Any inbound frame | mitigate | Every frame parsed via zod discriminated-union schema; parse failures close 1003 + logged |
| T-34-09 | Information Disclosure | Snapshot fan-out | accept | The snapshot contains SessionState for all fleet sessions; any authenticated Skynet user can see it (same trust model as the existing per-pane WSes which stream conversation contents) |
| T-34-10 | Denial of Service | Watcher flooding | accept | Watchers run under Ashley's control on managed boxes; if a watcher misbehaves we restart it; upstream mitigations are out of scope for this phase |
