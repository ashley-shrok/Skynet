<objective>
Create a new backend helper file `src/backend/claude-session/session-file-range.ts` next to `session-file-tail.ts` that exports TWO functions Wave 2's `fetch_older` WS handler will call:

1. `readSessionFileRange(conn, sessionFile, startLine, endLine): Promise<ParsedLine[] | null>` — one-shot `sed -n 'M,Np'` range read + parse via existing `parseSessionLine`; shape matches `context-pct-from-jsonl.ts` exactly (the 43-PATTERNS.md § 3 analog).
2. `resolveEventIdToLine(conn, sessionFile, eventId): Promise<number | null>` — one-shot `grep -n '"uuid":"<eventId>"' <path> | head -1 | cut -d: -f1` lookup that returns the 1-based line number where the event lives, or null if not found. This is REQUIRED because the wire contract in plan 43-03 carries ONLY `anchorEventId` (no line offset); the server must resolve it to a line on demand.

Both functions share the same discipline: one-shot `execCommand` + `Promise.race` timeout, catch-and-return-null on any failure, single-quote wrap the path.

Purpose: These are the two atomic backend primitives Wave 2's `handleFetchOlder` will call in sequence: (a) resolve `anchorEventId → anchorLine` via grep, (b) compute `startLine = max(1, anchorLine - count)` and `endLine = anchorLine - 1`, (c) call `readSessionFileRange` for the slice. Landing both helpers with tests in isolation means the Wave 2 handler is pure wiring.

Output: A new file `src/backend/claude-session/session-file-range.ts` exporting BOTH functions. A dedicated unit test file locking all documented behaviors. Both files self-contained; no callers wire up yet (Wave 2's job).
</objective>
