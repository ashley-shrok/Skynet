<objective>
Land a backend `POST /voice/transcribe` endpoint that reverse-proxies a multipart audio blob to the tailnet-only faster-whisper STT service and returns the transcript JSON to the caller. Add matching nginx `location` blocks in BOTH nginx.conf and nginx-https.conf so the route survives the Docker frontend static-file fallthrough. Nginx routing is a mandatory fork gotcha (per CLAUDE.md) — every new backend route needs matching location blocks in both configs or the endpoint returns index.html and the frontend crashes trying to parse it as JSON.
Output: New route file + tests + database.ts mount + two nginx location blocks. No frontend touched in this plan.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PWA client → nginx | HTTPS public internet (untrusted); nginx terminates TLS and forwards to backend |
| nginx → backend (30001) | Loopback, trusted; body already authenticated at nginx layer by cookie propagation |
| Backend → faster-whisper STT (100.80.122.111:8000) | Tailnet-only, low-trust but internal; STT does not authenticate but is reachable only via Tailscale |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-01 | Denial-of-Service | POST /voice/transcribe multipart handler | mitigate | `multer({ limits: { fileSize: 25 * 1024 * 1024 } })` caps blob size before the buffer materializes; 25 MB is generous for a spoken clip (~20 minutes at high-bitrate PCM, longer at compressed audio) but bounded so a malicious client cannot exhaust backend memory |
| T-16-02 | Denial-of-Service | Backend → STT fetch call | mitigate | `AbortController` with 30-second `setTimeout` unconditionally aborts the outbound fetch if STT is slow/unreachable; a stuck STT cannot pin backend request-handling threads indefinitely |
| T-16-03 | Information disclosure | STT non-2xx response body | mitigate | Handler returns a fixed shape `{error: "STT non-2xx", status: <int>}` — does NOT forward the STT body verbatim on errors (STT could leak internal tailnet paths / stack traces in dev builds); the STT status code IS forwarded so the client can distinguish 5xx from 4xx |
| T-16-04 | Spoofing / Elevation-of-privilege | Voice route auth | mitigate | Route wires `authenticateJWT` (AuthManager.createAuthMiddleware) BEFORE the multer middleware — same middleware chain as every other /compose-drafts, /message-queue, /sessions route (unauthenticated requests get 401 from AuthManager before the body is even parsed) |
| T-16-05 | Tampering | Multipart content-type smuggling | mitigate | Handler does NOT parse-and-reserialize the client's multipart body — multer strips it into `req.file.buffer` and the handler constructs a FRESH FormData for the STT request using known-safe values (`file` field name, mimetype from multer's `req.file.mimetype`); no client-controlled Content-Type header reaches STT |
| T-16-06 | Information disclosure | STT URL leaking to client | accept | STT URL is a private tailnet IP; leaking the constant in an error message would still not let a public-internet attacker reach STT (they aren't on the tailnet). Handler doesn't leak the URL, but a code review discovering the constant is not a leak — it's the design contract |
| T-16-SC | Tampering | npm installs (multer, undici) | mitigate | multer + undici already present in package.json (verified via `grep multer package.json`); no new npm installs required in this plan. No `[ASSUMED]` / `[SUS]` packages introduced. |
</threat_model>
