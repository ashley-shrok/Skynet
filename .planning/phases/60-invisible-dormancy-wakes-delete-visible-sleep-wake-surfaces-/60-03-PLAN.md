<objective>
Delete the entire visible dormancy/wake surface from the frontend. When a pane is dormant, PrettyView renders identically to an awake-idle pane — same message list, same compose box (enabled), no bubble, no badge, no ambient marker. Also delete the now-consumer-less backend surfaces (`msg.type === "wake"` handler at claude-session-server.ts:5806-5831, `__applyWakeMessageForTests` seam at L2472-2492, `WakeResultEvent` API export at claude-session-api.ts:308+383) so the backend contract matches the frontend reality.

Purpose: Plan 01 taught the backend send-path to trigger wake invisibly. Plan 02 widened the watchdog window. This plan closes the loop by ripping out every UI surface that mentions dormancy/waking to the user. The pane feels the same whether or not its underlying claude session happens to be in memory — dormancy becomes a hardware detail the user never sees. "Delete, don't hide" (shape file philosophy).

Output: Two `.tsx` files fully deleted (DormancyOverlay + its component test); one dormant-disable test file deleted (ComposeBox.dormant-disable.test.tsx); PrettyView.tsx / ComposeBox.tsx / claude-session-api.ts / claude-session-server.ts pruned of every wake-UI surface; PrettyView.test.tsx + dormant-poll.test.ts updated to reflect the deletions (tests for DormancyOverlay mount / Wake-button click / wake_result WS round-trip either deleted or flipped to the new expectation: "no overlay ever mounts, compose stays enabled").
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| frontend WS -> backend `msg.type === "wake"` handler | Handler being DELETED in this plan. If the frontend ever sends `{type:"wake"}` after this ships (stale cached bundle, external client, etc.), the backend's outer `switch(msg.type)` falls through with no side effect — safe by default. |

So whether the frontend's local state thought the pane was dormant or awake, the backend uses its own current snapshot. If dormant at backend-entry, the dormant branch fires; if awake, normal send fires. Either way, correct. |
