## Trust Boundaries

This plan introduces a presentational component with one callback prop (`onRetry`). The callback is invoked in response to a user-gesture click; no untrusted input enters the component. No network I/O, no eval, no dangerous ref manipulation. Retry semantics (what onRetry actually does) are the concern of the plan 29-04 caller — this component is pure UI.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-29-02-01 | Spoofing | Retry button | accept | Button fires only on real DOM `click` event via React synthetic event; no programmatic invocation path exposed. Same UX shape as DormancyOverlay Wake button which passed prior fleet review. |
| T-29-02-02 | Tampering | Motion-channel guardrail | mitigate | Regression test (`animate-spin` negative assertion) prevents accidental future addition of the spinner class that would violate patch #72's state-vs-work channel invariant. |
| T-29-02-03 | Information disclosure | Copy text | accept | Copy is a static human-readable string with no PII or system state; safe for display on any surface. |

**Attack-surface delta:** none. This component is presentational; its onRetry callback is a user-gesture-triggered function reference passed in by the parent. Callback semantics are the parent's concern.
